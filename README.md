# MooX

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE) [![Release](https://img.shields.io/github/v/release/mooyang-code/moox)](https://github.com/mooyang-code/moox/releases) ![Go](https://img.shields.io/badge/Go-1.27-00ADD8.svg) ![平台](https://img.shields.io/badge/平台-macOS%20%7C%20Linux%20%7C%20Windows-lightgrey.svg)

**生产级分布式实时量化平台。** 行情采集、因子计算、策略决策、实盘交易、监控告警全链路一体化，部署在你自己的服务器上，一句话交给 AI Agent 装好。

- **实时**：1 分钟 K 线收盘后 **2.5 秒**，522 个永续合约、16 个因子、每个标的 5 万根历史全部算完，策略目标同步给出。
- **分布式**：采集、存储、计算、管控分布在多台机器上，各司其职。行情就近采集，海外行情走海外节点，云函数按地域横向扩展；重计算放到算力充足的机器上，家里或局域网的服务器也能加入；加机器即可扩容，不受单台机器的 CPU、内存和网络限制。
- **解耦、通用**：一套链路同时服务**加密货币、A 股、港股、美股**，各市场独立运行、互不干扰；采集、存储、因子、策略、交易、监控彼此解耦，可以单独升级、扩容或替换；因子和策略与市场无关，写一次就能用在不同市场。
- **实盘交易**：策略目标自动换算成订单，持续下单直到达到目标持仓，组合账户与人工干预随时可用；同一套策略先在模拟盘验证，再直接切到实盘。支持 Binance、OKX 与模拟盘（实现中），A 股、港股、美股券商接入（实现中）。
- **高性能**：单次计算覆盖 **2,610 万根 K 线**；包含 **1,960 个子策略**的复杂选币策略，从收线到出结果不到 5 秒（见[性能](#性能)）。
- **生产级稳定**：机器重启、网络中断、上游缺数据，都不会悄悄算错。缺的数据自动补齐，暂停后自动追平再恢复，同一份数据重算结果完全一致；全程签名鉴权，配置加密存储。
- **可观测、好运维**：从采集到策略，每个环节都有监控；数据一旦延迟或缺失，立即告警到企业微信 / 飞书，管理台首页汇总所有待处理事项；暂停、恢复、升级、回滚都只需一条命令。
- **上手快**：把一段话发给 AI Agent 就能完成部署和初始化，下载即用、无需编译；写因子像写公式，写策略像填表，上线前可以校验、试算和历史回放；Web 管理台与命令行功能对等。

MooX 是单用户系统：唯一的登录用户拥有全部管理能力，登录、会话、请求签名、防重放和配置加密始终开启。

## 性能

2026-10-29 生产环境实测，连续 6 小时（02:39～08:39 UTC），三个场景共 794 期全部成功、无跳期：

**规模**

| 场景 | 周期 | 标的 | 每个标的回看 | 参与计算的 K 线 | 因子 | 子策略 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 永续合约多因子 | 1 分钟 | 522 | 50,000 根 | 2,610 万根 | 16 个 | — |
| 轻量因子（含自定义算子） | 1 分钟 | 522 | 400 根 | 20.9 万根 | 3 个 | — |
| 复杂多因子选币策略 | 5 分钟 | 522 | 50,000 根 | 2,610 万根 | 45 个 | 1,960 个 |

**端到端耗时**（K 线收盘到策略目标产出）

| 场景 | 采集入库 | 因子计算 | 策略决策 | 全链路 p50 | 全链路 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 永续合约多因子 | 0.57 秒 | 1.35 秒 | 0.57 秒 | **2.48 秒** | 2.72 秒 |
| 轻量因子（含自定义算子） | 0.56 秒 | 0.52 秒 | 0.51 秒 | **1.61 秒** | 1.90 秒 |
| 复杂多因子选币策略 | 0.69 秒 | 2.69 秒 | 1.28 秒 | **4.64 秒** | 5.44 秒 |

- 永续合约多因子包含 EMA、MACD、RSI、布林带、ATR、VWAP 等 14 种因子。分段耗时取中位数：**采集入库**是 K 线收盘到行情入库、开始计算因子；**因子计算**包括读取、计算和写回结果；**策略决策**包括读取因子结果、求值、保存结果与目标权重。
- 测试环境：存储机 4 核 16G、管理台机 4 核 4G（腾讯云）；因子机 Intel Xeon E5-2696 v4、88 线程、128G 内存（局域网）。行情来自 Binance U 本位永续合约。

## 功能

| 环节 | 能做什么 |
| --- | --- |
| 采集 | 加密货币（Binance 现货、U 本位合约）实时推送与定时拉取，A 股、港股、美股行情接入；缺口自动巡检补采，K 线合成多周期，标的上下架自动同步 |
| 存储 | 统一管理市场、数据源、标的、标签、数据集与字段；行情与因子结果统一存储、按需保留，查询视图随时可重建；按日 / 月归档成 CSV |
| 因子 | 公式化定义因子（`ts_mean`、`cs_rank`、`ema` 等算子），每个周期实时计算，支持历史补算；公式写不出的算法可以用 Rust 编写自定义算子 |
| 策略 | 声明式策略：截面排序选股 / 选币、逐标的信号、分批持仓三类规则，统一止损止盈，策略模板与参数表批量生成；按周期输出目标权重，可用历史数据逐期回放 |
| 交易 | 目标权重自动换算为订单并收敛到目标持仓，组合账户、人工干预、模拟盘；Binance、OKX 实盘（实现中），A 股、港股、美股券商接入（实现中） |
| 监控 | 组件、主机、数据链路与业务检查的分层健康，数据集时效告警推送到企业微信 / 飞书，管理台首页汇总待处理事项 |
| 运维 | 所有调用签名鉴权、按方法授权，配置整份加密；部署、升级、回滚、暂停与恢复、系统重置都是一条命令，可以交给 AI Agent 操作 |

## 设计上的不同

MooX 和常见的开源交易框架定位不同：它不是嵌进代码的交易库或单机机器人，而是一套分布式部署的完整平台，数据、计算、执行和运维放在一起。

| | MooX | [freqtrade](https://github.com/freqtrade/freqtrade) | [nautilus_trader](https://github.com/nautechsystems/nautilus_trader) | [vn.py](https://github.com/vnpy/vnpy) | [WonderTrader](https://github.com/wondertrader/wondertrader) |
| --- | --- | --- | --- | --- | --- |
| 形态 | 分布式服务集群（多台主机分工协作）+ Web 管理台 + CLI | 单进程交易机器人 | 交易引擎库（Rust 核心、Python 接口） | Python 交易平台（桌面 GUI 与各类应用模块） | C++ 交易引擎 + Python 外壳 |
| 多市场 | 同一系统同时运行加密货币、A 股、港股、美股 | 加密货币 | 多资产，经适配器接入交易所与券商 | 国内期货、股票等，经各类交易接口接入 | 国内期货、股票等 |
| 数据 | 自带采集、补采、元数据目录和存储，因子与策略直接读系统里的数据 | 从交易所下载历史数据到本地文件 | 由使用者接入数据 | 数据库适配与数据服务 | 自带数据落地组件 |
| 因子与策略 | 因子是公式，策略是声明式规则，都可以先校验、试算再上线；输出截面目标权重 | 策略是 Python 类，逐交易对产生信号 | 用 Python / Rust 写事件驱动策略 | 用 Python 写 CTA、价差等策略 | 用 C++ / Python 写 CTA、选股、高频等策略 |
| 回测 | 按实盘时序逐期回放（因子 → 策略 → 纸面成交），不是向量化回测，也没有参数寻优 | 回测、参数寻优、FreqAI | 回测与实盘同一套引擎 | 回测模块 | 回测引擎 |
| 运维 | 签名鉴权与方法级授权、加密配置、全链路监控告警，由 Agent 通过 skill 和 CLI 完成部署与管理 | 配置文件、Telegram、FreqUI | 由使用者自建 | GUI | 由使用者自建 |

表中其他框架的描述只概括其公开定位，具体能力以各项目文档为准。

MooX 的特点：

- **分布式、解耦、通用**：多台机器分工协作，模块之间只通过标准接口和事件交互，每个模块可以单独暂停、恢复、升级和扩容；同一套系统同时运行多个市场。
- **声明式**：因子和策略是数据而不是代码，上线前能校验、试算和回放；同一类策略写个模板、换参数表即可批量生成。
- **为 Agent 设计**：管理台的功能在命令行里都有对应入口，skill 告诉 Agent 怎么部署、怎么排查、哪些操作要先问用户；密码与密钥只在用户本机的页面里输入，不经过 AI。
- **弹性采集**：海外节点接收 WebSocket 推送保证实时性，云函数按地域横向扩展拉取，自动补采缺口。

不适合的场景：高频与盘口级交易（最小周期 1 分钟）、需要大规模参数寻优的研究。

## 前置条件

- **云账号**：云上的自动化操作目前通过腾讯云 API 完成（其他云厂商后续接入）。建一个腾讯云子用户的 API 密钥，授权 `QcloudSCFFullAccess`、`QcloudCOSFullAccess`、`QcloudCLSFullAccess`、`QcloudLighthouseFullAccess`、`QcloudCVMFullAccess`、`QcloudVPCFullAccess` 六个预设策略。
- **服务器**（Linux x86_64；目前需要是上面这个腾讯云账号下的轻量应用服务器或 CVM，以便自动识别地域规格、开放防火墙）：

  | 角色 | 是否必需 | 建议配置 |
  | --- | --- | --- |
  | 存储机 | 必需 | 4 核 16G、100G 磁盘 |
  | 管理台 | 必需，可与存储机或海外机共用 | 2 核 4G |
  | 海外机 | 采集加密货币行情时需要，建议香港 | 2 核 4G |
  | 因子机 | 可选，可以是家里或局域网的 Linux 机器 | 8 核 16G |

- **本机**：macOS、Linux 或 Windows（amd64），能 SSH 到这些服务器。**不需要**安装 Go、Docker 或 Node：发布页提供编译好的产物。
- **告警**：企业微信或飞书群机器人的 Webhook 地址。

## 快速开始

把下面这段话发给你的 Agent（Claude Code、Codex 等能执行命令的 Agent）：

```text
请帮我安装并部署 MooX 量化系统：
1. 从 https://github.com/mooyang-code/moox/releases （国内网络用 https://cnb.cool/mooyang-code/moox/-/releases ）
   下载最新版本的 moox-bundle_<版本>_linux_amd64.tar.gz、适合我这台电脑的 moox-cli_<版本>_<系统>_<架构> 和 SHA256SUMS，校验后解压：
   产物包解压出 moox-<版本>/ 目录，把 moox-cli 放进 moox-<版本>/bin/。之后所有命令都在 moox-<版本>/ 目录里执行。
2. 把 moox-<版本>/skills/moox 安装成你的 skill（Claude Code：复制或软链到 ~/.claude/skills/moox），然后读取其中的 SKILL.md，按 references/install.md 执行。
3. 运行 ./bin/moox-cli config init，让我在自己的浏览器里填写云账号密钥、服务器 IP、开通 SSH 免密登录、设置管理员和告警。
   你不要打开、填写或读取这个页面和生成的 moox.toml。
4. 我填完后，按 skill 依次完成部署、初始化和验收，最后告诉我管理台地址和还需要我做的事。
所有写操作先给我预览，删除、清空、重置等操作必须等我确认。
```

Agent 会按 [安装与初始化](skills/moox/references/install.md) 逐步完成，部署完成后用浏览器打开 `https://<管理台地址>:9527`。

## 从源码构建

```bash
bash scripts/build/check-build-env.sh --profile all   # 检查 Go（版本见 .go-version）、Docker、Node、pnpm
make build      # 构建默认目标
make test       # Go 与前端测试
make verify     # 提交前的完整检查（与 CI 相同）
scripts/release/build-release.sh vX.Y.Z               # 生成发布产物
```

仓库是 Go Workspace（`go.work`），每个模块、共享包都是独立的 Go module；模块之间只通过 RPC 和事件交互。构建环境见 [构建手册](docs/构建手册.md)。
