## 定位

`moox-factor` 是单进程因子控制面与计算运行时。它通过 `FactorMgr` 管理因子集、定义
和补算任务；消费 Collector 的周期完成事件；经 Storage PrimaryStore 按需读取源
Dataset，将携带列和因子结果整行写入结果 Dataset，并报告 `FactorPeriodComputed`。

Factor 不消费 View 就绪事件，不依赖 View 进行输入读取，也不维护本地实时事件账本、
binding、Merge 服务或 Factor DAG。View 是 Storage 为查询提供的索引；`factor_result`
Dataset 激活时由 Storage 创建默认结果 View。Spot 与 Swap 行使用 `series_tag` 共存于
同一源 Dataset。

## 持久化模型

Factor SQLite 只包含三张业务表：

- `t_factor_sets`：source Dataset、space、频率、subject scope、结果 Dataset 与集合状态。
- `t_factor_defs`：因子类型、源码及 hash、完整输入列、输出列、静态参数、lookback 和状态。
- `t_factor_recalc_jobs`：异步补算范围、筛选条件、进度、结果摘要与恢复状态。

集合 ID 和结果 Dataset ID 由 source Dataset 与频率确定。输出列归属用 Storage 列元数据
中的 `origin=factor`、`origin_id=<factor_id>` 表示。删除因子定义或禁用因子不删除结果
列；禁用后流水线不再写该因子的结果。

因子定义显式声明完整 `input_columns`，框架不推断源码依赖，也不默认注入 OHLCV。
`params_json` 必须为 JSON object。`lookback_periods` 按不同 `data_time` 周期计数，
不按同一周期的 `series_tag` 行数计数。保留系统列为 `subject_id`、`freq`、
`data_time`、`series_tag`，系统列不得声明为输入或输出。

## 周期流水线

实时事件链路如下：

```text
CollectorPeriodCompleted
  -> durable factor_collector_period_v1
  -> 因子集 lane 排队
  -> 冻结启用定义并规划最大 lookback 窗口
  -> Storage PrimaryStore 读取源 Dataset
  -> Python worker 批量执行
  -> Storage WriteFactorRows（携带列 + 因子列）
  -> ReportFactorPeriodComputed
  -> ACK
  -> Storage View 发布 ViewDataReady
```

每个因子集有串行 lane，不同因子集可并行。一个周期先冻结当时启用的因子定义；一个
因子集只读一次共享时间窗，因子在同一个 Python 请求内批量运行。按 subject 读窗口，
时序因子逐 subject 执行，截面因子使用同周期面板。结果行以
`(data_time, series_tag)` 为身份，写入结果 Dataset 时同时保留源业务字段。实时和补算
调用同一个 `pipeline.Runner`。

同一 Dataset 的行与周期标记由一个 DataNode outbox 保序。`WriteFactorRows` 使用确定性
commit ID 幂等去重，固定 `write_kind=factor_result`；只有该专用 RPC 可以写因子结果
列。完成标记在结果行写入之后报告，因此 View 消费者应用标记时，结果数据已经在其输入
日志顺序中。

一次因子计算失败只影响该因子或 subject；可恢复的 Storage 基础设施错误会让消息重投，
其他计算错误汇总为周期状态后仍报告完成并 ACK，避免坏因子阻塞整条 lane。durable 名为
`factor_collector_period_v1`，使用 `DeliverNew`，处理期间定期续期；崩溃导致的未 ACK
事件由 JetStream 重投。历史回补通过异步 Recalc job 执行，不额外建立实时账本。

## 时间、范围与补算

当前只支持 crypto 连续周期日历；不支持的 space 返回 `unsupported space calendar`。
窗口按升序返回，目标范围采用左闭右开 `[start, end)`。补算按最多 2000 个目标周期分块，
每块不拆分同一 `data_time` 下的 tag cohort，并在块起点前读取所需 lookback。已完成块
不会因后续块失败回滚；相同 request ID 可用于幂等提交。

因子集配置 `subject_mode=all` 或明确的 include 集合。补算可按因子和 subject 缩小执行
范围，但不能增加或覆盖持久化定义中的输入、输出和参数。重启时 `running` job 恢复为
可继续执行状态。

## Python 契约

因子源文件定义 `compute(df, params, context)` 并返回 pandas DataFrame。输入列仅包含
`data_time`、`series_tag` 与已声明业务输入；行按 `(data_time, series_tag)` 升序。输出
必须包含系统身份列和全部声明输出列，且身份唯一。数值必须有限；NaN 与正负无穷归一为
显式 null。省略字段表示保留旧值，显式 null 用于清除单元格。

模块版本缓存按 `source_hash` 隔离。Go 与 Python 使用常驻进程池和 JSON 帧协议，批量
请求中各因子各自返回结果或错误；一项失败不改变其它因子结果。

## RPC、CLI 与可观测性

FactorMgr 管理因子集、因子定义、状态和异步补算；定义接口包括 `CreateFactorSet`、
`ListFactorSets`、`CreateFactor`、`SetFactorStatus` 和 `RecalcFactors`。新定义以
disabled 创建，启用前对齐结果 Dataset 列并提交补算任务。禁用保留列和已有值，但停止
后续写入。

`moox-factor-cli` 提供 `init`、`import`、`import-catalog`、`recalc`、`run-once`、
`status`。服务配置分为 `database`、`storage`、`eventbus`、`python`、`pipeline`、
`recalc`；Python 与 pipeline 配置不再置于 engine 配置块。

Prometheus 指标包括：

- `factor_period_duration_seconds{set,stage}`、`factor_period_lag_seconds{set}`。
- `factor_period_total{set,status}`、`factor_failures_total{set,factor,reason}`。
- `factor_lane_backlog{set}`、`factor_python_busy`、`factor_last_period_time{set}`。
