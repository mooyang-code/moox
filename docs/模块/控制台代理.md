# 控制台代理

状态：实施中。已有组件目录、软件打包和目标主机编排，现行生产部署仍使用外置 Caddy；原生部署入口和完整系统验收尚未交付。
本页只描述已有模块能力，完成状态以[执行计划](../2026-10-09-console-proxy-embedded-caddy-execution-plan.md)和实际验证为准。

`modules/consoleproxy` 构建为 `moox-console-proxy`，独立进程内嵌 Caddy `v2.11.4`。
`serve --config <path>` 运行服务；`validate --config <path>` 仅做配置校验与 JSON 构造，不 provision、不签发证书；
`check-state --config <path>` 只读核验现有 CA 证书/私钥、有效期、基线和已发布指纹，输出含公开指纹的 JSON（指纹值不含换行）；缺少 internal CA 会失败，不 provision、不写入 legacy 基线。安装器用它核对停止前后、状态复制后和启动后的 CA 连续性。
默认 `check-state` 要求持久基线已经存在；`check-state --for-import` 改为历史导入前的只读检查，允许尚无基线，但必须有原始发布的根证书与指纹。证书文件只接受单张 PEM，拒绝夹带其他信任根。
`initialize-state --config <path>` 显式离线初始化空状态，只加载 PKI，不监听 HTTP/健康端口、不申请站点证书、不安装系统信任；`--import-existing` 校验原始发布的根证书与指纹后补齐持久基线。两者均由持维护锁的部署编排调用，不能对运行中的状态使用。
`version` 输出组件版本、提交、构建时间与引擎版本；`stop-budget --config <path>` 输出外层启停等待秒数。

配置见 `modules/consoleproxy/config/app.yaml`。相对状态路径以配置文件目录为基准；健康密钥沿用 `MOOX_HEALTH_AUTH_*`，
不写入发布配置。现有 CA 在 Caddy 加载前核对证书、私钥及持久指纹；常规启动不生成缺失 CA，也不自动补写历史基线。配置不再接受 `initialize_ca`。
目标 bootstrap 在部署根 `identity/console-proxy/` 保存独立于发布和数据快照的私密授权凭据及完整初始材料。请求通过 `proxy_ca.create` 明确授权首次生成，或用 `proxy_ca.import_directory` 指定关闭后的规范历史状态，两者互斥。凭据先记录 pending，完整材料同步并原子发布后记录 ready；生成阶段未发布的状态可重试，已消费材料丢失则拒绝重建。首次失败和强杀恢复复用同一 CA，升级校验其与持久身份一致并复制最新关闭状态，保留证书缓存。
public-only 安装不加载 PKI、不创建 internal CA；有 internal 历史时仍验证并保留原来的 CA 与持久指纹。

公开入口默认 9527，只转发 `/api/admin/*` 和页面/静态资源。其他 API 与诊断路由返回 404。
诊断默认 `127.0.0.1:19528`，沿用 health HMAC 和共享健康 payload；TLS 握手通过后才就绪。
SIGTERM 关闭新请求准入，先排空已有 HTTP、流式及升级请求，再停止引擎与清理锁。

当前还没有正式发布包、现行 Monitor 注册或真实环境验收证据；这些工作和新网关协议完成后一起切换。
