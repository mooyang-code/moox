# 控制台代理

控制台代理已接入组件目录、软件打包、原生 `setup bootstrap --stage control`、CA 授权与恢复、
Monitor 的进程及 HTTPS 页面探针。生产切换与完整系统验收另行确认；当前范围见[实现状态](../实现状态.md)，
历史决策与阶段证据见[执行计划](../2026-10-09-console-proxy-embedded-caddy-execution-plan.md)。

## 1. 进程与离线命令

`modules/consoleproxy` 构建为 `moox-console-proxy`，独立进程内嵌 Caddy `v2.11.4`。
`serve --config <path>` 运行服务；`validate --config <path>` 仅做配置校验与 JSON 构造，不 provision、不签发证书；
`check-state --config <path>` 只读核验现有 CA 证书/私钥、有效期、基线和已发布指纹，输出含公开指纹的 JSON（指纹值不含换行）；缺少 internal CA 会失败，不 provision、不写入基线。安装器用它核对停止前后、状态复制后和启动后的 CA 连续性。
`check-state` 要求持久基线已经存在。证书文件只接受单张 PEM，拒绝夹带其他信任根。
`initialize-state --config <path>` 显式离线初始化空状态，只加载 PKI，不监听 HTTP/健康端口、不申请站点证书、不安装系统信任；由持维护锁的部署编排调用，不能对运行中的状态使用。
`version` 输出组件版本、提交、构建时间与引擎版本；`stop-budget --config <path>` 输出外层启停等待秒数。

## 2. 配置与 CA 生命周期

配置见 `modules/consoleproxy/config/app.yaml`。相对状态路径以配置文件目录为基准；健康密钥沿用 `MOOX_HEALTH_AUTH_*`，
不写入发布配置。现有 CA 在 Caddy 加载前核对证书、私钥及持久指纹；常规启动不生成缺失 CA，也不自动补写历史基线。配置不再接受 `initialize_ca`。

**证书寿命**：internal 模式下叶子证书固定 90 天、中间证书 1 年（根证书约 10 年不变）。Caddy 默认叶子证书只有 12 小时、约每 8 小时换一次；
浏览器里只对“当前这张证书”点过继续访问、没有安装根证书的用户，每次换证后页面的后台请求（例如定时拉取接口）就会报 Network Error，
要刷新页面重新信任才恢复。拉长寿命后换证变得很少（到期前约 30 天自动续期）。**根本的办法仍是把已发布的根证书 `certs/caddy/root.crt`
安装到系统信任库**：根证书不变，换叶子证书和中间证书都不会再影响浏览器。

**根证书下载（登录前可用）**：internal 模式下，公开入口额外提供三个只读的公开路径，由 `moox_console_ca` 处理器直接读取 `certs/caddy/` 发布目录：
`/ca/root.crt`（根证书）、`/ca/root.sha256`（SHA-256 指纹）、`/ca/moox-root-ca.zip`（安装包）。安装包含根证书、指纹、各系统的安装脚本
（`install.sh` 与 `scripts/deploy/install-caddy-ca.sh` 同源，由测试保证一致；`install.ps1` 面向 Windows）和给 Agent 阅读的 `AGENT-INSTALL.md`
（先让用户通过可信渠道核对指纹、不索取密码、不绕过证书校验，再安装并验证）。处理器只接受“恰好一张证书”的 PEM 文件，不会输出私钥或目录里的其他内容；
public 模式下不注册这些路径。入口在管理台“秘钥管理”页的“HTTPS 根证书”按钮和登录页的“下载并安装根证书”链接。
**可信边界与迁移**：安装包经由尚未被信任的连接下载，包内的指纹、说明和脚本都可能被一起替换，所以唯一的可信锚点是用户通过另一条渠道确认的指纹；
`AGENT-INSTALL.md` 要求 Agent 自己计算证书指纹、优先用系统命令安装、不要不加检查地运行包内脚本。初始化主机（`moox-cli setup init` / `setup trust-browser`）
会经 SSH 从控制机取回根证书并安装到当前机器（不经过 HTTPS，没有中间人问题），`setup init` 的 `browser_trust` 输出记录缓存路径、指纹和其他机器的做法。
手机同样要各装一次：iPhone 用 Safari 下载后在“VPN 与设备管理”安装，并且必须在“关于本机 → 证书信任设置”里打开完全信任；Android 在“加密与凭据 → 安装证书 → CA 证书”安装。弹窗会按设备自动停在对应页签。
换电脑或迁移机器时，每台新机器：拿到可信指纹 → 下载安装包核对并安装 → 重启浏览器；有仓库和 SSH 权限的机器直接运行 `setup trust-browser`。
浏览器之外的客户端读的证书库不同：系统自带 curl 和 Go 程序读系统信任库，Node.js 要设 `NODE_EXTRA_CA_CERTS`，Python 要设 `REQUESTS_CA_BUNDLE`，
Homebrew 的 curl 用 `--cacert`；`moox-cli` 自己用系统信任加初始化缓存的根证书，校验失败会经 SSH 重新取回。任何客户端都不应使用 `-k` 之类关闭校验的开关。
原生 bootstrap 在部署根 `identity/console-proxy/` 保存独立于发布和数据快照的私密授权凭据及完整初始材料。请求通过 `proxy_ca.create` 明确授权首次生成。凭据先记录 pending，完整材料同步并原子发布后记录 ready；生成阶段未发布的状态可重试，已消费材料丢失则拒绝重建。首次失败和强杀恢复复用同一 CA，升级校验其与持久身份一致并复制最新关闭状态，保留证书缓存。
public-only 安装不加载 PKI、不创建 internal CA；有 internal 历史时仍验证并保留原来的 CA 与持久指纹。

## 3. 访问与退出

公开入口默认 9527，只转发 `/api/admin/*` 和页面/静态资源。其他 API 与诊断路由返回 404。
诊断默认 `127.0.0.1:19528`，沿用 health HMAC 和共享健康 payload；TLS 握手通过后才就绪。
SIGTERM 关闭新请求准入，先排空已有 HTTP、流式及升级请求，再停止引擎与清理锁。

## 4. 部署与验证

软件包含在 `control` profile 中。core 阶段只准备制品，不启动代理；control 阶段根据控制主机地址渲染
公开 Host、TLS 模式与 Monitor 页面探针。internal 模式的首次创建必须显式传入授权，
普通 serve 不隐式修复身份。流程及参数见[部署与运维](../部署与运维.md)。

`make test-console-proxy` 执行模块测试和 vet；完整 Linux 场景还需 `test-unit-runtime-linux`、
`test-unit-bootstrap-linux`、`test-unit-core-linux` 的真实制品。已有软件包和测试入口不等于生产切换已完成。

## 5. 访问方式的安全考量

管理台直接在公网 IP 上提供 HTTPS，证书由控制台代理的内置 CA 签发。下面记录这样选的理由，以及考虑过但没有采用的方案（2026-10 讨论后确定）。

**为什么不用纯 HTTP。** 登录密码和接口鉴权只能防住没有凭据的人，防不住能看到或改动流量的人（公共 Wi-Fi、所在网络、链路上的设备）：

- 登录时前端用“盐值 + 时间戳”派生 AES 密钥加密密码（`packages/security/crypto.go`），但盐值是同一连接里明文下发的，窃听者能还原出密码。前端加密代替不了传输加密。
- 访问令牌和请求签名密钥都在登录响应里下发，被看到后对方不需要密码就能以你的身份调用所有接口。
- 秘钥管理里新增、修改交易所或云账号的 API Key 时提交的是明文；中间人还能往页面里注入脚本，或改掉提交的内容（包括手动下单）。
- 前端的请求签名用浏览器 WebCrypto（`web/src/utils/request-signing.ts` 的 `crypto.subtle`），浏览器只在安全上下文（HTTPS 或 `localhost`）提供它：用 `http://公网地址` 打开，签名做不了，所有管理接口都会失败。

**为什么不靠“继续前往”。** 不装证书也能点浏览器警告页的“继续前往”打开页面，但这只放行那一次页面加载：页面里的后台请求需要新建连接时
（空闲一段时间后、服务重启后、同时发很多请求时）会在证书校验处失败，表现为成片的“无法连接管理台”；浏览器重启后还要再点一次。
安全上，每次都点“继续”等于接受对方给的任何证书，真被冒充时看到的警告和平时一样，分辨不出来。所以常用的电脑和手机都应安装根证书，
偶尔临时查看才点“继续前往”。前端对网络层失败只显示一条带证书指引的中文提示（`web/src/api/network-error.ts`），相同提示自动去重。

**考虑过的替代方案：**

| 方案 | 优点 | 没采用的原因 |
| --- | --- | --- |
| 域名 + 公共证书（控制台代理的 public 模式） | 任何浏览器直接信任，不用装证书 | 需要域名；境内机器用 80/443 做证书校验时，未备案域名可能被拦，改走 DNS 校验要给内嵌 Caddy 加插件 |
| Tailscale 一类的内网工具（可签发 `*.ts.net` 公网证书） | 不用装证书，9527 可以不再对公网开放 | 每台设备要装客户端并保持连接；手机同时只能开一个 VPN，和代理 App 冲突；国内直连打不通时走海外中转，延迟高；访问者都要加入 tailnet |
| 只在本机监听 + SSH 隧道访问 `http://localhost` | 不用装证书，`localhost` 是安全上下文 | 每次要开隧道、要有 SSH 权限，手机上不现实 |

**结论：保持公网 IP + 内置 CA。** 这样电脑和手机在任何网络下都能直接用浏览器访问；代价是每台设备、每个浏览器装一次根证书，
已经用登录页与“秘钥管理”页的下载入口、带 Agent 说明的安装包、初始化时自动安装来降低成本。根证书约 10 年不变，换叶子证书和中间证书都不影响已安装的设备。
将来有了可用的域名，可以切换到 public 模式改用公共证书。
