# 主机代理（HostAgent）

`moox-host-agent` 是每台 Linux 主机上的用户级服务，采集本机资源并发布到 EventBus，
由 Monitor 统一入库和告警。它不保存样本，也不内嵌 broker。

代码位置：`modules/hostagent`；快照协议在 `packages/hostmetricpb`。

## 1. 进程与端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| `HostAgentMgr` | loopback tRPC `11426` | `GetStatus`、`GetSnapshot`、`RunOnce` |
| 健康检查 | `11425` | 生产部署绑定 `0.0.0.0`，只接受 health HMAC 签名，供 Monitor 跨机探测 |
| `sample.timer` | 每分钟（启动时立即执行） | 采集并发布一次主机快照，单次超时 30 秒 |

## 2. 采集

- 读取 CPU、内存、文件系统、磁盘 I/O 和网络计数器，算出使用率和速率。
- 读取 `/proc/<pid>/stat`，随快照上报占用最高的进程（`top_processes`）：CPU 前 5 与内存前 5 合并去重，最多 10 个。
  - CPU 是两次采样之间的平均占用，按单核百分比表示，与 `top` 一致（340% 即 3.4 个核）。算法是“进程 CPU 时间的增量 ÷ 整机 CPU 时间的增量 × 核数”；第一次采样、进程在上一次采样时还不存在、PID 被新进程复用时没有 CPU 值。
  - 进程名取可执行文件的文件名（`/proc/<pid>/exe` 指向的路径）；别的用户的进程和内核线程读不到，用内核里的进程名 `comm`（最多 15 个字符）。`comm` 可以被进程改写（例如 `sshd: user@pts/0`），只取空白之前的第一段；内核线程的名字本身带斜杠（`ksoftirqd/0`），原样保留。两种来源最后都把控制字符换成问号。
    不读 `/proc/<pid>/cmdline`：进程可以改写自己的命令行（sshd、postgres、Node 等），里面可能带参数甚至密钥；而且读它要拿目标进程的内存映射锁，目标进程卡住时会把采集一起卡住。
  - 核数取 `/proc/stat` 里 `cpuN` 的行数。内存是常驻内存（RSS），包含文件映射和共享内存，和整机“已用内存”（按 `MemAvailable` 算）不是一个口径，各进程相加会超过整机已用。
  - 短命的子进程（定时任务、崩溃后反复重启的进程）在两次采样之间就结束了，排行里看不到。`/proc` 挂载了 `hidepid` 时只能看到 HostAgent 同一用户的进程。
  - 这一项读不到不影响其他指标，采集状态里记为 `process` 失败。只有 Monitor 用它（告警正文、告警事件、主机监控详情页），不写入 Storage，也没有历史。
- 每次采集生成一条主机快照事件（`MOOX_OBSERVABILITY`，凭据角色 `hostagent-publisher`），尽力发送，失败不重试。
- 定时和手动 `RunOnce` 共用同一把非重入锁，同一时刻只有一次采集。采集由 tRPC 定时器驱动，
  首次或后续采集失败会更新错误状态并等待下一轮；首次成功采集前 `/readyz` 不就绪，发布失败不影响采集就绪。

## 3. 身份

每台主机有一个稳定的 4 位字母数字 `agent_id`，保存在 0600 身份文件
`~/.local/state/moox/hostagent/identity.yaml`（第 3 版：`version`、`agent_id`、`created_at`），
这是 HostAgent 自身保存的采集身份。原生 host 单元把 `identity_path` 渲染到发布内
`host-agent/data/identity.yaml`，由发布状态复制保持稳定。

`config/app.yaml` 的 `host_id` 关联 Admin 登记的主机，由原生安装器注入；`host_name` 只用于展示，
操作系统 hostname 不参与关联。没有 host_id（或不在登记里）的 Agent 不会进入主机监控列表，Monitor 只按登记主机汇总最近上报的采集器。

## 4. 主机策略同步

原生 host 单元里的 HostAgent 还负责把告警渠道带到本机：部署时渲染 `gateway_client`（调用方 `host-agent`）与
`host_policy_path`（`<部署根>/run/host-policy.json`），启动时拉一次、之后每 5 分钟经本机网关调用 Monitor 的 `GetHostPolicy`
（服务目录只允许调用方 `host-agent`），拿到全部通知渠道与主机守护参数。内容摘要变化时版本号加一并原子写入（0600），
内容不变不重写；拉取失败或返回非法渠道时保留旧文件。指标：`moox_hostagent_host_policy_sync_total{result}`、
`moox_hostagent_host_policy_last_success_timestamp_seconds`、`moox_hostagent_host_policy_version`。
本机守护（`moox-runtime watch`）与 Admin 证书巡检只读这个文件，控制面不可用时也能直接推送告警。
独立运行的 HostAgent 不设置这两项，不拉取。打不开网关客户端只记录错误，不影响采样。

Monitor 3 分钟收不到某台主机的快照时，会结合该主机网关的心跳区分“主机失联”（网关心跳也停）与“host-agent 停止上报”（网关心跳正常）。

## 5. 部署

Host Agent 通过 `moox-cli setup deploy-host --file ./moox.toml --host <主机ID>` 与 HostGateway
一起安装，使用 `moox-runtime` 管理；EventBus 凭据在安装时从 Admin 导出写入发布目录。
`/readyz` 只看采集循环（至少成功采集过一次，且最近一次采集没有出错），**不依赖 EventBus**：EventBus 不可达（还没部署、所在主机宕机）时 HostAgent 仍然就绪，
只是发布不出样本；发布错误和连接状态放在状态接口（`eventbus_connected`、`last_error`）与指标里，发不出样本由 Monitor 的“host-agent 停止上报”告警。
否则部署流程会因为远端服务不可用而反复杀掉它。验证时使用 `moox-cli doctor diagnose --node <node>`，
不要用未签名的远程 `curl` 访问健康端口。
