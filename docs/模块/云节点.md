# 云节点（CloudNode）

CloudNode 是 MooX 对云函数平台（目前是腾讯云 SCF）的控制面：管理云账号、函数代码包和函数节点，
把创建、部署、删除、运行配置变更这类云端操作做成可追踪的异步批次，并提供函数调用。

代码位置：`modules/cloudnode`。

## 1. 进程与端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| `CloudNodeMgr` | loopback tRPC `11401` | 经主机网关供 Collector、CLI 调用，经 Admin 供管理台调用；空间标识从 `X-Space-Id` 元数据读取 |
| 健康检查 | `11411` | `/healthz`、`/readyz`、`/metrics` |
| `metrics` 定时器 | 每 30 秒 | 上报指标 |

数据保存在 `data/moox_cloudnode.db`（SQLite），表结构见 `schema/cloudnode.sql`。

Collector 复用进程级 `gatewayclient`，CLI 复用命令持有的 SSH 隧道客户端；Admin 的垃圾回收使用独立的 `admin` 签名身份，该方法不放行 `console`。同步函数调用的 RPC 超时上限为 960 秒，客户端按服务目录使用此预算，调用上下文可以进一步缩短。代码包的 COS 上传继续使用预签名 HTTPS 地址。

## 2. 领域模型

| 对象 | 表 | 说明 |
| --- | --- | --- |
| CloudAccount | `t_cloud_accounts` | 云账号业务配置，只保存 `credential_secret_id`，不保存密钥本身 |
| FunctionPackage | `t_cloud_function_packages` | 代码包：COS 地域、桶、路径、版本、运行时、状态 |
| CloudNode | `t_cloud_nodes` | 一个云函数：地域、命名空间、函数名、代码包、触发方式、Timer 期望与实际状态、运行配置、业务类型 |
| NodeBatch / Item | `t_cloud_node_batches`、`t_cloud_node_batch_items` | 一次批量变更及其逐项状态 |

## 3. 云账号与密钥

腾讯云 SecretID/SecretKey 由 Admin 的 SecretMgr 加密保存。CloudNode 每次操作 SCF 或 COS 时，
复用进程级 `gatewayclient`，以 `cloudnode` 身份调用原生 `SecretMgr.GetSecretValue` 实时读取，并校验密钥处于启用状态、
类别为 `cloud`、厂商为 `tencent`；密钥不缓存、不落库、不写日志。

## 4. 代码包

`InitPackageUpload` 返回 COS 上传地址，上传完成后调用 `CompletePackageUpload` 登记为可用；
`GetPackageList`、`GetPackageDetail`、`GetPackageDownloadURL`、`DeletePackage` 用于查询和清理。
代码包不包含任何凭据。

`CollectGarbage` 由 Admin 每天调用一次，`dry_run` 只统计不删除：

| 清理对象 | 条件 |
| --- | --- |
| 代码包记录及其 COS 对象 | 没有任何未删除节点在用，且已被 `DeletePackage` 删除或创建超过 6 小时；有进行中的批次时整体跳过 |
| 孤立 COS 对象 | 位于 `moox/cloud-packages/` 下、没有代码包记录引用、最后修改超过 6 小时 |
| 已删除节点记录 | 软删除且最后修改超过 24 小时 |
| 节点批次及明细 | 已结束超过 7 天，且没有待释放的发布租约 |

先删记录再删 COS 对象；COS 删除失败的对象成为孤立对象，在下一次清理时删除。云账号的 COS
凭据不可用时保留该账号下的代码包记录，结果的 `skipped` 说明原因。

## 5. 函数节点与批量变更

| 方法 | 作用 |
| --- | --- |
| `SubmitCreateNodes` | 批量创建函数（首次发布时写入完整环境变量） |
| `SubmitDeployNodes` | 批量部署新代码包：先读取函数完整环境，更新代码后只替换 `MOOX_CODE_PACKAGE_ID` 并更新函数配置 |
| `SubmitDeleteNodes` / `BatchDeleteNodes` | 批量删除 |
| `SubmitUpdateNodeRuntimeConfigs` | 批量更新运行配置：环境变量、Timer 开关与 cron 等 |
| `GetNodeBatchChange` | 查询批次进度 |
| `GetNodeList` / `UpdateNode` | 查询节点、修改节点元数据 |
| `PreviewSCFFunctions` / `ImportSCFFunctions` | 把云上已有函数导入为节点 |
| `ListCloudRegions` | 可用地域 |

批量变更在后台由节点批次执行器处理（每次取 3 项，轮询间隔 500 ms）。每项操作对函数加锁，
本地记录只在云端操作都成功后才更新；采集函数的变更还要校验 Admin 签发的采集发布租约，
避免多个发布流程同时修改同一组函数。

Collector 通过 `SubmitUpdateNodeRuntimeConfigs` 把函数的分片任务、DNS 路由等写进环境变量；对 Timer 模式的
函数（stockcn）还控制 Timer 的启停，实际状态会回读并记录，供 `moox-cli collector function timer-inventory` 核对。

## 6. 函数调用

`InvokeFunction` 以同步（RequestResponse）或异步（Event）方式调用一个函数节点。Collector 用它以异步方式
驱动 crypto 的 Invoke 函数池完成每个周期的采集，也用它执行重试、补采和探针任务。

## 7. 本地节点

地域为 `local` 的节点不调用腾讯云，只需要一个可用的代码包描述，用于端到端测试。

发布租约及操作围栏的七个 Admin 方法共用此客户端，空间元数据与 fencing token 参与原请求。退出时先取消并等待批处理循环，再释放客户端和数据库；初始化失败使用同一清理入口。
