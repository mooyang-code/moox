# 前端（Web）

MooX 管理台基于 Vue 3、Vite 5、TypeScript、Pinia 和 Arco Design，源码在 `web/`；
静态资源由 `web-host/` 打包成单个 Go 二进制提供。

## 1. 访问链路

```text
浏览器 ─► moox-console-proxy :9527 ─┬─ /api/admin/* ─► Admin 管理入口 :11000
                                   └─ 其他路径 ─► moox-web-host :9528（静态资源与 SPA 回退）
```

- 生产构建只调用同源的 `/api/admin/{service}/{method}`，不直接访问各后端服务；开发模式可用 `VITE_ADMIN_ORIGIN` 覆盖 HTTP 与 WebSocket 的入口。
- Storage 统一走 `/api/admin/storage/{method}`，由 Admin 的 Storage BFF 映射到 Storage 服务；
  BFF 只开放管理台实际使用的方法。
- SSH 终端用 WebSocket `/api/admin/ssh/WsConnect`，先换取短时票据再连接；建连只传登记主机的字符串 `host_id`，登记了 SSH 端口的主机才能打开终端和文件管理，其余置灰并说明原因；终端外观存浏览器本地。
- 主机、部署、数据节点在管理台**只读**，页面提示通过 moox skill（`moox-cli`）新增、部署、启停与移除；系统只有一个超级用户，前端不区分角色，也没有权限指令。
- 每个管理请求都带会话签名和当前空间（`X-Space-Id`），见[管理后台](管理后台.md)。
- 页头的空间下拉只列交易市场空间：以 `mooxsys` 开头的是系统内部空间（主机指标及其视图），不在下拉里出现，
  空间管理页里也不能设为当前（`src/store/modules/space.ts` 的 `isSystemSpace`）。
- `web-host` 收到 `/api/*` 直接返回 404，避免误把它当成代理。

## 2. 页面

菜单由 `src/api/modules/system/static-menu.ts` 静态声明，路由在 `src/router/route.ts`：

| 菜单 | 页面 |
| --- | --- |
| 首页 | 总览 |
| 数据采集 | 采集任务（排第一，也是目录落地页；从菜单进来默认看“运行状态”页签；任务、运行状态、补采、执行器即云函数实例、采集结果，页签和各自的筛选都在 URL 里）；数据源、数据对象（页签和所选标签进 URL）、基础字段 |
| 因子计算 | 因子总览；因子定义（新建 / 编辑）；计算任务页（即因子任务：任务、计算结果、补算）——新建任务要填展示名，加成员时选固定 / 可变并实时预览成员键与全部列名（`src/utils/factor-name.ts`，与 Go 的 `packages/factorname` 共用测试向量），详情列出每个成员的列名（可复制）与关联的策略实例；结果页默认隐藏系统列 `__params`，「显示参数」开关打开后按成员展开 |
| 策略管理 | 策略总览；策略定义（新建 / 编辑，含动态调参模板）；运行实例（工作台）；实例详情（创建实例时按策略的市场模式绑定因子任务：只涉及一个市场绑一个；现货、永续都涉及时选“输入方式”——现货、永续各一个因子任务（双任务，两个 View 本期都到齐才求值），或统一数据集上的一个任务；策略池按各成员所需市场的并集绑定；只能选未关联的任务，并列出全部列名，可变成员提示要写 `factor_params`；策略池实例的结果里另有成员净值、分配比例和择时曲线；详情页看绑定解析、最近一次参数提交与各期投递状态、外显设置；实例没有删除，不能改绑因子任务（停用后仍可改定义和账户）） |
| 交易管理 | 交易账户（只此一项，路由 `/trading/accounts`）：列表页顶部用页面标题页签分模拟盘、测试网、生产环境（`?env=`），下面用圆角子页签分组合账户、执行账户（`?list=execution`）：组合账户页签是平表，执行账户页签列出当前环境的全部执行账户（市场、所属组合、状态、权益，展开改账户设置，未加入组合的行上直接加入组合）；组合详情是整页 `/trading/accounts/:logical_account_id?tab=`，页签为概览、持仓与目标（按币一行，现货、永续的目标、实际、偏差分开算）、订单、成交、资金流水、成员与设置；新建账户四步（类型、交易所与密钥、市场与参数、组合），模拟盘、测试网、生产环境都可以建（生产环境选密钥后先检测账户类型和权限，并要确认密钥没有提现权限；币安测试网一个账户只能开通一个市场）；危险操作按环境分三档确认，生产环境要输入组合名称 |
| 数据归档 | 归档任务（`/archive/tasks`：顶部一行执行器状态，点进归档存储；任务列表与详情，详情页签有分区（远端已校验的分区可下载，未就绪的置灰并在悬停里写原因）、运行记录（导入运行显示文件名与“只补空缺 / 覆盖已有”，长消息折叠后点开看全部）、最新数据（选标的看暂存库里最近的行，默认 200 行、“更早”翻页）；新建任务填目录名，默认建议值，冲突时标红并显示完整路径预览）；归档存储（`/archive/storage`：执行器所在主机、归档根目录、磁盘已用 / 总量 / 可用与下限、对象存储、当前避让规则与依据、`datasets.csv` 说明）。下载与最新数据走 Admin 的裸 HTTP 路由（`src/api/archive/raw.ts`），只支持执行器装在 control 或只出站主机上，见 `docs/模块/归档.md` 第 9 节 |
| 事件中心 | 一页（`/events`，一级菜单），页内三个页签（`?tab=`）：事件（可订阅的事件、订阅条数、详情里的 data 字段说明和示例请求体；“订阅”切到订阅页签并预选事件；“标的即将下架”的详情写发现与处理方式和系统订阅状态，这一行有“手工登记”）；订阅（`?tab=subscriptions`：订阅列表、新建或编辑订阅时显示所选事件的说明，工具栏“接收说明”打开抽屉；`&new=事件名` 打开新建并预选）；执行记录（`?tab=executions&rule_id=&status=&execution=`：订阅每次被触发后的执行结果，筛选和打开的记录都在 URL 里，每 30 秒自动刷新，打开详情时暂停；详情里受影响的组合可以点进去，先切到组合所在空间）。监控告警的事件中心关注项都进执行记录：通知失败带失败筛选，其余（发现下架、系统动作处理失败）不带筛选（善后未完成、步骤失败等记录的状态不是“失败”） |
| 资源与运维 | 监控告警（默认）；服务（按主机分组的服务、网关路由、服务拓扑）；主机工作台（登记主机列表、SSH 终端、文件管理、主机监控）；存储节点（数据节点只读）；活动日志 |
| 系统设置 | 业务空间、密钥（全局管理员可“导出全部”为口令加密的迁移包，在新环境“导入”） |

**统一数据集（现货、永续在同一个数据集里）的页面支持**：采集任务页同时选了同一数据源的现货、永续两个标签时，出现“组织方式”选择——“合并为一个数据集”（一个任务）或“按市场拆成两个任务”（任务名加“现货”“永续”后缀；第二个失败时保留已建好的第一个并提示补建哪个，修正后再点“保存任务”只补建没建成的那个，不会重复建第一个）；数据源不同或市场组合不是现货加永续时直接提示不能合并。
新建合成任务直接选同空间已启用的采集任务或合成任务作源，不按市场筛选，源周期和序列标签（统一数据集带现货、永续两个）由系统带出。视图浏览页的 series_tag 列显示“现货”“永续”（悬停显示原始 tag；没有 `market:` 段的 tag，例如 A 股的 `default`，原样显示），行详情显示市场，
数据集信息显示“统一数据集（现货、永续）”；导入页输入框的占位文字是实际的 tag 取值（`venue:binance|market:spot|source:spot_http`）。tag 到市场的换算在前端有与 `packages/seriesset` 的 `SeriesTagMarket` 等价的实现。

**附加字段（资金费率、复权因子、申万行业、财务等可选输出字段）的页面支持**：可选的附加字段不写死在前端，来自 `GetDataTypeConfigWithFields("kline")` 返回的 `extra_fields`（字段、市场、品种、适用频率、提供方），显示名和分组取 Storage 字段目录；判断逻辑在 `collection-task-params.ts`。
- 新建 K 线采集任务：输出字段按字段分组（行情、复权、行业、财务等）列出，每组可以整组勾选。附加字段只在所选标签的市场、品种和所选频率都支持时出现，默认不勾；换了标签或频率后不再支持的已选附加字段自动去掉，提交前再按同一条件过滤一次。基础 K 线字段仍按前端的白名单（`KLINE_OUTPUT_FIELD_IDS`）显示。
- 编辑已有任务：输出字段只能减少。任务原来没有的字段不能勾（置灰），已选的可以取消，表单里提示“输出字段只能减少，要新增请新建任务”；后端 `UpdateTask` 也会拒绝新增。
- 数据源页（`/data/sources`）在数据源列表下方有只读的“附加字段来源”：当前空间里每个提供方一行，列出来源 ID、名称、适用品种、适用频率和提供的字段（显示名加字段 ID）。这些提供方只给 K 线补字段，不登记在 Storage 的数据源里，中文名写在 `extra-field-sources.ts`；当前空间没有附加字段时不显示这一块。字段目录没导入时字段只显示 ID，新建任务的输出字段清单里也不会出现它们。

侧栏菜单随路由展开父菜单：每次路由变化（页面内链接、标签页、浏览器前进后退）以及菜单树加载完成时，都把当前页面的整条父菜单链展开
（`resolveOpenKeys`）；手风琴模式只保留这一条链，否则并入已展开的分组。Arco 的 `auto-open-selected` 只在菜单挂载时生效，不再使用。

监控告警位于 `/ops/monitor`，服务页位于 `/ops/deployments?tab=services|routes`。前者使用 Monitor 结构化概览（结论、当前告警、48 小时告警经过、四层健康，详见 `docs/模块/监控.md` 第 11 节），后者使用 SysDeploy v2 与共享组件目录；主机、部署和名称由 CLI/目录管理，页面只读并提示通过 moox skill 操作；外部程序（因子引擎、归档 Worker）与普通组件一样按部署显示在因子机列，拓扑数据流的“因子”步骤引用组件 `factor-engine`。组件抽屉保留探测与 Reporter 的独立结论、实例和版本；告警的 host_id/component_id 可直接定位。

路由按服务、上游与限额分组，方法展开显示实际 ACL；调用方与方法筛选作用于同一路由。定义、期望和已应用哈希分开展示；时间标为“本次编译”。待同步起点只使用与当前哈希匹配的 Monitor 持久观测，不由浏览器猜测。分页完整加载，读取错误明确显示；晚到请求和停用页面的轮询不会覆盖当前视图。

首页的服务在线与组件健康率来自 Monitor `summary.components`；主机负载、告警和链路也使用真实观测，缺失或读取失败显示未知/暂无。没有实时交易统计的部分只展示已登记账户数量，不填充示例数字。主机行跳到 `/ops/hosts?tab=monitor&host_id=<登记主机ID>`，服务行定位到具体部署。主机监控只展示登记主机（中文名、主机 ID、IP），多个采集器取最近上报的，没有上报显示“未上报”，未登记的采集器只提示数量；历史曲线按该主机选中采集器的 `agent_id` 查询。活动日志有“全局”选项，查看登录等不属于任何空间的事件。

## 3. 开发

```bash
cd web
pnpm install
pnpm dev                 # 本地开发；需在 .env.development 设置 VITE_ADMIN_ORIGIN 指向一个 Admin 入口
pnpm test                # vitest 单元测试
pnpm build:prod          # vue-tsc 类型检查 + vite 生产构建
pnpm check:menu          # 菜单结构
pnpm check:deployments   # “服务”页、v2 API 与旧页面清理契约
pnpm check:data-browse      # 另有 check:detail-pages、check:host-monitor、check:health-monitor，对应 `scripts/check-*.mjs` 的页面契约脚本
```

前端在本机构建；含 CGO 的 Go 目标（Storage）在本机的 Docker 编译镜像里构建，见[构建手册](../构建手册.md)。`web/package.json` 的 `engines.node` 与 jsdom 29 的要求一致（`^20.19.0 || ^22.13.0 || >=24.0.0`），
CI 与 `web/.nvmrc` 使用 Node 24；测试文件与用例数量以当次 `pnpm test` 输出为准。低于要求的 Node（如 22.11）下 Vitest 会在加载测试环境时出现 `ERR_REQUIRE_ESM`，不会执行任何测试。

## 4. 发布

```bash
./scripts/build/build.sh web-host   # 先在 Docker 里按当前源码构建前端，再内嵌并构建 moox-web-host
# 已用本机 pnpm 构建好 web/dist 时：MOOX_WEB_DIST_READY=1 ./scripts/build/build.sh web-host
```

原生 `setup bootstrap --stage admin` 的制品准备会在本机使用 pnpm 构建前端并嵌入 web-host；
完整 control 阶段复用这份原始制品。

`moox-web-host` 默认监听 `127.0.0.1:9528`（`MOOX_WEB_HOST_ADDR`），健康检查 `127.0.0.1:19527`
（`MOOX_WEB_HOST_HEALTH_ADDR`）。
