# 前端（Web）

MooX 管理台基于 Vue 3、Vite 5、TypeScript、Pinia 和 Arco Design，源码在 `web/`；
静态资源由 `web-host/` 打包成单个 Go 二进制提供。

## 1. 访问链路

```text
浏览器 ─► 控制台代理（Caddy）:9527 ─┬─ /api/admin/* ─► 管理后台的控制台 API :11000
                                    └─ 其他路径 ─► moox-web-host :9528（静态资源与 SPA 回退）
```

- 前端只调用同源的 `/api/admin/{console_name}/{method}`，不直接访问各后端服务。`console_name` 来自组件目录：
  单服务组件用组件 ID（`collector`、`strategy`、`cloudnode`、`monitor`、`factor-mgr`、`trade`），管理后台内部的
  服务用短名（`ssh`、`space`、`secret`、`sysdeploy`），存储接口用 `storage`。
- 控制台 API 以 `console` 身份经主机网关转发；浏览器能调用哪些方法，由组件目录的 ACL 是否放行 `console` 决定。
- SSH 终端用 WebSocket `/api/admin/ssh/WsConnect`，先换取短时票据再连接。
- 每个管理请求都带会话签名和当前空间（`X-Space-Id`），见[管理后台](管理后台.md)。
- `web-host` 收到 `/api/*` 直接返回 404，避免误把它当成代理。

## 2. 页面

菜单由 `src/api/modules/system/static-menu.ts` 静态声明，路由在 `src/router/route.ts`：

| 菜单 | 页面 |
| --- | --- |
| 首页 | 总览 |
| 数据采集 | 数据源、数据对象、基础字段；采集任务（任务、任务实例、执行器即云节点、采集结果） |
| 因子计算 | 因子总览；因子定义（新建 / 编辑）；计算任务（任务、计算结果、补算） |
| 策略管理 | 策略定义、运行实例、实例详情 |
| 交易管理 | 账户、持仓、订单 |
| 资源与运维 | 监控告警（默认页：当前告警、数据链路、组件 × 主机矩阵、主机、业务检查、未登记的进程、告警推送设置）；主机工作台（主机列表、SSH 终端、文件管理、主机监控）；服务部署（服务：主机 × 组件的部署与启用状态；网关路由：每台主机编译后的路由、期望与已应用的哈希、网关心跳）；存储（数据节点、归档文件） |
| 系统设置 | 业务空间、密钥 |

## 3. 开发

```bash
cd web
pnpm install
pnpm dev                 # 本地开发；需在 .env.development 设置 VITE_ADMIN_ORIGIN 指向一个 Admin 入口
pnpm test                # vitest 单元测试
pnpm build:prod          # vue-tsc 类型检查 + vite 生产构建
pnpm check:menu          # 等 node 检查脚本：菜单结构、页面样式、主机监控等契约
```

本机 macOS 环境下 rollup/fsevents 等原生模块可能被系统隔离导致构建卡住，生产构建在编译机上执行。

## 4. 发布

```bash
cd web && pnpm build:prod                           # 生成 web/dist（在编译主机上执行）
cd ../web-host && make statik                       # 把 dist 嵌入 internal/statik
cd .. && moox-cli setup deploy-service --component web-host
```

部署命令使用 `web-host` 当前已嵌入的静态资源，所以前端更新后要先完成前两步。

`moox-web-host` 默认监听 `127.0.0.1:9528`（`MOOX_WEB_HOST_ADDR`），健康检查 `127.0.0.1:19527`
（`MOOX_WEB_HOST_HEALTH_ADDR`）。
