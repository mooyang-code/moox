# 前端（Web）

MooX 管理台基于 Vue 3、Vite 6、TypeScript、Pinia 和 Arco Design，源码在 `web/`；
构建产物内嵌在 `moox-admin` 里，由 Admin 的浏览器入口（HTTPS 9527）提供。

## 1. 访问链路

```text
浏览器 ─► moox-admin :9527（HTTPS）─┬─ /api/admin/* ─► 管理网关（进程内分派或转发到各服务）
                                   ├─ /ca/*        ─► MooX CA 根证书下载
                                   └─ 其他路径     ─► 内嵌的静态页面（SPA 回退到 index.html）
```

- 生产构建只调用同源的 `/api/admin/{service}/{method}`，不直接访问各后端服务；开发模式也走同源路径，由开发服务器把 `/api/admin`（含终端 WebSocket）与 `/ca` 代理到 `VITE_ADMIN_PROXY_TARGET` 指向的 Admin 入口。
- Storage 统一走 `/api/admin/storage/{method}`：服务目录里 Storage 的三个服务（`Metadata`、`PrimaryStore`、`DataView`）共用服务名 `storage`，
  管理网关按方法名转到对应服务，只有目录里对管理台开放的方法能调。
- SSH 终端用 WebSocket `/api/admin/ssh/WsConnect`，同源连接自己带会话 Cookie；建连只传登记主机的字符串 `host_id`，登记了 SSH 端口的主机才能打开终端和文件管理，其余置灰并说明原因；终端外观存浏览器本地。
- 主机、部署在管理台**只读**，页面提示通过 moox skill（`moox-cli`）新增、部署、启停与移除；系统只有一个超级用户，前端不区分角色，也没有权限指令。
- 登录后靠 HttpOnly 会话 Cookie 认证，前端不保存令牌；每个管理请求带当前空间（`X-Space-Id`），见[管理后台](管理后台.md)。
- 请求只有一个入口 `call(服务, 方法, 请求体, { spaceId, timeout })`（`src/api/http.ts`），发到 `/api/admin/<服务>/<方法>`。**请求层不弹提示**：失败抛成 `RequestError`（业务失败带完整响应体与错误码，交易服务的英文错误换成中文），页面自己决定在错误条、对话框里显示，或用 `reportError` 提示一次；页面没有处理、一路抛出的请求失败由 `main.ts` 的全局错误处理提示一次。Storage 的读取有 3 秒读缓存并合并在途的同一请求，任何 Storage 写入都会清空缓存。
- 页头的空间下拉列出 Storage 里启用的空间（都是交易市场空间；空间只登记在 Storage，增删改查经 `src/api/storage/spaces.ts` 调 Storage 元数据接口，列表缓存在本地）。
  “系统设置 › 空间管理”删除空间前二次确认，写明会清空该空间全部数据。`mooxsys` 是“不属于任何市场”的范围标签，不是 Storage 里的空间：
  首页把归在它下面的告警标为“系统”（`src/store/modules/space.ts` 的 `isSystemSpace`）。
- `/api/admin/*` 以外的 `/api/*` 在入口直接返回 404，不会回退成页面。

## 2. 页面

路由只有 `src/router/route.ts` 一份：侧栏菜单按它生成（一级菜单的顺序、标题、图标写在路由与 meta 里，`meta.hide` 的编辑页、详情页不进菜单，用 `meta.activeMenu` 高亮所属菜单），交易三个环境的菜单也从它读。同一路径只有 query 变化时页面组件复用、不重建（页面自己监听 query），同一页面有几条地址时写相同的 `meta.viewKey`：

| 菜单 | 页面 |
| --- | --- |
| 首页 | 总览 |
| 数据采集 | 数据源（数据源、字段定义两个页签，页签和筛选进 URL：数据源页签维护主数据源并在下方只读展示“附加字段来源”及跳转链接；字段定义页签为只读左分组右表工作台，汇总当前空间全部原始数据字段——K 线基础、附加字段及非因子数据集列，支持一键复制字段 ID 与详情抽屉查看已落地数据集）；数据对象（页签和所选标签进 URL）；采集运行（位于数据对象之后，也是目录落地页；从菜单进来默认看“采集结果”页签；采集任务、采集结果、运行状态、补采四个页签，页签和各自的筛选都在 URL 里；运行状态页“函数”区上方有“云账号”“代码包”两个按钮，函数表有“云上状态”一列，计划外的函数单列一组） |
| 因子计算 | 因子定义（因子定义、产出字段两个页签，页签和筛选进 URL：因子定义页签管理算法定义与分类树并支持新建 / 编辑；产出字段页签为只读左分类右表工作台，汇总当前空间全部计算任务成员实际生成的因子结果列名，支持按任务/参数模式/状态筛选、一键复制列名与点击查看因子表达式详情）；计算任务页（即因子任务：任务、计算结果、补算；任务页签顶部是引擎状态条——引擎、实时消费、表达式引擎、计算队列、数据预热、进行中补算——以及进行中的补算与近 24 小时失败的补算）——新建任务要填展示名，加成员时选固定 / 可变并实时预览成员键与全部列名（`src/utils/factor-name.ts`，与 Go 的 `packages/factorname` 共用测试向量），详情列出每个成员的列名（可复制）与关联的策略实例；结果页默认隐藏系统列 `__params`，「显示参数」开关打开后按成员展开 |
| 策略管理 | 策略定义（新建 / 编辑；“插入示例”有截面选股、择时、动态调参、混合市场、策略池几段写法，只插入编辑器里的 DSL）；策略运行（工作台，运行实例、运行结果、策略回放三个页签；运行实例页签顶部列出排队或运行中的回放，要人处理的实例在首页）；实例详情（创建实例时按策略的市场模式绑定因子任务：只涉及一个市场绑一个；现货、永续都涉及时各绑一个因子任务（两个 View 本期都到齐才求值）；要绑定的任务键、是否策略池、建不了实例的问题都取自后端 `GetStrategy` / `ValidateStrategy` 返回的 `requirement`（试算、回放发起表单按 DSL 草稿调 `ValidateStrategy` 推出），前端不解析 DSL 的市场；参考市场（后端给出 `reference_markets`）标为“参考市场”，只用于年龄判定；建实例的账户筛选、回放的股票判断与资金费列只看主帧市场，回放照样提交参考市场的任务（从实例发起时原样提交实例的任务键）；因子现算支持现货、永续两个主帧任务；策略池按各成员所需市场的并集绑定；DSL 写了 `factor_params` 的只能选没有关联到别的实例的任务，其余定义可以选任何运行中的任务（多个实例共用一个任务，只读它的列），并列出全部列名，可变成员按定义提示要写 `factor_params` 或只读；策略池实例的结果里另有成员净值、分配比例和择时曲线；详情页看绑定解析、最近一次参数提交与各期投递状态、外显设置；已停用的实例可以删除（确认框分组列出随实例删除与保留的任务），不能改绑因子任务；页面不能改实例，改定义和账户用 `strategy instance update`；停用后 Trade 没确认关闭会话时弹“实例已停用，但 Trade 未确认”的对话框，写明怎么重试、怎么立刻停手，已停用的实例在运行实例列表“更多”和实例详情里有“再次停用”；建实例时组合账户选项里已被启用实例绑着的置灰）；回放（发起表单有“因子数据来源”单选——结果 View 或因子现算，声明了 `factor_params` 的定义只能选因子现算、策略池只能选结果 View——和滑点输入框，因子现算的逐期明细显示这一期生效的参数，见[策略](策略.md)第 10 节） |
| 交易管理 | 四个菜单：模拟账户（`/trading/paper`）、测试账户（`/trading/testnet`）、实盘账户（`/trading/live`）共用一个列表页，环境写在路由 `meta.env`；下架名单（`/trading/blocked`，全局，不分环境和空间）：上段是下架处理记录（进行中与最近结束的，列标的、范围、下架时间、状态、已规划轮次，展开看各轮各组合的动作状态与错误，动作号链接到组合详情的动作跟踪，进行中的每 30 秒刷新），下段是名单（范围、下架记录，可解除，解除会一并取消进行中的下架处理），工具栏“手工登记下架”。列表页用圆角子页签分组合账户、执行账户（`?list=execution`）：组合账户页签是平表，执行账户页签列出当前环境的全部执行账户（市场、所属组合、状态、权益，展开改账户设置，未加入组合的行上直接加入组合）；组合详情是整页 `<菜单地址>/:logical_account_id?tab=`，侧栏高亮所属菜单（只带组合编号的 `/trading/accounts/:logical_account_id` 给策略页、下架名单页用，读到组合后换到所属环境的地址，页面不重建），页签为概览、持仓与目标（按币一行，默认按市值排序，列出市值、开仓均价、未实现盈亏，现货、永续的目标、实际、偏差分开算，没有现货一侧时不显示现货列）、订单、成交、资金流水、成员与设置（左侧分段导航）；新建账户四步（类型、交易所与密钥、市场与参数、组合），模拟盘、测试网、生产环境都可以建（生产环境选密钥后先检测账户类型和权限，并要确认密钥没有提现权限；币安测试网一个账户只能开通一个市场）；危险操作按环境分三档确认，生产环境要输入组合名称；组合账户列表与详情页头的“关联策略”读 Strategy 的实例列表（Trade 不存归属）：取绑了这个账户的启用实例，没有启用的就退回显示最近创建的那个停用实例（同一账户可能留着几个停用的旧实例；列表里写明实例已启用还是已停用），读不到实例列表时写“策略读取失败”，读到了但没有实例绑它时写“尚未绑定策略”，自主下单的组合在列表里写“自主下单”、详情页头写“自主下单，没有关联策略” |
| 数据归档 | 归档任务（`/archive/tasks`：顶部一行执行器状态，点进归档存储；任务列表与详情，详情页签有运行记录（导入运行显示文件名与“只补空缺 / 覆盖已有”，长消息折叠后点开看全部）、分区（远端已校验的分区可下载，未就绪的置灰并在悬停里写原因）、最新数据（选标的看暂存库里最近的行，默认 200 行、“更早”翻页）；新建任务填目录名，默认建议值，冲突时标红并显示完整路径预览）；归档存储（`/archive/storage`：执行器所在主机、归档根目录、磁盘已用 / 总量 / 可用与下限、对象存储、`datasets.csv` 说明）。下载与最新数据走 Admin 的裸 HTTP 路由（`src/api/archive/raw.ts`），只支持执行器装在 control 或只出站主机上，见 `docs/模块/归档.md` 第 9 节 |
| 资源与运维 | 监控告警（默认）；服务管理（按主机分组的服务、网关路由、服务拓扑三个页签）；主机工作台（登记主机列表、SSH 终端、文件管理、主机监控）；日志中心（`/ops/logs`，活动日志、重要日志两个页签，`?tab=important` 打开重要日志） |
| 系统设置 | 空间管理、密钥管理（全局管理员可“导出全部”为口令加密的迁移包，在新环境“导入”） |

**现货加永续只按市场分开放**：一个采集任务的标签只属于一个市场。采集任务页同时选了同一数据源的现货、永续两个标签时，提示并在提交时按市场拆成两个任务（任务名加“现货”“永续”后缀；第二个失败时保留已建好的第一个并提示补建哪个，修正后再点“保存任务”只补建没建成的那个，不会重复建第一个）；数据源不同或市场组合不是现货加永续时直接提示不能一起建。
新建合成任务直接选同空间已启用的采集任务或合成任务作源，不按市场筛选，源周期和序列标签由系统带出。数据浏览（采集结果、因子计算结果两个页签共用的 `src/views/data/view-browse` 组件，按数据集 ID 浏览：每个数据集恰好有一个查询索引，列只取 `ListDatasetColumns` 里启用的列，列标题用列的 `display_name`；页面拆成 `index.vue`（数据集页签、状态行、加载与分发）、`query-controls.vue`（查询条件）、`result-table.vue`（时序表、记录表、排序、翻页与详情），K 线取数在 `composables/use-view-kline.ts`）的 series_tag 列显示“现货”“永续”（悬停显示原始 tag；没有 `market:` 段的 tag，例如 A 股的 `default`，原样显示），行详情显示市场，
按 series_tag 筛选时按 tag 原值（例如 `venue:binance|market:spot|source:spot_http`）精确匹配，当前结果里只有一种 tag 时默认填它。tag 到市场的换算只在前端做（`src/views/data/shared/series-market.ts`），只用于展示。
数据浏览要读的数据集 ID 由调用方按自己所在的空间给出：切空间时组件只清空旧内容，不拿旧 ID 去新空间读（取不到行会弹 `metadata row not found`），等调用方换上新空间的数据集 ID 或重新挂载组件再读；采集结果页签被页签容器缓存、停用期间切了空间，重新打开时按当前空间重读任务。

**附加字段（资金费率、复权因子、申万行业、财务等可选输出字段）的页面支持**：可选的附加字段不写死在前端，来自 `GetDataTypeConfigWithFields("kline")` 返回的 `extra_fields`（字段、市场、品种、适用频率、提供方），每一项都带 Collector 字段规格里的显示名（`display_name`）、一级分组（`group`）、值类型（`value_type`）和缺失填充策略（`fill`）；判断逻辑与字段目录的归并在 `collection-task-params.ts`。采集任务页拆成 `collection-tasks.vue`（列表）、`task-editor-drawer.vue`（编辑抽屉）、`output-field-picker.vue`（输出字段选择）、`task-detail-drawer.vue`（详情抽屉），共用的数据类型、标签、源任务与输出字段目录在 `use-collection-catalog.ts`。
- 新建 K 线采集任务：输出字段按字段规格的分组（行情价格、成交估值、财务数据、行业、复权、合约指标等）列出，显示中文名，每组可以整组勾选。附加字段只在所选标签的市场、品种和所选频率都支持时出现，默认不勾；换了标签或频率后不再支持的已选附加字段自动去掉，提交前再按同一条件过滤一次。基础输出字段取 `GetDataTypeConfigWithFields` 返回的 `base_output_fields`（结果数据集能建的列），字段清单读到之前不清理已选字段。
- 编辑已有任务：输出字段只能减少。任务原来没有的字段不能勾（置灰），已选的可以取消，表单里提示“输出字段只能减少，要新增请新建任务”；后端 `UpdateTask` 也会拒绝新增。
- 数据源页（`/data/sources`）分“数据源”“字段定义”两个页签：“数据源”页签下方保留只读的“附加字段来源”表（当前空间每个提供方一行，列出来源 ID、名称、适用品种、适用频率及字段摘要，点击可跳到“字段定义”页签按该提供方筛选）；“字段定义”页签以只读左栏分组 + 右表工作台汇总当前空间全部原始数据字段（K 线基础、附加字段及 Storage 非因子数据集列），附加字段的中文名、值类型与填充策略取自 `extra_fields`（提供方中文名在 `extra-field-sources.ts`），点击行可打开只读详情抽屉查看已落地数据集；因子计算产出的结果列名归在“因子计算 › 因子定义”的“产出字段”页签。

侧栏菜单随路由展开父菜单：每次路由变化（页面内链接、标签页、浏览器前进后退）以及菜单树加载完成时，都把当前页面的整条父菜单链展开
（`resolveOpenKeys`）；手风琴模式只保留这一条链，否则并入已展开的分组。Arco 的 `auto-open-selected` 只在菜单挂载时生效，这里不用它。

监控告警位于 `/ops/monitor`，服务管理页位于 `/ops/deployments?tab=services|routes|topology`。前者使用 Monitor 结构化概览（结论、当前告警、48 小时告警经过、四层健康，详见 `docs/模块/监控.md` 第 11 节），后者使用 SysDeploy 与共享组件目录；主机、部署和名称由 CLI/目录管理，页面只读并提示通过 moox skill 操作；外部程序（因子引擎、归档 Worker）与普通组件一样按部署显示在因子机列，拓扑数据流的“因子”步骤引用组件 `factor-engine`。组件抽屉显示上报（是否新鲜）与就绪判断（未就绪时写明原因）、实例和版本，没有探测（组件健康只看上报）；告警的 host_id/component_id 可直接定位。

路由按服务、上游与限额分组，方法展开显示实际 ACL；调用方与方法筛选作用于同一路由。定义、期望和已应用哈希分开展示；时间标为“本次编译”。同步状态只比较 Admin 记下的期望哈希与已应用哈希：相等为“已同步”，不等为“待同步”，没有期望哈希为“同步状态未知”。分页完整加载，读取错误明确显示；晚到请求和停用页面的轮询不会覆盖当前视图。

首页的服务在线与组件健康率来自 Monitor `summary.components`；主机负载、告警和链路也使用真实观测，缺失或读取失败显示未知/暂无。没有实时交易统计的部分只展示已登记账户数量，不填充示例数字。主机行跳到 `/ops/hosts?tab=monitor&host_id=<登记主机ID>`，服务行定位到具体部署。主机监控只展示登记主机（中文名、主机 ID、IP），每台一行，按 `host_id` 对上 Monitor 的上报，没有上报显示“未上报”；历史曲线按 `host_id` 查询。日志中心的活动日志页签有“全局”选项，查看登录等不属于任何空间的事件。

## 3. 开发

```bash
cd web
pnpm install
pnpm dev                 # 本地开发（端口 9527）；在 .env.development 设置 VITE_ADMIN_PROXY_TARGET（如 https://<控制机>:9527），并把开发服务器的来源加进控制机 console.yaml 的 console.allowed_origins
pnpm test                # vitest 单元测试
pnpm build:prod          # vue-tsc 类型检查 + vite 生产构建
pnpm test:e2e            # Playwright 页面测试（接口都在用例里拦截，不连后端）；本机有 Google Chrome 时加 PLAYWRIGHT_CHANNEL=chrome，否则先 pnpm exec playwright install chromium
pnpm check:deployments   # “服务”页与 SysDeploy 接口的契约
pnpm check:data-browse      # 另有 check:detail-pages、check:host-monitor、check:health-monitor，对应 `scripts/check-*.mjs` 的页面契约脚本
```

发布用的前端默认在本机的 Docker 里构建（`scripts/build/build-web-docker.sh`，见第 4 节），含 CGO 的 Go 目标（Storage）也在本机的 Docker 编译镜像里构建，见[构建手册](../构建手册.md)。`web/package.json` 的 `engines.node` 与 jsdom 29 的要求一致（`^20.19.0 || ^22.13.0 || >=24.0.0`），
CI 与 `web/.nvmrc` 使用 Node 24；测试文件与用例数量以当次 `pnpm test` 输出为准。低于要求的 Node（如 22.11）下 Vitest 会在加载测试环境时出现 `ERR_REQUIRE_ESM`，不会执行任何测试。

## 4. 发布

```bash
./scripts/build/build.sh admin   # 先在 Docker 里按当前源码构建前端，再内嵌进 moox-admin 编译
# 已用本机 pnpm 构建好 web/dist 时：MOOX_WEB_DIST_READY=1 ./scripts/build/build.sh admin
```

`scripts/build/build.sh admin`（以及 `build-linux-local.sh admin`）编译 admin 时按当前源码构建前端并嵌入 moox-admin；
编译时 `web/dist` 临时拷到 `modules/admin/internal/webui/dist`，编译完删掉。
