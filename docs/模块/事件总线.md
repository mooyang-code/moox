# 事件总线（EventBus）

`moox-eventbus` 内嵌 NATS JetStream，是系统中唯一的 JetStream 所有者。业务服务直接连接它发布和
消费事件；EventBus 只负责声明 Stream、维持拓扑，并提供只读的管理接口。

代码位置：`modules/eventbus`；事件注册表与客户端在 `packages/events`、`packages/jetstream`。

## 1. 端点

| 端点 | 说明 |
| --- | --- |
| NATS `4222` | 客户端连接；生产环境开启 TLS 并按角色鉴权，对 SCF 和操作员机器开放 |
| `EventBusMgr` loopback tRPC `11420` | 只读管理接口：`GetOverview`、`ListEvents`、`ListStreams`、`ListConsumers`、`GetConsumer` |
| 健康检查 `11419` | `/healthz`、`/readyz`、`/metrics` |

运行数据在 `data/eventbus/jetstream`，不进入发布包。单条消息上限 8 MiB。

## 2. 拓扑

`config/app.yaml` 只声明 broker、内部客户端、健康检查和 Stream。事件名称、版本、负载类型、
所属 Stream 和 Subject 族都在 `packages/events/registry.go` 中以代码声明，业务模块不能自行声明。

| Stream | Subject | 保留策略 | 时间上限 | 容量上限 |
| --- | --- | --- | --- | --- |
| `MOOX_STORAGE` | `rows.upserted` v2、`collector.period.completed`、`dataset.factor_period.computed`、`view.data.ready`、`dataset.sync_point` | limits | 72 小时 | 8 GiB |
| `MOOX_OBSERVABILITY` | `moox.event.observability.>`（服务指标、主机快照） | limits | 24 小时 | 128 MiB |
| `MOOX_MARKET_FETCH` | `market.fetch.batch.completed` | limits，去重窗口 10 分钟 | 24 小时 | 128 MiB |
| `MOOX_TRADE` | `trade.target.weight_requested` | work queue | 7 天 | 128 MiB |

`limits` 类 Stream 统一 `discard: old`，旧消息按时间和容量自然淘汰；这只影响事件，不会删除 Storage
等模块已经提交的业务事实。

Subject 格式为 `moox.<事件名>.v<版本>.<space>[.<subject>]`，`space` 和 `subject` 使用可逆的小写
Base32 编码，保证任意字符都能安全放进 Subject。

## 3. 对账规则

EventBus 在就绪前对每个声明的 Stream 做对账：

- 不存在则创建；可变参数（时间、容量、去重窗口等）就地更新。
- 存储类型、保留策略等不可变参数发生变化时拒绝启动，不删除重建。
- 从 Stream 移除某个 Subject 时，只有该 Subject 下没有存量消息才允许。
- 拒绝与已声明 Stream 的 Subject 重叠的未管理 Stream。
- 不创建、不删除任何 Consumer：每个消费方用 `packages/events` 自己创建并拥有 Consumer，
  可变参数就地更新，过滤条件等不可变参数冲突时显式失败。

## 4. 角色与凭据

生产环境的 TLS 证书、各角色 token 和用户权限文件由 Admin 的 CLI 生成，token 永久保存在 Admin 的
密钥表中，并导出到 `~/.config/moox/eventbus/<角色>.yaml`。每个角色的发布和订阅权限精确到 Subject
和 Consumer：

| 角色 | 使用方 | 权限要点 |
| --- | --- | --- |
| `eventbus-internal-admin` | EventBus 自身、运维工具 | 全部 JetStream API |
| `storage-eventbus` | Storage（DataNode Outbox、View） | 发布 Storage 事件；管理 View 的消费者 |
| `metrics-publisher` | 各服务的指标上报 | 只能发布服务指标快照 |
| `hostagent-publisher` | HostAgent | 只能发布主机快照 |
| `monitor-observability-consumer` | Monitor | 消费 `MOOX_OBSERVABILITY` 的固定消费者 |
| `market-fetch-publisher` | SCF 采集函数 | 只能发布批次完成事件 |
| `collector-market-fetch-consumer` | Collector | 消费批次完成事件和 Storage 写入事件 |
| `factor-eventbus` | Factor Engine | 消费 `CollectorPeriodCompleted` 的固定消费者 |
| `strategy-eventbus` | Strategy | 消费 `ViewDataReady`，发布目标权重 |
| `trade-eventbus` | Trade | 消费目标权重的固定消费者 |
| `archive-eventbus` | Archive | 消费行变更的固定消费者 |

本机服务连接 `tls://127.0.0.1:4222`，SCF 和操作员机器使用公网地址。SCF 代码包只携带公开 CA，
token 写在函数环境变量中。轮换 CA 或 `market-fetch-publisher` token 后需要重新发布 SCF 函数。

## 5. 运维

```bash
./scripts/build/build.sh eventbus
go test -count=1 ./modules/eventbus/...
./scripts/check/verify-event-contracts.sh   # 事件注册表与拓扑契约检查
```

管理台的“事件总线”页面使用 `EventBusMgr` 展示 Stream、消费者积压和事件定义。
