# 事件总线（EventBus）

`moox-eventbus` 内嵌 NATS JetStream，是系统中唯一的 JetStream 所有者。业务服务直接连接它发布和
消费事件；EventBus 只负责声明 Stream、维持拓扑，并提供只读的管理接口。

代码位置：`modules/eventbus`；事件注册表与客户端在 `packages/events`、`packages/jetstream`。

## 1. 端点

| 端点 | 说明 |
| --- | --- |
| NATS `4222` | 客户端连接；生产环境开启 TLS 并按角色鉴权，供内部服务与外置因子引擎连接；当前采集 SCF 不连接 |
| `EventBusMgr` loopback tRPC `11420` | 只读管理接口：`GetOverview`、`ListEvents`、`ListStreams`、`ListConsumers`、`GetConsumer` |
| 健康检查 `11419` | `/healthz`、`/readyz`、`/metrics` |

运行数据在 `data/eventbus/jetstream`，不进入发布包。单条消息上限 8 MiB。

## 2. 拓扑

`config/app.yaml` 只声明 broker、内部客户端、健康检查和 Stream。事件名称、版本、负载类型、
所属 Stream 和 Subject 族都在 `packages/events/registry.go` 中以代码声明，业务模块不能自行声明。

| Stream | Subject | 保留策略 | 时间上限 | 容量上限 |
| --- | --- | --- | --- | --- |
| `MOOX_STORAGE` | `dataset.rows.upserted` v2、`dataset.period.completed`、`view.data.ready` v2、`dataset.sync_point` | limits | 72 小时 | 8 GiB |
| `MOOX_OBSERVABILITY` | `moox.event.observability.>`（服务指标、主机快照） | limits | 24 小时 | 128 MiB |
| `MOOX_TRADE` | `trade.target.weight_requested` | work queue | 7 天 | 128 MiB |
| `MOOX_COLLECTOR` | `moox.event.collector.kline.backfilled.v1.>`（K 线在周期结束后被补写，只带元数据） | limits | 72 小时 | 128 MiB |

`limits` 类 Stream 统一 `discard: old`，旧消息按时间和容量自然淘汰；这只影响事件，不会删除 Storage
等模块已经提交的业务事实。

Subject 格式为 `moox.<事件名>.v<版本>.<space>.<路由键>`，`space` 和 `subject` 使用可逆的小写
Base32 编码，保证任意字符都能安全放进 Subject。

## 3. 对账规则

EventBus 在就绪前对每个声明的 Stream 做对账：

- 不存在则创建；可变参数（时间、容量、去重窗口等）就地更新。
- 存储类型、保留策略等不可变参数发生变化时拒绝启动，不删除重建。
- 从 Stream 移除某个 Subject 时，只有该 Subject 下没有存量消息才允许。
- 拒绝与已声明 Stream 的 Subject 重叠的未管理 Stream。
- 不创建、不删除任何 Consumer：每个消费方用 `packages/events` 自己创建并拥有 Consumer，
  可变参数就地更新，过滤条件等不可变参数冲突时显式失败。

## 4. 角色与凭据

生产环境的 TLS 证书、各角色 token 和用户权限文件由 Admin 的 CLI 生成，token 永久保存在 Admin 的
密钥表中。`export` / `export-clients` 按 `--output-dir` 导出；原生安装再放入各组件发布目录的 `secrets/eventbus/`（HostAgent 的角色文件在 `host-agent/config/eventbus.yaml`）。仓库配置里的 `~/.config/moox/eventbus/` 是开发路径，不是所有部署的固定位置。每个角色的发布和订阅权限精确到 Subject
和 Consumer：

| 角色 | 使用方 | 权限要点 |
| --- | --- | --- |
| `eventbus-internal-admin` | EventBus 自身、Admin 代执行维护 | 全部 JetStream API |
| `storage-eventbus` | Storage（DataNode Outbox、View） | 发布 Storage 事件；管理 View 的消费者（每个数据集一个 `view_<12 位十六进制>`） |
| `metrics-publisher` | 各服务的指标上报 | 只能发布服务指标快照 |
| `hostagent-publisher` | HostAgent | 只能发布主机快照 |
| `monitor-observability-consumer` | Monitor | 消费 `MOOX_OBSERVABILITY` 的固定消费者 |
| `factor-eventbus` | Factor Engine | 消费 `DatasetPeriodCompleted` 的固定消费者（`factor_collector_period_v1`） |
| `strategy-eventbus` | Strategy | 消费 `ViewDataReady`，发布目标权重 |
| `trade-eventbus` | Trade | 消费目标权重的固定消费者 |
| `collector-eventbus` | Collector | 发布 `event.collector.kline.backfilled`；每个空间各两个固定消费者，消费源周期完成（`DatasetPeriodCompleted`，`MOOX_STORAGE`）和补采完成（`MOOX_COLLECTOR`），用于 K 线合成 |

**EventBus 是独立的部署单元**（`eventbus` profile），装在 `moox.toml` 的 `[deployments]` 登记它的那台主机上，默认是存储机：
Storage 内部的行变更事件（storage-node 发布、storage-view 消费）占流量的九成以上，同机后不再经公网往返。

连接地址的规则只有一条：客户端与 EventBus 同机，连 `tls://127.0.0.1:4222`；否则连 EventBus 所在主机的对外地址（因子机、海外机、控制机都是如此）。
broker 对其他主机宣告的 `client_advertise` 始终是对外地址，服务端证书同时覆盖对外地址与回环地址。当前计划采集与补采 SCF 的标准部署不连接 EventBus；若手动配置 `MOOX_METRICS_EVENTBUS_URL`、`MOOX_EVENTBUS_URL` 或 `NATS_URL`，仍可启用 SCF 的一次性指标 Reporter，此类定制客户端也须纳入凭据同步。

**TLS 身份与 EventBus 的地址绑定**（记在 CA 记录的 `nats_url` 里）：EventBus 换主机后，`ensure`、`export`、`export-clients` 都会拒绝旧身份，
必须先执行 `moox-admin-cli eventbus-credentials rotate-tls --confirm`（按部署记录里的新地址重新生成 CA 与服务端证书，角色令牌不变；CA 私钥不保存，所以只能连 CA 一起换），
然后所有客户端和 EventBus 单元重新部署，才能拿到新 CA。broker 的证书、私钥和用户表只随 `eventbus` 单元下发（`export-clients --server`），别的单元一律不带。

## 5. 运维

```bash
./scripts/build/build.sh eventbus
go test -count=1 ./modules/eventbus/...
./scripts/check/verify-event-contracts.sh   # 事件注册表与拓扑契约检查
```

`EventBusMgr` 提供 Stream、消费者积压和事件定义的只读 RPC。当前前端静态菜单没有独立“事件总线”页面；
不能把后端接口已经存在等同于页面已经交付。
