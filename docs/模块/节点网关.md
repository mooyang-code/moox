# 节点网关（Gateway）

`moox-gateway` 是每台机器上的本地服务网关：接收带服务签名的调用，只转发到 Admin 为本节点
登记的本机服务。浏览器流量不经过它，浏览器入口是 Admin 的管理网关。

代码位置：`modules/gateway`；签名与转发的公共实现在 `packages/gatewayauth`、`packages/gatewayproxy`。

## 1. 两个平面

| 平面 | 所有者 | 路径 |
| --- | --- | --- |
| 浏览器与路由控制面 | Admin `11000` | `/api/admin/*`、`/api/gateway-control/*` |
| 机器间服务数据面 | Gateway `11002` / `11003` | `/api/service/{service}/{method}`、tRPC 原生调用 |

Gateway 不读 Admin 数据库，也不代理到其他机器；它只按自己的 `node_id` 拉取本节点的完整路由快照。

## 2. 端口

| 端口 | 说明 |
| --- | --- |
| `11002` | HTTP 服务入口 `/api/service/*`，只监听本机；control 主机由 Caddy `11001` 对外暴露 |
| `11003` | tRPC 原生入口；control 主机监听 `0.0.0.0`，供 SCF 用签名调用 Collector 和 Storage |
| `11012` | 本机诊断：`/healthz`、`/readyz`、`/metrics` |

## 3. 路由同步

1. 启动时先加载上次有效的路由缓存 `<store.path>/routes.json`，再从 Admin 拉取当前快照；
   没有有效缓存的节点必须完成首次拉取才能就绪。
2. 定时器 `trpc.moox.gateway.route_refresh.timer` 每 15 秒刷新一次（单次超时 10 秒，跳过重叠执行），
   同时上报心跳。
3. 新快照整体校验，非法快照整体拒绝，继续使用旧路由。
4. Admin 暂时不可用时，缓存的路由仍可继续服务；但最近一次成功同步或心跳确认超过 90 秒
   （`MOOX_GATEWAY_ROUTE_SYNC_STALE_AFTER_SECONDS`）时 `/readyz` 返回不可用，Monitor 会据此告警。

路由的修改只在 Admin 的服务目录中进行，不要手工编辑 `routes.json`。

## 4. 鉴权

- 服务签名使用 HMAC，签名覆盖方法、路径、请求体哈希、时间戳、nonce 和目标节点；请求头为
  `X-Moox-Key-Id`、`X-Moox-Caller`、`X-Moox-Timestamp`、`X-Moox-Nonce`、`X-Moox-Target-Node`、
  `X-Moox-Signature`。
- nonce 持久化在 `<store.path>/nonces`，进程重启不会重新打开重放窗口。
- 多调用方部署使用 `auth.credentials_file`（每个调用方一把密钥，如 `factor-engine`、`collector`），
  单调用方可以使用 `auth.hmac_key_file`。服务密钥、控制面密钥必须是独立的 0600 文件，不写进 YAML。
- 路由记录里声明允许的方法和调用方；`moox-skill` 调用方只能调用
  `PrimaryStore.ReadTimeSeriesRows`。
- 原生入口只对幂等的读方法做重试，写方法不重试。

## 5. 诊断

```bash
moox-gateway-cli check-config --config config/app.yaml   # 校验配置
moox-gateway-cli routes --config config/app.yaml         # 查看缓存的路由
moox-gateway-cli health --url http://127.0.0.1:11012/readyz
```

关键指标：`gateway_route_sync_errors_total`、`gateway_route_report_errors_total`、`gateway_route_sync_stale`。
