# 主机网关（HostGateway）

`moox-host-gateway` 是系统中唯一的网关。每台 MooX 主机上恰好运行一个，它是这台主机上所有跨进程 tRPC 调用的入口：
校验服务签名和 ACL，再把请求原样转发到本机服务。它不跨主机转发，也不读 Admin 数据库。

代码位置：`modules/hostgateway`；签名在 `packages/gatewayauth`，路由校验与查表在 `packages/gatewayroute`，
组件目录和路由编译在 `packages/servicecatalog`，调用方客户端在 `packages/gatewayclient`。

## 1. 入口与端口

| 端口 | 监听 | 说明 |
| --- | --- | --- |
| `11003` | `0.0.0.0`，tRPC + TLS | 跨主机入口：其他主机上的组件、外部接入、其他主机网关拉快照都走这里；证书由 MooX 私有 CA 签发 |
| `11002` | `127.0.0.1`，tRPC 明文 | 本机入口：本机组件和经 SSH 隧道的 moox-cli；本机的服务目录（`Directory`）也在这里 |
| `11012` | `0.0.0.0` | `/healthz`、`/readyz`、`/metrics`，需要 health HMAC，防火墙只对 control 开放 |

两个转发入口共用 tRPC 服务名 `trpc.moox.hostgateway.Gateway`，方法是通配的：路由来自快照，变化时不需要重启网关。

## 2. 转发

1. 校验服务签名：调用方、KeyID、时间戳、nonce、目标主机和请求体摘要。目标主机必须是本机 ID；nonce 持久化在
   `<store.path>/nonces`，进程重启不会重新打开重放窗口。
2. 按 tRPC service path 和方法查快照中的路由，再按组件目录的 ACL 判断调用方是否放行。ACL 判定和控制台进程内调用
   共用 `servicecatalog` 的同一份实现。
3. 转发到 `127.0.0.1:<目录端口>`，请求体原样透传（PB 或 JSON 都不重新序列化）；已校验的调用方身份放进
   `x-moox-verified-caller` 元数据交给下游服务。外部接入转发时另在元数据 `x-access-principal` 中写入外部调用方
   名称，只用于日志和指标。
4. 只有只读方法在上游失败时重试，写方法不重试。

路由只来自「部署在本机且已启用」的组件在组件目录中声明的 tRPC 服务，上游端口取自目录，不能在别处配置。

## 3. 快照

快照由管理后台的网关控制（`trpc.moox.admin.GatewayControl`，端口 `11112`）为每台主机单独编译，内容包括：

- 本机路由；
- 全局服务目录：每个 tRPC 服务部署在哪些主机，以及每台主机的公网地址、私网地址和地域；
- 允许调用本机路由的调用方校验密钥；
- 版本号和哈希。

同步规则：

1. 启动时先加载 `<store.path>/snapshot.json`（权限 0600），再向网关控制拉取；没有有效缓存的主机必须完成首次拉取
   才能就绪。
2. 定时器 `trpc.moox.hostgateway.route_refresh.timer` 每 15 秒拉取一次，请求带上当前哈希，没有变化就不返回内容；
   同时上报心跳：实例 ID（进程启动时随机生成）、版本、已应用的哈希、路由数、最近一次错误和证书到期时间。
3. 新快照先整体校验，不通过就整体拒绝，继续使用旧快照。
4. 网关控制暂时不可用时，缓存的快照照常服务；最近一次同步成功超过 90 秒（`MOOX_GATEWAY_ROUTE_SYNC_STALE_AFTER_SECONDS`）
   时 `/readyz` 返回不可用，Monitor 据此告警。

control 主机的网关直连本机的 `127.0.0.1:11112`；其他主机经 control 的 `11003` 拉取，以 `host-gateway@<主机>` 签名，
网关控制只接受与请求中主机 ID 一致的身份。新增主机或调用方后，其他主机网关在下一次快照（15 秒内）就能识别，
不需要逐台重新部署。

## 4. 服务目录

`trpc.moox.hostgateway.Directory/GetDirectory`（`packages/gatewayroute/proto/directory.proto`）只在 `11002` 上提供，
返回当前快照里的服务目录；请求带上客户端已有的版本，没有变化时只返回 `changed=false`。

`packages/gatewayclient` 的内部方式用它选路：目标在本机时连 `127.0.0.1:11002`，在其他主机时连 `<主机>:11003`。
客户端把目录落盘缓存，每 15 秒比对一次版本；目标网关返回「服务不在本机」或拒绝连接时立即刷新目录。

## 5. 配置

`config/app.yaml` 由 `moox-cli setup deploy-host` 按主机渲染，相对路径按配置文件所在目录解析：

```yaml
host:
  id: compute-1
server:
  remote_addr: 0.0.0.0:11003
  local_addr: 127.0.0.1:11002
  health_addr: 0.0.0.0:11012
tls:
  cert_file: ../../certs/host-gateway/server.crt
  key_file: ../../certs/host-gateway/server.key
  ca_file: ../../certs/moox-ca.crt
control:
  target: 106.53.107.122:11003    # control 主机上填 127.0.0.1:11112，且不配置 key_file
  caller: host-gateway@compute-1
  key_file: ../../secrets/caller-host-gateway.key
store:
  path: ../../data/host-gateway
```

主机网关不配置调用方密钥表，校验用的密钥来自快照。主机证书在每次部署该主机时重新签发，SAN 包含主机 ID、
公网地址和私网地址。

## 6. 诊断

```bash
moox-host-gateway-cli check-config --config config/app.yaml   # 校验配置
moox-host-gateway-cli snapshot --config config/app.yaml       # 查看缓存的快照：哈希、路由、目录和调用方 KeyID，不输出密钥
moox-host-gateway-cli health --url http://127.0.0.1:11012/readyz
```

`trpc.moox.hostgateway.metrics.timer` 每 30 秒上报一次指标快照。关键指标：

| 指标 | 含义 |
| --- | --- |
| `host_gateway_route_sync_stale` | 快照同步是否已过期 |
| `host_gateway_route_sync_errors_total`、`host_gateway_route_validation_failures_total` | 拉取失败、快照校验失败 |
| `host_gateway_route_report_errors_total` | 心跳上报失败 |
| `host_gateway_auth_failures_total`、`host_gateway_replay_failures_total` | 签名校验失败、重放 |
| `host_gateway_upstream_failures_total` | 转发到本机服务失败 |
| `host_gateway_requests_total`、`host_gateway_request_duration_seconds` | 请求数与耗时 |

控制台「服务部署」页的「路由」标签展示每台主机的期望哈希、已应用哈希和网关心跳；实例冲突、心跳超时和哈希长期
不一致由 Monitor 告警（见[监控](监控.md)）。
