# 主机网关（HostGateway）

`moox-host-gateway` 是系统中唯一的服务网关。每台 MooX 主机上恰好运行一个，是别的主机调用这台主机上服务的入口：
按原始 PB/JSON 字节校验服务签名和 ACL，再把请求原样转发到本机固定的 loopback 端口。同一台主机上的组件互相调用不经过它，直连服务的回环端口（第 4 节）。它不读 Admin 数据库，跨主机转发只有两种：control 网关为只能出站的主机做字节级中转（第 5 节），中转内容是调用方与目标网关之间的端到端 TLS；
登记成外部入口的主机，网关另开 `11004` 接外部身份（云函数 SCF、Skill、采集名单干预工具）的签名请求，目标服务不在本机时转给目标主机（第 6 节）。
浏览器流量不经过它，浏览器入口是 Admin 自己监听的 9527（见[管理后台](管理后台.md)第 3 节）。

代码位置：`modules/hostgateway`；签名在 `packages/gatewayauth`，目录协议在 `packages/gatewayroute/proto`，
组件目录与按部署算路由在 `packages/servicecatalog`，调用方客户端在 `packages/gatewayclient`。



## 1. 入口与端口

| 端口 | 监听 | 说明 |
| --- | --- | --- |
| `11003` | `0.0.0.0`，tRPC + TLS | 跨主机入口：其他主机上的组件、入口主机的网关替外部身份转发、其他主机的网关拉快照都走这里；证书是 MooX CA 签的主机证书，客户端按主机 ID 校验。同一端口握手后按 ALPN 分流：`moox-relay-attach`、`moox-relay-open` 是反向连接（第 5 节），其余交给 tRPC |
| `11002` | `127.0.0.1`，tRPC 明文 | 本机入口：本机组件在这里取目录（`Directory`，只有主机与部署）；经 SSH 隧道的 `moox-cli` 的请求也从这里进，照常验签 |
| `11004` | `0.0.0.0`，tRPC 明文 + 签名 | 外部入口，只有登记成外部入口的主机才监听，只接三个外部身份（第 6 节） |
| `11012` | `127.0.0.1` | `/healthz`、`/readyz`、`/metrics`，不验签，防火墙不放行 |

control 主机上的网关直连本机 Admin 的网关控制 `127.0.0.1:11112`；其他主机经 control 的 `11003` 访问。
没有 HTTP 入口，也没有 `/api/service/*`。

## 2. 转发

1. 校验调用方签名（ed25519，见下文“调用方身份与签名”）：目标主机必须是本机 ID；签名在时间窗内；带签名主机的用那台主机的公钥，
   并要求这个调用方确实部署在那台主机上；不带的用非主机身份的公钥。
2. 防重放：nonce 记在进程内存里，有效期等于签名窗口；签名时间早于本进程启动时间的请求一律拒绝，所以重启不会放过重放
   （网关启动后等过当前这一秒才开始监听）。
3. 按 tRPC service path 和方法查本机的路由（网关自己按快照里的部署和内嵌的服务目录算，第 3 节），再按组件目录的 ACL
   判断调用方是否放行。ACL 判定与控制台进程内调用共用 `servicecatalog` 的同一份实现。
4. 转发到 `127.0.0.1:<目录端口>`，请求体原样透传，不重新序列化。外面带进来的 `x-moox-*` 字段一律不往后传（签名到网关为止）；
   只有 `GatewayControl` 另外收到网关写的 `x-moox-verified-host`：验过的签名主机 ID，Admin 用它认是哪台主机的网关在调，自己不验签。

第 1、2 步和调用名单任何一项不过，都在转发之前拒绝，并返回专用错误码（`gatewayauth.RetRejected`，11403），不透露具体原因。
客户端（`gatewayclient`）只对这个错误码刷新目录、重新签名重发一次，对写方法也一样：请求没有到达服务，重发是安全的。
服务自己返回的鉴权类错误不重发。

### 调用方身份与签名

- **每台主机一把 ed25519 私钥**（`<部署根>/secrets/host.key`，0600），这台主机上的全部组件共用，各自以自己的组件 ID 签名；管理台（Admin）以 `console` 的身份用控制机的主机密钥。
  私钥由控制机上的 `moox-admin-cli host-bundle`（控制机自己是 `bootstrap`）生成，随身份包经操作电脑中转到目标机，Admin 只登记公钥（`t_hosts.c_sign_public_key`）。
- **不属于主机的身份各一把**：`moox-cli`（操作电脑 `~/.config/moox/moox-cli.key`，`setup operator` 生成）、`scf-collector`（控制机 `secrets/scf-collector.key`，随控制机身份包签发）、
  `moox-skill`、`collector-operator`（使用方本机生成）。公钥登记在 Admin 的 `t_identity_keys`。主机网关的 `11003`、`11002` 上，这四个里只有 `moox-cli` 能调方法，其余三个是外部身份，只能从外部入口（`11004`）进来。
- **签名头 6 个**：`X-Moox-Caller`（组件 ID 或非主机身份）、`X-Moox-Host`（签名主机 ID，非主机身份为空）、`X-Moox-Timestamp`、`X-Moox-Nonce`、`X-Moox-Target-Node`、`X-Moox-Signature`。
  签名材料按行拼接：`moox-gateway-auth-v2`、调用方、签名主机、被调服务、方法、请求体 SHA-256、时间戳、nonce、目标主机；签名有效期 60 秒，允许 30 秒时钟偏差。
- **公钥怎么到网关**：随快照下发，全部主机拿到的是同一份——每台主机带着自己的公钥，加各非主机身份的公钥。一台主机上谁能用它的密钥签名，
  由网关按快照里的部署自己算：这台主机上启用的组件，部署了 admin 的主机另有 `console`，每台主机都有 `host-gateway`。快照里没有秘密。
- **换密钥没有新旧并存**：一个身份只有一把公钥。例行部署不换主机密钥（部署先在目标机上算出现有私钥的公钥，和 Admin 登记的一致就沿用，只重签主机证书）；
  私钥丢了、对不上，或 `setup deploy --host <主机> --rotate-host-key` 显式要求时签发新的，旧私钥随即作废，这次部署按整台部署处理（`--component` 不起作用），这台主机上的组件全部重启，网关最先。
  控制机的主机密钥不单独换：删掉控制机上的 `secrets/host.key` 再重新部署控制机。换操作电脑用 `moox-cli setup operator --register`（经 SSH 在控制机上替换 `moox-cli` 的公钥，原电脑随即不能用）。

已知差别（按单用户原则接受）：

- 网关重启后的头几十秒内，时钟偏慢的调用方会被拒；客户端重签重发一次，仍被拒就报错。
- 拿到一台主机就能以这台主机上任何组件的身份签名（它们共用主机密钥）；拿不到别的主机上的组件身份，也拿不到 `moox-cli`、`console`（除非那台就是控制机）。
- EventBus 的服务端证书就是所在主机的主机证书（和 11003 同一张），客户端用 MooX CA 根证书校验；认证仍按角色令牌，不走网关签名。
- 目标事件走 EventBus，Trade 消费时不验来源：拿到存储机（EventBus 服务端）仍然能让 Trade 下单；因子机能写坏因子值，间接影响下单。这两条不在签名保护之内。
- 登记或更换外部身份（`moox-skill`、`collector-operator`、`scf-collector`）的公钥后，各网关要等下一次拉到快照才认新公钥，最多约 5～10 秒。
- 同机调用不查逐方法的调用名单（第 4 节）：同一台主机、同一个系统用户，本来就能直接连这些回环端口。例如 Collector 与 Admin 同在控制机，
  `GetCloudCredential` 这类“只给某个组件”的方法对同机的其他组件没有隔离作用。逐方法名单限制的是别的主机。
- 解压在验签之前：未认证的对端用几 KB 的合法帧就能让网关解出最大 64MB，全进程解压额度只限住同时在解的总量；排队不保证先来先得，小解码持续涌入时大请求可能久等。

## 3. 快照

快照由 Admin 的网关控制（`trpc.moox.admin.GatewayControl`，loopback `11112`）给出，**全部主机拿到同一份**，内容只有三样加哈希：

| 内容 | 字段 |
| --- | --- |
| 登记的主机 | 主机 ID、地址、内网地址、可达性（`direct` / `outbound`）、是否启用、是否外部入口、签名公钥（还没签发过身份包的主机为空） |
| 部署 | 主机 ID、组件 ID、是否启用 |
| 不属于主机的身份 | 身份名、签名公钥 |

快照里没有路由、端口、超时、调用名单，也没有秘密。这些由每个网关按**内嵌的服务目录**自己算（`servicecatalog.Compile`）：

- **本机路由**：部署在本机且已启用的组件在目录里声明的服务与方法；上游地址是 `127.0.0.1:<目录端口>`，超时、请求体上限、只读、能调它的调用方都取自目录。
- **验签名单**：每台主机上能用主机密钥签名的调用方（见第 2 节）。
- **中转许可**（只有 control 算）：出站主机的哪些端口对哪些调用方开放（第 5 节）。
- **本机停用**：快照里本机 `enabled = false` 时没有路由，请求一律拒绝。
- **不认识的组件**：快照里有、本进程内嵌目录里没有的组件 ID（Admin 比这台网关新）会被忽略并记一条日志，其余路由照常生效。
  所以升级时网关与 Admin 不必同时换；但新增的服务要等所在主机的网关升级后才能从别的主机调通。

网关只做格式上的整体校验（格式版本、大小、哈希、主机 ID 与地址、公钥长度、部署指向已登记主机、不重复），拓扑是否合法
（单副本、端口冲突、控制机组件的位置）由 Admin 在写入登记时校验。控制机不随快照下发：它就是部署了 admin 的那台。

同步规则：

1. 启动时先加载 `data/host-gateway/snapshot.pb`，再向网关控制拉取；没有有效缓存的主机必须完成首次拉取才能就绪。
   落盘的就是收到的那份快照（主机、部署、公钥），加载时重新算一遍路由；Unix 目录与文件权限分别为 0700 和 0600。
2. 定时器 `trpc.moox.hostgateway.route_refresh.timer` 每 5 秒拉取一次，请求带上当前哈希，没有变化就不返回内容；同时上报心跳：
   实例 ID（进程启动时随机生成）、版本、已应用的哈希和最近一次错误。快照与客户端目录都是每 5 秒刷新，为 15 秒的部署可见性预算
   留出处理时间。
3. 新快照先整体校验，不通过就整体拒绝，继续使用旧快照。权限撤回先应用到内存，落盘失败会持续重试。
4. 控制面暂时不可用时，缓存的快照照常服务；最近一次同步或心跳成功超过 90 秒
   （`MOOX_GATEWAY_ROUTE_SYNC_STALE_AFTER_SECONDS`）时 `/readyz` 降为不可用，Monitor 据此告警。

其他主机的网关以 `host-gateway` 的身份、用本机的主机密钥签名；网关控制只接受“验过的签名主机”与请求里的主机 ID 一致的调用。
新增主机、部署或换了公钥，其他主机网关在下一次快照就能识别，不需要逐台重新部署。停用的主机在各网关算出来只剩 `host-gateway` 这一个调用方：
它还要验签取到快照（从中得知自己已停用），它上面的组件不能再签名。

## 4. 目录与同机直连

`trpc.moox.hostgateway.Directory/GetDirectory` 只在 `11002` 上提供，返回快照里的主机与部署（不含公钥），版本就是快照哈希；
请求带上客户端已有的版本，没有变化时只返回 `changed=false`。

`packages/gatewayclient` 和网关一样用内嵌的服务目录把“主机加部署”展开成“每个服务在哪些主机上”，再选路：

| 目标服务在 | 怎么连 | 签名 | 压缩 | 查调用名单 |
| --- | --- | --- | --- | --- |
| 本机 | 直连 `127.0.0.1:<服务端口>`，不经本机网关 | 不签 | 不压 | 不查 |
| 其他主机 | `<主机地址>:11003`，TLS，按主机 ID 校验证书 | 签 | 压 | 客户端先查一遍，目标网关再查 |
| 只能出站的主机 | 经 control 中转（第 5 节），流上再与目标网关做端到端 TLS | 签 | 压 | 同上 |

同机直连时请求只带应用元数据（`X-Space-Id`、`X-User-Id`、`X-Trace-Id`），超时取目录里的值。本机回环端口不验签；
同机调用不经过网关，所以不查逐方法的调用名单，也不计入网关的请求指标。管理台（Admin 以 `console` 的身份）同样处理，
它自己在转发之前按 `operators` 判断一次（`console.dispatcher`），所以“只给 `moox-cli`”的方法管理台仍然调不了。
`moox-cli` 走 SSH 隧道进目标主机的 `11002`，不属于同机直连，照常验签、查名单。

客户端把收到的主机与部署落盘缓存（`data/<组件>/gatewayclient/directory.json`），每 5 秒比对一次版本；控制面暂时不可达时继续使用有效缓存。
缓存里不存展开后的结果：升级后的进程按自己的服务目录重新展开，不认识的组件忽略。

## 5. 反向连接（只能出站的主机）

家庭网络等只能出站、出口 IP 会变的主机，在 `moox.toml` 的 `[hosts.<ID>]` 写 `reachability = "outbound"`（Admin `t_hosts.c_reachability`），
`address` 只作身份与证书 SAN，不要求可达。快照与目录里它的可达性是 `outbound`，调用方据此经 control 中转；control 的网关自己算它的中转许可：
跨主机端口 `11003` 对能调用该主机任一服务的调用方开放，外部程序的 `relay_http` 端口只对它声明的调用方开放（见下文）；组件健康端口不进中转许可（组件健康只看上报，Monitor 不探测）。control 不能是出站主机。

- **建立会话**：出站主机的网关看到快照里本机是 `outbound` 后，用本机网关证书（Admin 为出站主机签发的证书同时带 `ClientAuth`）
  以 ALPN `moox-relay-attach` 连 control 的 `11003`（即 `control.target`），再以 `host-gateway` 的身份用本机的主机密钥签名一次 attach（control 核对签名主机就是声明的主机）。
  control 校验证书链与 SAN、签名与 nonce、目录登记（已启用的出站主机）后，这条连接成为多路复用会话（`hashicorp/yamux`），
  每 15 秒心跳，约 45 秒无响应判定断开。每台主机只保留最新的会话；断开后 1 秒起指数退避重连，最长 30 秒，出口 IP 变化只表现为一次重连。
- **打开中转流**：调用方以 ALPN `moox-relay-open` 连 control 的 `11003`，发送签名的打开流前导（目标主机、端口）；control 按中转许可
  校验调用方与端口后在会话上开一条流，出站主机只把它接到本机 `127.0.0.1` 上允许的端口。之后调用方在流上与目标网关做端到端 TLS
  （RPC，`ServerName` 为目标主机 ID），或直接说 HTTP（Admin 转发归档下载与预览），control 只转发字节，没有大小上限。
  `gatewayclient` 自动完成这一步（连接池按目标隔离、可复用）：control 上的调用方连本机 `127.0.0.1:11003`；CLI 隧道模式经 SSH 转发到
  control 的 `11003`，需要操作端身份目录里的 `moox-ca.crt`（安装操作端身份时写入）。
- **外部程序的 `relay_http`**：服务目录里外部程序（`external_program: true`）可以声明一个只听回环地址的 HTTP 端口 `relay_http: {port, callers}`，例如 archive-worker 的数据端口 `11428`、`callers: [console]`（分区下载与最新数据预览，见[归档](归档.md)第 9 节）。
  - 只许外部程序声明；`callers` 为 1～16 个、不重复，只能是内置调用方（非外部组件、`console`、`moox-cli`）；端口不能用网关跨主机端口，也不能与目录里任何其他组件的端口相同（计入跨组件端口冲突检查与部署预检，防火墙只看健康端口，不会放行它）。
  - 外部程序装在出站主机上时，control 算出的中转许可带上这个端口与声明的调用方，出站主机的网关把它列进允许接入的本机端口；端口本身不验签，放行靠 control 按调用方白名单验签。
- **外部程序的服务**：外部程序也可以在服务目录里声明只监听本机的服务，例如因子引擎的 `trpc.moox.factor.EngineControl`（端口 `11423`；回放的三个方法只给 strategy，生命周期、任务检查与本地写入的方法只给 `moox-cli`，见[因子](因子.md)第 9 节）。
  它与普通组件的服务一样算：所在主机的网关有指向 `127.0.0.1:<端口>` 的路由；装在出站主机上时，这些调用方并入跨主机端口 `11003` 的中转许可，
  服务端口本身不进中转许可。外部程序仍不能声明 `ports`；它作为调用方和别的组件一样，用所在主机的密钥、以自己的组件 ID 签名，直连存储机与控制机的 `11003`。
- **信任边界**：网关只持有公钥，拿到任何一台主机的网关快照都伪造不了别人的签名。control 网关校验打开中转流的签名；端到端 TLS 保证传输机密性并校验目标主机身份。
  因子机上的进程只能以因子机上的组件身份（`factor-engine`、`archive-worker`、`host-gateway`、`host-agent`）签名，调不了只给 `moox-cli`、`console` 的方法。
- **连接保护**：认证在握手之后，所以连接在接受时就占配额并保持到关闭：单个来源 IP 最多 256 个、全局 8192 个；同时握手的单 IP 上限 64，握手 5 秒超时，前导须在 10 秒内完成，不带 ALPN 的普通连接由 tRPC 空闲 1 分钟关闭；中转流总数 4096，每个会话 1024。
- **可观测**：control 网关的心跳带上各出站主机的会话（是否在线、网关实例、建立时间、重连次数、活动流数，从未接入的出站主机也列为离线），
  Admin 存入 `t_host_gateway_status.c_relay_sessions`，管理台与 `moox-cli host routes` 能看到。中转链路没有单独的告警：因子机的实时链路（读行情、写因子、心跳、上报）
  都是它主动出站的，不经过中转；经中转的只有人发起的操作，断了当场报错。
- **暂停接入**：在 Admin 停用该主机（control 不再中转，并断开已有会话），或停掉该主机的网关：`moox-cli setup stop --host <主机> --component host-gateway --yes`（`systemctl --user disable --now`，之后的部署保持停用，恢复用 `setup start-component`）。

## 6. 外部入口

外部调用方（云函数 SCF、Skill、采集名单干预工具）不在部署里，没有主机密钥，也不做目录发现。它们固定连一台**入口主机**的网关 `11004`：
tRPC 明文加签名，签名的目标主机就是入口主机的 ID。哪台主机是入口登记在 `moox.toml` 的 `[hosts.<ID>] external_entry = true`
（Admin `t_hosts.c_external_entry`，随快照下发）；只能出站的主机不能登记。默认部署里存储机和海外机是入口，控制机、因子机不是。
没有独立的接入进程：因子引擎与归档 worker 是普通组件，用因子机的主机密钥直连存储机、控制机的 `11003`，不走这里。

### 入口上的处理

1. 登记里本机不是外部入口（或本机已停用）时一律不接。
2. 请求体不超过被调服务在组件目录里的上限。
3. 验签、调用名单、防重放与 `11003` 相同，公钥取自快照里“不属于主机的身份”。只接组件目录里标了 `external: true` 的身份
   （`scf-collector`、`moox-skill`、`collector-operator`），并且这个身份要在被调方法的 `callers` 里；组件和 `moox-cli` 的签名拿到 `11004` 上不认。
   这三项不过都返回拒签专用错误码（`gatewayauth.RetRejected`），调用方重新签名重发一次。
4. 往后只带 `X-Space-Id`、`X-Trace-Id` 两个元数据字段，其余（含全部 `x-moox-*` 与用户权限元数据）到此为止。
5. 目标服务在本机就转给本机的回环端口；在别的主机，就由网关进程内的 `gatewayclient` 以 `host-gateway` 的身份、用本主机的密钥签名，
   转到目标主机的 `11003`（TLS），并带上头 `X-Moox-Origin-Caller`：值是验过签的外部身份。请求体原样透传，沿用入站帧的压缩类型。
   入口对每台目标主机保持 32 条连接常驻（空闲上限 64），整分钟几十个函数同时写入时不用现建跨地域的 TLS 连接。
   连接池从第一次转发到这台目标主机的请求开始预热（之后每 10 秒补到 32 条），不是启动即建；超过 15 分钟没有请求的目标不再补。

外部入口没有“授权的服务全部进入目录才就绪”这样的就绪条件：目标服务没有部署时，那一次调用直接失败。

### 目标网关对来源头的三条检查

每台主机都有 `host-gateway`，任何一台主机的私钥都能以它的身份签名。所以 `11003`、`11002` 上收到带 `X-Moox-Origin-Caller` 的请求时，
下面三条缺一条就拒绝并计数：

1. 签名的调用方是 `host-gateway`，并且签名主机在快照里登记成外部入口（且已启用）。控制机、因子机带这个头一律不认。
2. 头里的值是组件目录里标了 `external: true` 的身份。`moox-cli`、`console` 和任何组件名都不行。
3. 这个外部身份在被调方法的 `callers` 里。

三条按上面的顺序判断，拒绝原因记在指标 `moox_gateway_external_denials_total` 的 `reason` 标签里，依次是 `origin_host`、`origin_identity`、`origin_method`。
先判签名主机：因子机（不是入口主机）用自己的主机密钥以 `host-gateway` 的身份带任何来源头，原因都是 `origin_host`，不管头里写的是 `moox-cli` 还是 `scf-collector`；
存储机（入口主机）带 `X-Moox-Origin-Caller: moox-cli` 是 `origin_identity`；带外部身份但方法不在它名单上是 `origin_method`。
不带来源头、以组件身份直接调名单外的方法（例如因子机以 `factor-engine` 的身份调 Trade 下单），按普通的调用名单拒绝，不计入这个指标。

不带这个头时，`host-gateway` 只能调它自己名单里的方法（`GatewayControl` 的两个）。来源头不往被调服务传。

所以入口主机被拿到之后，借转发能冒充的只有三个外部身份，合计 7 个方法：

| 外部身份 | 能调用的服务与方法 |
| --- | --- |
| `scf-collector` | `PrimaryStore`：`CommitTimeSeriesBatch`、`UpsertFields`（写行情行） |
| `moox-skill` | `PrimaryStore`：`ReadTimeSeriesRows`（只读行情查询） |
| `collector-operator` | `CollectMgr`：`SetSubjectExclusions`、`ClearSubjectExclusions`、`ListSubjectExclusions`、`SyncSubjects`（采集名单干预的旁路程序，不在部署拓扑里） |

名单只写在组件目录里（`packages/servicecatalog/catalog.yaml`：外部身份列在 `identities`，能调的方法是 `callers` 里写了它的那些）。
改名单要改组件目录并重新发布入口主机与目标主机的网关。Storage 只靠服务端口只监听本机加网关的调用名单，不校验调用方密钥。

### 外部调用方怎么连

```yaml
gateway_client:
  entry_address: 203.0.113.11:11004   # 入口主机地址加 11004
  entry_host: storage                 # 入口主机的 ID，也是签名的目标主机
  caller: moox-skill                  # scf-collector / collector-operator / moox-skill
  key_file: .moox-skill-keys/moox-skill.key   # 这个身份自己的 ed25519 私钥（base64 的 32 字节种子，0600）
```

- `moox-skill`、`collector-operator` 的私钥在使用它的电脑上生成，公钥用 `moox-cli setup export-skill-config`（Skill）或
  `setup register-identity` 经 SSH 登记到控制机。`scf-collector` 的私钥在控制机 `<部署根>/secrets/scf-collector.key`，随控制机的身份包签发。
  一个身份只有一把公钥，再登记一次就是替换，旧私钥随即不能用。公钥随快照下发，登记完不用再对哪台主机做什么。
- 云函数没有配置文件：Collector 发布函数时把入口写进环境变量 `MOOX_ENTRY_ADDRESS`、`MOOX_ENTRY_HOST`，把 `scf-collector` 的私钥写进 `MOOX_CALLER_KEY`
  （`MOOX_CALLER_KEY_ID` 是公钥的十六进制，只用来判断云上函数是不是还带着当前这把密钥）。函数在地域的 VPC 里运行，入口地址是同地域入口主机的私网地址（见[采集](采集.md)）。

### 传输压缩

跨主机调用恒定压缩，没有开关，覆盖经主机网关、经 control 中转、SSH 隧道和经外部入口的调用（含云函数到入口）；本机回环从不压缩。
压缩算法是 zstd 加训练字典，由共享包 `packages/wirecompress` 实现，系统内部所有传输与编码都用它（浏览器流量与对外文件格式除外）。
请求按 tRPC 帧头的压缩类型压缩，**不设请求体大小门槛**：服务端按请求的压缩类型压缩响应，读接口请求很小、响应很大，小请求也必须标记压缩。
网关解压后再验签，签名始终覆盖未压缩的原始请求体。解压只接受声明了原始长度的单个 zstd 帧，按帧上限分配缓冲，框架内置的 gzip 等算法一律拒绝。
块数不够输出声明长度的帧在分配之前就拒绝。全进程同时在解压的缓冲合计不超过两个最大帧（约 128MB），用满时后来的解码排队，不直接拒绝。
全系统只用一个默认字典：压缩类型号对应一个字典版本，解码按帧头里的字典 ID 选字典。
入口手里只有原始字节，把入站帧的压缩类型沿用到出站一跳。字典版本与当前使用的版本见 `packages/wirecompress/dicts/registry.yaml`，维护工具见 `tools/zstddict`。
跨境一跳的背景：2026-10-19 实测海外机出口约 3 Mbit/s，未压缩时整分钟突发约 600KB 排队丢包，压缩后没有重传。

## 7. 配置

`config/app.yaml` 使用 `packages/servicecatalog/hostgatewayconfig` 的共享配置结构，由部署工具按主机渲染，相对路径按配置文件
所在目录解析；配置只包含路径与公开身份，严格拒绝未知字段与多个 YAML 文档：

```yaml
host:
  id: storage
server:
  remote_addr: 0.0.0.0:11003
  local_addr: 127.0.0.1:11002      # 必须是回环地址
  health_addr: 127.0.0.1:11012
  external_addr: 0.0.0.0:11004     # 只有登记成外部入口的主机才写；不写就不开外部入口
tls:
  cert_file: ../../secrets/host.crt
  key_file: ../../secrets/host.tls.key
  ca_file: ../../secrets/moox-ca.crt
control:
  host_id: control
  target: 192.0.2.1:11003          # control 主机上固定为 127.0.0.1:11112
  key_file: ../../secrets/host.key   # 本机的主机签名私钥
store:
  path: ../../data/host-gateway
```

`config/trpc_go.yaml` 配置快照刷新与指标两个定时器。`app.yaml` 由部署按拓扑生成；MooX 私有 CA、主机证书和主机签名私钥来自控制机签发的身份包，
运行端只读取已有的身份文件，不生成证书或密钥。`store.path` 下只有快照缓存。`moox-host-gateway-cli sign-public-key --key-file <文件>` 打印一个签名私钥对应的公钥，
部署用它核对目标机上的私钥和 Admin 登记的是否一致（私钥不离开目标机）。

## 8. 诊断

```bash
moox-host-gateway-cli check-config --config host-gateway/config/app.yaml
moox-host-gateway-cli routes --config host-gateway/config/app.yaml      # 按落盘快照算出的本机路由、目录与不认识的组件，不含公钥
moox-host-gateway-cli health --config host-gateway/config/app.yaml      # 请求配置里本机的 /readyz（只听 127.0.0.1、不验签）；也可用 --url
```

网关自己的指标在 `/metrics` 中暴露。关键指标：

| 指标 | 含义 |
| --- | --- |
| `host_gateway_route_sync_stale` | 快照同步是否已过期 |
| `host_gateway_route_sync_errors_total`、`host_gateway_route_validation_failures_total` | 拉取失败、快照校验失败 |
| `host_gateway_route_report_errors_total` | 心跳上报失败 |
| `host_gateway_route_last_sync_timestamp_seconds`、`host_gateway_route_last_report_timestamp_seconds` | 最近一次同步与上报时间 |
| `host_gateway_routes_current`、`host_gateway_route_info` | 当前路由数与快照信息 |
| `host_gateway_auth_failures_total`、`host_gateway_replay_failures_total` | 签名校验失败、重放 |
| `host_gateway_upstream_failures_total` | 转发到本机服务失败 |
| `host_gateway_requests_total`、`host_gateway_request_duration_seconds` | 请求数与耗时 |
| `moox_gateway_external_denials_total` | 外部身份的请求在转发之前被拒的次数，标签 `caller`、`service`、`method`、`reason`。入口上的原因：`authentication`（验签）、`permission`（不是外部身份或不在方法名单上）、`replay`、`request_limit`、`metadata`、`not_entry`（本机没登记成外部入口）；目标网关对来源头的原因：`origin_host`、`origin_identity`、`origin_method` |
| `moox_gatewayclient_pool_dials_total`、`moox_gatewayclient_pool_warmups_total`、`moox_gatewayclient_connect_retries_total` | 入口主机到目标主机的连接池：拨号、预热、建连重试的结果。预热到位后新建连接数稳态接近 0 |

控制台「服务」页的「网关路由」标签展示每台主机的期望哈希、已应用哈希和网关心跳；实例冲突、心跳超时和哈希长期不一致由
Monitor 告警（见[监控](监控.md)）。
