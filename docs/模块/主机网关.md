# 主机网关（HostGateway）

`moox-host-gateway` 是系统中唯一的服务网关。每台 MooX 主机上恰好运行一个，是这台主机上所有跨进程 tRPC 调用的入口：
按原始 PB/JSON 字节校验服务签名和 ACL，再把请求原样转发到本机固定的 loopback 端口。它不跨主机转发，也不读 Admin 数据库。
浏览器流量不经过它，浏览器入口是[控制台代理](控制台代理.md)。

代码位置：`modules/hostgateway`；签名在 `packages/gatewayauth`，路由校验与查表在 `packages/gatewayroute`，
组件目录与路由编译在 `packages/servicecatalog`，调用方客户端在 `packages/gatewayclient`。

执行计划：[网关与服务部署重构](../计划/网关与服务部署重构执行计划.md)；设计：[网关与服务部署重构设计](../计划/网关与服务部署重构设计.md)。

## 1. 入口与端口

| 端口 | 监听 | 说明 |
| --- | --- | --- |
| `11003` | `0.0.0.0`，tRPC + TLS | 跨主机入口：其他主机上的组件、外部接入、其他主机的网关拉快照都走这里；证书由独立的 MooX 私有 CA 签发，客户端按主机 ID 校验 |
| `11002` | `127.0.0.1`，tRPC 明文 | 本机入口：本机组件和经 SSH 隧道的 `moox-cli`；本机服务目录（`Directory`）也在这里，只含主机和服务目录 |
| `11012` | `0.0.0.0` | `/healthz`、`/readyz`、`/metrics`，需要 health HMAC，防火墙只对 control 开放 |

control 主机上的网关直连本机 Admin 的网关控制 `127.0.0.1:11112`；其他主机经 control 的 `11003` 访问。
没有 HTTP 入口，也没有 `/api/service/*`。

## 2. 转发

1. 校验服务签名：调用方、KeyID、时间戳、nonce、目标主机和请求体摘要。目标主机必须是本机 ID；nonce 使用独立的持久化存储，
   进程重启不会重新打开重放窗口。
2. 按 tRPC service path 和方法查快照里的路由，再按组件目录的 ACL 判断调用方是否放行。ACL 判定与控制台进程内调用共用
   `servicecatalog` 的同一份实现。
3. 转发到 `127.0.0.1:<目录端口>`，请求体原样透传，不重新序列化。普通业务上游会剥离所有 `x-moox-*` 字段；只有
   `GatewayControl` 保留已验证的六个签名字段，供 Admin 再次验证原调用主机和原始请求，该转发层不重试，下一次同步由调用方
   生成新 nonce。
4. 只有只读方法在上游失败时重试，写方法不重试。

路由只来自「部署在本机且已启用」的组件在组件目录中声明的 tRPC 服务，上游端口取自目录，不能在别处配置。

## 3. 快照

快照由 Admin 的网关控制（`trpc.moox.admin.GatewayControl`，loopback `11112`）为每台主机单独编译，内容包括本机路由、
全局服务目录、允许调用本机路由的调用方校验密钥以及版本号与哈希。

同步规则：

1. 启动时先加载 `data/host-gateway/snapshot.pb`，再向网关控制拉取；没有有效缓存的主机必须完成首次拉取才能就绪。
   路由、目录和校验密钥一起保存在这个文件里，Unix 目录与文件权限分别为 0700 和 0600。
2. 定时器 `trpc.moox.hostgateway.route_refresh.timer` 每 5 秒拉取一次，请求带上当前哈希，没有变化就不返回内容；同时上报心跳：
   实例 ID（进程启动时随机生成）、版本、已应用的哈希和最近一次错误。快照与客户端目录都是每 5 秒刷新，为 15 秒的部署可见性预算
   留出处理时间。
3. 新快照先整体校验，不通过就整体拒绝，继续使用旧快照。权限撤回先应用到内存，落盘失败会持续重试。
4. 控制面暂时不可用时，缓存的快照照常服务；最近一次同步或心跳成功超过 90 秒
   （`MOOX_GATEWAY_ROUTE_SYNC_STALE_AFTER_SECONDS`）时 `/readyz` 降为不可用，Monitor 据此告警。

其他主机以 `host-gateway@<主机ID>` 签名，网关控制只接受与请求主机 ID 一致的身份。新增主机或调用方后，其他主机网关在下一次
快照就能识别，不需要逐台重新部署。

## 4. 服务目录

`trpc.moox.hostgateway.Directory/GetDirectory` 只在 `11002` 上提供，返回当前快照里的服务目录；请求带上客户端已有的版本，
没有变化时只返回 `changed=false`。目录只含主机地址和每个服务部署在哪些主机，不含密钥与 ACL。

`packages/gatewayclient` 的内部方式用它选路：目标在本机时连 `127.0.0.1:11002`，在其他主机时连 `<主机>:11003`。客户端把目录落盘
缓存，每 5 秒比对一次版本；控制面暂时不可达时继续使用有效缓存。

## 5. 配置

`config/app.yaml` 使用 `packages/servicecatalog/hostgatewayconfig` 的共享配置结构，由部署工具按主机渲染，相对路径按配置文件
所在目录解析；配置只包含路径与公开身份，严格拒绝未知字段与多个 YAML 文档：

```yaml
host:
  id: storage
server:
  remote_addr: 0.0.0.0:11003
  local_addr: 127.0.0.1:11002      # 必须是回环地址
  health_addr: 0.0.0.0:11012
tls:
  cert_file: ../../certs/host-gateway/server.crt
  key_file: ../../certs/host-gateway/server.key
  ca_file: ../../certs/moox-ca.crt
control:
  host_id: control
  target: 192.0.2.1:11003          # control 主机上固定为 127.0.0.1:11112
  caller: host-gateway@storage
  key_id: replace-with-issued-key-id
  key_file: ../../secrets/caller-host-gateway.key
store:
  path: ../../data/host-gateway
```

`config/trpc_go.yaml` 配置快照刷新与指标两个定时器。主机配置、MooX 私有 CA、主机证书和调用方密钥由离线的 Admin
bootstrap 输出，运行端只读取已有的身份文件，不生成证书。

## 6. 诊断

```bash
moox-host-gateway-cli check-config --config host-gateway/config/app.yaml
moox-host-gateway-cli routes --config host-gateway/config/app.yaml      # 公共诊断字段，省略校验密钥
moox-host-gateway-cli health --config host-gateway/config/app.yaml      # 从配置推导本机 /readyz，使用健康鉴权环境变量；也可用 --url
```

网关自己的指标在 `/metrics` 中暴露。关键指标：

| 指标 | 含义 |
| --- | --- |
| `host_gateway_route_sync_stale` | 快照同步是否已过期 |
| `host_gateway_route_sync_errors_total`、`host_gateway_route_validation_failures_total` | 拉取失败、快照校验失败 |
| `host_gateway_route_report_errors_total` | 心跳上报失败 |
| `host_gateway_route_last_sync_timestamp_seconds`、`host_gateway_route_last_report_timestamp_seconds` | 最近一次同步与上报时间 |
| `host_gateway_routes_current`、`host_gateway_route_info` | 当前路由数与快照信息 |
| `host_gateway_auth_failures_total`、`host_gateway_replay_failures_total` | 签名校验失败、重放 |
| `host_gateway_upstream_failures_total` | 转发到本机服务失败 |
| `host_gateway_requests_total`、`host_gateway_request_duration_seconds` | 请求数与耗时 |

控制台「服务部署」页的「网关路由」标签展示每台主机的期望哈希、已应用哈希和网关心跳；实例冲突、心跳超时和哈希长期不一致由
Monitor 告警（见[监控](监控.md)）。

## 7. 测试

```bash
go test -count=1 ./modules/hostgateway/...
make test-host-gateway-control-e2e
```

真实 Admin 联调是单独的必跑门禁：在 Linux 上以真实 SQLite、Badger、PKI、GatewayControl 和生产网关二进制运行六组场景，
实际等待 90 秒的陈旧阈值，整体时限 6 分钟；缺少产物、构建标签或任何场景都会失败。执行细节见
`modules/hostgateway/README.md`。
