# 管理后台（Admin）

Admin 是 MooX 的控制面：负责登录认证、业务空间、组件目录与主机登记和部署、密钥与 PKI、控制台终端（SSH）和系统初始化，
同时是浏览器访问所有后端服务的唯一入口（管理网关，浏览器经[控制台代理](控制台代理.md)到达），并通过网关控制为每台机器的
[主机网关](主机网关.md)下发完整快照。

代码位置：`modules/admin`。

## 1. 进程与端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| 控制台 `trpc.moox.admin.Console` | `11000` | 浏览器 API `/api/admin/*`（loopback，由控制台代理转发） |
| `Auth` | `11100` | 登录、会话、用户信息 |
| `Ssh` | `11106` | 按登记主机建立终端会话（WebSocket）、SFTP |
| `SpaceMgr` | `11107` | 业务空间 |
| `SecretMgr` | `11108` | 加密保存的密钥（云账号、交易所、EventBus 等） |
| `SysDeploy` | `11109` | 组件目录、主机登记（中文名、可达性、控制台 SSH）、组件部署与网关路由状态 |
| `Setup` | `11110` | 系统初始化（供 `moox-cli setup` 调用） |
| `CollectorPublishLease` | `11111` | SCF 采集函数的发布租约 |
| `GatewayControl` | `11112` | 主机网关拉取完整快照与上报心跳（loopback 原生 tRPC，其他主机经 control 的主机网关 `11003` 到达） |
| `ActivityLog` | `11113` | 内部组件追加活动日志，控制台按空间或全局查询 |
| 健康检查 | `11010` | `/healthz`、`/readyz`、`/metrics` |

定时器：`metrics`（30 秒）、`auth_cache_cleanup`（5 分钟，清理 Badger 认证缓存）、
`certificates`（每天，校验 MooX CA、各主机网关证书和独立 EventBus CA，到期前 90 天告警）、`garbage_collection`（每天 03:47，避开整点与零点任务，
单次最长 15 分钟）。

`garbage_collection` 负责清理系统垃圾，避免无用数据持续增长：

- 调用 CloudFunction 的 `CollectGarbage`，清理无节点使用的代码包及其 COS 对象、孤立 COS 对象、
  已删除节点和已结束的节点批次（规则见[云函数实例](./云函数管理.md)）。

`CollectGarbage` 只允许该定时器调用，浏览器经管理网关请求会被拒绝。Collector、Monitor、Storage View
各自按配置保留数据，不在此清理。

数据：SQLite `data/admin.db`（`schema/admin.sql`），认证缓存 Badger `data/badger`。

证书巡检读取 `MOOX_ADMIN_PKI_DIR` 中的 `ca.crt` 和 `hosts/<host-id>.crt`；默认路径与主密钥文件同目录下的 `pki/`。每轮从数据库读取全部已登记主机，包含停用主机，只检查公有证书，不读取私钥或修复文件。检查 CA、自签名、有效期、主机证书签名、服务端用途与登记的 SAN；缺失或异常汇总为 critical，90 天内到期汇总为 warning。首次部署未签发的主机证书会报告异常，但不阻止 Admin 启动，使部署和续签可以继续。EventBus CA 仍由 `MOOX_EVENTBUS_CA_FILE` 配置，旧的两项网关 CA 巡检已删除。

九个内部 RPC 服务使用 loopback 原生 tRPC，端口保持不变；Console 与健康接口使用 HTTP。机器调用由主机网关验证各自身份，浏览器请求由生成 handler 在 Admin 进程内分派。Setup 启动预检要求 loopback 的 TCP/tRPC 11110。

## 2. 认证与会话

MooX 是单用户系统，唯一用户拥有全部管理能力，但认证始终开启：

1. 前端先调用 `GetLoginSalt` 获取一次性盐值挑战，提交加密后的密码材料；`Login` 在服务端解密并用 bcrypt 校验已保存的密码哈希；
   登录接口单独限流，连续失败会锁定账户。
2. 登录后签发 JWT 会话（默认 24 小时，`jwt.access_expired` 必须与 `security.session_ttl` 一致）；登录成功写一条全局活动日志（类别 `auth.login`，不属于任何空间，管理台“活动日志”选“全局”查看），不再单独保存登录历史。
3. 之后每个管理请求还要附带会话 HMAC 签名，包含时间戳和一次性 nonce，防止重放。
4. WebSocket 等无法携带签名头的请求先用 `IssueRawSessionTicket` 换取短时票据。

服务之间的调用使用独立的服务 HMAC（见[主机网关](主机网关.md)），健康检查使用独立的 health HMAC，
三类密钥互不复用。

## 3. 管理网关

浏览器请求经控制台代理（`9527`）进入 `11000`，路径形如 `/api/admin/<服务>/<方法>`：

- **鉴权与限流**：校验会话和签名，按方法限流，处理 CORS。
- **空间作用域**：请求头携带当前空间，网关把 `space_id` 注入下游上下文；部分方法只允许机器调用方
  使用，浏览器无法调用。
- **转发**：方法与权限由 servicecatalog 定义，Directory 从 Admin 拓扑表生成；自身服务通过生成 handler 在进程内调用，其他服务经共享客户端转发原始 JSON。
- **Storage**：浏览器使用目录中的 `storage` 服务名，经同一签名客户端调用原生 RPC，保留用户、空间和 trace 元数据。
- **原始通道**：SSH 终端和 SFTP 通过专门的 raw handler 处理 WebSocket 与流式传输。

## 4. 服务目录（SysDeploy）

SysDeploy 是面向少量机器的静态服务目录，不是动态注册中心：

- `t_hosts` 和 `t_deployments` 保存主机与组件部署关系，`t_hosts` 是唯一的主机登记处：除地址、可达性外还有中文名 `c_label` 与控制台终端用的 `c_ssh_port`、`c_ssh_user`、`c_ssh_fingerprint`（端口为 0 表示不开放终端；凭据存 `t_secrets` 的系统密钥 `moox:ssh-host:<主机ID>`，指纹按“地址:端口”首次连接时固定，只认当前登记的端点），servicecatalog 定义方法、端口与权限，按主机编译网关快照和 Directory。主机带可达性 `c_reachability`（`direct` / `outbound`）：出站主机的网关证书加签 `ClientAuth`，经 control 网关反向连接接入（见[主机网关](主机网关.md)第 5 节）。
- 每个服务在每个节点只有一个入口；`enabled` 表示配置启用，不代表健康，健康由 Monitor 探测。
- 服务不自行注册或续约，拓扑通过 SysDeploy v2 和离线 bootstrap 管理。旧 `t_gateway_nodes`、`t_service_deployments`、SysDeploy v1 和部署种子已删除；CLI 按规范主机 ID 同步完整组件部署，保留已保存的启用/停用状态；机器的新增、部署、启停与移除只经 `moox-cli`，管理台只读。EventBus 凭据工具从有效主机与 EventBus 部署派生地址。
- 主机网关通过原生 GatewayControl 获取本机完整快照并报告应用状态，使用独立 `host-gateway@<主机ID>` 身份；见[主机网关](主机网关.md)。

## 5. 其他服务

| 服务 | 说明 |
| --- | --- |
| SpaceMgr | 空间的增删改查；Admin 的空间与 Storage 的 Space 由 `moox-cli setup init` 同步 |
| SecretMgr | 密钥加密保存；`GetSecretValue` 只允许机器调用方按 ID 读取单条明文，浏览器只能看到掩码。迁移用 `ExportSecrets` / `ImportSecrets`（只允许全局管理员，服务目录只对控制台开放）：导出把全部密钥连同明文（属于本环境的除外：系统空间 `mooxsys` 里的网关密钥环与 EventBus 内部凭据、`moox-config-backup`，导入也拒收这些）用导出口令加密成迁移包（`moox.secrets/v1`，口令至少 12 个字符，PBKDF2-SHA256 60 万次派生 AES-256-GCM 密钥，格式与 KDF 参数参与认证），明文只在 Admin 进程内出现；导入用同一口令解开，按 `secret_id` 写入（保留原标识，引用它的配置迁移后仍然有效），已存在时按选择跳过或覆盖，逐个报告新增、覆盖、跳过与失败 |
| Ssh | 按登记主机的 SSH 端口与凭据建立 Web 终端和 SFTP，不提供主机增删改，也不记录会话日志；只能出站或没有登记 SSH 的主机不能连接 |
| Setup | `ApplySetup` / `GetSetupStatus`，供初始化流程创建空间、基础数据和交易所密钥（`moox.toml` 的 `[[exchange_keys]]`：固定 ID `exchange-<交易所>-<环境>-<名称>`，只建不改，库里已有的——包括已软删除的——不覆盖也不重建，结果里逐把返回 created / exists / deleted）；`PutConfigBackup` / `GetConfigBackup` 只对登录的管理台会话开放，保存 CLI 用管理员密码加密的 `moox.toml` 备份（服务端解不开，入库时再用主密钥加密，存为 `t_secrets` 里的 `moox-config-backup`） |
| CollectorPublishLease | SCF 采集函数发布的租约与操作令牌：CLI 发布前获取租约，CloudFunction 执行变更前校验，避免并发发布 |
| ActivityLog | `AppendActivityLogs` 仅接受内部组件写入；`ListActivityLogs` 按指定空间或 `global=true` 查询，两者互斥 |

## 6. 命令行

`moox-admin-cli`：

| 命令 | 作用 |
| --- | --- |
| `init` | 按 `schema/admin.sql` 初始化数据库 |
| `reset-business [--scope data\|all] [--db-path] --yes` | 系统重置里 Admin 的业务部分：备份整个库到 `reset-backups/`（保留最近 3 份）后清活动日志与采集发布租约/操作；`--scope all` 再清全部业务空间（由 `setup init` 重建）。**保留引导身份层**：用户、密钥、主机（含 SSH 登录信息）与部署、主机网关状态。`--dry-run` 只列行数；每张表必须归类，schema 新增表漏了清单会拒绝执行；不依赖 Admin 进程是否运行 |
| `bootstrap` | 离线初始化主机拓扑、调用方密钥和 MooX CA，生成完整 control 网关部署包；参数与重跑约束见 [Admin README](../../modules/admin/README.md#离线初始化与恢复) |
| `host-bundle` | 从现有拓扑导出指定主机的私密身份包，复用调用方 KeyID、重签叶证书，按部署下发 Access 外部验证表；不生成 CA 或主密钥，不修改启停状态 |
| `host set-status` / `deployment set-status` | 离线修改主机或组件启停状态，复用在线拓扑校验；不创建数据库或 schema |
| `user ensure` | 创建管理员（用户名已存在时不改动）。管理员密码设定后不能修改：配置备份用初始化时的管理员密码加密；需要别的账号时用新用户名再创建一个管理员 |
| `random-secret` | 生成随机密钥 |
| `eventbus-credentials ensure / export / export-clients / rotate / rotate-tls` | 生成或导出 EventBus 身份；`rotate` 轮换角色 token，`rotate-tls` 重签 CA 与服务端证书，`export-clients` 仅导出指定角色（EventBus 单元另带 `--server`） |
| `keys ensure / info / export / export-access / rotate / retire` | 管理加密保存的调用方签名密钥；轮换保留新旧密钥，确认部署完成后再退役旧 KeyID |
| `pki ensure-ca / issue / export-ca` | 复用持久 MooX 私有 CA，签发主机网关证书或只导出公有根；发现 CA 丢失或损坏时拒绝替换 |
