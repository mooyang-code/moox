# 管理后台（Admin）

Admin 是 MooX 的控制面：负责控制台 API、登录认证、业务空间、主机与部署、网关控制、调用方密钥与 PKI、密钥、SSH 主机
和系统初始化。浏览器访问所有后端服务都经过它的控制台 API；每台主机的主机网关从它的网关控制拉取路由快照。

代码位置：`modules/admin`。

## 1. 进程与端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| 控制台 API `trpc.moox.admin.Console` | `11000` | 浏览器的 `/api/admin/*`（HTTP），由控制台代理转发进来 |
| `trpc.moox.infra.Auth` | `11100` | 登录、会话、用户信息 |
| `trpc.moox.ops.Ssh` | `11106` | SSH 主机、会话（WebSocket）、SFTP |
| `trpc.moox.admin.SpaceMgr` | `11107` | 业务空间与成员 |
| `trpc.moox.ops.SecretMgr` | `11108` | 加密保存的密钥（云账号、交易所、EventBus 等） |
| `trpc.moox.ops.SysDeploy` | `11109` | 组件目录、主机、部署与网关状态 |
| `trpc.moox.admin.Setup` | `11110` | 系统初始化（供 `moox-cli setup` 调用） |
| `trpc.moox.admin.CollectorPublishLease` | `11111` | SCF 采集函数的发布租约 |
| `trpc.moox.admin.GatewayControl` | `11112` | 向主机网关下发快照、接收心跳 |
| 健康检查 | `11010` | `/healthz`、`/readyz`、`/metrics` |

除控制台 API 外的服务都是 tRPC，只监听 `127.0.0.1`，其他组件经主机网关访问。

定时器：`metrics`（30 秒）、`auth_cache_cleanup`（5 分钟，清理 Badger 认证缓存）、
`certificates`（每天，巡检 MooX 私有 CA、EventBus CA 和各主机网关证书，到期前 90 天告警）、
`garbage_collection`（每天 03:47，避开整点与零点任务，单次最长 15 分钟）。

`garbage_collection` 负责清理系统垃圾，避免无用数据持续增长：

- 删除 90 天前的登录历史和 SSH 会话记录；
- 以 `admin` 身份调用 CloudNode 的 `CollectGarbage`，清理无节点使用的代码包及其 COS 对象、孤立 COS 对象、
  已删除节点和已结束的节点批次（规则见[云节点](./云节点.md)）。

`CollectGarbage` 的 ACL 只放行 `admin`，浏览器调不到。Collector、Monitor、Storage View 各自按配置保留数据，
不在此清理。

数据：SQLite `data/admin/admin.db`（`schema/admin.sql`），认证缓存 Badger `data/admin/badger`。

## 2. 认证与会话

MooX 是单用户系统，唯一用户拥有全部管理能力，但认证始终开启：

1. 前端先调用 `GetLoginSalt` 获取一次性盐值挑战，再用 bcrypt 校验密码完成 `Login`；
   登录接口单独限流，连续失败会锁定账户。
2. 登录后签发 24 小时的 JWT 会话。
3. 之后每个管理请求还要附带会话 HMAC 签名，包含时间戳和一次性 nonce，防止重放。
4. WebSocket 等无法携带签名头的请求先用 `IssueRawSessionTicket` 换取短时票据。

服务之间的调用使用独立的服务签名（见[主机网关](主机网关.md)），健康检查使用独立的 health HMAC，三类密钥互不复用。

## 3. 控制台 API

浏览器请求经控制台代理进入 `11000`，路径形如 `/api/admin/<console_name>/<方法>`，`console_name` 按组件目录映射到
tRPC 服务：

- **鉴权与限流**：校验会话和签名，按方法限流，处理 CORS。
- **空间作用域**：请求头携带当前空间，控制台核实后把 `space_id` 注入下游上下文；交易相关的空间由
  `TradeSpaceAuthorizer` 单独授权。
- **权限**：控制台以调用方身份 `console` 发起调用。浏览器能调用哪些方法，只看组件目录的 ACL 是否放行 `console`；
  例如 `CloudNode.CollectGarbage`、`SecretMgr.GetSecretValue` 都不放行 `console`。
- **管理后台自己的服务**（Auth、Ssh、SpaceMgr、SecretMgr、SysDeploy、Setup、CollectorPublishLease）在进程内直接调用，
  不经过主机网关，同样按 `console` 的 ACL 校验，判定逻辑与主机网关共用。所以即使网关异常，也能在页面上处理部署。
- **其他服务**经 `gatewayclient.Forward` 以 JSON 透传：请求体原样签名发送，响应原样写回。
- **Storage**：浏览器侧的 Storage 接口（`console_name: storage`）只开放管理台实际使用的方法；控制台额外注入
  Storage 应用层鉴权需要的 `auth_info`。
- **原始通道**：SSH 终端和 SFTP 上传下载（`ssh/WsConnect`、`ssh/SftpUpload`、`ssh/SftpDownload`）由进程内的原始
  处理器处理 HTTP/WebSocket，不走 RPC。

内部任务（每日垃圾回收、发布租约校验等）使用另一个调用方身份 `admin`，与 `console` 分开授权。

## 4. 组件目录、主机与部署（SysDeploy）

组件定义写在代码里（`packages/servicecatalog` 的 `catalog.yaml`）：名称、二进制、部署范围、副本数、是否受保护、
健康检查方式、tRPC 服务与端口、ACL、外部调用方白名单。Admin 只保存「哪个组件部署在哪台主机」：

| 表 | 内容 |
| --- | --- |
| `t_hosts` | 主机：ID（即主机名）、公网地址、私网地址、地域、启用状态 |
| `t_placements` | 部署：主机 × 组件，带启用状态；主机组件（主机网关、主机采集器）在注册主机时自动创建，不能编辑 |
| `t_host_gateway_status` | 主机网关心跳：实例 ID、版本、期望与已应用的快照哈希、路由数、最近一次错误、实例替换与冲突记录 |

主机和部署由 CLI 在部署时登记，Admin 启动时不写任何部署数据。

| 方法 | 使用者 | 说明 |
| --- | --- | --- |
| `GetCatalog`、`ListHosts`、`ListPlacements`、`GetHostRoutes`、`GetDirectory` | 控制台 | 组件目录、主机、部署、每台主机编译后的路由与网关状态、服务目录 |
| `SetHostStatus`、`SetPlacementStatus` | 控制台 | 启用或停用；受保护的组件和 control 主机拒绝停用 |
| `SyncHostPlacements` | CLI | 按 `moox.toml` 的部署表同步一台主机：先整体校验（组件存在、部署范围、副本数、受保护组件不能移除），再在一个事务里写入主机、补上缺少的部署、删除列表里已经没有的部署；已有部署的启用状态保持不变 |
| `DeleteHost` | CLI | 主机上仍有部署时拒绝 |

**实例替换与冲突**：心跳中的实例 ID 与当前实例不同时记为「替换」（正常重启，不告警）；5 分钟内被替换掉的旧实例又
上报心跳（A→B→A 交替）时记为「冲突」，由 Monitor 告警；5 分钟内没有再交替就清除。

**受保护组件**：`admin`、`host-gateway`、`console-proxy`、`web-host` 和 control 主机本身。停用它们会切断控制台和
恢复入口，所以接口、页面和部署同步都拒绝停用。误停用其他组件、而页面又无法恢复时，用离线命令直接改数据库
（见第 7 节），下一次快照会下发新的路由。

## 5. 网关控制

`GatewayControl` 只允许 `host-gateway@<同一主机>` 调用：

- `PullSnapshot(host_id, current_hash)`：按「组件目录 × 已启用的部署」为这台主机编译快照，包括本机路由、全局服务
  目录和允许调用本机路由的调用方校验密钥；哈希没有变化时不返回内容。白名单涉及的方法会自动把 `access` 加入允许的
  调用方。
- `ReportStatus`：记录心跳和证书到期时间，区分实例替换与冲突。

control 的主机网关直连本机 `127.0.0.1:11112`；其他主机经 control 的 `11003` 访问。

## 6. 调用方密钥与 PKI

- **调用方密钥**：每个调用方身份一把服务签名密钥（各组件、`admin`、`console`、`host-gateway@<主机>`、`access`、
  `moox-cli`）；外部调用方（`scf-collector`、`factor-engine`、`moox-skill`）另有一套，只登记在外部接入上。主副本加密
  存放在密钥表，首次需要时生成，之后一律复用。轮换时新旧 KeyID 并存，确认新密钥生效后再停用旧的。
- **MooX 私有 CA**：CA 私钥只放在 `secrets/pki/`（权限 0600），不放进 `admin.db`，重置 control 数据时不会丢失。
  部署工具每次部署一台主机，都用它为主机网关签发新证书（SAN 包含主机 ID、公网地址和私网地址）。

## 7. 其他服务

| 服务 | 说明 |
| --- | --- |
| SpaceMgr | 空间的增删改查与成员；Admin 的空间与 Storage 的 Space 由 `moox-cli setup init` 同步 |
| SecretMgr | 密钥加密保存；`GetSecretValue` 只放行内部调用方按 ID 读取单条明文，浏览器只能看到掩码 |
| Ssh | 维护 SSH 主机，提供 Web 终端和 SFTP；SSH 主机与 `t_hosts` 只按地址关联，用于界面跳转 |
| Setup | `ApplySetup` / `GetSetupStatus`，供初始化流程创建空间和基础数据 |
| CollectorPublishLease | SCF 采集函数发布的租约与操作令牌：CLI 发布前获取租约，CloudNode 执行变更前校验，避免并发发布 |

## 8. 命令行

`moox-admin-cli` 在 control 上运行，大部分命令由部署工具经 SSH 调用：

| 命令 | 作用 |
| --- | --- |
| `init` | 按 `schema/admin.sql` 初始化数据库（组件启动前自动执行） |
| `bootstrap` | 空环境离线初始化：建表、生成 CA、按部署表写入全部主机和部署、生成调用方密钥、为 control 签发主机网关证书（`moox-cli setup bootstrap` 调用） |
| `placement set-status`、`host set-status` | 离线恢复：直接修改部署或主机的启用状态，不依赖 Admin 和网关 |
| `keys ensure / export / rotate / retire / list / export-principals` | 调用方密钥的生成、导出、轮换、停用，以及导出外部接入用的外部调用方密钥集 |
| `pki ensure-ca / issue / export-ca` | 生成 CA、签发主机网关证书、导出 CA 证书（部署工具内部使用） |
| `user ensure` / `user reset-password` | 创建唯一用户、重置密码 |
| `random-secret` | 生成随机密钥 |
| `eventbus-credentials ensure / export / rotate` | 生成、导出、轮换 EventBus 的 TLS 证书和各角色 token |

离线恢复示例：

```bash
cd /data/moox/prod
current/bin/moox-admin-cli placement set-status --db-path data/admin/admin.db \
  --host compute-1 --component trade --status enabled
current/bin/moox-admin-cli host set-status --db-path data/admin/admin.db --host compute-1 --status enabled
```
