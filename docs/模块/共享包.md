# 共享包

`packages/` 下是多个模块共用的 Go 包。每个包都是独立的 Go module，通过 `go.work` 组织。
共享包只放跨模块的契约和基础设施，不放某个模块独有的业务逻辑；只有一个模块使用的包放在那个模块的 `internal/` 下（例如 CLI 的历史数据导入 `seriesimport`、`seriesformat` 与系统暂停编排 `sysctl`，Collector 的通达信协议 `tdx` 与批次结果结构 `marketfetchpb`）。

## 1. 协议（Protobuf）

| 包 | 内容 |
| --- | --- |
| `commonpb` | 公共的 `RetInfo`、错误码等 |
| `storagepb` | Storage 事件负载（周期完成、View 就绪、K 线补采完成、标的下架计划等） |
| `metricspb` | 服务指标快照事件 |
| `hostmetricpb` | 主机快照协议（HostAgent 随 `GetHostPolicy` 报给 Monitor）；主机身份只用登记的 `host_id` |
| `tradeeventpb` | Strategy 发给 Trade 的目标权重事件 |

各包下的 `Makefile` 负责重新生成代码。

## 2. 事件与消息

| 包 | 内容 |
| --- | --- |
| `events` | 事件注册表（名称、版本、负载、Stream、Subject 族）、编码解码和消费者封装；业务模块只能使用这里声明的事件 |
| `jetstream` | JetStream 客户端、连接凭据、消费者与投递设置，以及测试用的内嵌 JetStream |
| `netguard` | 出站连接的地址防护：解析域名后逐个检查 IP（回环、链路本地、组播、内网段），通过才拨号并直接用该 IP 拨号，防 DNS 重绑定；出口代理用它 |
| `wirecompress` | 系统内部传输与编码统一使用的压缩：zstd 加训练字典（全系统一个默认字典，新增或更换字典版本必须分两次发布）；事件信封、主机网关与签名 tRPC 的压缩都走它 |

## 3. 网关与鉴权

| 包 | 内容 |
| --- | --- |
| `gatewayauth` | 调用方身份的 ed25519 签名与校验：绑定调用方、签名主机、目标主机、被调方法、请求体摘要与 nonce，按原始 PB/JSON 字节验签；校验表是“主机公钥加身份公钥”，并核对组件确实部署在签名主机上；另有进程内防重放（早于进程启动的签名一律拒绝）与签名私钥文件的读写 |
| `gatewayclient` | 签名 tRPC 的统一调用方：内部身份从本机网关 `11002` 取主机与部署、按内嵌目录展开后选路（同机直连服务的回环端口，不签名、不查名单；跨主机 TLS `11003`）、外部身份固定连接一台入口主机网关的外部入口（`11004`）、操作员经 SSH 隧道；目录落盘缓存。请求未发出的建连失败可重试；可能发出后仅重试只读或目录声明的幂等写方法，一次调用最多尝试两次，受超时预算约束。主机网关只转发一次，不另外重试。子包 `directorypb` 是主机网关的本机目录协议（`Directory`：登记的主机与部署），[主机网关](主机网关.md)与客户端共用 |
| `servicecatalog` | 组件目录（`catalog.yaml`）、逐方法 ACL、外部调用方白名单与按主机、部署算路由和目录（`Compile`、`Resolve`，主机网关、客户端、Admin 共用）；`hostgatewayconfig` 定义主机网关配置，`hostbundle` 定义身份包的清单；组件的二进制、启动参数、配置模板、启动顺序也登记在这里，部署按它渲染；副本类型只有 `single`。Doctor、Admin、主机网关、CLI 都读取同一份目录 |
| `security` | 加解密等安全基础函数 |
| `hostpolicy` | 每台主机上的策略缓存文件 `<部署根>/data/host-agent/host-policy.json`：全部告警渠道，由 HostAgent 从 Monitor 同步，文件仅本人可读 |
| `healthz` | 统一的 `/healthz`、`/readyz`、`/metrics` 处理器（只听本机、不验签）；`cmd/trpctransportcheck` 检查 tcp + trpc 服务端都显式使用 go-net |

## 4. 运行时与可观测性

| 包 | 内容 |
| --- | --- |
| `timerjob` | 同步、可观测的 tRPC 定时器处理器：显式超时、跳过重入 |
| `report` | 模块健康检查清单、数据集健康策略和数据集指标定义，Monitor 和各模块共用；各组件每 30 秒上报一次，随指标快照带上就绪判断（与 `/readyz` 同一个函数）和模块级生命周期，组件健康只看这份上报；没有 tRPC 定时服务的进程（collector-stream、egress-proxy）用 `Handler.Run` 自己按周期上报；订阅了 `FlushOnOutputAdvance` 的处理器在数据集输出水位前进时 1 秒内补报一份 |
| `doctor` | 诊断引擎；从 `servicecatalog/catalog.yaml` 生成现有 Manifest 接口并校验发布副本，供 `moox-cli doctor` 使用；目录里每个组件的 `doctor` 段只有 `transport`（健康怎么到 Monitor）与 `functional_observability` 两项 |
| `notification` | 告警发送：企业微信、飞书、钉钉群机器人与通用 Webhook；出站 Webhook 的签名函数 `WebhookSignature` |
| `clsreporter` | 腾讯云日志服务（CLS）的有界批量上报，SCF 使用；子包 `logcls` 把常驻服务的日志上报到 CLS（服务的 `main` 空白引入它） |
| `report/logsink` | tRPC 日志的输出 `moox`：Error 及以上日志和关键事件发给 Monitor（经 EventBus），启用了 CLS 时警告及以上日志和关键事件另外交给 CLS 的发送方；见[监控](监控.md)“重要日志”一节 |
| `healthz/trpclog` | 给进程的日志加 `service_name` 字段。要在 `trpc.NewServer` 之后调用（`NewServer` 读配置时会换掉默认日志对象） |

## 5. 领域工具

| 包 | 内容 |
| --- | --- |
| `marketcalendar` | 内嵌的交易日历，全系统共用，每份在进程内只解析一次：A 股 `cn_stock`、港股 `hk_stock`、美股 `us_stock`，各自一个数据文件和一个清单。日历可以登记提前收市日（半日市）：港股的圣诞前夕、新年前夕、农历新年前夕 12:00 收市，美股的感恩节次日、平安夜 13:00 收市，`barclock` 在这些天收市之后不切桶；A 股没有半日市。美股按纽约时区换算，夏令时切换（周日凌晨，不交易）不用另外处理，每个交易日都是 09:30～16:00 当地时间，半日市 5m 只有 42 根；日内周期可选 5m、15m、30m，不含 1h（390 分钟不能被 60 整除）。每年更新三份后重新发布：A 股用 `internal/gencn` 按国办节假日通知追加次年交易日，港股、美股把交易所假期通告里的休市日和半日市写进 `internal/genhk`、`internal/genus` 后整份重新生成；`scripts/marketdata/update-calendar.sh` 只替换 A 股 `cn_stock`，不碰港股、美股，三份要分别执行各自的生成器；加密货币 7×24 的日历由使用方（Strategy 的 `input/calendar.go`）自己换算 |
| `cnstock` | A 股公共行情的抓取与解析，只依赖标准库：腾讯实时快照（`qt.gtimg.cn`，GBK 按字节切分、字段位置常量、一次最多 60 只，带涨跌停价和停牌标记）、东方财富 clist 标的列表（主备地址、按接口自报的总数校验翻页，Collector 的 A 股标的列表和成分股、Trade 的 A 股标的都用它）、标的 ID 与腾讯代码互转（`600519.XSHG` ↔ `sh600519`）、板块整手规则 |
| `cloudprovider` | 云厂商抽象及腾讯云实现（SCF、COS 等），Collector 和 CLI 使用 |
| `factorexpr` | 因子表达式语言：YAML spec 解析与参数展开、编译（类型、输入列、回看推导、规范文本）、多因子程序（公共子表达式合并、需求区间）、算子内核与列式执行器，Factor 使用 |
| `factorudf` | 因子自定义算子（wasm UDF）的宿主侧实现：元数据与回看公式、模块检查、加载与调用、实例池、预算准入、分批、一致性测试与 `.udfpkg` 包格式；`moox-cli udf`、FactorMgr、因子引擎共用，本地检查与服务端复核的结论因此一致，见[因子](因子.md)第 12 节 |
| `factorname` | 因子成员键、结果列名、任务相关 ID（`ftask_`、`dataset_factor_`）的**唯一**拼接、解析与校验实现：Factor、Strategy、CLI、Monitor 都调用它，前端 `web/src/utils/factor-name.ts` 是对应的 TS 实现，两边共用 `testdata/vectors.json`；规则见[因子](因子.md)的「成员键与列名」。Storage 不引用它，只按列属性做字符串比较 |
| `frequency` | 规范频率、输入别名归一化、时间边界与时长计算 |
| `barclock` | 「K 线桶」的切分方式与交易序号集中在一处：采集过滤与完整性检查、K 线合成、因子的交易序号时间轴、策略的 A 股日内周期、Monitor 的应收 K 线与行情探针都调用它；含加密货币 7×24 与交易时段市场（按交易日历从各时段开盘起分桶）；`Hours` 给出是否在交易时段、下一次开盘、最近一次休市、最近一次日收盘，Trade 的 A 股交易时段用它 |
| `storagepolicy` | 按空间/频率的数据保留与 View 容量策略、解析及校验 |
| `lifecycle` | 模块级生命周期：运行、暂停、恢复追赶三种状态；pause / resume / release 三个命令；暂停两种（手动 / 系统），手动暂停可带到期时间（`ExpiresAt`，Refresh 到点自动恢复）；恢复追赶的进度钩子（`Hooks.Catchup`，先补齐暂停期间缺失的数据，追平后放行；系统级恢复停在待放行等 release）、等在途操作结束的钩子（`Hooks.Quiesce`，收敛时间 `QuiescedAt`）、状态变化回调（重启后载入暂停时 Run 开始会以 from 为空通知一次）、JSON 文件持久化（恢复追赶不跨重启，重启后回到暂停）、RPC 的服务端实现（各模块服务的 `GetLifecycle`、`ControlLifecycle` 转给控制器，消息在 `commonpb`）与经网关调用的客户端 `Remote`；`Options.Audit` 接收暂停恢复命令的审计事件。模块自身的就绪检查、对象（因子任务、策略实例）能不能计算都不在这里，由各模块自己判断 |
| `seriesset` | 时间序列集合的规范键、排序、稠密序号与 hash；序列身份只有 `subject_id` 与 `series_tag` 两项，Collector 登记快照与 Storage 的采集周期快照共用这一份实现 |
