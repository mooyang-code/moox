# 共享包

`packages/` 下是多个模块共用的 Go 包。每个包都是独立的 Go module，通过 `go.work` 组织。
共享包只放跨模块的契约和基础设施，不放某个模块独有的业务逻辑。

## 1. 协议（Protobuf）

| 包 | 内容 |
| --- | --- |
| `commonpb` | 公共的 `RetInfo`、错误码等 |
| `storagepb` | Storage 事件负载（行变更、周期完成、View 就绪等） |
| `marketfetchpb` | 采集函数一次调用的批次结果结构 |
| `metricspb` | 服务指标快照事件 |
| `hostmetricpb` | 主机快照事件，以及 HostAgent 的 4 位 `agent_id` 校验 |
| `tradeeventpb` | Strategy 发给 Trade 的目标权重事件 |

各包下的 `Makefile` 负责重新生成代码。

## 2. 事件与消息

| 包 | 内容 |
| --- | --- |
| `events` | 事件注册表（名称、版本、负载、Stream、Subject 族）、编码解码和消费者封装；业务模块只能使用这里声明的事件 |
| `jetstream` | JetStream 客户端、连接凭据、消费者与投递设置，以及测试用的内嵌 JetStream |

## 3. 网关与鉴权

| 包 | 内容 |
| --- | --- |
| `gatewayauth` | 服务签名与校验：绑定调用方、KeyID、目标主机、请求体摘要与 nonce，按原始 PB/JSON 字节验签 |
| `gatewayroute` | 路由表、路由快照校验与查表，以及主机网关的本机服务目录协议（`Directory`），由 Admin 和[主机网关](主机网关.md)共用 |
| `gatewayclient` | 签名 tRPC 的统一调用方：内部身份经本机网关目录选路（同机 loopback `11002`，跨主机 TLS `11003`）、外部身份固定连接一个 Access、操作员经 SSH 隧道；目录落盘缓存，只读调用有限重试，写调用只发一次 |
| `servicecatalog` | 组件目录（`catalog.yaml`）、逐方法 ACL、外部调用方白名单与按主机编译路由；`hostgatewayconfig` 定义主机网关配置，`hostbundle` 定义私密身份包。Doctor、Admin、主机网关、Access 都读取同一份目录 |
| `requestauth` | MooX 规范的请求签名协议，`gatewayauth` 和 `healthz` 的签名都基于它；`Permission`（如 `reset`）由服务端按密钥映射到请求上下文 |
| `security` | 加解密等安全基础函数 |
| `healthz` | 统一的 `/healthz`、`/readyz`、`/metrics` 处理器和 health HMAC 校验（可配第二对重置专用密钥，签名通过的请求带 `reset` 权限）；`cmd/trpctransportcheck` 检查 tcp + trpc 服务端都显式使用 go-net |

## 4. 运行时与可观测性

| 包 | 内容 |
| --- | --- |
| `timerjob` | 同步、可观测的 tRPC 定时器处理器：显式超时、跳过重入 |
| `trpcretry` | 幂等 tRPC 读调用的有界重试 |
| `report` | 模块健康检查清单、数据集健康策略和数据集指标定义，Monitor 和各模块共用；指标快照每 30 秒定时上报，订阅了 `FlushOnOutputAdvance` 的处理器在数据集输出水位前进时 1 秒内补报一份 |
| `doctor` | 诊断引擎；从 `servicecatalog/catalog.yaml` 生成现有 Manifest 接口并校验发布副本，供 `moox-cli doctor` 使用 |
| `notification` | 企业微信、飞书告警发送 |
| `clsreporter` | 腾讯云日志服务（CLS）的有界批量上报，SCF 使用 |

## 5. 领域工具

| 包 | 内容 |
| --- | --- |
| `marketcalendar` | 内嵌的交易日历（目前只有 `cn_stock`，进程内只解析一次）；加密货币 7×24 的日历由使用方（Strategy 的 `input/calendar.go`）自己换算 |
| `routeprobe` | 行情源访问通道的探测与结果模型（HTTP、HTTPS、TCP） |
| `tdx` | 通达信行情协议客户端，Collector 用于 A 股数据 |
| `cloudprovider` | 云厂商抽象及腾讯云实现（SCF、COS 等），CloudNode 和 CLI 使用 |
| `factorexpr` | 因子表达式语言：YAML spec 解析与参数展开、编译（类型、输入列、回看推导、规范文本）、多因子程序（公共子表达式合并、需求区间）、算子内核与列式执行器，Factor 使用 |
| `frequency` | 规范频率、输入别名归一化、时间边界与时长计算 |
| `storagepolicy` | 按空间/频率的数据保留与 View 容量策略、解析及校验 |
| `sysctl` | 系统级暂停与恢复的编排（设计见[暂停恢复与重置设计](../计划/暂停恢复与重置设计.md)）：按模块依赖顺序逐个调用各模块自己的生命周期接口——暂停下游到上游，恢复先追赶（上游追平后才启动下游）、除采集外的模块全部追平后按上游到下游放行（Trade 先于策略；采集没有副作用，追平后自行放行恢复实时采集）；本身无状态，命令幂等 |
| `lifecycle` | 模块与对象（因子集合、策略实例）的生命周期状态机：阶段与颜色、启动前检查、init / start / confirm / pause / resume / release、暂停类型（手动 / 系统 / 自动）与详情、恢复追赶（先补齐暂停期间缺失的数据，追平后放行）、实时门禁与追赶门禁、控制意图 `hold`、检查失败自动暂停与恢复、阶段持久化与重启恢复、健康端口上的状态与命令接口（`/v1/lifecycle/*`）、客户端与精简快照；重置框架（`Hooks.Reset`）：plan 出步骤与一次性令牌 → apply 后台分步执行并写 `reset-journal.json`，失败可凭 `operation_id` 续做或放弃，完成后回到未初始化并带 `post_reset` 门禁；HTTP `/v1/lifecycle/reset/*`（plan / apply / abort 需 `reset` 权限） |
| `seriesformat` | 时序数据文件的格式解析（`Decoder` 注册表，目前有 csv）与通用校验（`Checker`），导入服务使用 |
| `seriesimport` | 导入的编排：先校验全部文件再写入、按时间边界切批、SQLite 断点、写入目标（Storage、因子机本地存储）、引擎本地接口客户端 |
| `seriesreplay` | 逐期回放的编排：因子帧 → 策略决策 → Trade 纸面账本，周期记录与各阶段完成标记、续跑、暂停与取消、结果汇总，以及 `moox-replay` 与 `moox-cli replay` 共用的命令实现 |
