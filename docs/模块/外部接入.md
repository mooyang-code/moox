# 外部接入（Access）

`moox-access` 是外部调用方访问 MooX 的唯一入口。外部调用方是不运行在 MooX 主机上的调用方：SCF 采集函数、
操作员机器上的因子引擎和 moox-skill。外部接入校验它们的签名，按组件目录里的白名单放行，再以 `access` 身份经本机
主机网关把请求原样转发给目标服务。

代码位置：`modules/access`；外部调用方白名单在 `packages/servicecatalog/catalog.yaml` 的 `principals`。

## 1. 部署与端口

外部接入是目前唯一允许多份部署的组件，每份的实例 ID 为 `access@<主机>`：

| 实例 | 主机 | 地域 | 用途 |
| --- | --- | --- | --- |
| `access@storage` | storage | ap-nanjing | 因子引擎、moox-skill；同地域 SCF 走私网，其他地域的 SCF 走公网兜底 |
| `access@compute-1` | compute-1 | ap-hongkong | 香港 SCF 函数池（绑定 compute-1 所在 VPC，走私网） |

| 端口 | 监听 | 说明 |
| --- | --- | --- |
| `11004` | `0.0.0.0`，tRPC 明文 | 外部入口 `trpc.moox.access.Access`，方法通配，请求体不解码 |
| `11014` | `0.0.0.0` | `/healthz`、`/readyz`、`/metrics`，需要 health HMAC，防火墙只对 control 开放 |

## 2. 请求处理

1. 请求体超过 `max_body_bytes`（默认 32MB）直接拒绝。
2. 从本机主机网关的服务目录取得本机主机 ID；还没拿到目录时返回不可用。
3. 校验外部调用方的签名，签名的目标必须是本实例 `access@<本机>`；校验密钥来自 `secrets/access-principals.json`。
4. 按组件目录的白名单判断外部调用方能否调用该方法。白名单写在代码里，不能通过配置放宽。
5. nonce 记入 SQLite（`data/access/nonces.db`），重放的请求拒绝。
6. 用 `gatewayclient.Forward` 把 PB 字节原样转发：调用方身份为 `access`，签名针对实际发送的字节；外部调用方的名称
   写入元数据 `x-access-principal`，只用于日志和指标。入站的签名头不会继续往下传。
7. 目标服务在本机时走 `127.0.0.1:11002`，在其他主机时走目标主机网关的 `11003`（TLS）。

拒绝时返回网关错误码：`4401` 未通过签名或被重放、`4403` 白名单不放行、`4413` 请求体过大、`4503` 还没有服务目录。

## 3. 外部调用方白名单

| 外部调用方 | 允许调用的方法 |
| --- | --- |
| `scf-collector` | PrimaryStore：`EnsureDatasetPeriod`、`CommitTimeSeriesBatch`、`RecordDatasetPeriodFailures`、`GetDatasetPeriodStatus`、`UpsertFields`；Metadata：`ListSubjects`；MarketFetchRuntime：`ClaimTimerBatch` |
| `factor-engine` | PrimaryStore：`ReadTimeSeriesRows`、`WriteFactorRows`、`ReportFactorPeriodComputed`、`GetFactorPeriodComputed`；Metadata：`GetDataset`、`ListDatasetColumns`、`ListDatasetSubjects`；FactorEngine：`SyncEngineCatalog`、`EngineHeartbeat`、`PullRecalcJob`、`ReportRecalcProgress` |
| `moox-skill` | PrimaryStore：`ReadTimeSeriesRows` |

编译路由时，白名单涉及的方法会自动把 `access` 加入允许的调用方，不需要在 ACL 里另写。

## 4. 外部调用方怎么连

外部调用方使用 `packages/gatewayclient` 的外部方式：没有服务目录，不需要 CA，只配置外部接入地址和实例 ID。

```yaml
# 因子引擎 engine.yaml
gateway_client:
  mode: access
  caller: factor-engine
  key_file: ~/.config/moox/factor-engine.key
  access_address: 146.56.196.204:11004
  access_id: access@storage
```

SCF 不读配置文件，从环境变量 `MOOX_ACCESS_ADDRESS`、`MOOX_ACCESS_ID`、`MOOX_CALLER`、`MOOX_CALLER_KEY` 取值。
这些变量由 Collector 经 CloudNode 写进函数，代码包里不带地址和凭据。选择规则：

- 与函数同地域的主机上有外部接入，且函数已绑定该主机的 VPC（`moox-cli setup attach-scf-vpc`）时，使用它的私网地址；
- 否则使用 `access@storage` 的公网地址。

## 5. 配置与密钥

`config/app.yaml` 由部署工具渲染：

```yaml
gateway_client:
  mode: local
  caller: access
  key_file: ../secrets/caller-access.key
  ca_file: ../certs/moox-ca.crt
  cache_dir: ./data/gatewayclient
principals_file: ../secrets/access-principals.json
nonce_path: ./data/nonces.db
max_body_bytes: 33554432
timeout: 30s
```

外部调用方密钥的主副本加密存放在 Admin 密钥表，部署外部接入时由 CLI 用 `moox-admin-cli keys export-principals`
导出并下发到 `secrets/access-principals.json`。轮换外部调用方密钥后，需要重新部署全部外部接入实例。

## 6. 指标

| 指标 | 含义 |
| --- | --- |
| `moox_access_rejected_total` | 拒绝的请求数，按外部调用方和原因（`unauthenticated`、`forbidden`、`replayed`、`too_large`、`unavailable`）区分 |
| `moox_access_requests_total` | 转发的请求数，按外部调用方、服务、方法和返回码区分 |
| `moox_access_request_duration_seconds` | 处理耗时 |
