# 命令行工具

MooX 的运维入口是 `moox-cli`（`modules/cli`），各模块另有只操作本模块数据的 CLI。

## 1. moox-cli

`moox-cli` 读取 `moox.toml`（主机、部署表、云账户、编译主机等），负责部署、初始化、数据导入和诊断。
命令不会输出 `moox.toml` 中的密码和密钥。

访问 MooX 服务时，`moox-cli` 使用 `gatewayclient` 的隧道方式：先经 SSH 隧道连 control 的 `127.0.0.1:11002` 取服务
目录，再对目标主机建立 SSH 隧道，连接该主机主机网关的本机入口。调用方身份为 `moox-cli`，签名密钥在操作员机器的
`~/.config/moox/caller-moox-cli.key`（`MOOX_CLI_CALLER_KEY_FILE` 可覆盖），由 `setup bootstrap` 取回。

| 命令 | 作用 |
| --- | --- |
| `setup validate` / `status` / `hosts` / `trust-host` / `trust-browser` | 校验配置与连接、查看初始化状态、列出主机、记录 SSH 指纹、安装管理台证书信任 |
| `setup bootstrap` | 空环境首次部署：离线初始化管理后台并部署全部主机；`--control-only` 只处理 control |
| `setup deploy-host` / `deploy-service` | 部署一台主机（可用 `--components` 只部署其中几个组件）；在部署了某个组件的主机上重新部署它 |
| `setup rollback` / `render` | 把主机切回上一个发布；把一台主机的发布渲染到本地目录检查 |
| `setup service <start\|stop\|restart\|status>` / `pause` / `resume` | 启停组件、查看状态；暂停与恢复组件 |
| `setup apply` | 写入初始用户、云凭据和 SSH 主机 |
| `setup init` / `factors` | 导入默认空间、数据集、字段和因子；导入本地 Python 因子 |
| `setup build-linux` | 在编译主机上构建需要 CGO 的 Linux 二进制（部署命令也会自动调用） |
| `setup firewall` | 按部署表同步腾讯云主机的入站规则；`--prune` 删除受管端口上多余的旧规则，`--dry-run` 只列出差异 |
| `setup export-state` | 导出采集函数（版本、环境变量、VPC）和各主机的防火墙规则，供停机切换回滚使用 |
| `setup host-diagnostics` / `reboot-host` | 检查主机磁盘和服务进程；重启无响应的腾讯云主机 |
| `setup private-network` / `scf-network-plan` / `attach-scf-vpc` / `inspect-scf` / `invoke-scf` | 主机网络拓扑、SCF 访问外部接入的路由计划、SCF 绑定 VPC 与诊断 |
| `setup export-skill-config` | 导出 moox-skill 使用的数据访问配置（外部接入地址与 `moox-skill` 签名密钥） |
| `config plan` / `config publish` | 把 `moox.toml` 的变更发布到组件配置（见 1.1） |
| `collector function package` / `delete` | 构建 SCF 代码包；删除空间中的全部函数 |
| `collector function publish submit` / `status` | 按 fleet 发布 SCF 函数（先向 Admin 申请发布租约） |
| `collector function timer-inventory` / `probe-egress` / `activate-stockcn` | Timer fleet 盘点、出口探测、按门禁启用 A 股采集 |
| `collector period-inventory` / `task purge` | 只读盘点采集周期状态；清理采集任务（默认只输出清单） |
| `metadata apply` / `import` / `spaces` | 存储元数据 seed |
| `storage import` | 把本地历史数据（CSV 等）导入 Storage |
| `storage repair-view` / `force-rebuild-view` / `reconcile-view-consumers` / `reset-view-consumers` | View 修复与消费者维护 |
| `data kline get` / `data rows export` | 读取 K 线、导出数据集行 |
| `doctor bootstrap` / `diagnose` / `repair-view-consumers` | 新部署检查；解读 Monitor 的诊断事实；修复 View 消费者 |
| `ops tencent cls ...` / `ops tencent lighthouse firewall ...` / `ops tencent private-network` | 腾讯云日志服务、轻量服务器防火墙、主机网络拓扑 |

部署相关命令的完整流程见[部署与运维](../部署与运维.md)。

### 1.1 配置发布

修改 `moox.toml` 后，用 `config` 把由它派生的组件配置发布出去：

```bash
moox-cli config plan    --file ./moox.toml           # 渲染并与主机当前发布中的文件对比，不做修改
moox-cli config publish --file ./moox.toml --yes     # 以复用二进制的方式重新部署配置有变更的组件
```

| 目标 | 组件 | 文件 | 来源 |
| --- | --- | --- | --- |
| `storage-policy` | storage-primary、storage-view | 两个组件各自的 `config/storage-policy.json` | `[storage_retention]`、`[storage_view]` |
| `collector-runtime` | collector | `collector/config/app.yaml` 中由 `moox.toml` 派生的段落 | 出口代理、SCF 地域黑名单、运行数据保留、stockcn 容量 |

- `plan` 输出每个目标的状态（`unchanged` / `changed` / `missing`）、变化的键名、要重新部署的组件和告警，
  不输出任何值；告警包括保留期覆盖不足（有交易时段的市场按近似计算）。
- `publish` 只处理有变更的目标：对每个目标所在的主机执行一次 `deploy-host --components <组件> --reuse-binaries`，
  生成新的发布，启动失败时安装器自动切回原发布；之后的目标不再执行。重复执行是幂等的，未变更的目标不重新部署。
- 缩短任何保留期都会在下一次清理时删除超出新保留期的数据，`publish` 会拒绝执行，除非加
  `--allow-retention-shrink`；`plan` 的 `retention_shrinks` 列出每一项。
- `--only <目标>` 只处理指定目标。部署命令使用同一批渲染函数生成这些文件。

## 2. 模块 CLI

| CLI | 主要命令 |
| --- | --- |
| `moox-admin-cli` | `init`、`bootstrap`、`placement set-status`、`host set-status`、`keys`、`pki`、`user`、`random-secret`、`eventbus-credentials`（见[管理后台](管理后台.md)） |
| `moox-host-gateway-cli` | `check-config`、`snapshot`、`health`（见[主机网关](主机网关.md)） |
| `moox-storage-cli` | `init`、`register-node`、`import-seed`、`activate-datasets`、`period-inventory`、`repair-view`、`force-rebuild-view`、`retain-views`、`reconcile-view-consumers`、`reset-view-consumers`、`purge-dataset-events` |
| `moox-collector-cli` | `init`（应用 schema，导入内置采集任务 seed） |
| `moox-cloudnode-cli` / `moox-monitor-cli` / `moox-trade-cli` | `init`（应用 schema）；Trade 另有 `eventbus-check` |
| `moox-factor-mgr-cli` | `init`、`import`、`import-catalog`、`recalc`、`status` |
| `moox-strategy-cli` | `validate`（校验策略 DSL） |
| `moox-host-agent-cli` | `identity`（查看本机身份） |
| `moox-archive-cli` | `backfill`、`compact`、`verify`、`sync-cos`、`status` |

模块 CLI 只操作本模块的数据，不读写其他模块的数据库。组件启动前的准备步骤（例如 `init` 应用 schema）由主机运行
脚本自动执行。
