# 命令行工具

MooX 的运维入口是 `moox-cli`（`modules/cli`），各模块另有只操作本模块数据的 CLI。

## 1. moox-cli

`moox-cli` 读取 `moox.toml`（主机、云账户、编译机、Storage 主机等），负责初始化、部署、数据导入和诊断。
命令不会输出 `moox.toml` 中的密码和密钥。

| 命令 | 作用 |
| --- | --- |
| `setup validate` / `status` / `hosts` / `trust-host` / `trust-browser` | 校验配置与连接、查看初始化状态、列出主机、记录 SSH 指纹、安装管理台证书信任 |
| `setup apply` | 写入初始用户、云凭据和主机 |
| `setup init` | 导入默认空间、数据集、字段和因子，注册 `mooxsys` 元数据 |
| `setup factors` / `metadata-import` | 导入本地因子；通过 SSH 隧道导入选定业务空间 |
| `setup build-linux` | 在编译机上构建需要 CGO 的 Linux 二进制 |
| `setup deploy-control` / `deploy-storage` / `deploy-service` | 部署控制面、Storage 组件或单个服务包 |
| `setup verify-storage` / `host-diagnostics` / `restart-host` / `reboot-host` | 验证 Storage、检查主机、拉起服务、重启无响应的云主机 |
| `setup rebuild-storage` / `purge-eventbus-data` | 全量重建 Storage 与 View；清理 EventBus 中可重建的数据 |
| `setup install-storage-watchdog` | 在 Storage 主机安装自动恢复监控 |
| `setup firewall` / `private-network` / `scf-network-plan` / `attach-scf-vpc` / `inspect-scf` / `invoke-scf` | 腾讯云防火墙、私网与 SCF 网络 |
| `setup render-runtime-config` / `export-skill-config` | 渲染 Collector / Trade 运行配置；导出 Skill 使用的数据访问配置 |
| `config plan` / `config publish` | 把 `moox.toml` 的变更发布到各主机的模块配置（见 1.1） |
| `setup e2e-storage` / `browser-e2e-storage` | Storage 元数据生命周期验证、管理台浏览器验证 |
| `collector function package` / `deploy` / `delete` | 构建 SCF 代码包；单节点部署；删除节点 |
| `collector function publish submit` / `status` | 按 fleet 发布 SCF 函数（先向 Admin 申请发布租约） |
| `collector function timer-inventory` / `probe-egress` / `activate-stockcn` | Timer fleet 盘点、出口探测、按门禁启用 A 股采集 |
| `collector period-inventory` / `task purge` | 只读盘点采集周期状态；清理采集任务（默认只输出清单） |
| `metadata apply` / `import` / `spaces` | 存储元数据 seed |
| `storage import` | 把本地历史数据（CSV 等）导入 Storage |
| `storage repair-view` / `force-rebuild-view` / `reconcile-view-consumers` / `reset-view-consumers` | View 修复与消费者维护 |
| `data kline get` / `data rows export` | 读取 K 线、导出数据集行 |
| `doctor bootstrap` / `diagnose` / `repair-view-consumers` | 新部署检查；解读 Monitor 的诊断事实；修复 View 消费者 |
| `ops tencent cls ...` / `ops tencent lighthouse firewall ...` | 腾讯云日志服务、轻量服务器防火墙 |

### 1.1 K 线查询与网关身份

`data kline get` 及 Collector 金丝雀的 Storage 证明使用 `gatewayclient` 的隧道方式：从 `moox.toml` 取得可信 SSH 主机，查询 control 的本机 Directory，再转发目标主机的 `127.0.0.1:11002`。`--file` 默认 `./moox.toml`，可传绝对路径；目录返回的公网地址不作为连接目标。操作员身份位于 `~/.config/moox/gateway-client.yaml`，配置 `caller: moox-cli`、Admin 分配的 `key_id` 和独立的 `key_file`，配置与密钥均要求普通文件、0600 且禁止符号链接。Admin bootstrap bundle 已生成身份配置；自动取回安装在部署阶段完成。

K 线数据配置只包含 Storage 角色认证与数据类型映射，旧 `gateway` 字段被严格拒绝，须重新导出。网关签名与 Storage 请求角色认证分别校验。命令退出会释放目录刷新、连接池和 SSH 隧道；JSON 结果写 stdout，RPC 诊断写 stderr。

### 1.2 配置发布

修改 `moox.toml` 后，用 `config` 把由它派生的主机配置文件更新到各主机，不必重新部署：

```bash
moox-cli config plan    --file ./moox.toml           # 渲染并与主机上的文件对比，不做修改
moox-cli config publish --file ./moox.toml --yes     # 写入有变更的文件，重启受影响的服务并等待就绪
```

| 目标 | 主机 | 文件 | 重启 |
| --- | --- | --- | --- |
| `storage-policy` | Storage 主机 | `<storage_root>/config/storage-policy.json`（`[storage_retention]`、`[storage_view]`） | storage-primary、storage-view |
| `collector-runtime` | 控制机 | `<control_root>/collector/config/app.yaml` 中由 `moox.toml` 派生的段落 | collector |
| `trade-dns` | `dns_resolver.trade_node` | `<control_root>/trade/config/app.yaml` 的 `dns_resolver` 段 | trade |

- `plan` 输出每个目标的状态（`unchanged` / `changed` / `missing`）、变化的键名、要重启的服务和告警，
  不输出任何值；告警包括保留期覆盖不足（有交易时段的市场按近似计算）和主机上的文件在上次发布后被手工修改。
- `publish` 只处理有变更的目标，按目标顺序逐个执行：取得 `<root>.maintenance.lock`（与部署、健康检查互斥）、
  写临时文件、把原文件保存为 `<file>.last`、原子替换、记录 `<file>.sha256`、重启服务；`start.sh` 等待就绪探针，
  失败时恢复 `<file>.last` 并再次重启，之后的目标不再执行。重复执行是幂等的，未变更的目标不重启。
- 缩短任何保留期都会在下一次清理时删除超出新保留期的数据，`publish` 会拒绝执行，除非加
  `--allow-retention-shrink`；`plan` 的 `retention_shrinks` 列出每一项。
- `--only <目标>` 只处理指定目标。部署（`setup deploy-storage` 等）使用同一批渲染函数生成这些文件。

### 1.3 按组件边界打包

`setup package` 收集已编译的 Linux 制品和 Git 跟踪的配置模板，输出可复现的 `.tar.gz`。打包不读取 `moox.toml`；运行配置、证书、签名密钥和安装生命周期仍由后续部署流程接入。当前产物属于软件与模板层，不能直接代替现有安装器的发布包。

| `--profile` | 服务进程 |
| --- | --- |
| `host` | Host Gateway、Host Agent |
| `control` | Console Proxy、Web Host、Admin、EventBus、Monitor、Collector、CloudNode、FactorMgr、Strategy |
| `storage` | Storage Primary、Storage Node、Storage View |
| `access` | Access |
| `egress-proxy` | Egress Proxy |
| `trade` | Trade |

只有 `host` 包包含 Host Gateway；每个包同时收集本组件需要的管理 CLI、配置模板、schema 和静态资源。Web 前端由已编译的 Web Host 内嵌。编译位置与打包位置独立：纯 Go 制品在本机交叉编译，需要 CGO 的 Linux 制品在 Linux 编译机编译，下载后也可在本机打包。

```bash
# 先构建本机可运行的 moox-cli，并准备 bin/linux-amd64 中的目标制品
./bin/moox-cli setup package --repo-root . --profile host \
  --binary-dir ./bin/linux-amd64 --goarch amd64 --output ./dist/host.tar.gz
./bin/moox-cli setup package inspect ./dist/host.tar.gz

# 脚本入口与 CLI 使用相同的参数；MOOX_CLI 可指定本机 CLI
./scripts/build/package-deployment.sh --profile access \
  --binary-dir ./bin/linux-amd64 --output ./dist/access.tar.gz
make test-deployment-packages
```

支持 Linux amd64/arm64。JSON 结果包含整个归档的 SHA256 和 `package-manifest.json`：记录平台、组件、共享服务目录摘要，以及逐文件的路径、权限、长度和 SHA256。`inspect` 不解压到文件系统，校验平台、组件边界、文件清单与摘要，拒绝链接、越界路径、重复条目、未知字段和多余压缩载荷。摘要用于核对制品一致性，发布来源仍须由部署流程确认。

打包、检查与软件准备共用独立的 [unitpackage](../../modules/cli/internal/setup/unitpackage/README.md)，不依赖旧部署器。远端 `moox-runtime extract` 接收生产端摘要，只按所在 Linux 主机的平台解包；校验成功后原子发布到新目录，已有目标不覆盖。它不切换 current、不注入身份或数据、不启动服务，完整安装仍须接通运行配置、维护锁、激活和回滚。

身份包读取与 SSH 下载共用独立的 [unitbundle](../../modules/cli/internal/setup/unitbundle/README.md)。调用方提供当前拓扑、完整放置、已确认 CA 和期望快照；库校验清单、逐文件摘要、配置、证书/私钥和目标调用方，再发布全新私密目录，并可生成排除操作员身份的服务材料。`moox-runtime inspect-bundle` 复用同一验证，只输出公开清单。[发布准备层](../../modules/cli/internal/setup/unitinstall/README.md) 已接入按组件身份投影、KeyID/Host Agent 配置注入、私密运行计划和七个共用助手包装脚本，并在维护锁下原子发布候选目录。`moox-runtime prepare --request PATH` 读取部署器生成的 0600 规范请求，`inspect-release --directory PATH` 核对尚未启动候选的完整文件清单。`activate`、`recover`、`rollback` 已连接持锁停止、独立状态复制、current 切换、启动验证和失败恢复；持久标记保护安装器退出后的恢复窗口。实际 CLI 部署、五步 bootstrap、首次 CA 授权消费/历史导入和操作员本机安装仍待接通。

## 2. 模块 CLI

| CLI | 主要命令 |
| --- | --- |
| `moox-admin-cli` | `init`、`user`、`random-secret`、`eventbus-credentials`、`bootstrap`、`host-bundle`、`host`、`placement`、`keys`、`pki`（见[管理后台](管理后台.md)） |
| `moox-runtime` | host 包携带的 Linux 运行助手；`extract` 核验软件，`prepare` 注入身份并准备候选发布，`inspect-release` 验证候选完整性；`start`、`stop`、`restart`、`pause`、`resume`、`healthcheck`、`status` 读取私密发布计划并共用持久维护锁与暂停标记（见[运行助手](../../modules/cli/internal/setup/unitruntime/README.md)） |
| `moox-host-gateway-cli` | `check-config`、`routes`、`health` |
| `moox-storage-cli` | `init`、`register-node`、`import-seed`、`activate-datasets`、`period-inventory`、`repair-view`、`force-rebuild-view`、`retain-views`、`reconcile-view-consumers`、`reset-view-consumers`、`purge-dataset-events`、`bleve`、`duckdb` |
| `moox-collector-cli` | `init`（应用 schema，导入内置采集任务 seed） |
| `moox-cloudnode-cli` / `moox-monitor-cli` / `moox-trade-cli` | `init`（应用 schema）；Trade 另有 `eventbus-check` |
| `moox-factor-mgr-cli` | `init`、`import`、`import-catalog`、`recalc`、`status` |
| `moox-strategy-cli` | `validate`（校验策略 DSL） |
| `moox-host-agent-cli` | `identity`（查看本机身份） |
| `moox-archive-cli` | `backfill`、`compact`、`verify`、`sync-cos`、`status` |

模块 CLI 只操作本模块的数据，不读写其他模块的数据库。
