# 交易（Trade）

Trade 是 MooX 的交易执行与交易事实来源：管理执行账户和组合账户，接收 Strategy 的目标权重，
换算成具体数量并通过交易所下单收敛，记录订单、成交和持仓，并提供人工干预和模拟盘。

代码位置：`modules/trade`。`moox.toml.example` 将 Trade 放在海外机（`overseas`）；原生 `trade` 单元可部署，实际启用状态由部署与运行配置决定。

## 1. 进程与端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| `TradeConsoleService` | tRPC `11200` | 账户、模拟盘、组合账户、人工订单、查询与执行能力 |
| 健康检查 | `11210` | `/healthz`、`/readyz`、`/metrics` |
| `equity` 定时器 | 每 20 秒 | 记录账户与组合账户权益曲线 |
| `metrics` 定时器 | 每 30 秒 | 上报指标 |

Trade 是单进程、单 SQLite（`data/moox_trade.db`）的设计：用 SQLite 事务、账户锁、组合账户锁、
幂等 ID、交易所查询恢复和定期同步覆盖个人量化需要的一致性，不引入分布式事务或任务框架。
启动时只校验已有表结构与 `schema/*.sql` 一致，不做历史迁移。

```text
目标权重事件 / 人工操作 RPC
          │
LogicalAccount ─ TargetExecutor ─ OrderService
          │
     ExchangeSession（Binance、OKX、Paper）
          │
SQLite：账户、组合账户、目标、人工操作、合约、订单、成交、持仓、权益
```

## 2. 核心对象

| 对象 | 含义 |
| --- | --- |
| TradingAccount（执行账户） | 一个实际交易账户，配置为实盘（Live）或模拟盘（Paper） |
| LogicalAccount（组合账户） | 一个或多个同质执行账户组成的策略资金单元，由一个策略实例的当前会话控制 |
| LogicalAccountTarget | 组合账户当前唯一、可替换的完整目标 |
| TargetReceipt | 首次接受目标时的不可变回执：权益、报价、实际成员和换算出的数量 |
| Order / Fill / Position | 订单意图、交易所成交事实、已确认持仓 |
| OperatorAction | 人工下单、撤单、逐账户清仓的幂等操作记录 |

- 一个执行账户最多加入一个启用的组合账户；组合账户的成员必须是相同的模拟/实盘模式、
  相同的 SPOT/SWAP 市场和相同的结算资产，可以来自不同交易所，也可以是同一交易所的不同密钥（主账户、子账户）。
- 同一交易所账户不能录入两次：两个会话看到同一批订单，会互相当成外部订单。Binance 现货和合约钱包分开，按交易所、环境、市场、密钥判重；OKX 共用账户，按交易所、环境、密钥判重。
- 模拟盘也支持组合：创建模拟账户时可以不填组合账户名称，之后再加入成员；关闭模拟账户时移出成员，组合账户保持暂停。
- 自动交易的唯一归属身份是 `owner_instance_id + owner_session_id`。策略实例重新启用会产生新会话，
  会话切换通过 `auth_fence` 做 CAS，只有获胜的切换才会清理旧目标。
- 订单归属由服务端写入：`TARGET`（属于当前目标）、`OPERATOR`（属于一次人工操作）、
  `EXTERNAL`（账户同步发现、非 MooX 创建）。

## 3. 目标权重的接收

Strategy 发布的 `event.trade.target.weight_requested`（Stream `MOOX_TRADE`，durable
`trade_target_weight_v1`）是组合账户的完整快照，字段见[策略](策略.md)第 8 节。

- `target_weight` 是相对组合账户权益的带符号权重；遗漏的旧标的目标为 0，空列表表示全部归零。
- `hold=true` 的目标项表示保持该标的当前持仓数量：不读取它的参考价、不按权重换算数量，执行器不为它提交新的调仓订单。权重只供策略预留预算；全为保持项的快照可直接生成保持回执，无需估值。
- 只接受当前持有组合账户的 `(instance_id, session_id)`；过期、尚未生效、旧会话或旧 `bar_end_time`
  的事件在估值和下单之前拒绝。相同 `target_id` 和内容的重投幂等，同一会话按 `bar_end_time`
  保留最新快照。
- 首次接受时按启用且就绪成员的合计权益和参考价格换算数量，结果写入不可变的 TargetReceipt；
  重投复用回执，不重新估值。
- 组合账户处于 PAUSED 时仍保存最新目标，但不下单；只有人工 Resume 才恢复收敛。
- SPOT 目标不能为负数；SWAP 用正负号表示方向。交易所原生代码、精度、最小量和合约张数由 Trade 解析。
- 上游标的是 `BTC-USDT`，Trade 内部是 `BTC-USDT-SPOT`、`BTC-USDT-SWAP`，由 `exchange.NormalizeInstrumentID` 按组合账户的市场转换；股票原样使用，如 `600519.XSHG`。无法识别的标的整条目标拒绝。策略绑定组合账户时校验市场一致。

目标事件的 `shadow` 字段为真时（试运行中的策略实例发来的影子目标）：Trade 只做权重到数量的换算（权益与参考价同正式目标）并写入 `t_shadow_targets`
（按 `target_id` 幂等），**不接受为正式目标、不拿账户锁、不预留资金、不唤醒执行器**。`GET /v1/shadow/targets?space=&instance=&limit=`（健康端口）与 `moox-cli lifecycle shadow` 查看。

## 4. 目标收敛

TargetExecutor 一轮下一批子单，每个标的最多一笔，批内并发发往交易所，等账户事实更新后再算下一批：

1. 有在途子单（待提交、提交中、结果未知、挂单中）时本轮只处理这些单：从未发出的残留待提交单丢弃，结果未知的批量查询（每笔在未知窗口内最多查两次），挂单中的市价单等它结束，不撤单；
2. 跨标的先减后加：减仓批的结果回来、资金释放之后才发加仓批；减仓全部下不了时才加仓；
3. 减仓优先选择可减持仓绝对值最大的账户；
4. 加仓按成员优先级、可用资金和交易所限制择优，资金用完才用下一个账户，不按比例分配；
5. 当前账户无法承接剩余数量时再换下一个合格成员；
6. 每个执行账户每批永续最多 16 单、现货 8 单，同一组合账户每秒最多一批（约为交易所下单限额的 80%）。额度用完算本轮跳过，不换成员；交易所接口限流暂停或权重用到 90% 时不发新批。

批量提交（`SubmitBatch`）持组合账户执行锁覆盖整批，逐笔持账户锁落 `SUBMITTING`，账户锁不跨请求；发送前再确认一次目标授权；私有流的订单和成交事件在整批结束后入账。

一个成员未就绪时整个组合账户暂停收敛，恢复后继续。

防重复下单：

- 防抖只合并同步请求，不下单；所有重试都按本地事实重算差额，经过同一套准入检查。
- 只丢弃确定没发出的单：未写提交时间、交易所明确未受理（限流、封禁），或未知单过了 30 秒窗口仍查无此单。超时、408、503 未知都按结果未知处理，只查询不重发。
- 下单前持仓校验：目标子单记录下单前持仓（`c_position_before`）。持仓回退到最近 10 分钟同方向成交段里某笔子单下单前的值时，说明持仓没反映已成交子单，整条标的本轮跳过、写入 `blocked_targets`，不换成员，同步纠正后自动重算。
- 同一目标、同一执行账户、同一标的的已发出子单方向切换 1 次时放行纠正单并告警 `target_reversal`，切换 2 次后本目标内跳过这个标的。
- 调仓阈值见 4.2：默认整条标的的成员持仓都与目标同号时，差额不超过目标数量 5% 不下单；建仓、清仓、反向持仓、多成员对冲不受影响。

完成判定按交易规则：剩余量在全部成员上都达不到最小数量或最小名义金额时，目标为 0 或已有同向持仓算完成（零头）；
从空仓开新仓就达不到最小量才写入 `blocked_targets`。有成员本来能下单、只是被拒单排除时不算完成。
合约全平的只减仓订单只查最小数量。持仓够但可卖量不足（如 T+1）时为 `BLOCKED`，原因是“可卖量不足”。

拒单：交易所明确拒绝后，同一目标不再向该账户下单，下一轮换成员；全部被拒写入 `blocked_targets`，下一个目标重试。
待提交子单的报价过期时丢弃，下一轮按最新持仓和报价重新下单。

不同执行账户上方向相反的持仓不会被净额抵消成“已完成”。

## 4.2 下单设置与资金设置

两组设置存在组合账户上（`c_order_settings_json`、`c_fund_settings_json`），由 `UpdateLogicalAccountOrderSettings`、`UpdateLogicalAccountFundSettings` 写入，`LogicalAccount` 只读返回当前生效的值（没写的项已填默认值）。
写入时严格校验：未知键、大小写不规范的键、类型不对和越界的值都拒绝，库里只存规范 JSON。执行器每轮收敛都读最新设置，保存后对之后的收敛立即生效；设置读不出来时这个组合不下单，原因写进目标。

下单设置（键名、默认值）：

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `rebalance_threshold_mode`、`rebalance_threshold_ratio` | 调仓阈值：`TARGET_RATIO`（差额不超过目标数量 × r 不调）、`POSITION_RATIO`（调仓金额低于持仓金额 × r）、`EQUITY_RATIO`（低于组合最近权益采样点 × r）、`ALWAYS`。建仓、清仓、反向持仓任何模式都不受限 | `TARGET_RATIO`，0.05 |
| `min_notional_spot`、`min_notional_swap` | 子单最小下单额，与交易所最小名义金额取大。**差额低于它视为已满足**（与调仓阈值同口径）：跳过这个标的，不阻塞，`blocked_targets` 不记，过期告警也不算持仓未到位；合约减仓、清仓例外，低于门槛也照常下 | 10、5 |
| `hourly_cap_spot`、`hourly_cap_swap` | 每个标的每个自然小时（UTC）累计下单金额上限，键是内部标的 ID 或 `*`；**只限制加仓和建仓**，减仓（包括目标改 0、受管但不在目标里按 0 卖出）不受限，金额照常计入汇总。从订单表汇总（结束的单按成交额，没结束的按全部数量，被拒绝和本地丢弃的不算），超出的部分顺延到下一个整点，顺延的标的和原因写进目标的 `blocked_targets`（带 `deferred` 标记，界面用中性色显示“顺延”），但不算阻塞（目标仍定为已收敛，不触发“目标持续阻塞”告警） | 不限 |
| `max_child_notional`、`randomize_split` | 单笔上限（不超过 1000000）；随机化时每笔取上限的 50%～100%，种子是组合、目标、标的和已发子单数，可复现 | 100000，关 |
| `batch_interval_seconds` | 批间隔，写了就覆盖默认（实盘 1 秒、模拟盘 0.3 秒） | 不写 |
| `order_mode`、`slippage_step`、`slippage_max`、`max_attempts` | `PSEUDO_MARKET`：限价 + IOC，价格 = 参考价 ×（1 ± 滑点），买入向上、卖出向下取整到价格精度；没成交完的剩余量下一轮按新持仓补，滑点每次加一份直到上限；尝试次数按（目标，标的）统计（换成员不重新计数）= 最近连续没成交完的 IOC 子单数，一笔 IOC 全部成交即清零，非 IOC 子单跳过不打断；用满次数记“未到位”并告警一次，不再重试。`MARKET` 为市价单 | `PSEUDO_MARKET`，0.015、0.06、4 |
| `resting_ratio`、`resting_ttl_seconds` | 挂单：加仓、减仓、调仓按此比例（每个方向的金额预算）挑标的改成限价 GTC 挂单（买一、卖一价），建仓、清仓不挂；挂单剩余量从差额里扣除，反向或超出差额的挂单撤掉；寿命 0 表示保留到下一份目标到达或过期，否则到期撤单 | 0，0 |

资金设置（键名）：`reserve_ratio`（资金预留比例）、`bnb_discount`（只会打开交易所的 BNB 抵扣开关，不会关）、`bnb_reserve_amount`（BNB 市值低于它减 10 时市价补买缺口）、
`dust_convert_enabled`、`dust_convert_interval_days`（默认 15 天，**只兑受管的零头**（MooX 成交过留下的），用户自持、MooX 从没碰过的币不动；仍排除当前目标和排除资产、低于 5 USDT；这是对“非目标、非排除”的有意收窄，时间记在账户的 `c_last_dust_convert_at`）、
`stablecoin_margin`（稳定币及目标比例，必须含组合的结算币（默认 USDT）、和为 1）、`margin_coins`（保证金币及配置的固定 U 值）、`arbitrage_base_assets`（套利底仓）。
保证金率监控的四个键放在资金设置里（口径和动作见 5.2，只对币安生产环境的实盘组合生效）：`margin_ratio_threshold`（普通账户阈值，默认 0.5，范围 (0, 10]）、`unified_mmr_threshold`（统一账户 uniMMR 阈值，默认 1.5，范围 (1, 100]）、`margin_reduce_ratio`（触发后每个持仓减掉的比例，默认 0.1，范围 (0, 1)）、`margin_monitor_disabled`（关闭监控，默认开启）；读不出来时数值取默认值，关闭开关读不出来按开启处理（监控是保护，不能因设置写坏就悄悄关掉）。

已保存的设置读不出来时（`LogicalAccount.order_settings_error`、`fund_settings_error` 非空，包括资金设置里个别数值读不出来、执行器按默认值处理的情况），界面提示并禁止保存，不按默认值显示；
修复步骤：在设置表单点“按默认值重置”确认（会丢掉原来保存的整组设置，用默认值覆盖），再重新填写；或直接重新提交一份合法的设置。

资金维护（`fundmaint` 服务 + `FundWorker`，每小时一次、设置变更后和账户第一次就绪时马上一次）：BNB 抵扣、BNB 补买、小额兑 BNB、稳定币调平（统一账户，各稳定币占比与目标的绝对差超过 5 个百分点才动，每轮只做一个方向、先卖，买单挂买一价、挂满 55 分钟没成交才撤，卖出用 IOC；BNB 补买单刚下出时调平让路）。
只对币安生产环境的实盘账户生效：模拟盘、测试网、OKX 不做；含非币安成员的组合、模拟盘组合写入这些项时被拒绝。BNB 保留金额按**每个币安执行账户**各 N（普通账户内部现货、合约钱包对半，划转由 1B 实现），换算目标时按账户逐个计缺口再求和，两处口径一致；保留金额要大于 10。BNB 抵扣的查询和设置在组合锁外进行。
补买和调平的单归属 `SYSTEM`：不暂停组合、不算执行器的子单、成交不让资产变成受管；组合暂停或正在清仓、减仓时不下单。权益里除结算币外的目标稳定币按对结算币的现货价折算计入。

## 4.1 账户同步

- 同步分四种：轻量同步（成交、持仓、账户事件 250 毫秒防抖后触发，下单之后也用它）只读持仓和账户，补拉不一致标的的成交，永续一致时 10 权重；30 秒对账读账户、持仓、挂单，加轮转批次（全集十分之一，单次最多 20 个标的）；增量同步不推进轮转，用于撤单确认；会话启动和手动同步先拉必须的标的，再从全集补到 60 个，其余靠轮转。轻量同步没能恢复准入时按 0.5、1、2 秒退避重排，最多 5 次。权重用到 80% 时推迟对账。
- 持仓数量只由成交投影和 REST 决定，私有流持仓事件只关闭准入。本地持仓 10 秒保护期内不删、不被更旧的 REST 覆盖，过了保护期以 REST 为准。
- 现货 REST 余额的交易所更新时间早于待确认水位时，不恢复准入。
- 成交重放只按订单、方向、数量、价格判重，手续费等字段不一致只记日志。
- 账户创建之前的成交只推进游标，不入账，也不算外部成交；创建之后的外部成交暂停组合账户。
- 余额确认用本地读取时间：读取账户快照前记录时间，晚于成交时间才清除待确认水位。
- 现货受管资产由系统推导：结算资产、当前目标里的标的、有成交的策略或人工订单涉及的标的。其他资产不估值、不卖出，持仓页照常显示。账户里只有币没有结算资产时权益为 0，要先准备结算资产。
- 杠杆按需设置：合约账户默认 `*` 倍杠杆，单标的配置优先；首次在某标的开仓前设置全仓和杠杆，结果记在会话内存里，改杠杆不重启会话。

## 5. 人工干预

| 操作 | 行为 |
| --- | --- |
| `PauseLogicalAccount` | 停止新的自动下单，需要填写原因 |
| `ResumeLogicalAccount` | 用已保存的最新目标恢复收敛 |
| `PlaceManualOrder` | 先暂停组合账户并撤销活动的 TARGET 订单，完成后保持 PAUSED |
| `CancelOrder` | 策略驱动的组合账户撤单会暂停整个组合账户，自主下单账户不暂停 |
| `FlattenLogicalAccount` | 逐账户清仓：同步全部成员、撤销全部活动订单、在原账户提交平仓单，逐账户记录结果，最终保持 PAUSED 且保留最新目标。每笔子单前等账户就绪（实盘每笔成交都会关闭准入），等不到就结束本轮；没有撤单时用轻量同步 |
| `ReduceLogicalAccount` | 按比例减仓（`REDUCE`）：先暂停组合、撤全部订单，再把现货和合约同比例减掉（比例大于 0 小于 1）。每个持仓的目标数量在发起时写定并存进动作结果（`reduce_targets`、`reduce_done_accounts`），之后各轮、重试和重启恢复都收敛到这个数量，不会再减一次；减不动一个最小数量的持仓（零头）不登记，套利底仓的对冲腿不减 |
| `FlattenInstrument` | 单标的下架清仓（`DELIST_FLATTEN`），只供事件中心调用，见 5.1 |

人工下单、撤单和清仓都必须带幂等 `action_id` 和操作原因。`ListOperatorActions` 按组合分页列出这些操作记录（可按类型过滤），概览页的“人工操作记录”用它。

清仓、减仓、下架清仓共用一套执行框架（`operator/flatten*.go`）：范围收窄到一个标的时，撤单、撤单确认、恢复子单、剩余统计和完成判断都只看这个标的；同一组合里整组清仓、减仓和下架清仓互斥（整组动作遇到任何运行中的这一族动作返回“忙”），不同标的、不同交易所的下架清仓之间不冲突、排队执行。重启后 `ResumeOperatorAction` 与工作线程按持久化的请求继续这一族动作；它们运行期间组合不能恢复自动执行。

### 5.1 下架名单与下架清仓

下架检测由 Collector 负责，决定何时动手、找出持有者由事件中心的系统动作“卖出策略持有的下架币”负责，Trade 只提供下面的接口。
接口都用（交易所、市场、交易所代码）定位标的（交易所用枚举 `EXCHANGE_BINANCE`、`EXCHANGE_OKX`，市场只收 `MARKET_TYPE_SPOT`、`MARKET_TYPE_SWAP`），由 Trade 按标的表换算内部标的 ID。

| 接口 | 说明 | 调用方 |
| --- | --- | --- |
| `BlockInstrument` | 写入下架名单；重复写入不改已有记录。Trade 没有这个标的（没开通对应市场的账户）时照常写入，响应 `instrument_unknown` 为真，不算失败 | 事件中心 |
| `UnblockInstrument` | 解除禁止，不在名单里不算错误 | 事件中心、管理台 |
| `ListBlockedInstruments` | 列出名单（只读） | 事件中心、管理台、moox-cli |
| `ListInstrumentHolders` | 跨空间列出策略持有该标的的执行账户（只读，每个执行账户一行，调用方按空间和组合聚合）；`paper_only` 只返回模拟盘；每项带 `quantity`（保留原精度）、`dust`（零头，和清仓同一个口径：有报价时按最小数量和最小金额判断，取不到报价时只按最小数量，`note` 里标注）、`paper`、`status`（执行账户状态，停用和出错的账户照常列出）、`note`；查询时出错的账户进 `skipped_accounts`（带原因，调用方不能把它当作没有持有，不会让整个查询失败），明确不算持有的说明进 `notes` | 事件中心、管理台、moox-cli |
| `FlattenInstrument` | 在调用时带的空间里，对组合中属于该交易所的成员发起 `DELIST_FLATTEN`，返回操作；响应 `busy` 为真表示暂时忙（`ret_info` 是 `CONFLICT`，不带动作），稍后再试且不计入重试次数；`unblocked` 为真表示标的已被解除禁止而提前结束 | 事件中心 |
| `GetOperatorAction` | 查平仓结果；结果 JSON 顶层带 `unblocked: true` 表示“已解除禁止” | 事件中心、管理台、moox-cli |

名单、`ListInstrumentHolders` 是全局方法（下架是交易所层面的事实），Trade 不检查空间头；`FlattenInstrument`、`GetOperatorAction` 仍按空间。`holders` 没有持有者时是空数组（经网关的 JSON 序列化不会省略，有测试锁住）；`holders` 为空且 `instrument_unknown` 为假表示确认没有策略持有。
“策略持有”：现货必须是受管资产且余额大于 0，永续持仓不为 0（套利底仓的对冲腿不算）；标的的计价币不是账户结算币的不算（例如手工屏蔽 FOOBTC，清仓什么也不会卖，写进 `notes`）；只看该交易所、在组合里的执行账户，测试网不算。
交易所、市场、交易所代码在所有入口一律转大写，传小写也能对上标的。写入名单时如果标的是某个组合的套利底仓对冲腿或排除资产（BNB 保留、稳定币保证金、保证金币），打一条关注项日志（固定文字）：下架时没有任何动作会碰它们，要人工处理。

**名单标的“只减不增”**：名单只禁止买入。执行器在 `loadMembers`、`constrainDesired`（`target/delist.go`）三处处理，Converge 和 `HasDifference` 共用：

- 标的还能交易：目标截到不超过当前持仓（多头不超过持仓，空头绝对值不超过持仓，反号或没有持仓截成 0），加仓和反向开仓的部分去掉并按组合、标的每天告警一次；减仓、卖出照常，受管持仓不在目标里的仍按目标 0 卖出；截断发生在挂单对账之前，名单标的的买入挂单随之撤掉。组合里只有部分成员的交易所在名单里时，目标不动，受限成员不会被选来加仓；
- 标的已经不能交易：整项跳过，不买不卖，剩下的持仓或余额不再让目标置为 `BLOCKED`；现货按基础资产且只匹配 `SPOT` 条目（永续下架不会豁免同名现货余额），永续按（交易所、`SWAP`、代码）匹配；
- 接收目标时，名单里已经不能交易的标的只跳过这一项（改成“保持”），不拒绝整份目标。截断告警只在截掉的买入量确实会下出去时才发（目标只比持仓多一点点、低于调仓阈值或最小下单额的不算）。
名单是按成员所在交易所匹配的，别家交易所的同名标的不受影响。写入或解除名单后、下架清仓结束后都会唤醒目标重新判断（已收敛、已阻塞的目标不被定时器扫描）。

**`DELIST_FLATTEN`**：伪市价单（限价 + IOC，滑点固定 3%，买入向上、卖出向下取整到价格精度），不暂停组合、只看这一个标的和这个交易所的成员；零成交的 IOC 不算终结。子单号固定 32 位（`mf` + 30 位十六进制，第几次尝试并进哈希，OKX 的 `clOrdId` 上限 32 位，有契约测试），两笔 IOC 之间至少隔 3 秒：间隔没到时直接睡到间隔结束（受本账户预算约束），中间不做账户同步，不会空转打满交易所限频。每次进入运行（创建、或同一个动作号在 FAILED、PARTIAL 之后重试）在结果 JSON 里记一个起点（`attempt_started_at`），被拒和连续未成交只统计起点之后创建的子单：这一轮最近一笔被交易所拒绝，或连续 20 笔 IOC 一股都没成交（部分成交说明在推进，不计入），这一轮以 `PARTIAL` 结束，同一个动作号重试会重新来过（30 分钟期限也从这一轮的起点算，不看动作创建时间；起点取到秒，上一轮结束不到一秒就用同一个动作号重试会看到上一轮同一秒的被拒单，事件中心至少隔 30 秒才重试，碰不到）；执行器不碰清仓中的标的，它的单不算冲突、不暂停组合。每一轮先查名单，已解除禁止就撤掉本动作自己的订单，撤单后同步并确认它们都结束了，才记 `COMPLETED` 并带 `unblocked` 标记（不记 `FAILED`、`PARTIAL`，免得事件中心重试）；撤单还没确认结束就继续运行、下一轮接着确认，不记完成也不唤醒目标（没结束的 OPERATOR 单会被执行器当冲突、暂停组合）。同标的同交易所已经有另一个动作号在平（例如演练和真实下架同时平同一个模拟盘组合）时，新的动作号返回“忙”，不创建动作、也不返回别人的动作。下架的恰好是套利底仓的对冲腿时不自动平仓：以 `PARTIAL` 结束并写明原因、打关注项日志，不会静默记完成。

### 5.2 保证金率监控

每分钟检查一次币安生产环境、已启用且就绪的实盘永续账户（`marginmonitor` 服务，复用资金维护的定时任务外壳）。口径（读数不全一律不触发，不会凭空减仓）：

- 币安普通账户（`BINANCE_STANDARD`）：交易所总权益 ÷ 合约持仓名义，**不高于** `margin_ratio_threshold` 触发。总权益取账户快照的 `exchange_equity`：现货快照不填这个字段、多市场合并时相加，所以普通账户上它就是合约接口的 `totalMarginBalance`（钱包余额 + 未实现盈亏 + 多资产模式下的抵押，保证金币手工划到合约钱包的部分也算在内，正是币安决定强平的口径）。计划 4.6 的“策略权益不用交易所总权益”指换算目标用的权益，和这里的风控读数不冲突。持仓名义 = Σ |数量| × 标记价，没有标记价用开仓均价；没有持仓时不触发；
- 币安统一账户（`BINANCE_PORTFOLIO_MARGIN`）：uniMMR = 总权益 ÷ 维持保证金，**低于** `unified_mmr_threshold` 触发；总权益取 `exchange_equity`，维持保证金取快照的 `maintenance_margin`，两者缺一或维持保证金为 0 不触发；
- 账户快照超过 3 分钟没更新不判断；
- **OKX 暂不监控**：官方样例里账户级的维持保证金在 `mmr`、`adjEq`，币种明细里的 `mmr` 和 `mgnRatio` 是空串，现有快照读不对，宁可不监控也不读错。含 OKX 账户的组合每个账户告警一次“OKX 保证金率监控未接入”，资金设置表单只在组合里没有币安生产实盘成员（全是 OKX 等不被监控的成员）、测试网、模拟盘时隐藏这一组设置（隐藏时保存提交库里已存的值，不重置）；混合组合（既有币安生产实盘成员、又有 OKX 成员）照常显示并注明：OKX 成员不参与保证金率判断，触发减仓时按设置的比例对整组减仓（含 OKX 成员）；接入账户级 `adjEq`/`mmr`（或 `mgnRatio`）后再开放；
- **依赖账户类型检测**：账户类型（`c_account_mode`）由交易所检测（1B 的 T5）写入；还没有写入的实盘永续账户同样不监控，并告警一次“账户类型还没有检测写入”。测试网、模拟盘不监控。

触发后：暂停组合并发起 `REDUCE`（比例 `margin_reduce_ratio`，现货和合约同比例）。暂停原因是固定文字“自动暂停：保证金率过低…”，不带比值（暂停原因会作为 `auto_paused` 告警的详情上报，带变化的数字会让每次触发产生新的指标序列），进入已有的“组合账户自动暂停”告警；比值只写日志。同时只要暂停原因还是保证金风控的，`margin_ratio_low` 关注项就持续上报（按库里的状态推出，不带时间窗口），详情是固定文字“保证金率风控已暂停，等待确认后恢复”，用户恢复后消失。减仓动作发出之后才写日志；有下架清仓在跑、减仓排不进去时先把组合暂停停住，下一轮再补减仓。减仓结束后，普通账户把现货钱包的 USDT 归集回合约钱包（用执行器的钱包划转；划转还没接入，只告警一次，请手动划转。风控划转没有目标，`target_id` 为空串，归集接口带这次风控事件的幂等键——风控减仓的动作号 `margin-<组合>-<时间>`，接入划转时必须按它做幂等，不能只按（组合、空目标、方向），否则第二次风控事件的归集会被当成已做过）。

不会重复触发：整组清仓、减仓在跑时这一轮不叠加（人工单、撤单这类动作不挡监控）；上一次风控减仓之后，组合要恢复过（用户确认安全后手动恢复）才会再触发，所以用户在暂停期间人工下单、撤单、清仓改写了暂停原因，比值仍低也不会再自动减一次。“恢复过”记在库里（`t_logical_accounts.c_resumed_at`，每次从暂停恢复自动执行时写入，新增列，Trade 库要全新初始化），Trade 重启不丢；人工暂停的组合、历史上有过风控减仓但之后已恢复的组合照样监控。风控先把组合暂停、减仓还排不进去（有下架清仓在跑）时，暂停原因写“减仓待执行”而不是“已减仓”（`margin_ratio_low` 照报），下一轮（含重启之后）会把减仓补上，补上后原因换成“已减仓”。动作号 `margin-<组合>-<时间>`。

### 5.3 收益拆解

`SummarizeAccountPnl`（按组合或单个执行账户、时间范围默认近 7 天）：手续费和已实现盈亏从成交表汇总（十进制累加，手续费**按手续费资产分别汇总，不折算成结算币**，已实现盈亏按结算资产，只来自合约成交，现货成交的已实现盈亏记为 0）；资金费从交易所流水即查（每个有永续的执行账户翻页取 `FUNDING_FEE`，最多 5 页、共用 11 秒期限，按流水号去重；多个账户都没取完时，统计起点取各账户已取到的最老时间里最晚的一个）。时间范围最长 90 天（请求校验限制，成交汇总逐行读成交表，不放开）；翻页没取完、有账户流水查不了时 `funding_truncated` 为真并写明 `funding_note`；模拟盘、没有永续或交易所没有流水接口的账户 `funding_available` 为假。

## 6. 订单与交易所

- 公共数量统一使用基础资产数量，交易所适配器负责合约换算。
- `FillPolicy` 支持 `GTC`、`IOC`、`FOK`；`ReducePositionOnly` 由服务端根据已确认持仓推导，
  调用方不能设置。
- 状态为 `SUBMITTING` / `SUBMIT_UNKNOWN` 的订单先用相同的 client order ID 查询交易所，禁止盲目重发；
  成功但非 OPEN 的下单响应立即触发轻量同步，回执里的累计成交量写入观察成交量并关闭准入。
- 限流统一由 `httpclient` 处理：429、418、WAF 403 按域名暂停全部请求，-1015、-1008、OKX 50011 只暂停该账户下单；暂停期间本地直接拦截、不发请求，也不在请求内等待。确定未受理的下单回到待提交，不算拒单。会话重连等暂停结束；暂停期间跳过 listenKey 续期。
- 交易所适配器：Binance、OKX（client order ID 用 `xid` 生成并校验格式）。
- 模拟盘使用公共行情做简化撮合：市价单按最差可成交价；限价单能立即成交按 taker 成交，
  否则 GTC 挂单在行情穿价后按 maker 成交，IOC/FOK 无法全部立即成交则整单取消。
  不模拟盘口深度、排队和部分成交。

### 接入新场所清单

新增交易所或券商时，`application`、`runtime` 不用改：

1. 新建适配器目录，实现 `execution.ExecutionAdapter`，并实现 `ExchangeIdentity`（`Exchange()`）。行情、参考价、标的加载、按交易所单号查询都是必须实现的方法。
2. 按需实现可选接口：有私有流实现 `AccountEventSource`，否则会话每 3 秒同步一次；有杠杆配置实现 `SymbolConfigurer`。
3. 在 `bootstrap.registerBuiltins` 注册工厂和 `VenueDescriptor`：可用订单类型、成交策略、交易时段函数（不填表示全天）。凭据校验放在工厂里，账号、网关地址从 `Credential.Extra` 读取。
4. 在 `trade_service.proto` 的 `Exchange` 枚举加一个值，在 `rpc/convert.go` 的 `exchangePBNames` 表加一行。
5. 新市场类型在 `exchange/market_rule.go` 的规则表加一行，并同步 proto `MarketType`、`schema/logical_account.sql` 的 `CHECK`。

股票沿用现货模型：持仓放进 `Balances`，`Available` 是可卖量，当日买入的数量计入 `Locked`；一手 100 股直接表示为数量步长 100。不在交易时段时目标保持等待，不算错误，也不暂停。`test/fake_broker_e2e_test.go` 是完整示例。

## 7. 密钥与环境

实盘默认关闭：启用 PRODUCTION 账户和提交实盘订单都需要显式配置 `live_trading_enabled=true`。
Trade 复用进程级签名网关客户端，以独立 `trade` 身份调用原生 `GetSecretValue(secret_id)` 逐条读取交易所密钥，不列出也不加载无关密钥。
TESTNET 与 PRODUCTION 使用适配器内的固定端点；Binance 分别使用测试网与生产端点，OKX REST 共用 `https://openapi.okx.com`，TESTNET 请求增加 `x-simulated-trading: 1`，私有 WebSocket 按环境区分。

交易所密钥可以在 `moox.toml` 的 `[[exchange_keys]]` 里录入（`config init` 录入页、`config edit`），`setup apply` 写进密钥管理：category=exchange，provider 为小写交易所名，固定 ID `exchange-<交易所>-<环境>-<名称>`，passphrase 放进 `extra_config`；`readonly = true` 的密钥再写 `"readonly":"true"`，`loadCredential` 据此拒绝用它建执行账户（例如 Collector 检测币安现货下架读的 `exchange-binance-production-readonly`）。写入只建不改，换密钥以管理台为准。apply 时 Trade 已部署就经网关调 `InspectExchangeCredential` 检测，否则部署后执行 `moox-cli trade inspect-credential`。

## 8. 生命周期与逐期回放

> 状态：已实现（设计 6、9）。

- **生命周期**：Trade 的模块自身检查就是就绪判定（数据库、EventBus、账户会话、各工人）；没有对象。`/v1/lifecycle/status|command|catchup` 与 `/healthz` 的 `details.lifecycle` 同其他模块。
- **暂停与恢复**：暂停同时关闭**目标接收**（真实目标不被接收，也不被销毁：延迟重投，放开后照常接收，已过有效期的按过期终止——策略暂停前刚发布、暂停期间才送到的目标因此不会被静默终止；影子目标只是记录，照常接收）和**订单执行**（`TargetWorker` 不再收敛目标），并等在途的收敛（订单提交）结束才算停下；**不撤单、不平仓**，回报与账户对账照常。
  门禁看「是否被有意停下」（暂停、恢复追赶、重置、故障），不看就绪检查，所以就绪抖动不会让 Trade 丢目标。
  恢复先进入追赶：每个启用的实盘账户最近一次交易所对账在 2 分钟内、已就绪、无错误、余额已确认，并且没有目标在收敛，才算追平；暂停前未收敛的目标不强制过期，按各自的有效期自然过期。
  Strategy 对追赶或过期周期成功求值时只保存规则状态，不发布新目标；这与 Trade 已收到、随后过期的旧目标不同。策略理论状态推进不表示实际账户已成交，也不会由 Trade 补执行这些历史周期。
- **回放纸面账本**：`/v1/replay/session|advance|periods|close|delete`（健康端口，签名鉴权）。每次回放一个会话，初始资金、费率、滑点固定；`advance` 带回放时钟（决策时刻毫秒）、
  回放报价（估值价与成交价）和策略决策（`UPDATE_TARGET` 带完整目标集合，不在其中的持仓目标为 0；`SKIP` 只估值）。撮合：先卖后买，买单受可用现金限制（部分成交或拒绝），
  只做多现货，缺价报错、不回退实时报价；同一期按 `(replay_id, period)` 幂等，内容不同则冲突，周期必须逐期向前。结果在 `t_replay_sessions`、`t_replay_periods`、`t_replay_orders`，
  **不接触实盘账户、订单、预留与执行器**，回放绝不产生实际下单。编排见[因子](因子.md)第 9 节。

## 10. 告警

Trade 每 30 秒扫描一次需要人看的情况，上报 `moox_trade_attention_active`，Monitor 生成 `trade_attention:*` 检查并发告警：目标被拒绝、组合账户自动暂停、目标持续阻塞超过 1 根 K 线、执行账户持续未就绪超过 2 分钟、连续 3 个目标过期且有差额、同一目标内反向下单（`target_reversal`）、交易所接口限流（`rate_limited`）、1 小时成交额超过权益 6 倍（`turnover_high`）、1 分钟内结果未知超过 5 笔（`unknown_results`）、实盘账户保证金率跌破阈值（`margin_ratio_low`，风控已暂停组合并减仓，等用户确认后手动恢复）、交易账户密钥检测发现阻断项（`inspection_blocked`）、密钥复查连续 6 次没有检测成功（`inspection_failing`）、普通账户合约钱包可划转资金不足导致现货买入被缩小或挡下（`transfer_shortfall`：每份目标的事件，加上每轮扫描从当前目标状态推出——目标 BLOCKED 且带着资金不足的项就持续上报，文字固定，不依赖时间窗口）、钱包划转或归集出问题（`transfer_failing`：连续失败、划转前的查询持续失败、未结划转超过 10 分钟）。同步持续失败走已有的余额同步检查。

下单量指标只在本地 Prometheus：`moox_trade_orders_total{account,result}`、`moox_trade_cancels_total`、`moox_trade_order_notional_total`、`moox_trade_reversals_total`、`moox_trade_target_child_orders`、`moox_trade_rate_weight_used`、`moox_trade_rate_pauses_total`。

交易所接口说明见 `modules/trade/docs/exchange-apis.md`。

## 普通账户钱包划转与归集

币安普通账户的现货、合约是两个钱包，USDT 平时放在合约钱包。执行器的第 4、6 阶段由 `application/wallet` 处理（经 `target.NewWalletTransfer` 接入）；统一账户、OKX、模拟盘不划转。划转只在同一个账户的两个钱包之间进行，没有提现和跨账户路径。

- **第 4 阶段（现货买入前）**：划转金额 = max(0, 现货买单名义总额 × 1.02 − 现货钱包可用 USDT)，不超过合约钱包可划转额度 × 0.99。可划转额度取合约资产的 `maxWithdrawAmount`（官方说明：最多可转出），不是可用余额。划转前现查两个钱包的余额。现货钱包够用就直接放行。
- **额度不足**：划转金额被合约钱包可划转额度封顶（小于需要的金额）时，记录上打“封顶”标记；封顶的划转完成后，这个目标不再追加，只把现货买单按“本轮能用的资金 ÷ 本轮需要的资金”缩小（比例和缩小后的数量都向下取到 8 位小数，每轮重算、不累计；`blocked_targets` 记缩小前的原始差额；缩小后低于最小下单额的也记 blocked，不当作已满足），告警每个目标一次。没封顶的划转完成后如果仍缺 1U 以上（比如价格上涨），再划一笔差额，不告警；缺口不到 1U 起划额时，现货钱包已经够付买单的名义金额（不含 2% 余量）就不缩小，不够只缺一点就按 1U 划转，不会为了不到 1U 的缺口把买单缩得下不了单；同一个目标往现货钱包最多划 3 次，防止余额口径异常时一直追加。划转被交易所拒绝或连续失败 3 次，这个账户的买入比例记为 0，原因写进目标的 `blocked_targets`，不影响同组合其他账户，也不会让整轮收敛报错。
- **先排除本来就不会下的买单**：调用钱包之前，先按缩小前的原始差额判断——低于设置的最小下单额，或交易规则下下不了单且已有同向持仓（零头）的现货买入，视为已满足，不下单、不计入划转需求（不为不会下的单划转资金，缺钱时也不判 BLOCKED）；因为非资金原因注定下不了的买单（交易规则、所有成员在本目标都拒过单、同目标反向次数已满、伪市价次数用满），用下单前的试算（`placeActionMode` 的 dryRun）排除，直接记非资金原因的 BLOCKED，不划转（否则先划进现货钱包、再归集回去、再划进来，钱停在现货钱包）。兜底：这个目标已经把现货钱包多出来的资金归集回合约钱包后，不再往现货钱包划，只按现有资金缩小。试算先看全部成员（下单时会换成员），再看要划转的这个账户：首选成员自己下不了单、别的成员能下，就不为首选成员划转，下单照常换成员；试算遇到目标过期、会话变化、还没生效这类目标级错误原样返回，不先划转。单币每小时上限已经用完时买单顺延到下一个整点，不为它划转（划进去这个小时也买不了），已有的现货资金也不归集；“持仓未反映已成交子单”这种暂时状态下同样不归集。剩下的买单如果缩小后太小，一律记 BLOCKED 和缩小前的原始差额，不再走“已有同向持仓就算完成”的跳过；差额本身够下单只是没钱，是真实的资金缺口，记 BLOCKED。这类缺口只发 `transfer_shortfall`，不再重复发 `target_blocked`。
- **归集只让位给在等资金的买单**：账户有现货买单被每小时上限顺延、在等划转、或因合约钱包可划转资金不足被缩小或挡下时不归集；被拒单、反向次数超限等非资金原因被挡的买单用不上资金，不拦归集。
- **软失败不阻塞**：限频、本地限流暂停（请求没有被受理）和“对账宽限期后交易所记录里没有这笔划转”不计入连续失败。限频这类软失败让这个账户按退避等待后自动重试（目标保持收敛中，`blocked_targets` 里用“顺延”显示原因，类别是中文）。
- **按账户等待**：划转、对账、等快照、失败后退避，都只挡对应账户自己的现货买单；同组合其他账户（包括 OKX、统一账户）的买单照常下。只要还有账户在等，目标保持收敛中，不归集、不定终态。
- **没有幂等键怎么防重复**：币安的万向划转接口没有客户端流水号。先写一条 PENDING 记录再请求；请求超时或进程崩溃后，按请求时间、方向、资产、金额对账交易所的划转记录，认领到就记流水号，宽限期（1 分钟）内查不到不下结论，过了才作废重试。发起新划转前先对账这个账户所有未结的记录（不论哪个目标），有未结的就等待。查不到交易所记录、查不到余额时按账户指数退避（1 秒起，最长 30 秒）：钱包服务记着每个账户“下次可以请求交易所的时间”，目标每秒收敛一次，退避期内直接返回等待，不请求交易所；连续 5 次告警。未结划转超过 10 分钟的告警里带划转编号，核对交易所划转记录后，由用户确认，用 `ResolveWalletTransfer`（`moox-cli gateway call trpc.moox.trade.TradeConsoleService ResolveWalletTransfer --data '{"transfer_id":"…","result":"COMPLETED"}' --yes`，没到账填 `FAILED`）人工结束这条记录；只处理超过 10 分钟的未结记录，已经结束的原样返回。Agent 不代用户判断到账与否。
- **划转完成后等现货钱包快照**：现货钱包的存储快照更新时间不早于划转的完成时间（交易所记录的时间）才放行买入，等待最长 2 分钟。重启后从划转表接着走。
- **第 6 阶段（归集）**：目标执行完后，现货钱包多出来的 USDT 划回合约钱包。现货钱包留 1U，开启 BNB 保留时再留 BNB 补买所需（保留金额的一半减去现货钱包 BNB 的市值）；资金设置或 BNB 价格取不到时不归集并告警。多出来的低于 max(100U, 权益 × 1%) 不划，避免 1 分钟级策略每期来回划转。每个目标最多归集一次，归集是收尾动作，失败只告警、跳过。本目标里还有现货买单在等资金（被每小时上限顺延、缩小后太小、资金不足被挡、还在等划转）的账户不归集，否则刚划进现货钱包的资金又被划回合约钱包，剩下的买单再也买不了。
- **风控归集**：保证金率监控触发后的归集（`CollectForRisk`）没有目标，划转记录的 `target_id` 为空串；一次风控事件由幂等键标识（风控减仓的动作号 `margin-<组合>-<时间>`），本地引用号写成 `<幂等键>:TO_FUTURES:1`。同一个幂等键最多归集一次（重复调用不重复划转，未结的记录对账到完成）；不同幂等键各自归集，不会被上一次的记录当成已经做过，（账户、本地引用号）唯一约束也不冲突。风控归集必须做成，不沿用目标归集“收尾吞错”的语义：出错（查余额限频、划转没发出、被拒绝）返回错误，监控下一轮重试；账户上有别的未结划转时返回 pending；限频、没到账的软失败记录不算“做过”，重试的本地引用号递增（`<幂等键>:TO_FUTURES:<第几次>`）；被交易所确定拒绝连续 3 次后不再自动重试，告警并继续返回错误。
- **资金流水**：`ListAccountLedger` 把已完成的划转合并进返回结果；合约收益流水里已经带的划转（流水号相同）不重复合并。

## 币安统一账户的未核对项（V3 小额实测必须覆盖）

统一账户没有测试网，下面几点只能靠官方样例和用户本人小额实测核对，不能由 Agent 下真实订单：

- 统一账户同时开通合约时，现货买单的本地资金校验用账户级可用资金（含 UM 钱包）。如果交易所要求现货买单只能花杠杆钱包里的资金（需要先 `POST /papi/v1/asset-collection` 把 UM 钱包的资金归集到杠杆钱包），带 `sideEffectType=NO_SIDE_EFFECT` 的买单会被交易所拒绝；目前没有核对，也没有实现归集。
- `GET /papi/v1/margin/openOrders` 不传 symbol：官方文档说明返回全部标的，但限频权重按交易中的标的数量计；SDK 的参数校验却把 symbol 标成必填。只有会话启动、增量同步和手动全量同步按文档说明不传 symbol；30 秒一次的周期对账改为按“本地未结束订单、持有资产对应的交易对、当前目标里的现货标的”逐个查（传 symbol，权重 5），合约照常列全部。因此没有出现在这些标的里的外部现货挂单，要等会话启动或手动全量同步才发现。实测时核对不传 symbol 的返回和权重消耗，必填的话全量路径也改成按相关标的逐个查询。
- 资金流水去重假定：合约收益流水（`/fapi/v1/income`、`/papi/v1/um/income`）里 `incomeType=TRANSFER` 那一行的 `tranId` 就是万向划转的 `tranId`；如果不是同一个编号，已完成的划转会在资金流水里出现两次（一次来自划转表、一次来自合约收益）。未核对。
- 等现货钱包快照追上划转：用现货账户 `GET /api/v3/account` 的 `updateTime` 和划转完成时间比较。如果划转不会更新现货账户的 `updateTime`，每笔划转后都要等满 2 分钟（`snapshotGrace`）才放行买入；买入前的余额是现查的，只是慢，不会多花钱。未核对。
- 保证金率监控读数（统一账户）：直接取 papi account 的 `uniMMR` 比阈值（币安常见问答：uniMMR = 调整后权益 ÷ 维持保证金，调整后权益计入抵押率、再扣掉挂单浮亏 openLoss；接口文档里 `accountEquity` 是计入抵押率的账户权益、`actualEquity` 是不计抵押率的权益，所以分子对应 `accountEquity`，不是 `actualEquity`，用 `actualEquity` 会读数偏高、漏触发）。`uniMMR` 为空时才退回自己算的 `accountEquity ÷ accountMaintMargin`，它没扣挂单浮亏，有挂单时可能略高于币安的 `uniMMR`。官方样例里几个数字彼此对不上，只是示例填充值。私有事件更新了维持保证金时清掉上一次的 `uniMMR`，监控退回自己算。未核对：V3 小额实测时日志里同时记着交易所的 `uniMMR` 和自己算的值，对照两者是否一致。
- `totalAvailableBalance` 的真实取值（官方样例是空串）、私有流的 ping 间隔、papi 整体权重额度。
