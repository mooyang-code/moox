# Strategy 前端管理台设计

本文是待实现的目标设计，修订日期为 2026-09-05，不表示当前界面或接口已经支持。
领域合同以[策略执行框架设计](策略执行框架设计.md)和
[实施计划](superpowers/plans/2026-08-29-moox-coin-selection-strategy.md)为准。
Strategy 采用定义、实例、结果三表；异步投递信息保存在结果中，不提供独立 outbox 管理页。

## 页面边界

管理台围绕四类事实组织：

- `StrategyDef`：共享 DSL 与派生的 `strategy_name`。
- `StrategyInstance`：独立输入绑定、资金单元、启用状态和运行会话。
- `StrategyResult`：一次成功计算的历史快照、目标、规则后态与投递状态。
- Trade 事实：组合账户、当前 LogicalAccountTarget、订单、成交、持仓和
  OperatorAction。

页面支持 DSL 编辑，不提供任意 Python 源码执行，不复制 Trade 数据到 Strategy。
只展示有实际数据来源的结果、规则状态和运行摘要，不虚构本地绩效或真实持仓。

## 页面结构

### Strategy 列表与详情

列表展示：

- `strategy_name`、`strategy_id`、创建时间与修改时间。
- 引用实例数量和启用数量。

列表、搜索和排序直接使用 strategy_name，不逐条解析 YAML。
详情展示 dsl_yaml 和引用实例列表；修改前必须停用所有引用实例，由后端校验，不只禁用按钮。
名称只在 DSL.name 中编辑，后端保存时同事务同步 strategy_name，不提供另一份独立名称输入。
保留 strategy_id 原地编辑，不创建定义版本、hash 或编译制品页面；历史结果展示自身 snapshot_json。

### 实例列表与详情

列表展示：

- `instance_id`、引用策略、输入绑定，以及 DSL 中的 bar 和触发方式。
- enabled 对应的启用/停用状态，当前 `session_id` 标注为“运行会话”。
- `logical_account_id` 或“观察模式”。
- 最近成功周期与创建时间，从当前会话最新 Result 派生；错误由服务运行摘要提供。

详情分为：

1. 定义与输入：当前策略 dsl_yaml、结构化输入绑定、定时/事件配置。
2. 当前理论目标：当前 instance_id + session_id 最新成功 Result 的 targets_json。
3. 结果历史：bar_end_time、created_at、目标、snapshot_json、rule_states_json 和 publish_status。
4. 组合账户：Trade 自动化状态、readiness、成员执行账户和当前接受目标。

实例启停只调用实例控制接口，不等于撤单或清仓。切换定义、输入绑定或资金单元前必须完成停用清理。
同一定义可创建多个独立实例，禁止把其会话、结果和规则状态混在一起。
正常进程重启保持 session_id；重新启用产生新值。false + 非空 session_id 表示控制操作未完成，
重启后仅清理、不自动续启，界面不能显示为正在计算，也不为此增加另一套持久化状态枚举。
不维护 current_targets、last_result_id、command_sequence 等展示用数据库副本。

### 组合账户执行面板

执行面板展示：

- ACTIVE/PAUSED、暂停原因、readiness 和具体原因。
- paper/live、SPOT/SWAP、`settlement_asset`。
- owner 实例、运行会话和成员执行账户优先级。
- 当前 LogicalAccountTarget 的状态、bar_end_time、valid_until、targets 和 blocked targets。
- 目标数量与执行账户 Position 的偏差。
- 最近 OperatorAction。

Strategy 的 `target_weight` 是相对账户权益的 FULL 目标权重，界面不得把它标成订单量或
变化量。Trade 的 `TargetReceipt` 才展示权益、参考价格和换算后的绝对数量；两者必须分开展示。
PAUSED 期间收到的有效新权重目标仍要显示，同时明确“已保存，尚未执行”。
恢复前展示当前授权与有效期；过期目标不能继续触发新交易，消息过期也不是自动清仓。

## 人工控制

### Pause 与 Resume

Pause 要求操作原因。Resume 前展示：

- 当前保存的 FULL 目标。
- 尚未解决的外部订单冲突。
- 成员 readiness。
- “人工清仓后恢复可能重新开仓”的明确提示。

### 人工下单与撤单

所有修改请求生成并携带 `action_id` 与 reason。人工下单选择一个组合账户成员执行账户，
并填写 instrument、方向、类型、数量和可选限价。owner 字段不能由前端设置。

提交前确认文案明确说明：整个组合账户将进入 PAUSED，活动 TARGET 订单会先被
撤销，操作完成后不会自动 Resume。

### 逐账户清仓

UI 文案使用“逐账户清仓”，RPC 名称为 `FlattenLogicalAccount`。确认框列出全部成员并
说明：

- 先同步和撤销各账户活动订单。
- 每个持仓在原账户独立平仓，不按逻辑净额抵消。
- 失败和剩余持仓按账户显示。
- 最新 Strategy 目标不会删除，之后 Resume 可能重开。

页面轮询同一 `action_id` 的 OperatorAction，展示 RUNNING、COMPLETED、PARTIAL 或
FAILED，以及逐账户结果；重复点击必须继续同一 action，而不是生成重复订单。

## FULL 目标展示

每个成功 StrategyResult 的 targets_json 都是指定资金单元的 FULL 权重目标：

- 遗漏旧标的表示该资金单元内目标归零。
- 明确成功的空列表表示完整零目标；缺数和计算失败不展示成空目标。
- 每个新成功周期都产生结果及目标，即使权重不变，不再区分 hold/rebalance。
- 观察模式保存目标但永不投递；无当前会话成功结果时不冒充沿用旧会话目标。

界面应区分：

| 数据 | 含义 |
| --- | --- |
| 当前实例与会话的最新成功 Result | Strategy 理论 FULL 权重目标 |
| LogicalAccountTarget | Trade 当前接受并收敛的 FULL 目标 |
| TargetReceipt | 接受时冻结的权重、权益、价格证据和数量换算 |
| Position | 执行账户已确认实际持仓 |
| blocked targets | 暂时无法执行的剩余目标及原因 |

### 计算与投递分开显示

| publish_status | 显示含义 |
| --- | --- |
| none | 观察结果，无需投递 |
| pending | 等待投递或重试，尚未确认送达 |
| sent | broker 已确认，不表示 Trade 接受或订单成交 |
| cancelled | 停止重试，不保证此前从未送达 |

业务快照不可变，只有投递状态更新。后台扫描结果发送，不另设消息表或单独的 outbox 页面。
详细评分明细仅在诊断日志存在时显示链接，不要求 Result 增加 details 列或前端自行计算评分。

## API 使用

Strategy：

- `CreateStrategy`、`UpdateStrategy`
- `ListStrategies`、`GetStrategy`
- `ListInstances`、`GetInstance`
- `SetInstanceEnabled`
- `ListStrategyResults`、`GetStrategyResult`
- `ListStrategyTargets`

上述实例接口是命名目标，对应旧 ListRunners/GetRunner/SetRunnerStatus；实施时同步 Proto、
管理转发、前端调用与测试，不能假定当前后端已提供。其他实例 CRUD 同步更名，不新增重复入口。
UpdateStrategy 是本次目标新增接口，使用 strategy_id 定位定义，只以 dsl_yaml 提交定义内容；
创建也以 dsl_yaml 为准。后端拒绝编辑仍有启用引用的定义，成功后返回同事务同步的 strategy_name。
列表返回 strategy_name，定义写入仍以 dsl_yaml 为准；最新目标接口返回当前会话成功结果，
不返回旧 sequence，也不让前端据当前绑定重建历史投递消息。

Trade：

- `ListLogicalAccounts`、`GetLogicalAccount`
- `GetLogicalAccountTarget`
- `PauseLogicalAccount`、`ResumeLogicalAccount`
- `PlaceManualOrder`、`CancelOrder`
- `FlattenLogicalAccount`、`GetOperatorAction`
- `ListOrders`、`ListFills`、`ListPositions`

前端只展示服务返回的 readiness 与原因，不在浏览器重新推导一套健康状态。

## 状态和空页面

- 无实例：提示创建实例，不把它当故障。
- 观察型实例：展示理论目标，但不显示执行控制，不将 none 标成投递失败。
- 当前会话无 StrategyResult：显示“本次运行尚无成功结果”。
- 已计算但 pending：展示目标并说明尚未确认投递，不显示成未计算。
- cancelled：显示停止重试，与计算失败和完整零目标区分。
- PAUSED：把暂停原因放在操作区首要位置。
- PARTIAL/FAILED OperatorAction：保留逐账户错误和可继续操作入口。
- 服务不可达：区分 Strategy 与 Trade，不用一个空表掩盖错误。

## 验收

- 页面围绕 StrategyDef、StrategyInstance、StrategyResult 与真实 Trade 事实组织。
- strategy_name 与 DSL.name 保存后始终一致；存在启用引用实例时编辑被后端拒绝。
- 实例和会话可区分；同定义不同实例的结果互不混用，重启与重新启用行为不同。
- 空 FULL、缺数失败、同权重新周期和观察模式的文案、数据与测试一致。
- 结果投递四态与 broker/Trade/成交分开；旧会话和过期目标不会被显示成待恢复执行。
- PAUSED 新目标不会被显示成已执行。
- 人工下单提示暂停整个组合账户。
- 逐账户清仓展示每个成员结果并提示 Resume 风险。
- RuleState 仅展示结果保存的理论状态，不称为真实持仓；不增加本地绩效或余额投影。
- 界面不依赖独立 outbox、sequence、结果指针、定义 hash 或持久化编译制品。
