# Strategy 前端管理台设计

## 页面边界

管理台围绕四类事实组织：

- `Strategy`：不可变源码、清单和 hash。
- `StrategyRunner`：独立参数、数据 View、频率、状态和组合账户关联。
- `StrategyResult`：一次已接受输出。
- Trade 事实：组合账户、当前 LogicalAccountTarget、订单、成交、持仓和
  OperatorAction。

页面不提供在线 Python 编辑，不复制 Trade 数据到 Strategy，不展示没有生产写入来源
的本地绩效或策略内部状态。

## 页面结构

### Strategy 列表与详情

列表展示：

- 名称、`strategy_id`、source hash、创建时间。
- Runner 数量和启用数量。

详情展示只读 `manifest_yaml`、源码和 Runner 列表。Strategy 不可原地修改；发布新代码
使用新的 `strategy_id`。

### Runner 列表与详情

列表展示：

- `runner_id`、Strategy、View、frequency。
- ENABLED/DISABLED 运行状态。
- `logical_account_id` 或“观察模式”。
- 最近成功时间、最近错误和 `command_sequence`。

详情分为：

1. 参数与输入：`params_json`、View、frequency。
2. 当前理论目标：`current_targets` 中的 `instrument_id` 和 `quantity`。
3. StrategyResult：触发时间、action、input hash、输出和 sequence。
4. 组合账户：自动化状态、readiness、成员执行账户和当前 Trade 目标。

Runner 启停只调用 Runner 状态接口。切换 Strategy 或 LogicalAccount 前必须先停用。

### 组合账户执行面板

执行面板展示：

- ACTIVE/PAUSED、暂停原因、readiness 和具体原因。
- paper/live、SPOT/SWAP、`settlement_asset`。
- owner Runner 和成员执行账户优先级。
- 当前 LogicalAccountTarget 状态、sequence、targets 和 blocked targets。
- 目标数量与执行账户 Position 的偏差。
- 最近 OperatorAction。

`InstrumentTarget.quantity` 是绝对目标持仓量。界面不得把它标成订单量、变化量或权重。
PAUSED 期间收到的新目标仍要显示，同时明确“已保存，尚未执行”。

## 人工控制

### Pause 与 Resume

Pause 要求操作原因。Resume 前展示：

- 当前保存的 FULL 目标。
- 尚未解决的外部订单冲突。
- 成员 readiness。
- “人工清仓后恢复可能重新开仓”的明确提示。

### 人工下单与撤单

所有修改请求生成并携带 `action_id` 与 reason。人工下单选择一个组合账户成员执行账户，
并填写 instrument、方向、类型、数量和可选限价。owner 字段不能由前端设置。

提交前确认文案明确说明：整个组合账户将进入 PAUSED，活动 TARGET 订单会先被
撤销，操作完成后不会自动 Resume。

### 逐账户清仓

UI 文案使用“逐账户清仓”，RPC 名称为 `FlattenLogicalAccount`。确认框列出全部成员并
说明：

- 先同步和撤销各账户活动订单。
- 每个持仓在原账户独立平仓，不按逻辑净额抵消。
- 失败和剩余持仓按账户显示。
- 最新 Strategy 目标不会删除，之后 Resume 可能重开。

页面轮询同一 `action_id` 的 OperatorAction，展示 RUNNING、COMPLETED、PARTIAL 或
FAILED，以及逐账户结果；重复点击必须继续同一 action，而不是生成重复订单。

## FULL 目标展示

StrategyResult 的 `rebalance.targets` 和 Runner `current_targets` 都是 FULL：

- 遗漏旧标的表示目标归零。
- 空 rebalance 表示全部目标归零。
- hold 不产生新目标命令。

界面应区分：

| 数据 | 含义 |
| --- | --- |
| Runner `current_targets` | Strategy 最新理论 FULL 目标 |
| LogicalAccountTarget | Trade 当前接受并收敛的 FULL 目标 |
| Position | 执行账户已确认实际持仓 |
| blocked targets | 暂时无法执行的剩余目标及原因 |

## API 使用

Strategy：

- `ListStrategies`、`GetStrategy`
- `ListRunners`、`GetRunner`
- `SetRunnerStatus`
- `ListStrategyResults`、`GetStrategyResult`
- `ListStrategyTargets`

Trade：

- `ListLogicalAccounts`、`GetLogicalAccount`
- `GetLogicalAccountTarget`
- `PauseLogicalAccount`、`ResumeLogicalAccount`
- `PlaceManualOrder`、`CancelOrder`
- `FlattenLogicalAccount`、`GetOperatorAction`
- `ListOrders`、`ListFills`、`ListPositions`

前端只展示服务返回的 readiness 与原因，不在浏览器重新推导一套健康状态。

## 状态和空页面

- 无 Runner：提示创建 Runner，不把它当故障。
- 观察型 Runner：展示理论目标，但不显示执行控制。
- 无 StrategyResult：显示“尚无已接受结果”。
- 无当前目标：显示“尚未发布 FULL 目标”。
- PAUSED：把暂停原因放在操作区首要位置。
- PARTIAL/FAILED OperatorAction：保留逐账户错误和可继续操作入口。
- 服务不可达：区分 Strategy 与 Trade，不用一个空表掩盖错误。

## 验收

- 页面只使用 Strategy、StrategyRunner、StrategyResult、LogicalAccount、
  LogicalAccountTarget、InstrumentTarget 和 OperatorAction。
- 空 FULL 清仓和 hold 保留目标的文案、数据和测试一致。
- PAUSED 新目标不会被显示成已执行。
- 人工下单提示暂停整个组合账户。
- 逐账户清仓展示每个成员结果并提示 Resume 风险。
- 不存在策略内部状态、旧式运行记录、资本权重或本地余额投影 UI。
