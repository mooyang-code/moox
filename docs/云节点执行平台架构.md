# 云节点执行平台架构

> 本文的通用 Job/EventBus 执行平台与实时行情 Timer 链路是两个边界。实时
> `crypto` 节点记录为 `node_type=scf-event, trigger_type=timer`，任务和 DNS
> 由 Collector 协调到每个函数 Environment，Timer 直接触发 SCF；只有 Symbol 快照、补采、
> 出口探针和人工 E2E 使用下方的有界 Invoke/Completion 路径。不要把实时 Timer 重新接回
> 常驻 Consumer 或心跳保活。详见 [SCF 短时行情采集架构](architecture/scf-short-lived-market-fetch.md)。

## 责任边界

| 组件 | 责任 |
| --- | --- |
| Admin | SecretMgr、Service Gateway、初始化服务目录 |
| CloudNode | CloudAccount/Node/Package、队列 ensure、任务提交、终态状态 |
| EventBus | JetStream Stream 和 Consumer 传输 |
| Collector SCF | bind 作业路由 Consumer、执行 handler、report-before-ack |

Events 拥有消息语义，JetStream 拥有传输，`packages/cloudjobqueue` 拥有作业队列身份。

## 执行链

```text
SubmitJobItems
  -> EnsureJobExecutionQueue
  -> CreatePending
  -> Publish
  -> SCF BindConsumer / Fetch
  -> Collector handler
  -> ReportJobItemStatus
  -> ACK or TERM
```

可重试非末次失败不报告终态并 NAK。永久失败或末次失败先报告 failed 再 TERM。报告失败
一律 NAK。CloudNode 不拉取或确认消息，也不维护 attempt/running lease。

## 静态服务目录

初始化时 `service-deployments import --public-host --eventbus-nats-url` 同时写入公开网关
地址和目标节点的 `eventbus.extra_config.nats_url`。凭据导出从该记录读取唯一 URL。
Broker bind 地址仅是本机监听配置：loopback URL 推导为 `127.0.0.1`，公网 URL 推导为
`0.0.0.0`。

SCF 的 URL、worker token 和 CA 在 publish 时注入 Environment；代码包始终无密钥。
