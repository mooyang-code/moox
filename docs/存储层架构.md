# 存储层最终架构

本文记录 Storage 的当前架构。scalar `series_tag` 与 Metadata Schema v6 已在代码中
完成破坏性切换；生产发布与真实跨模块 E2E 验收仍按
[实施计划](superpowers/plans/2026-07-29-factor-runtime-correctness-hardening.md)
继续执行。详细协议取舍见
[Storage Dataset 单归属与多进程简化设计](superpowers/specs/2026-07-19-storage-dataset-node-simplification-design.md)
以及 2026-07-22 DataNode 管理模型设计。TimeSeries `series_tag` 的目标契约见
[Time-Series `series_tag` 统一设计](superpowers/specs/2026-07-29-time-series-series-tag-design.md)。
新旧协议和数据目录不得混跑。

## 进程边界

```text
Admin / Service Gateway
  |-> storage-primary
  |     |-> Metadata SQLite v6 + Metadata Snapshot
  |     `-> PrimaryStore -> storage-node-* (HMAC)
  |
  `-> storage-view
        |-> DataView / ViewIndex
        `-> storage_view JetStream Consumer

storage-node-*
  |-> Pebble Field/Attribute Keys
  |-> pebble/outbox_message.go (原子绑定 Outbox ID)
  `-> datanode/outbox (Relay + JetStreamPublisher)
        `-> moox.storage.dataset.rows.upserted.v2.<space>.<dataset>
```

- `storage-primary`：Metadata CRUD、Dataset/Field 校验，从同一 Snapshot 按
  `Dataset.data_node_id -> DataNode.service_target` 直接解析目标。
- `storage-node`：一个固定 `node_id` 的 Pebble Owner。一个节点可以承载多个
  Dataset，每个 Dataset 只能属于一个节点。
- `storage-view`：唯一 View Consumer、真实 DuckDB/Bleve、A/B 重建和公开查询。

Storage 的事件边界按职责拆分：`internal/eventmapper` 转换 Storage RPC 行模型和公共
Dataset payload；`service/datanode/outbox` 管理发送；`service/view/eventconsumer`
管理抓取、按 Subject 排序、心跳和 ACK/TERM，View 父包只负责索引应用与回填协调。

系统不实现 Dataset 内分片、副本、Leader Election、在线迁移或 Rebalance。
Dataset 创建为 disabled/unlocked；Doctor 只读检查，显式激活后变为 active/locked，
绑定不可修改。DataNode 由部署注册，管理台 DataNode 页面展示其全部 Dataset。

## Schema 与 RowKey

Dataset Schema 是 append-only：

- Field 只能新增，`field_id` 和 `value_type` 不可修改。
- 所有 Field 都允许缺失。
- 不提供字段删除、DeleteRows、ScanRows 或 Snapshot RPC。

TimeSeries：

```text
space_id + dataset_id + subject_id + freq + UTC data_time + series_tag
```

Record：

```text
space_id + dataset_id + record_id + version
```

`series_tag` 是可选的不透明 UTF-8 标量，空字符串表示默认序列。推荐写成
`venue:binance`、`device:sdb`，但 Storage 不解析其命名空间或值。系统不提供
Dimensions、Map、tag 数组、Dataset 级 tag 名称或允许值表；需要展示或计算的业务
属性仍建模为 Field/Attribute。Record 写入必须指定 version，空 version 只用于读取
字符顺序最大版本。

精确 RowKey 始终包含完整 `series_tag`。范围查询使用独立 selector：
`series_tag` 未出现表示匹配全部 tag，字段出现且为空表示只匹配默认序列，非空则
精确匹配完整字符串。

## 写入与 Outbox

PrimaryStore 从同一 Metadata Cache 快照完成 Dataset、DataNode、Field 和值类型
校验，然后按 `(space_id, dataset_id)` 分组调用 DataNode。

DataNode 在一个 Pebble Batch 中提交：

```text
0x01 Field Keys
0x02 Attribute Keys
__outbox/<outbox_id>
__meta/next_outbox_id
```

Outbox Relay 按内部 ID 逐条同步发布。发布失败时停止，只删除连续成功前缀。
事件外层是 `EventMessage`，事件名为 `storage.dataset.rows.upserted`，Payload 是
`packages/storagepb.DatasetRowsUpserted`；它携带变更行和变更字段，不是 Dataset 全量快照；Outbox ID 只用于稳定 `event_id` 和
JetStream `Nats-Msg-Id`，不暴露为业务序列。

## 时间桶

TimeSeries 物理键把规范化的 `bucket_start` 放在 Dataset 之后，因此清理可以对
完整桶执行有界 `DeleteRange`。清理键必须同时包含 Space 和 Dataset，防止不同
Space 的同名 Dataset 相互影响。提交删除后由后台 Compact 回收空间。

桶内完整物理身份按 `subject_id + freq + data_time + series_tag` 编码；同一时间点
不同 tag 的字段不会覆盖。

Primary 定时读取 Dataset `keep_duration` 并调用所属 DataNode。Record 的
`keep_duration` 固定为 `0`，不自动清理。

## View

所有 Dataset Subject 共用一个 Durable，客户端只绑定 EventBus 已声明的服务端配置：

```text
Durable: storage_view
Filter: moox.storage.dataset.rows.upserted.v2.>
FetchBatch: 8
MaxWorkers: 4
MaxAckPending: 8
```

永久无效的 Subject、Proto 或 Payload mismatch 执行 `Term`；临时 Active 写失败
保持当前 Delivery 并发送 `InProgress`，后续事件不能越过当前 Dataset Subject 队列。
不同 Dataset Subject 队列可以并行；Backfill 使用全局写优先 gate，避免与实时写同时
修改同一 View 边界。ACK/NAK/TERM/InProgress 错误进入低基数指标和日志。

View 的 Subject dispatcher 是 ViewBuilder 的有界执行策略，不是第二套 EventBus 拓扑
所有者。它通过每个 Subject 的有序队列保留同 Dataset 顺序、跨 Dataset 并行、queued
heartbeat 和 Backfill 写优先 gate。通用 Runner 当前为全局串行，不能在不改变这些语义
的情况下直接替换该策略。

每个 View 有 Active/New 两个目标：

1. Desired Revision、关联 Dataset 或 `2 * keep_duration` 触发 Reconcile。
2. 创建非活跃 DuckDB/Bleve 索引并安装实时双写。
3. 从旧 Active RowKey 小批 Backfill；新 Dataset 按相同 Grain 调
   PrimaryStore `ReadFields` 补列。
4. Backfill 只填缺失值，不覆盖实时写。
5. Metadata CAS 激活新 Revision，然后 DataView 切换不可变 Active。
6. 宽限期后删除 OldView。

Active 写失败会重试当前事件；New 写或 Backfill 失败只终止当前 Build，Active
继续服务。

TimeSeries DuckDB 使用 `series_tag VARCHAR NOT NULL`，主键为
`(subject_id, freq, data_time, series_tag)`。查询与分页使用
`subject_id, freq, data_time, series_tag` 的稳定全序；Backfill cursor 也必须包含
tag，不能在同一时间点漏行。

## 认证与故障边界

- Node、Primary、View secret 均为必填配置。
- DataNode 的所有 RPC、PrimaryStore、ViewIndex 和 DataView 都校验 HMAC。
- Metadata Cache 刷新失败继续使用上一份完整快照。
- Node 离线只影响其拥有的 Dataset。
- View 离线不阻塞事实写入，JetStream 保留未消费事件。
