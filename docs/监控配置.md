# 主机监控配置

> 架构边界、数据流、可靠性取舍和告警设计见 [主机监控架构设计](主机监控架构设计.md)。本文只说明部署与运行配置。

MooX 主机监控使用单一数据链路：

```text
moox-host-agent -> EventBus -> moox-monitor -> MooX Storage
```

Admin 不采集主机指标，也不保存主机监控历史。管理台通过 Admin 浏览器控制面调用 `moox-monitor`；跨节点 Monitor 互检通过目标节点的独立 Gateway。

## 健康鉴权

服务诊断面与业务 API 隔离。Monitor 调用 `/healthz`、`/readyz` 或 `/metrics` 时必须带 `X-Moox-Health-Auth`，其 version、access key 和 secret key 由部署生成的 `secrets/health-auth.env` 注入。签名覆盖 HTTP 方法、路径、body hash、时间戳和 nonce；缺失、过期或 nonce 重放返回 `401`。health HMAC 与 `/api/service/*` 的 service HMAC 是两套独立凭据。

Caddy 的公开 HTTPS 入口对诊断路由返回 `404`。web-host 诊断默认位于 `127.0.0.1:19527`，Admin 诊断契约为 `127.0.0.1:11010`。普通节点的 Gateway 诊断为 `127.0.0.1:11012`；control profile 为 SCF Sentinel 将 Gateway `11012` 和 Monitor `11409` 绑定到公网网卡。由于 SCF 出口地址不固定，这两个端口的防火墙来源为公网，但只接受独立 health HMAC 签名，且不承载业务或管理 API。其他模块端口应只绑定 loopback 或可控私网。实际端口和 header 注入以同版本部署配置为契约。

## Host Agent

Host Agent 仅支持 Linux `amd64` 和 `arm64`，采集 CPU、内存、文件系统、磁盘和网络指标。Agent 不使用 SQLite、outbox 或本地补发队列。

部署和配置参考：

- `skills/moox/references/host-agent.md`
- `skills/moox/scripts/hostagent-deploy.sh`

## EventBus

Host Agent 通过 NATS 用户名和共享 `eventbus_token` 连接 JetStream。部署流程负责生成凭据，并写入远端普通用户目录的 `0600` 文件。凭据不自动过期；轮换时发布流程提醒用户重新发布 Agent 和依赖服务。

Protobuf 二进制协议不是鉴权手段，NATS 账号、token 和 ACL 才是安全边界。

## Monitor

Monitor 按 `Validate -> Write Storage -> Update latest -> Evaluate alerts -> Ack` 消费 HostMetric。当前指标保存在 Monitor 内存中，历史只通过 Storage 查询；Monitor SQLite 只保存检查、告警规则和告警状态，不保存 HostMetric 样本。

Monitor 提供：

- `ListHostAgents`：返回最近上报的主机和当前快照。
- `QueryHostMetricHistory`：返回指定 `agent_id` 最近 1 小时、24 小时或 3 天的历史。

历史查询会返回 `storage_available` 和 `data_gap`。指标不可用时前端显示 `--`，不会转换成零值。

## Storage

Host 指标统一使用 `space_id=moox_system`、`freq=1m`，写入以下 Dataset：

- `host_resource_v1`
- `host_fs_v1`
- `host_disk_v1`
- `host_net_v1`

逻辑 metadata 直接绑定部署注册的 DataNode；Dataset 导入后保持 disabled，完成 Doctor
只读检查后再显式激活：

```bash
go run ./modules/cli/cmd/moox-cli metadata apply --file examples/setup/default/metadata.yaml
moox-storage-cli register-node --node-id storage-node-0 \
  --service-target ip://127.0.0.1:20107 \
  --metadata-target ip://127.0.0.1:20100
```

Storage 默认保留 48 小时主机指标。`trpc.moox.storage.host_metrics_cleanup.timer` 每小时执行有界多批清理：每数据集最多 10 批，每批每 target 最多 1000 行，单次超时 60 秒。Monitor 历史 API 接受最近 72 小时的请求，但默认部署中 48 小时之前的数据已被 Storage 清理。完整的自动清理与磁盘边界见[数据保留与磁盘空间](运维/数据保留与磁盘空间.md)。

`moox_system` 是系统级 Space，不受管理台当前业务 Space 筛选影响。

## 管理台

管理台入口为 `/ops/hosts?tab=monitor`。页面使用 `agent_id` 选择主机，通过 Monitor API 展示：

- 实时 CPU、内存、文件系统和网络摘要。
- 文件系统、磁盘和网卡明细。
- 最近 1 小时、24 小时或 3 天趋势。
- 主机离线、Storage 不可用和历史缺口状态。

管理台使用稳定 `agent_id` 选择主机。合法的 `0%` 会正常显示；只有 availability 为 false 或字段缺失时才显示 `--`。
