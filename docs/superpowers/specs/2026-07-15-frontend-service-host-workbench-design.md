# MooX 前端服务与主机工作台优化设计

## 状态

本设计已在讨论中确认。实施阶段按本文拆分任务，不再扩大到统一服务目录或主机资产后端重构。

## 背景

当前管理台存在四类体验问题：

1. 数据视图浏览页同时提供“刷新”“重新查询”和查询按钮，并重复展示已加载条数，操作和状态信息偏多。
2. “因子计算”与“数据采集”共用图标，“Strategy”与交易菜单共用图标，且中文环境中的菜单名称不统一。
3. “资源与运维”按前端功能拆成服务监控、应用指标、资源监控、主机管理、SSH 终端、会话管理和存储配置，入口多于用户任务。
4. 服务监控页没有采用项目统一的可滚动页面容器。长页面和详情抽屉中的表格难以浏览。

现有代码已经形成两条明确的业务关系：

- 服务部署记录是系统服务目录。服务监控从服务部署同步系统探测项，服务部署页也读取探测结果展示健康状态。
- 主机资源数据来自 Monitor 的 Host Agent，SSH 主机和会话来自 Admin SSH 服务。两者描述同一类运维对象，但没有共享主键。

因此，本次优化采用“混合工作台”方案：服务侧合并入口但保留数据边界；主机侧建立统一工作台，但不伪造跨系统身份关联。

## 目标

- 将“服务部署、可用性监控、应用指标”合并为“服务管理”。
- 将“资源监控、主机管理、SSH 终端、会话管理”合并为“主机工作台”。
- 将“资源与运维”的直接子入口收敛为“服务管理、主机工作台、存储配置”。
- 让数据视图浏览页只保留必要操作，并准确展示当前活跃视图的构建完成时间。
- 修复服务监控页面和详情抽屉的纵向滚动，优化长表格的密度、固定列和可视高度。
- 统一应用指标页与现有数据详情页的页面壳、标题、筛选区、状态行和结果区风格。
- 保留现有 Monitor、SysDeploy、SSH 和 Storage API 边界。

## 非目标

- 不新增统一服务目录后端，不要求探测项、部署记录和指标服务共享主键。
- 不新增统一主机资产表，不修改 Host Agent 或 SSH 主机的数据模型。
- 不重写 Monitor、SSH、SysDeploy 或 Storage 服务。
- 不改变指标采集、探测调度、告警评估、主机上报和视图构建语义。
- 不把存储拓扑配置合并进服务或主机详情。
- 不在本次改造中重新设计首页、交易、因子或采集业务页面。

## 总体信息架构

### 一级菜单

保持现有一级业务分组，只调整名称和图标：

- “因子计算”使用 Arco `icon-experiment`。
- “Strategy”统一更名为“策略管理”，使用 Arco `icon-mind-mapping`。
- 数据采集、因子计算、策略管理和交易管理必须使用不同图标。

### 资源与运维

“资源与运维”只保留三个直接子入口：

1. 服务管理。
2. 主机工作台。
3. 存储配置。

“系统设置”只保留空间管理和密钥管理。服务部署从系统设置迁入服务管理。

### 路由

新增两个工作台路由：

- `/ops/services?tab=deployments|availability|metrics`
- `/ops/hosts?tab=hosts|sessions`

默认值分别为 `deployments` 和 `hosts`。非法 Tab 回落到默认值，并通过 `router.replace` 规范化 URL。

旧入口改为路由重定向，避免现有收藏、首页快捷入口和部署后的旧标签页落入 404：

- `/settings/service-deployments` -> `/ops/services?tab=deployments`
- `/ops/service-monitor` -> `/ops/services?tab=availability`
- `/ops/metric-monitor` -> `/ops/services?tab=metrics`
- `/ops/resource-monitor` -> `/ops/hosts?tab=hosts`
- `/ops/ssh-hosts` -> `/ops/hosts?tab=hosts`
- `/ops/ssh-sessions` -> `/ops/hosts?tab=sessions`
- `/ops/ssh-terminal` 不再作为菜单或独立工作流；访问时转到主机工作台。

页面内切换使用 `replace` 而不是 `push`，避免用户连续切换 Tab 后产生冗长浏览器历史。

## 服务管理工作台

### 页面结构

服务管理使用与 `/collector/views` 相同的工作台模式：

- 外层组件只负责解析路由、展示标题 Tab 和挂载当前子页面。
- 标题为“服务管理”。
- 标题 Tab 依次为“服务部署、可用性监控、应用指标”。
- 三个子页面共享 `moox-page` 和 `moox-inner` 页面壳，不重复渲染独立 H2。
- 子页面继续调用各自现有 API，不在前端合并为一个请求。

默认打开“服务部署”，因为部署记录是系统服务的事实目录，也是探测同步的来源。

### 服务部署

保留现有列表、筛选、新增、编辑、删除和健康状态展示。调整范围仅包括：

- 移除独立页面标题，改由工作台标题 Tab 提供上下文。
- 保留 storage 地址变更提示。
- 保留健康状态容错。Monitor 不可用时，服务列表仍可查看和编辑，健康状态显示“未知”。
- 表格继续使用固定操作列和受视口约束的纵向滚动。

### 可用性监控

保留 HTTP/TCP 探测、系统服务同步、告警、Webhook 和监控实例能力。页面采用以下层次：

1. 一行紧凑状态摘要：总探测、健康、降级、故障、24 小时成功率和 P95 延迟。
2. 当前异常列表，仅在存在异常时显示。
3. 筛选栏和探测表格。

不再使用占据首屏的大号统计卡墙。状态摘要提供扫描信息，探测表格保持页面主体。

“同步系统服务、监控实例、Webhook、新增探测”保留为明确命令。“刷新”改为图标按钮并提供 Tooltip，避免头部出现五个同等权重的文字按钮。

### 应用指标

应用指标保留指标目录、最新值、历史趋势、告警规则、规则预览和评估记录。视觉结构参考数据视图浏览页：

- 使用统一页面壳和标题 Tab，不再渲染独立页面标题卡。
- 使用平铺筛选区：服务、实例、指标和标签过滤。
- 使用状态行展示当前选择、匹配序列数、陈旧序列数和部分失败状态。
- “最新值”表格占满内容宽度。
- “历史趋势”位于表格下方，不再与最新值表格并排放在两个卡片中。
- “指标浏览 / 告警规则”使用紧凑分段控件，不嵌套第二组大型标题 Tab。
- 告警规则表格、规则编辑抽屉和评估记录抽屉继续使用现有 API。

加载失败时保留上次成功数据，并在对应区域显示错误和重试入口。单个序列失败不得清空其他可用序列。

## 主机工作台

### 页面结构

主机工作台包含两个标题 Tab：

- 主机列表。
- 在线会话。

SSH 终端是主机列表中的“连接”动作，不再是独立页面或菜单。

### 统一主机行

前端构造 `HostWorkbenchRow`，每行最多包含：

- `monitor`：来自 `ListHostAgents` 的当前资源状态。
- `ssh`：来自 `ListHosts` 的 SSH 配置。
- `sessions`：按 SSH `host_id` 聚合的在线会话摘要。

Host Agent 和 SSH 主机没有共享主键。合并必须遵守以下规则：

1. 先按规范化后的 `monitor.agent_id` 与 `ssh.address` 精确匹配。
2. 仅当名称在两侧都唯一时，才允许按 `monitor.hostname` 与 `ssh.name` 精确匹配。
3. 不做模糊匹配、子串匹配或 DNS 反查。
4. 无法确定关系时保留两行，宁可显示未关联状态，也不错误合并主机。

资源侧独有的主机显示“未配置 SSH”，提供“配置 SSH”动作并用 agent ID 和 hostname 预填表单。SSH 侧独有的主机显示“未接入监控”，仍允许连接、编辑和删除。

### 主机列表与详情

主机列表采用紧凑表格或列表，不继续同时保留一套独立资源卡墙和一套 SSH 表格。每行展示：

- 主机名和地址。
- 在线、离线或错误状态。
- CPU、内存和最大文件系统使用率摘要。
- SSH 用户和端口。
- 在线会话数。
- 最后上报时间。
- 查看、连接、编辑和删除操作。

选择“查看”后，在同一页面展示资源详情：资源趋势、文件系统、磁盘 I/O 和网络接口。历史范围保留 1 小时、24 小时和 3 天。

资源 API 失败时保留 SSH 主机管理能力。SSH API 失败时保留资源监控能力。页面分别标记降级来源，不能因为一个接口失败而清空另一个接口的数据。

### SSH 终端弹窗

把现有终端逻辑拆为可复用的终端工作区组件。主机工作台点击“连接”后：

1. 以所选 SSH `host_id` 创建会话。
2. 打开宽度不超过 `92vw`、高度不超过 `84vh` 的终端弹窗。
3. 保留现有多终端 Tab、重连、清屏、断开和文件管理能力。
4. 文件管理使用右侧抽屉，避免在终端弹窗上再叠加居中弹窗。
5. 关闭终端弹窗前，如果存在活动连接，明确提示关闭将断开连接。
6. 确认关闭后断开当前弹窗创建的会话并释放 WebSocket、xterm、FitAddon 和 ResizeObserver。

创建会话或 WebSocket 连接失败时，弹窗保留错误状态和重试按钮，不生成空白终端。

### 在线会话

在线会话作为工作台第二个 Tab，保留自动刷新和强制断开。表格增加主机筛选，并支持从会话行返回对应主机或打开该主机详情。

## 数据视图浏览页

目标页面为 `/#/collector/views?tab=browse`，改动同时作用于复用 `ViewBrowse` 的其他入口。

### 删除冗余信息

- 删除页面头部“刷新”按钮。
- 删除页面头部“重新查询”按钮。
- 删除“已加载 xx 条”状态文本。
- 保留筛选区中的“查询”和“清空”。
- 保留分页器和预览窗口提示，因为它们描述查询边界，而不是重复展示行数。

页面首次进入、空间变化和视图变化时自动加载必要元数据与数据。用户修改筛选条件后，通过“查询”执行请求。

### 构建时间

状态行按以下顺序展示：数据集、视图类型、构建状态、活跃版本和构建时间。

“当前视图构建完成时间”只能来自当前活跃索引的构建记录：

1. `active_index_id` 存在。
2. `index_build.index_id === active_index_id`。
3. `index_build.finished_at` 存在且可解析。

满足条件时显示“构建完成于 YYYY-MM-DD HH:mm:ss”。当前有构建任务但尚未完成时，显示“构建中 · 开始于 ...”。活跃索引与返回的构建记录不一致时显示“构建时间未知”，不得用 `view.updated_at` 冒充构建时间。

## 服务监控滚动与表格

### 页面滚动

服务管理外层占满主内容区域，并将纵向滚动交给当前 Tab 的 `moox-page`。所有 flex 中间层设置 `min-height: 0`。不依赖 `body` 滚动，因为全局样式明确禁用了 `body` 滚动。

可用性监控主页面必须能滚动到探测表格底部和分页器。页面摘要、异常列表和筛选栏不能通过固定高度挤压表格。

### 主表格

- 表格使用视口相关的纵向高度和固定表头。
- 固定“名称”左列和“操作”右列。
- 将“运行、详情、告警、编辑、删除”收敛为一个主要动作和更多操作菜单，减少操作列宽度。
- 目标、错误和标识字段使用省略和 Tooltip。
- 分页器始终位于可滚动页面内，不覆盖表格内容。

### 详情抽屉

详情抽屉保留“结果、告警、实例”三个 Tab。抽屉内容使用显式的 flex 高度链：

- 抽屉 body `min-height: 0`。
- Tab 容器占满剩余高度。
- 每个 Tab pane 独立纵向滚动。
- 描述信息保持在表格上方。

结果表格继续展示最近 30 条，告警表格继续展示本探测项的事件。两张表都使用固定表头、最大纵向高度和水平滚动。实例表格补齐水平滚动。空状态显示在表格区域内，不拉伸抽屉。

## 组件边界

实施必须形成以下前端边界：

- `views/ops/services/index.vue`：服务管理路由和标题 Tab。
- `views/ops/hosts/index.vue`：主机工作台路由和标题 Tab。
- `views/ops/hosts/host-list.vue`：统一主机列表和详情编排。
- `views/ops/hosts/host-workbench-mapping.ts`：纯函数合并 Host Agent、SSH 主机和会话。
- `views/container/ssh-terminal/terminal-workspace.vue`：可复用终端主体。
- 现有服务部署、服务监控、应用指标、资源监控、SSH 主机和会话组件改为工作台子组件。

工作台组件只负责组合和路由。API 调用、数据映射、终端生命周期和具体表格各自保留清晰边界。

## 状态与错误处理

- 路由 Tab 非法：回落到默认 Tab 并规范化 URL。
- 服务部署 API 失败：仅服务部署 Tab 显示错误。
- Monitor 不可用：服务部署仍可编辑；服务监控和应用指标各自显示错误。
- 主机资源 API 失败：保留 SSH 主机与会话。
- SSH API 失败：保留资源监控数据，禁用连接和 SSH 编辑动作。
- 视图构建时间缺失或不匹配：显示“构建时间未知”，不推断时间。
- 终端连接失败：显示可重试错误，不留下不可操作的空白画布。

## 响应式与可访问性

- 在 1440x900、1280x720 和 390x844 视口验证所有工作台。
- 标题 Tab 和筛选栏在窄屏允许换行，但不能横向挤出页面。
- 图标按钮必须有 Tooltip 和 `aria-label`。
- 主机选择、终端 Tab 和表格操作必须支持键盘焦点。
- 终端弹窗打开后焦点进入终端区域，关闭后返回触发按钮。
- 状态不能只靠颜色表达，必须同时显示文本。
- 表格固定列不能遮挡内容或分页器。

## 发布验收

前端生产构建通过后，重新生成 `web-host` 内嵌静态资源并运行 `go test -count=1 ./web-host/...`。按现有 MooX 发布流程部署 `web-host`，再在实际管理台验证：

- 新菜单结构和新路由生效。
- 旧入口正确跳转。
- 服务管理和主机工作台调用真实 Admin Gateway。
- 服务监控页面与详情抽屉可以滚动到底。
- SSH WebSocket 通过统一网关建立和关闭。

## 风险控制

- **错误合并主机：** 只使用确定性规则；歧义数据保持分离。
- **工作台嵌套导致再次失去滚动：** 每层 flex 容器显式设置 `min-height: 0`，由单一 `moox-page` 承担滚动。
- **应用指标高基数拖慢页面：** 保留当前 50 条展示上限和 10 条趋势上限。
- **终端弹窗资源泄漏：** 统一在组件卸载路径关闭 WebSocket、会话和观察器。
- **服务合并扩大为后端重构：** 三个服务 Tab 只共享入口和视觉规范，继续使用各自现有 API。
