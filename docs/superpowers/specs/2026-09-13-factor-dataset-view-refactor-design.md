# 基础数据、复合因子数据集与单数据集 View 重构设计

日期：2026-09-13

状态：讨论结论整理，作为后续实施计划的设计基线；本文不表示功能已经实现。

## 1. 目标与约束

本次重构统一数据采集、数据构造、因子计算和查询索引的职责，支持外网控制面与内网计算引擎独立部署。

- 全新未上线系统，不保留旧协议、旧数据和旧架构兼容层。
- 基础历史数据在完成后不再修改，不实现历史修正传播和自动重算。
- 重复投递、任务重试、进程重启仍须正确处理；历史不变不等于消息只投递一次。
- 默认多源合并只支持相同对象、相同周期的横向字段合并。
- 每个 View 只关联一个 Dataset，一个 Dataset 可以拥有多个 View。
- 时序计算不依赖 View，不等待其他对象；截面计算等待完整周期输入。
- 因子输出写回复合因子 Dataset，View 自动维护对应索引。
- 本文中的新增字段、事件名称为目标协议命名，不能视作当前代码已有能力。

## 2. 对旧方案的替代

本文替代此前讨论中的以下设计，后续计划应以本文为准：

| 旧设计 | 新设计 |
|---|---|
| 时序消费 ViewSourceSubjectReady | 时序消费 Storage 发布的复合 Dataset 变更 |
| 时序历史窗口读取源 View | 读取复合 Dataset 的 Primary 时序数据 |
| View 聚合多个 Dataset | Merge 构造复合 Dataset，View 仅维护单 Dataset 索引 |
| 缓存跟随 View schema/revision | 缓存跟随 Dataset schema 与输入契约 |
| 因子输出单独组织为另一结果 Dataset | 基础输入与因子输出分字段写入同一 mdataset |
| 独立数据资产入口 | 基础数据管理归入数据采集，派生数据归属对应业务模块 |

不再为时序计算建设 ViewSourceSubjectReady 的发布、重建补发和消费链路。ViewSourcePeriodReady 保留源输入可读语义，不能再承担多 Dataset 聚合职责。

## 3. 整体架构

```text
外网控制面
  数据采集：数据源 / 采集对象 / 基础字段 / 采集任务 / 基础 Dataset
  因子计算：因子定义 / mdataset 构造配置 / 因子绑定 / View / 运行状态
          |
          | 配置快照、配置变更、计算任务
          v
Collector --> 基础 Dataset（Storage Primary）
                       |
                       | DatasetRowsUpserted
                       v
              独立 Merge 程序或用户程序
                       |
                       | 提交完整基础输入
                       v
               mdataset（Storage Primary）
                   |                  |
          Storage 行变更          View 自动维护索引
                   |                  |
          时序因子引擎         ViewSourcePeriodReady
                   |                  |
                   |             截面因子引擎
                   |                  |
                   +------ 写回因子字段 ------+
                                          |
                          mdataset --> View 应用结果
                                          |
                               结果可读事件 --> 策略
```

Merge 与因子引擎是独立程序，可以部署在同一内网机器，但必须能够独立启停。Storage 与 View 负责持久化和查询，不执行用户因子算法。

## 4. 数据模型

### 4.1 基础 Dataset

基础 Dataset 保存采集得到的基础事实。数据源、对象集、字段定义和采集规则由数据采集模块管理。

基础数据的历史不可变假设以“完整基础记录已确认”为边界。首次采集尚未完成不能被当成一条永久完整记录；无效输入和不完整输入不得进入可计算状态。

### 4.2 复合因子 Dataset

使用 `mdataset_` 前缀作为命名约定，但是否执行系统 Merge 由显式配置决定，不能由名称推断。

复合 Dataset 仍使用 Storage 现有 Dataset 存储能力，不引入另一套底层数据库。其业务定义包含：

| 配置 | 含义 |
|---|---|
| dataset_id | Storage 中唯一的数据集标识 |
| object_set | 目标对象集 |
| frequency / key_contract | 频率、周期边界及业务行键约定 |
| source_datasets | 关联的基础 Dataset，可以有多个 |
| merge_mode | system 或 custom |
| source_field_mapping | 源字段到目标基础字段的确定性映射 |
| required_sources | 每行必须到齐的数据源；第一版默认所有关联源均必需 |
| input_contract_version | 输入来源、键规则及基础字段语义的版本 |
| factor_bindings | 应用于该 Dataset 的因子绑定集合 |
| default_view | 自动创建的默认查询索引 |

字段分为公共行键、基础输入字段、因子输出字段及受系统管理的输入状态。实际字段类型和 schema 以 Storage 元数据为权威；控制面保存构造及计算配置，通过 Storage 接口管理实际 schema，不复制第二份独立权威 schema。

公共行键建议为 `subject_id + frequency + period_time + series_tag`，具体编码统一使用 Storage 的时序键协议。“数据 ID”指这个业务行键，不是 NATS 消息 ID。

基础字段统一映射为 `<源DatasetID>__<字段名>`。公共键不加前缀。创建配置时验证字段名合法性、长度及冲突，不允许运行时截断后发生重名。

### 4.3 因子定义与绑定

因子定义描述算法，包括因子 ID、版本、代码、类型、输入要求、参数规则、lookback 和输出类型。

`factor_type = timeseries | cross_section` 存储在因子定义中，由引擎读取并分派；不在 Python 函数签名中再声明一份类型。

因子绑定描述定义版本、参数、输入字段映射、输出字段映射及启用状态。一个算法可以绑定多个 mdataset，或以不同参数产生不同输出列。

同一输出列只能有一个有效绑定写入。第一版禁止因子输出作为其他因子的输入，不实现因子依赖图，避免计算循环和隐含执行顺序。

### 4.4 View

View 是所属 Dataset 的物化子索引，只包含：

- 唯一的 dataset_id。
- 字段投影。
- 对象或数据范围过滤。
- 排序、物理索引与保留范围配置。

View 不进行多源 JOIN、字段加工或数据聚合。一个 Dataset 可有多个 View，用于不同的字段集合、对象范围及查询保留范围。

创建 mdataset 时自动创建默认完整 View；用户可另外创建子集 View。默认完整指逻辑字段和对象范围完整，实际历史保留范围仍按 View 配置执行。

## 5. Merge 构造程序

### 5.1 默认构造规则

系统 Merge 消费配置中的基础 Dataset 行变更，将同一业务行键的数据横向聚合。第一版要求相同频率、相同周期边界和一致的对象标识，不隐式重采样、前向填充或进行近邻时间匹配。

处理步骤：

1. 校验源 Dataset、业务键、必需字段与输入契约。
2. 记录该行已到达的数据源及输入内容，等待状态必须持久化或能够从可靠日志恢复。
3. 同一对象、同一周期的所有必需源到齐后，一次提交完整基础字段及系统输入就绪状态。
4. Storage 提交成功后产生可重放的变更事件。
5. Merge 确认该行构造成功，推进周期构造状态。

不向 mdataset 写入可计算的半成品行。超时缺失记录保存在构造任务状态中，不能通过写入空值占位行冒充成功。

输入就绪状态必须与基础字段一起提交，且由受授权的构造程序设置。`input_ready` 是逻辑状态名称，实施时可以用系统元数据表示，不要求暴露成普通用户字段。

### 5.2 对象集与周期终态

每个周期固定 mdataset 的预期对象集和构造配置版本，不能随着源事件到达动态缩小名单。默认使用 mdataset 配置的对象集，而不是成功数据的交集。

每个预期对象最终为成功或缺失终态。截止时间到达后，将剩余等待项记录为缺失，该周期为 degraded；全部成功才为 complete。

原始 Dataset 的采集完成不能代替 mdataset 构造完成。基础周期终态用于帮助 Merge 判断输入来源是否结束，Merge 必须确认自身写入和所有预期对象的构造状态。

默认在周期终态固定后不自动接纳迟到输入改变该周期结果；需要恢复时走显式补算任务。这样不会把“历史不变”变成隐含的迟到数据重算系统。

### 5.3 自定义构造

`merge_mode=custom` 时系统 Merge 不写该 mdataset，由用户程序完成加工。用户程序必须遵守业务键、字段归属、完整输入提交、幂等及周期终态报告协议，否则只能提供数据，不能承诺系统截面和策略就绪通知。

## 6. 因子计算引擎

### 6.1 时序计算

引擎仅订阅被有效绑定引用的 mdataset 变更，不订阅所有基础 Dataset，也不依赖源 View。

1. 验证事件属于基础输入提交且该行输入已就绪。
2. 按输入契约、频率及计算窗口进行短窗口微批。
3. 读取本地缓存，缺失部分批量回源读取 mdataset Primary。
4. 按对象形成截至当前周期的历史窗口，不读取未来数据。
5. 运行时序因子，将结果作为字段级更新写回同一 mdataset。
6. 保存任务终态，供周期汇总使用。

微批只等待短时间聚合，不等待对象集全部到齐。历史数据不足时按定义的最小样本要求返回明确跳过或失败状态，不以零或前向填充伪造输入。

### 6.2 同 Dataset 回写防循环

基础字段只允许 Merge 或授权用户构造程序写入，因子绑定只允许写自己的输出列。必须使用字段级更新，不能因子回写时覆盖基础字段或其他因子列。

变更事件必须包含可验证的变更字段和写入类别等信息，引擎只接受完整基础输入提交。因子输出变化不能再次启动时序任务；不能仅凭普通客户端可任意填写的来源字符串防循环。

同一源提交的重复消息形成相同任务身份。任务身份包含 Dataset、业务键、输入契约、绑定版本等信息；处理完成后重投不重复生效。补算使用独立任务身份和明确输出版本，不能让旧任务覆盖新绑定结果。

### 6.3 截面计算

截面绑定指定 mdataset 下的一个源 View，该 View 必须包含算法所需基础字段和明确的对象范围。不同过滤范围的 View 表示不同截面对象集，不得因删除行或增加过滤条件而静默改变已有计算批次。

截面引擎消费 ViewSourcePeriodReady，读取固定周期、固定输入契约的面板，再写回所属 mdataset 的因子输出列。

默认仅 complete 输入周期允许计算。允许剔除缺失对象等降级方式必须在因子定义或受校验的绑定策略中显式声明，不能默认以残缺全集计算。

### 6.4 Python 契约

两类因子统一使用：

```python
def compute(df, params, context):
    ...
```

- df：时序为单对象历史窗口；截面为同周期对象面板。
- params：绑定参数。
- context：只读执行上下文，例如目标周期、输入契约和任务标识，不重复定义 factor_type。

输入字段通过绑定映射，使算法无需硬编码源 Dataset 前缀。输出按定义声明的字段与类型校验；时序写当前对象当前周期，截面输出必须携带唯一对象键，禁止写出绑定对象集之外的行。

## 7. 事件与完成屏障

以下区分业务完成与数据可读，禁止只因收到一个周期标记就推断整个链路完成。

| 事件或逻辑状态 | 责任方 | 含义 |
|---|---|---|
| DatasetRowsUpserted | Storage | 数据或字段更新已提交，包含可靠变更身份 |
| DatasetPeriodCollected | Collector 经 Storage 可靠发布 | 基础 Dataset 的冻结采集集合已终态 |
| 复合输入周期完成标记 | Merge 经 Storage 可靠发布 | mdataset 预期对象的构造已全部终态 |
| ViewSourcePeriodReady | View 模块 | 所属 Dataset 的本周期输入已按该 View 范围应用并可读 |
| FactorPeriodComputed | 引擎汇总后经 Storage 可靠发布 | 固定绑定集合及对象集合的计算任务已全部终态 |
| ViewFactorPeriodReady | View 模块 | 目标因子结果写入已在对应 View 应用，可以提供查询 |

View 不再聚合 N 个 Dataset 的完成标记，只验证其唯一所属 Dataset 的输入或结果提交位置。底层即使代码位于 Storage 模块，View 就绪事件的业务发布责任仍属于 View。

周期标记必须携带稳定批次身份、配置版本、预期对象集引用、失败集合和足以证明提交应用完成的写入位置。跨分区或数据节点时不能用某一个队列的顺序代表全部数据；应等待所有相关提交位置应用完成。

时序可以早于复合输入周期标记执行。周期汇总持久化收集早到的任务结果，随后用固定名单判断是否全部终态，不能以“当前收到的任务都完成”代替全集完成。

输入和输出屏障必须独立：截面因子等待输入屏障，策略等待指定绑定结果的输出屏障。禁止让输入屏障等待截面结果，造成环形等待。

同一 Dataset 下的多个 View 独立确认可读。仅基础字段的 View 不发布声称因子列可读的结果通知。所有 Ready 事件保留 complete/degraded 区别，策略显式决定是否接受降级结果。

## 8. 本地 DuckDB 缓存

### 8.1 内容与有效性

缓存是可丢弃的读优化，不是第二份数据权威。由 mdataset schema 创建结构，不扫描因子依赖临时拼表，不在线 ALTER。

缓存可保留完整 Dataset 列结构，但命中判断和数据复用仅针对已就绪的基础字段；因子输出列不作为计算输入，不依赖缓存中的输出列值。回源读取完整基础输入投影，避免部分字段被误判为完整缓存。

Dataset schema 或输入契约变化时，旧缓存代际失效，新建对应结构的空 DuckDB，不主动回填。新增因子若新增输出列导致 Dataset schema 变化，也走同一代际替换规则。

历史不变后无需历史修正序列和自动失效传播；仍需验证业务键、输入就绪状态及契约。缓存缺少历史窗口时回源，不能仅以总行数证明窗口完整；确认源不存在的数据不能无限重试。

### 8.2 容量与重建

- 使用 tRPC timer，默认 `check_interval = 2233s`，即 37 分 13 秒，首次检查延后一个周期。
- 采用非整周期减少固定对齐，但不能保证永不与采集重合；单次维护禁止重入，可额外使用启动错峰。
- 配置缓存目录总容量上限和保留行数 N；N 表示每个受维护缓存代际最多保留的行数。
- 超限时按缓存行的本地最后写入/更新时间降序保留最近 N 行，相同时间按业务键稳定排序。读取不更新此时间。
- 在新数据库文件中重建，而不是仅在旧文件内 DROP TABLE；切换后等待旧读者退出，再关闭并删除旧文件。
- 重建期间进入旧代际的新增缓存数据允许丢弃，后续回源补齐；不得影响真实 Storage 写入或计算结果。
- 总容量计算包含活动文件、退役文件、WAL 和临时文件。逐个重建、复查目录总量，不能给每个 Dataset 都重复分配整个总预算。

定时检查是软容量控制，不是严格磁盘硬上限。必须预留新旧文件并存空间；空间不足时停止缓存填充、退化为回源并报警。固定 N 不保证字节数一定小于限制，重建后仍超限时应继续释放缓存或停用填充，不允许无限重建。

## 9. 控制面、任务与部署

控制面 moox-factor 管理因子定义、mdataset 构造配置、因子绑定、补算受理及状态查询；Storage 元数据管理实际 Dataset/View schema。配置变更通过版本化快照和可靠通知同步，通知丢失可通过快照恢复。

内网 moox-factor-engine 负责消费、缓存、Python 执行和结果回写；Merge 使用独立程序入口。控制面不启动本地实时消费者或 Python 计算进程，也不需要主动连接内网引擎。

内网程序出站访问授权的 EventBus 和 Storage。控制面、Merge、Factor 的凭据权限分别限制到管理、基础字段写入、因子字段写入，不能共用无限制写权限。

实时消费者恢复已有 durable 的未处理消息，不能每次启动都重新 DeliverNew 丢弃积压。首次建立消费者的起点必须与启用周期一致；启用前历史只通过显式 Recalc。补算由控制面提交任务，引擎执行，不在控制面本机计算。

第一版单实例 Merge 和单实例因子引擎，内部受控并发与微批。后续时序可按对象分片；截面任务必须读取完整目标面板，由一个任务所有者协调，不能各分片独立计算局部截面并当作全集结果。

## 10. 前端信息架构

取消独立“数据资产”入口，按基础与派生数据归属迁移，不将所有历史资产不加区分地搬入数据采集。

| 一级模块 | 页面 |
|---|---|
| 数据采集 | 数据源、采集对象及对象集、基础字段管理、采集任务、基础数据集 |
| 因子计算 | 因子定义、复合因子数据集、构造配置及状态、因子绑定、计算任务及补算 |
| 策略管理 | 策略定义、策略运行及策略加工结果 |

View 作为数据集详情中的“索引”页签管理，可创建多个不同投影和过滤范围的索引。数据浏览使用所选 View，不再把 View 表现为多数据集聚合工具。

基础字段仅展示在数据采集字段管理中；因子输出字段在因子数据集及绑定配置中管理。底层共用 Storage 能力，前端按数据产生阶段组织。

## 11. 故障语义与可观测性

- Merge 重启：恢复未完成对象的源到达状态，重复源事件不重复产生有效输入。
- Storage 写成功但响应丢失：使用稳定提交身份重试，不能产生新的计算批次。
- 因子引擎重启：恢复 durable 和任务账本，已完成输出幂等确认，未完成任务继续执行。
- View 重建：不触发时序重算；源输入/结果 Ready 必须等活动索引真实可读，不能由回填写入冒充。
- View 过滤或输入契约变化：新计算批次使用新配置身份，旧批次不静默套用新对象集。
- 超时和失败：明确区分缺源、缺历史、算法失败、写入失败、View 未追平，不统一显示为成功 Ready。

监控至少包含 Merge 待聚合对象数、缺源集合、构造耗时、时序触发延迟、截面等待耗时、任务成功/失败/跳过数、View 应用滞后、缓存命中率、回源量、目录字节数和缓存重建失败。

## 12. 后续实施拆分与验收

实施应按以下顺序形成独立任务，不将本文当作已经执行的清单：

1. 数据模型及 Storage 协议：单 Dataset View、字段归属、输入提交和可读屏障。
2. 基础数据前端归并及元数据入口调整。
3. mdataset 构造配置、系统 Merge、对象周期账本及自定义协议。
4. 控制面与计算引擎拆分、统一 Python 契约和 Dataset 驱动时序计算。
5. 缓存读路径、容量维护、截面输入屏障与结果完成汇总。
6. 默认 View 自动创建、策略结果通知及实际部署验证。

关键验收场景：

- 同对象两源先后到达，仅到齐后发布可计算输入；其他对象缺失不阻塞该对象时序计算。
- 缺源超时不产生残缺输入行，周期明确 degraded；迟到不静默改写已终态批次。
- 同一 Dataset 多个 View 的字段和对象过滤独立生效，不支持多 Dataset JOIN。
- 因子回写不触发自身，两个因子并发写不同列不互相覆盖。
- 消息重投、写入响应丢失、Merge/引擎重启不会漏任务或重复生效。
- 截面只在目标输入面板可读后开始，策略只在指定因子结果可读后开始。
- View 重建不影响时序计算，重建后的 Ready 不绕过真实数据应用进度。
- schema 变化新建空缓存，容量重建不在线 ALTER，缓存完全删除后计算仍可回源完成。
- 外网控制面与内网 Merge/引擎独立部署，正式验收区分单测、模拟事件和真实新周期计算。

完成设计文档不代表实施完成。后续编码、独立代码审查、部署和真实数据验证需要另外执行并提供证据。
