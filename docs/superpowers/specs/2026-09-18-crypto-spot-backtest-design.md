# 加密现货历史回测第一版设计

日期：2026-09-18。状态：讨论结论整理，尚未实现。本文件不授权编码、部署、服务启停或交易。

## 1. 目标与能力边界

支持用户把一个新策略、新因子参数应用到过去的行情，重新计算目标组合，模拟成交并检查收益、风险和执行过程。定位是个人量化本地工具，不是通用研究平台。

| 能力 | 输入与目的 | 时间语义 |
| --- | --- | --- |
| 决策重放 | 已录制输入与前态，复现当时的策略计算 | 实际记录的时间 |
| 录制决策成交模拟 | 已录制目标与历史行情，研究执行假设 | 不早于实际 evaluated_at |
| Paper 模拟交易 | 在线行情与正在运行的策略，验证运行链路 | 当前真实时间 |
| 本文历史回测 | 新策略、参数和冻结行情，重新计算过去的决策 | 明确的 Bar 事件顺序与零计算延迟假设 |

原执行计划 C 是第二种能力，不等于本文回测，也不是回测的强制前置。复用其数据导出、独立账户、校验与记账设计，不依赖在线决策工件或完整交付 C。A 的数量规则收敛有直接价值；B 工件可用于诊断，但不是历史数据入口。

## 2. 第一版范围

- Crypto SPOT，单交易所、单账户、USDT 计价；候选标的必须为 USDT 报价，禁止隐式汇率转换。
- 多币组合，只做多、无杠杆、无借币；FULL 目标继续表达完整组合，空目标表示归零。
- 一次运行使用统一 Bar 频率、UTC 24x7、固定候选池和固定交易规则快照。
- 仅 MARKET 整单成交；固定非负手续费率、固定不利 BPS 滑点，手续费统一计入 USDT。
- 本地 CLI，单线程业务事件推进，独立运行目录与 SQLite；不增加服务、管理台、远程调度或持久化任务队列。
- 不做参数寻优、复杂撮合、部分成交、盘口容量、动态历史全市场、断点续跑及策略自动上线。

## 3. 固定候选池不是历史全市场

配置必须显式使用 `universe_mode=fixed_candidates`，展开保存完整候选名单，不能只记录可变的列表名称。

固定的是候选范围，不是持仓。策略可以依据当时可见的因子在候选池内筛选、排名和调仓。第一版不运行依赖当前交易所目录、实时接口或任意外部 UDF 的动态候选池解析。

报告首页与运行摘要必须显示：

> 标的池口径：固定候选池，非历史全市场。本次回测仅在所列币种内进行策略筛选，不还原历史上市、退市及全市场成员变化。候选池选择可能引入幸存者偏差或选择偏差；结果仅反映该候选池和所声明模拟假设下的历史表现。

候选币种必须覆盖正式区间和所需预热区间。缺数据时拒绝启动，不静默删除币种、缩短区间、补零或前向填充。用户可以显式修改名单和范围后重新运行；这会产生不同的运行输入指纹。

固定交易规则包括价格 tick、数量 step、最小量/名义金额等，只代表本次模拟使用的规则，不宣称还原历史规则。未来历史动态池必须使用独立模式，不改变 fixed_candidates 的含义。

## 4. 输入冻结与数据时间

输入由运行配置、策略 DSL、因子代码与参数、候选名单、OHLCV、交易规则构成。数据文件先复制到新运行目录并核对 SHA-256，随后只读使用；并发修订导致校验不一致就失败。运行期间禁止自动联网补数据。

逐标的检查时间键、频率、重复、覆盖范围、必需列、有限数值、正价格、非负成交量及 OHLC 大小关系。统一半开区间定义，不能仅检查 min/max 代替完整覆盖。

历史行情标记 `data_semantics=latest_materialized_snapshot`（如来源如此）；冻结快照保证可重复，不等于历史 as-of。禁止未来数据进入计算是执行保证，历史修订和候选池偏差则是来源限制，报告分别说明。

正式区间 `[start,end)` 表示交易与估值运行窗口。start 必须是 Bar 边界。start 的决策可使用在 start 刚刚闭合的预热末根 Bar；最后在 end 只处理末根收盘和期末估值，不产生新的策略订单，也不加载 end 开盘强行成交。

## 5. 因子与预热

复用现有因子计算实现，不复制公式，不把当前在线 Factor View 当作历史答案。第一版只支持白名单因子：只依赖已冻结 OHLCV及已支持因子输出、窗口明确、无外部 I/O，并通过时间因果性测试。

依赖图计算所需预热，无法推导的窗口必须由因子声明；循环依赖、不支持的输入或数据不足启动失败。无限历史敏感的指标必须有明确初始化与成熟标准，否则不进入白名单。不得凭空宣称已有全部因子可离线运行。

预热仅建立指标状态，不运行交易，不建立 Strategy holding/signals 前态，不计收益。start 时以初始 USDT 现金、空仓、空订单、空 Strategy RuleState 开始。正式每个周期沿用上次求值后态；指标预热不等于恢复实盘状态。

第一版按历史前缀/明确窗口计算。只给因子当前时间可见的输入，不能把整段未来数据交给任意代码再靠约定过滤。允许后续对已验证因果性的因子优化，但不得更改结果。

## 6. 模块边界与装配

```text
Archive 本地冻结导出
    -> Factor 离线计算（预热与各时点输出）
    -> Strategy 历史输入装配 + 现有 selection.Evaluate
    -> 完整目标事件文件
    -> Trade 离线事件推进 + Paper/Reducer
    -> 独立账户事实与报告
```

当前 Strategy 理论状态不依赖实际成交，允许先生成完整目标序列再执行模拟。两段运行必须保留每条决策的历史事件键，不得提前向 Trade 暴露未来目标。

每个模块的 CLI 只调用自己的 internal 包，跨模块通过版本化文件衔接；共享格式仅保存 DTO/校验，不建立共享交易引擎。一次运行目录容纳所有步骤，中间产物与源输入一起留档。统一顶层 CLI 的具体接线在实施计划中依据现有命令边界确定，不承诺尚不存在的命令。

源码依据与需要改造的边界：

| 现有入口 | 复用或改造要求 |
| --- | --- |
| modules/strategy/internal/selection/evaluator.go:Evaluate | 复用计算与 RuleState，不复制选择算法 |
| modules/strategy/internal/trigger/processor.go:marshalTargetEvent | 目标文件保留完整身份、时间和 FULL 语义，离线新建 session，不伪装成真实在线事件 |
| modules/factor/internal/taskrunner/read_pipeline.go | 是在线读取边界参考，不代表已经有离线 Runner；需在实施前确认纯计算接口与首批白名单 |
| modules/trade/internal/application/target/executor.go:Converge/laneIDs | 当前按标的 ID 排序、每次返回一个动作，已有开放订单会限制进一步收敛；不假设能同刻全组合成交 |
| modules/trade/internal/execution/paper/decider.go:Decide | 在线优先固化 PaperExecutionPrice，回测必须显式改用合资格 open |
| modules/trade/internal/execution/paper/matcher.go:MatchOrder | 复用事务、版本检查与 Reducer；不能直接修改余额制造成交 |

Trade 装配继续采用 store.Open、新 PAPER TradingAccount、PAUSED LogicalAccount、Member、Instrument、ClaimSession/AuthFence、权益采样后 ACTIVE 的正式链路。复用完整事件合同、owner/session、时效、receipt 幂等和 Store 最终检查，不使用裸 protobuf 或直接写目标表绕过验证。

## 7. 回测事件模型

本模式命名为 `bar_close_next_open_zero_latency`，与原 C 的 `recorded_time_strict_next_open` 分开，配置不可混用。

统一事件键为 `(timestamp, phase, stable_sequence)`。同一边界 t 严格按以下顺序：

1. CLOSE：所有标的旧 Bar 闭合，完整 H/L/C/V 才可见；刷新账户估值与权益。
2. DECIDE：使用截至 t 的因子、价格和前态求值，生成 FULL 目标并通过正式接受链；权重按此刻权益与收盘参考价换算数量。
3. SUBMIT：同步推进现有 Converge 的即时动作，不调用 Matcher。有开放订单、无动作、阻塞或达到进度上限即停止；上限触发标记运行失败，不默默截断。
4. OPEN：所有标的新 Bar 只发布 open；冻结本次可撮合订单集合，按稳定顺序撮合一次。
5. SETTLE：Reducer 记账、刷新权益，并允许有限的后续执行推进；此阶段新产生的订单不能参加本次 OPEN，最早参加下一次 OPEN。

资格由实际模拟提交事件键决定，而非仅 `SubmittedAt < open_timestamp`。DECIDE/SUBMIT 在 t 创建且实际提交的订单可参加同 t 后续 OPEN；仅有 target 意图而未提交的订单不能参加。真实录制决策模式仍按真实 evaluated_at 及严格后续 open，不套用零延迟。

开盘与收盘投影分离；底层事件源虽保存整行 OHLCV，因子、WeightResolver、估值服务不能直接读取未来字段。不能给旧价格重新盖 SourceTime 绕过 freshness。

计算、提交耗时假定为零，无网络延迟、点差或市场冲击。报告必须显著声明：下一开盘成交是模型假设，不是交易所成交保证。

## 8. 数量、资金与多币调仓

目标数量以决策阶段的权益与已知参考价确定，并遵守精度、最小量和名义金额。跳空不能用未来开盘价倒推重写已提交订单数量；实际权重偏差保留到后续决策。

不另建“同时把所有币调到目标权重”的理想组合账本。第一版保留 Trade 当前标的排序、开放订单约束、资金预留与目标替换逻辑，不宣称全局先卖后买。因而组合轮动可能跨多个 Bar，报告必须显示串行执行限制、未达目标与阻塞原因。

卖出释放的资金经真实 Reducer 记账后才可用。OPEN 后据此生成的买单只能等下一次 OPEN；禁止同一开盘无限循环卖出、释放资金、买入、再成交。若以后希望改变全局卖出优先级，应作为 Trade 的独立行为变更，同时评估在线影响，不在回测包中偷偷重写调仓策略。

完整目标事件保持 effective_at=bar_end。第一版复用线上有效期规则：AdvanceBarEnd 推进 strategyResultValidityBars（当前为 4），再由 tightenValidUntil 按求值后 RuleState 收紧；抽取同一纯函数，不复制一套规则，也不新增回测自定义有效期参数。manifest 记录实际采用的版本与 Bar 数。valid_until 必须大于 effective_at；接受和每次提交按模拟时钟校验。已提交订单不因目标到期被回测擅自撤销，遵守现有执行合同。目标更新不等于所有旧单自动成交或消失。

成交价格为 open 施加一次不利滑点，买入上浮、卖出下调；费率按成交名义额收取 USDT。手续费和滑点参数冻结，禁止负费率或使卖价非正的滑点。无真实盘口，Bid=Ask=Last=open 是模拟投影。

复用现有 Decider 的窄包装：符合事件资格后复制候选 OrderRecord，只清空副本 PaperExecutionPrice，再用当前 open 调生产 Decider；持久化订单不提前更改。保留既有费用、资金检查与 Matcher/Reducer。跳空资金不足按现有结果取消/阻塞，不透支，不自动部分成交。卖出手续费用卖出所得结算，现金、预留和成交账必须对得上。

## 9. 结束、报告与指标

end 时不强制清仓，不造最后收盘成交；按最后可用价格估值。分别展示现金、持仓市值、未成交订单、残余目标和费用。缺估值价不能当零；数据/估值契约破坏时运行标记失败。

输出包含 manifest.json、冻结配置与输入清单、因子/目标文件、独立 trade.db、orders/fills/equity 明细及 report.json。第一版不要求 Web 页面；权益曲线以带时间戳的数据序列交付。

指标口径：

- 总收益为期末权益/初始现金-1，无外部入金出金。
- 每个 CLOSE 与 SETTLE 留权益点；每日点取 UTC 日末最后有效估值，报告保留期末点。
- 最大回撤按这些采样点的历史权益峰值计算，并标明“不含 Bar 内未观测极值”。
- 换手采用累计成交名义额/同期平均每日权益，买卖均计入，明确是双边口径。
- 展示累计手续费、成交笔数、拒单/取消/阻塞、目标偏离和未成交；滑点成本为相对无滑点 open 的名义差额，不再从现金重复扣一次。
- 第一版少于 365 天不展示年化；达到门槛按实际时长计算 CAGR，非正权益不计算。不以年化作为表现保证。
- 暂不展示胜率和 Sharpe，避免成交笔、持仓批次、收益采样等口径不一致。
- 可选单币买入持有基准，使用同区间初始现金、首个可交易 open、相同费用/滑点与步长，留现金支付费用，期末同样不强制卖出；基准币必须在冻结覆盖范围内。

首页固定列出固定候选池、数据快照、指标预热/账户空仓启动、零延迟、整单无限容量、固定费用与交易规则、串行执行限制、非历史 as-of 等假设。失败运行保留诊断但不发布成功收益摘要。

## 10. 隔离与可重复性

必须指定全新输出目录，拒绝覆盖和任意生产数据库路径。只装配本地行情与 PAPER，不加载生产配置、凭据、NATS/Gateway 或在线服务 bootstrap。网络拒绝测试覆盖所有离线步骤，包括因子运行。

业务 Now 统一注入手动钟；真实网络超时与锁等待不使用历史钟。特别是 infra/store/target_receipt.go:acceptLogicalAccountTargetWithReceipt 和 infra/store/target.go:AcceptLogicalAccountTarget 当前直接使用 time.Now，两层事务校验必须改为共用受信任的本地业务钟。使用 Store/Tx 的实例级时钟注入，线上默认真实时间；不得从事件 payload 接受任意 now，不得删掉最终过期检查。仅给上层服务注入 Now 不足以运行历史目标。

从规范化配置、数据/代码版本构成的 run input hash 派生固定离线 space/account/instance/session 身份；源 message ID 由该 hash、bar 和事件序号派生，result/event/target ID 使用同一确定性生成链并保持合同中的相等关系。独立运行目录保证相同身份不与另一运行共享数据库。订单 ID 使用现有可注入入口和确定性序列，Paper 派生 ID 保持稳定；map、标的与事件排序确定。输出路径、运行开始墙钟不进入身份种子。随机策略/因子第一版不支持。

manifest 记录格式版本、完整输入 hash、代码/因子构建版本、dirty 状态、运行环境、模型参数和最终状态。只有输入、代码与求值环境一致才要求完全重现；耗时和本机路径不参与业务 hash。

## 11. 验收与实施前门槛

本次未运行业务测试，以下是未来实施必须证明的条件：

1. 同输入重复运行，规范化因子、目标、订单、成交与权益 hash 一致。
2. 修改时点 t 之后的行情，t 之前的因子、决策和成交不变；候选名单与配置固定比较。
3. 同时间 CLOSE/SUBMIT 订单可参加下一 OPEN，但 SETTLE 新单不得参加已冻结的 OPEN 集合。
4. 提交价 100、下一 open 110 时使用 110 加一次滑点，费用与资金守恒；无下一 open 时不成交。
5. 预热不足、缺 Bar、未知因子、实时 UDF、非法规则全部明确失败；不静默降级。
6. 多币轮动、全仓目标加手续费、跳空资金不足、旧目标替换与目标到期均通过真实 SQLite+Evaluator+Paper+Reducer 测试。
7. 固定候选池提示、行情修订限制、串行执行影响在配置留档和报告可见。
8. 阻断网络仍可完成合法运行；任何生产连接尝试使测试失败。
9. 历史 valid_until 在模拟窗口内通过真实 SQLite 接受链，边界时刻被拒绝；Store 两层检查时间一致，线上未注入时仍按真实时间拒绝旧目标。

实施计划必须先核验 Factor 纯计算接线及首批白名单、现有 Trade 多币执行与目标有效期，之后才给出确切改动文件和任务。不把“复用”当成已经存在的离线 API，不为支持全部因子扩建平台。若当前串行执行无法满足期望，应先说明实际影响并重新确认边界，而不是换一个理想化账本。
