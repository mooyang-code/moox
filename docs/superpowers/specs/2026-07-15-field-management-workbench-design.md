# 字段管理工作台优化设计

## 1. 背景与目标

MooX 的字段是 Space 内可复用的普通字段字典，通过两级 `FieldGroup` 组织，再由数据集列引用。当前 `#/data/fields` 已具备字段组目录、字段列表和基础新增编辑能力，但筛选、批量治理、上下文保持和编辑体验仍偏基础。

本次优化将页面建设为紧凑的元数据治理工作台，目标是：

- 让用户快速定位某个字段或某类字段。
- 支持批量移动字段组、启用和停用。
- 使用右侧抽屉完成字段新增和编辑，同时保留列表上下文。
- 明确并执行字段组最多两级的约束。
- 为加载、空数据、失败和窄屏场景提供完整反馈。

本次不引入字段版本管理、审批流、拖拽排序、跨 Space 移动、字段删除和跨页选择。

## 2. 已确认的产品决策

- 页面采用“左侧字段组目录 + 右侧紧凑表格”的双栏布局。
- 字段新增和编辑统一使用宽度约 `560px` 的右侧抽屉。
- 字段列表支持多选，并提供批量移动字段组、启用和停用。
- 字段组最多两级：一级分类和二级字段组。
- 字段 ID 是稳定英文标识，也是页面展示的英文名；不新增重复的 `english_name` 字段。
- 字段必须归属于字段组。`未分组字段`仅用于暴露历史或异常数据，不作为创建字段时的合法归属。
- 首期继续使用数值 `sort_order` 排序，不实现拖拽。

## 3. 页面信息架构

### 3.1 顶部区域

页面标题右侧显示当前 Space 的字段总数。工具栏从左到右包含：

1. 关键字搜索框：匹配字段 ID、中文名和描述。
2. 值类型筛选器。
3. 状态筛选器。
4. 刷新图标按钮。
5. `新建字段`主按钮。

所有筛选条件采用服务端查询。搜索输入防抖 `300ms`；筛选变化后回到第一页并清空已选字段。

### 3.2 左侧字段组目录

目录桌面宽度为 `240px`，包含：

- `全部字段`：显示当前 Space 的字段总数。
- `未分组字段`：仅在存在异常未归组记录时显示。
- 一级字段组：可展开和折叠，数量包含本组及其二级子组字段。
- 二级字段组：数量仅包含直接归属该组的字段。
- 底部 `新建字段组`入口。

选择一级组时，字段列表查询该组及所有二级子组；选择二级组时只查询该组。目录节点按 `sort_order`、`group_id` 依次排序。

节点悬停时显示更多菜单：

- 一级组：新增子组、编辑、删除。
- 二级组：编辑、删除。

删除字段组前由服务端检查子组和字段引用。非空字段组不能删除，页面展示服务端返回的具体原因。系统不提供级联删除。

### 3.3 字段表格

表格使用小尺寸、固定表头和横向滚动，列定义如下：

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 选择 | 多选框 | 仅选择当前页记录 |
| 字段 | 中文名 + 字段 ID | 中文名主行，字段 ID 次行 |
| 值类型 | 逻辑类型 | 使用统一类型文案 |
| 字段组 | 完整路径 | 例如 `行情数据 / K线行情` |
| 单位 | 默认计量单位 | 空值显示 `-` |
| 状态 | 启用或停用 | 使用低饱和状态标签 |
| 更新时间 | 最后更新时间 | 支持降序和升序 |
| 操作 | 编辑、更多 | 图标按钮带 Tooltip |

单击普通行区域打开编辑抽屉；单击复选框、链接或操作按钮不触发行编辑。表格默认按 `sort_order ASC, field_id ASC` 排序，用户选择更新时间排序时通过服务端排序。

分页默认每页 20 条，可选择 20、50、100。切页不保留选择。

## 4. 批量治理

选中字段后，常规筛选工具栏下方出现批量操作条，展示已选数量，并提供：

- `移动到字段组`
- `启用`
- `停用`
- `取消选择`

批量移动使用字段组级联选择器，只允许选择有效字段组。批量停用需要二次确认；批量启用和移动在用户确认目标后直接提交。服务端按单次请求事务处理：任一字段不存在、跨 Space 或目标字段组无效时，整批失败，不产生部分更新。

操作成功后重新查询当前页及字段组计数，并清空选择。操作失败时保留选择，方便用户修正后重试。

## 5. 字段编辑抽屉

新增和编辑共用一个表单组件，按以下区块组织：

### 5.1 基本信息

- 字段 ID：新增时填写，编辑时只读。
- 中文名。
- 描述。

### 5.2 数据定义

- 值类型。
- 单位。
- 校验规则 JSON。
- 写入示例。

校验规则在前端检查是否为合法 JSON，服务端继续执行最终校验。写入示例保持字符串表达，不在前端按值类型强制转换。

### 5.3 组织与管理

- 字段组：级联展示一级组和二级组，同时允许选择一级组，以兼容当前模型。
- 组内顺序。
- 状态。

抽屉底部固定显示`取消`和`保存`。保存期间按钮进入加载状态并禁止重复提交。表单存在修改时，关闭抽屉或切换 Space 必须二次确认；保存成功后关闭抽屉、刷新列表和字段组计数。

## 6. 字段组编辑

字段组新增和编辑继续使用轻量弹窗，避免与字段编辑抽屉叠加：

- 一级组不设置父组。
- 二级组必须选择一个一级父组。
- 二级组不提供新增子组入口。
- 编辑时 `group_id` 只读。
- 将一级组改为二级组或反向调整时，服务端仍需验证不会形成第三级或循环引用。

删除是独立确认操作，不放进编辑表单。删除成功后刷新目录和计数；如果当前选中组被删除，则回到`全部字段`。

## 7. URL 状态与响应式行为

页面将以下状态写入 hash route 的 query：

- `group`：当前字段组 ID，`all` 表示全部字段，`ungrouped` 表示异常未分组字段。
- `keyword`：搜索关键字。
- `value_type`：值类型。
- `status`：字段状态。
- `page`、`page_size`：分页。
- `sort`、`order`：排序字段和方向。

首次进入页面从 URL 恢复状态；无效字段组回退到全部字段并清理无效参数。切换 Space 时清空字段组、筛选、分页、选择和编辑状态，避免跨 Space 误操作。

宽度小于 `900px` 时，左侧目录收进可打开的侧栏；字段表格保持最小宽度并横向滚动。抽屉在窄屏使用 `min(560px, 100vw)`，字段名、按钮和分页不得互相遮挡。

## 8. 接口设计

### 8.1 字段列表查询

扩展 `ListFieldsReq`：

```protobuf
string status = 6;
string keyword = 7;
bool include_descendants = 8;
bool ungrouped_only = 9;
string sort_by = 10;    // sort_order、field_id、updated_at
string sort_order = 11; // asc、desc
```

约束：

- `keyword` 对 `field_id`、`name`、`description` 执行包含匹配。
- `include_descendants` 仅在 `group_id` 非空时生效。
- `ungrouped_only` 与 `group_id` 不能同时使用。
- `sort_by` 采用白名单，不将客户端字符串直接拼接到 SQL。

### 8.2 字段组计数

扩展 `ListFieldGroupsRsp`：

```protobuf
map<string, uint64> field_counts = 4;
uint64 total_field_count = 5;
uint64 ungrouped_field_count = 6;
```

`field_counts` 中一级组为递归计数，二级组为直接计数。计数统计所有状态的字段，保证目录数量不会随右侧状态筛选跳动。

### 8.3 批量更新字段

新增 `BatchUpdateFields` RPC：

```protobuf
message BatchUpdateFieldsReq {
  common.AuthInfo auth_info = 1;
  string space_id = 2;
  repeated string field_ids = 3;
  string target_group_id = 4;
  string target_status = 5;
}

message BatchUpdateFieldsRsp {
  common.RetInfo ret_info = 1;
  uint32 updated_count = 2;
}
```

请求至少包含 `target_group_id` 或 `target_status` 之一，最多接收 100 个字段 ID。服务端验证字段、目标组和状态后，在单个事务中更新。

### 8.4 删除字段组

新增 `DeleteFieldGroup` RPC，参数为 `space_id` 和 `group_id`。存在子组或直接、间接字段引用时返回业务错误；接口只删除空组。

## 9. 前端组件边界

避免继续扩大当前单文件页面，将职责拆分为：

- `index.vue`：页面编排、Space 切换、URL 状态和数据加载。
- `FieldGroupTree.vue`：两级目录、计数、展开状态和组操作事件。
- `FieldTable.vue`：筛选结果、分页、选择、排序和行操作事件。
- `FieldEditorDrawer.vue`：字段新增编辑表单、脏状态和校验。
- `FieldGroupDialog.vue`：字段组新增编辑表单。
- `FieldBatchBar.vue`：批量操作及确认交互。

组件不直接调用 API，由页面统一组织请求和刷新，避免列表、目录和抽屉各自维护不一致的数据副本。

## 10. 数据流与并发处理

1. Space 就绪后，并行加载字段组目录与字段列表。
2. 字段组响应提供目录数据和计数；字段列表响应提供当前查询页。
3. 搜索、筛选、目录选择、排序或分页变化时更新 URL，再触发字段列表查询。
4. 创建、编辑、批量更新或删除字段组成功后，重新加载受影响的数据。

列表请求使用递增请求序号或取消机制，只接受最后一次请求结果，避免快速输入和切换目录时旧响应覆盖新状态。目录和列表分别维护加载状态；一个请求失败不清空另一个已经成功的区域。

## 11. 错误与状态反馈

- 未选择 Space：保留现有警告，并禁用所有创建和治理操作。
- 首次加载：目录和表格分别显示骨架或加载态。
- Space 无字段组：显示空状态，并将`新建字段组`作为主要操作。
- 有字段组但无字段：显示当前范围空状态，并允许新建字段。
- 搜索无结果：保留筛选条件，提供清空筛选操作。
- 列表或目录失败：在对应区域显示重试，不把旧数据伪装成最新结果。
- 表单失败：抽屉保持打开，保留输入并展示服务端错误。
- 批量失败：保留选中项，不执行乐观更新。

## 12. 测试与验收

### 12.1 后端测试

- `ListFields` 覆盖关键字、状态、值类型、一级组递归、二级组精确、未分组和排序白名单。
- 字段组计数覆盖一级递归计数、二级直接计数、停用字段和异常未分组字段。
- 批量更新覆盖成功、空操作、超过 100 项、跨 Space、无效目标组、无效状态和事务回滚。
- 删除字段组覆盖空组成功、存在子组失败和存在字段失败。

### 12.2 前端测试

- URL 状态序列化和恢复。
- 搜索防抖、筛选重置分页以及旧请求结果丢弃。
- 目录两级渲染、数量、一级递归查询和无效组回退。
- 当前页多选、切页清空、批量操作成功和失败状态。
- 字段抽屉新增、编辑只读 ID、JSON 校验和未保存拦截。
- 字段组两级限制和删除错误反馈。

### 12.3 浏览器验收

- 在桌面和窄屏视口验证目录、表格、抽屉及批量操作条无重叠和跳动。
- 验证刷新页面后查询上下文能够恢复。
- 使用真实 Space 完成字段新增、编辑、批量移动、停用、启用和空字段组删除。
- 验证切换 Space 时不会保留上一 Space 的选择或编辑内容。

## 13. 完成标准

- 页面布局和交互符合已确认的方案 A。
- 字段编辑使用右侧抽屉，字段组保持两级约束。
- 搜索、筛选、目录查询、分页和排序均由服务端执行。
- 批量更新具有事务语义且不存在部分成功。
- URL 可恢复页面上下文，Space 切换会清理上下文。
- 后端、前端自动化测试通过，并完成桌面与窄屏浏览器验收。
