# MooX 主机工作台监控重建设计

## 状态

本设计已在讨论中确认。采用 MooX Host Agent 链路，并以主机工作台现有的两台 SSH 主机作为本次部署和验收范围。

## 目标

- 在“主机工作台”中新增“主机监控”子 Tab。
- 默认以卡片视图展示全部主机，并允许切换为左侧主机、右侧详情的主从视图。
- 展示 CPU、内存、文件系统、磁盘 I/O、网络和历史趋势。
- 重新构建并部署 `moox-host-agent` 到 `106.53.107.122` 和 `43.132.204.177`。
- 在 Monitor API 和生产页面中看到两台主机持续上报的实时及历史数据。

## 非目标

- 不恢复 Admin 旧 Node Exporter 抓取链路。
- 不开放新的主机采集端口。
- 不通过 SSH 临时执行系统命令来生成监控数据。
- 不新增统一主机资产后端，也不修改 SSH 主机表和 Host Agent 身份模型。
- 不在新增 SSH 主机时自动远程安装 Agent。页面只提示“未接入监控”。

## 信息架构

主机工作台包含三个子 Tab，顺序如下：

1. 主机列表。
2. 主机监控。
3. 在线会话。

工作台默认进入“主机列表”。旧路由按以下规则兼容：

- `/ops/resource-monitor` 跳转到 `/ops/hosts?tab=monitor`。
- `/ops/ssh-hosts` 跳转到 `/ops/hosts?tab=hosts`。
- `/ops/ssh-sessions` 跳转到 `/ops/hosts?tab=sessions`。

非法 Tab 回落到 `hosts`，并使用 `router.replace` 规范化 URL。

## 页面结构

### 工作台外壳

工作台外壳只负责标题、路由 Tab、终端弹窗和文件管理弹窗。各子页面负责自己的数据、操作和错误状态。

删除工作台标题区现有的“刷新监控”文字按钮。主机监控 Tab 在自身工具栏中提供带 Tooltip 的刷新图标和自动刷新开关，避免跨 Tab 操作含义不清。

### 主机监控工具栏

工具栏包含：

- 最近一次成功更新时间。
- 手动刷新图标按钮。
- 自动刷新开关，默认开启，每 15 秒刷新当前指标。
- “卡片视图 / 主从视图”分段控件。

首次进入使用卡片视图。用户选择保存在浏览器本地；后续进入恢复该偏好。切换布局只改变渲染方式，不重新请求数据，也不改变当前选中主机。

### 状态摘要

使用一行紧凑摘要展示：

- SSH 主机总数。
- 监控在线数。
- 需关注主机数。
- 未接入监控数。
- 历史存储状态。

不使用大号统计卡墙。状态必须同时使用文本和颜色表达。

### 卡片视图

卡片视图是默认布局。每张主机卡展示：

- SSH 主机名称和地址。
- 在线、离线或未接入状态。
- 最后上报时间。
- CPU 使用率。
- 内存使用率。
- 最大可用文件系统使用率。
- 聚合网络接收、发送速率。

可用百分比达到 80% 时标记“需关注”。不可用指标显示 `--`，不显示为零。点击卡片选中主机并更新下方详情。

卡片网格在宽屏显示三列，中等宽度显示两列，窄屏显示一列。

### 主从视图

主从视图左侧显示紧凑主机列表，右侧显示选中主机详情。左侧每项展示名称、地址、状态及 CPU、内存、文件系统摘要。

主机列表在桌面端保持固定宽度，详情区占用剩余空间。窄屏下改为上下布局。选择状态在两种视图间共享。

### 主机详情

详情区展示：

1. 1 小时、24 小时和 3 天资源趋势。
2. CPU 核心数、内存容量、文件系统数、磁盘数和网卡数。
3. 文件系统明细。
4. 磁盘 I/O 明细。
5. 网络接口明细。

趋势图只绘制有效样本，不把缺失值绘制为零。自动刷新只更新当前快照；切换主机、切换时间范围或手动刷新时才重新请求历史数据。

设备表格使用固定表头、受视口约束的高度和横向滚动。页面必须由主内容区正常纵向滚动，不能因嵌套高度导致底部表格不可达。

## 数据与身份关联

监控数据继续使用：

- `Monitor/ListHostAgents` 获取当前快照。
- `Monitor/QueryHostMetricHistory` 获取历史数据。
- `SSH/ListHosts` 获取主机管理清单和展示地址。

前端构造监控工作台行，每行包含可选的 SSH 主机和 Host Agent。关联规则为：

1. 名称完全一致时关联。Host Agent 的 `host_name` 部署配置必须写成对应 SSH 主机名称。
2. 如果 agent ID 与 SSH 地址完全一致，则允许关联。
3. 不做模糊匹配、子串匹配或 DNS 反查。
4. SSH 主机没有 Agent 时显示“未接入监控”。
5. Agent 没有对应 SSH 主机时保留为“未登记主机”，避免丢失真实上报。

展示地址优先使用 SSH 主机地址。没有匹配的 SSH 主机时展示 agent ID，并明确标记“未登记主机”。

## 采集与存储链路

采用现有原生链路：

`moox-host-agent -> EventBus -> moox-monitor -> MooX Storage -> Monitor API -> Web`

每台主机的 Agent 每 15 秒从 Linux 内核接口采集一次快照，并发布到 `moox.metrics.host.reported.v1`。Monitor 消费快照、维护最新状态并写入历史存储。

Agent 配置中的 `host_name` 分别为：

- `腾讯云-122` 对应 `106.53.107.122`。
- `腾讯云-香港` 对应 `43.132.204.177`。

部署时保留现有 EventBus 凭据、身份文件和用户 systemd 配置。二进制和默认配置采用版本化目录替换，切换前备份当前版本。服务启用用户级 systemd 自启动，并保持用户 linger，确保退出 SSH 后仍持续运行。

## 状态与错误处理

- Monitor 当前快照失败：保留上次成功数据，并显示非阻塞错误提示。
- SSH 主机列表失败：仍展示 Agent 数据，但地址退化为 agent ID。
- 历史存储不可用：当前指标保持可用，只在详情趋势区提示。
- 历史数据存在缺口：显示提示，不清空已有点。
- Agent 离线：保留主机卡和最后上报时间，无效实时指标显示 `--`。
- SSH 主机未部署 Agent：显示“未接入监控”，不伪造空指标。
- Agent 未登记为 SSH 主机：显示“未登记主机”，仍允许查看监控详情。
- 两个接口同时失败且无缓存：显示紧凑空状态和重试操作。

## 组件边界

- `views/ops/host-workbench/index.vue`：工作台路由、三个 Tab 和弹窗编排。
- `views/ops/host-workbench/host-monitor.vue`：监控页面状态、刷新周期和视图切换。
- `views/ops/host-workbench/host-monitor-card-grid.vue`：默认卡片布局。
- `views/ops/host-workbench/host-monitor-master-detail.vue`：主从布局。
- `views/ops/host-workbench/host-monitor-detail.vue`：趋势图和设备明细。
- `views/ops/host-workbench/host-monitor-mapping.ts`：SSH 主机、Agent、当前指标和历史数据的纯函数映射。

公共数据状态留在 `host-monitor.vue`，两个布局组件不发起请求。这样可以保证切换布局时不重复加载，并让映射和异常状态独立测试。

## 测试与验收

### 前端自动化

- 为主机与 Agent 的精确名称匹配、地址匹配、未匹配状态编写单元测试。
- 为注意阈值、不可用指标、网络聚合和文件系统最大值编写单元测试。
- 为视图偏好恢复和非法路由 Tab 回落编写测试。
- 运行 `vue-tsc --noEmit` 和生产构建。

### Agent 与后端验证

- 运行 Host Agent 模块测试并构建 Linux 二进制。
- 在两台主机验证 `moox-host-agent.service` 为 `active (running)` 且已启用。
- 验证 Agent 健康端点成功、日志持续发布且无循环错误。
- 通过 Monitor API 确认两台主机均在线，快照包含 CPU、内存、文件系统、磁盘和网络。
- 等待至少两个采集周期，再查询两台主机历史数据，确认时间戳持续推进。

### 浏览器验收

在生产地址 `/ops/hosts?tab=monitor` 验证：

- 默认显示两张主机卡，名称和 IP 与 SSH 清单一致。
- 两台主机均显示在线，并具有真实 CPU、内存和文件系统数据。
- 切换为主从视图后仍保留当前主机和数据。
- 两台主机均可打开详情并看到历史趋势、文件系统、磁盘 I/O 和网络表格。
- 页面在 `1440x900`、`1280x720` 和 `390x844` 下无重叠，底部表格可滚动到达。

只有以上证据全部成立，任务才视为完成。
