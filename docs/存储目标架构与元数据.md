# Storage 目标架构与元数据

Storage 的 `series_tag` 目标架构收敛到 Schema v6、直接 DataNode 绑定和显式激活
流程（实施前代码仍为 v5），详见
[存储层最终架构](存储层架构.md) 和
[Dataset 单归属设计](superpowers/specs/2026-07-19-storage-dataset-node-simplification-design.md)。

Metadata 目标使用 SQLite Schema v6，并由 `storage-primary` 的不可变 Metadata
Snapshot 读取。

核心关系：

```text
Space
  |-> DataSource
  |-> Subject
  |-> Field / Factor
  |-> Dataset -> data_node_id + binding_locked + revision
  `-> View -> primary_dataset_id + dataset_ids + active_slot
```

约束：

- Dataset 创建时必须指定 `data_node_id`，初始为 disabled/unlocked/revision 1；首次激活前可用 CAS 解绑到另一个 active DataNode，激活后绑定永久不可修改。
- DataNode 由部署注册 `node_id/service_target`，管理台只能修改名称和启停状态；删除必须先 disabled 且没有 Dataset 引用。
- Doctor 只读调用激活检查；显式激活校验 Schema、保留周期、DataNode 身份和运行就绪，成功后设置 active、binding_locked 并递增 revision。
- `data_kind`、`data_source_id`、Field `value_type` 均不可修改。
- Dataset Field 只增不减，所有 Field 可缺失。
- TimeSeries Dataset/View 使用 `keep_duration`；Record 必须为 `0`。
- View 使用 `desired_view_revision`、`active_view_revision`、`active_slot` 和
  `active_columns` 完成 A/B 切换。
- Metadata 列表接口在 SQLite 中执行 `COUNT + LIMIT/OFFSET`，不先全量载入内存。运行时读写只使用 Snapshot，不在热路径访问 SQLite。

实际表结构以 [metadata.sql](../modules/storage/schema/metadata.sql) 为准。
