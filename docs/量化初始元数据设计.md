# MooX 量化初始元数据设计

## 1. 目标与事实源

[`examples/metadata-quant-initial.seed.yaml`](../examples/metadata-quant-initial.seed.yaml) 是新系统的业务元数据事实源。它不承担“展示未来能力”的目录职责，只导入字段契约完整、可写入且可查询的最小数据闭环。

```bash
moox-cli metadata import \
  --file examples/metadata-quant-initial.seed.yaml \
  --metadata-url http://127.0.0.1:20200 \
  --if-not-exists
```

该 seed 仅面向空系统。项目不保留旧元数据契约；当结构调整时，可清理已有元数据和业务数据后重新导入。

## 2. 初始空间

| Space ID | 中文名 | 边界 |
| --- | --- | --- |
| `stock_cn` | A股市场 | A股、A股指数和财务数据 |
| `stock_hk` | 港股市场 | 港股证券与行情 |
| `stock_us` | 美股市场 | 美股证券、行情与估值 |
| `crypto_binance` | 币安市场 | Binance 现货和永续合约 |
| `crypto_okx` | 欧易市场 | OKX 现货和永续合约 |

Space 是业务、权限和数据隔离边界。DataSource 必须归属具体 Space，不将供应商或本地目录单独建成 Space。

## 3. Dataset 契约

| Space | Dataset | 类型 | 频率 |
| --- | --- | --- | --- |
| `stock_cn` | `stock_kline` | `time_series` | `5m`/`15m`/`1h`/`1d` |
| `stock_cn` | `index_kline` | `time_series` | `1h`/`1d` |
| `stock_cn` | `financial_statement_metric` | `record` | `quarter` |
| `stock_cn` | `financial_summary` | `record` | `quarter` |
| `stock_hk` | `ah_stock_kline_daily` | `time_series` | `1d` |
| `stock_us` | `stock_kline_daily` | `time_series` | `1d` |
| `crypto_binance` | `spot_kline_1h` | `time_series` | `1h` |
| `crypto_binance` | `perpetual_kline_1h` | `time_series` | `1h` |
| `crypto_okx` | `spot_kline_1h` | `time_series` | `1h` |
| `crypto_okx` | `perpetual_kline_1h` | `time_series` | `1h` |

Dataset ID 可包含频率后缀。当原始数据天然只提供一个频率，或不同频率具有不同来源和运维周期时，使用 `_1h`、`_daily` 等后缀能让契约更明确。同一来源、同一 Schema 的多频率数据可共用一个 Dataset，例如 `stock_kline`。

所有 Dataset 至少有一个结构化业务列。`raw_payload` 只用于无损保留未标准化列，不能作为 Dataset 的唯一业务契约。

## 4. 时间与粒度

`subject_id`、`freq`、`data_time` 是 TimeSeriesKey 的系统维度，不在 Field 和 DatasetColumn 中重复定义。原始文件中的交易日期在导入时转换为 `data_time`。

Time-series View 统一使用：

```text
subject_id + freq + data_time
```

Record 的存储键是 `record_id + version`。财报指标明细和财务摘要具有不同业务粒度，因此分成两个 Dataset 和两个 View，不进行不稳定的跨 Dataset 拼接。

## 5. View 设计

每个默认 Dataset 都有对应的可查询 View。

- Time-series Dataset 使用 `duckdb` View，并通过 `filter_json` 固定查询频率。
- Record Dataset 使用当前 Storage 支持的 `bleve` View。
- 每个 View 必须显式声明 `view_columns`，不允许只创建无活动 Schema 的 View 外壳。
- ViewColumn 使用 `dataset_id.column_name` 作为列名和 `origin_id`，避免未来多 Dataset View 中的列名冲突。
- 系统 Key 不重复定义为 ViewColumn，查询结果由行 Key 单独返回。

## 6. 演进规则

1. YAML 是初始元数据唯一机器事实源，文档只记录设计规则。
2. 默认 seed 不收录尚未提供导入、采集或查询闭环的 Dataset。
3. 新 Dataset 须同时提交 Field、DatasetColumn、View 和 ViewColumn 契约。
4. 只有频率、粒度、Schema 或数据生命周期不同时才新建 Dataset。
5. Subject 和 SubjectSymbol 属于运行数据目录，由采集或导入流程注册，初始 seed 不静态枚举数千个标的。
