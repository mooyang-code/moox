# MooX 量化初始元数据设计

## 1. 事实源与初始化

机器可导入事实源为 [`examples/metadata-quant-initial.seed.yaml`](../examples/metadata-quant-initial.seed.yaml)。本文只解释边界、命名和映射原则，不复制一份会漂移的配置。

```bash
moox-cli metadata import \
  --file examples/metadata-quant-initial.seed.yaml \
  --metadata-url http://127.0.0.1:20200 \
  --if-not-exists
```

该 seed 面向一个完全空的新系统，按 `Space -> DataSource -> FieldGroup -> Field/Factor -> Dataset -> DatasetColumn -> View` 建立元数据。Dataset 类型只允许：

- `record`：一条记录表达一个对象、报告或事件，例如财报、公告、评级、分红。
- `time_series`：同一 Subject 随时间连续产生观测值，例如 K 线、资金流、因子值。

历史枚举 `snapshot/event/document/table` 只保留 protobuf 编号兼容，不允许新建 Dataset。

## 2. 空间定义

| Space ID | 中文名 | 边界 |
| --- | --- | --- |
| `stock_cn` | A股市场 | A股、ETF、可转债、A股指数、财务、公司行动和另类市场数据 |
| `stock_hk` | 港股市场 | 港股证券与行情；AH 映射也在此空间表达 |
| `stock_us` | 美股市场 | 美股证券、指数、行情、分红与拆股 |
| `crypto_binance` | 币安市场 | Binance 现货、永续合约、CoinMarketCap 基本面 |
| `crypto_okx` | 欧易市场 | OKX 现货与永续合约 |

空间按业务语义和权限边界划分，不按文件夹或供应商划分。供应商属于 DataSource，原始目录写在 Dataset 的 `attributes.source_directories` 中用于追溯。

## 3. 字段组设计

FieldGroup 归属 Space，稳定键是 `(space_id, group_id)`，最多两级。Field 必须且只能归属一个组；Factor 仍独立管理，不伪装成普通 Field。

| Space | 一级组 | 二级组/用途 |
| --- | --- | --- |
| `stock_cn` | 标识信息、市场数据、财务数据、公司事件、资金筹码、文本信息 | 市场数据下分行情价格、成交估值 |
| `stock_hk` | 标识信息、行情价格 | 港股代码、日期和 OHLC |
| `stock_us` | 标识信息、行情价格、估值指标、公司事件 | 行情、PE、市值、分红、拆股 |
| `crypto_binance` | 标识信息、行情价格、合约指标、基本面 | K 线、资金费率、供应量和市值 |
| `crypto_okx` | 标识信息、行情价格、合约指标 | K 线和资金费率 |

字段中英文名、类型、单位、组内顺序均在 YAML 的 `fields` 段维护。字段 ID 使用小写 snake_case，中文名只承担展示语义；DatasetColumn 通过 `origin_id` 引用 Field 或 Factor。

每个 Dataset 至少声明一个 `raw_payload` JSON 列，用于无损承接尚未标准化的原始列；常用查询字段仍必须拆成独立的强类型列。`raw_payload` 是兼容兜底，不替代规范字段。K 线、财务摘要和因子等核心 Dataset 已声明完整的常用可写列。

## 5. 财务数据决策

`financial_summary` 不是一个 JSON 字段。它是独立的 `record` Dataset，列为 `revenue`、`net_profit_parent`、`total_assets`、`total_liabilities`、`operating_cash_flow`、`roe_ttm` 等常用指标，便于筛选、排序和研究。

完整的邢不行财务文件包含数百个动态指标，使用 `financial_statement_metric` 长表保存：

| 字段 | 含义 |
| --- | --- |
| `subject_id` | 证券主体 |
| `report_date` | 报告期 |
| `publish_date` | 发布日期 |
| `statement_format` | 报表格式 |
| `metric_id` | 原始稳定指标 ID，例如 `B_total_assets@xbx` |
| `metric_name` | 中文指标名，可后续补齐 |
| `metric_value` | 指标数值 |

这样既不丢原始指标，也避免把数百个供应商字段永久固化进每个查询接口。摘要表可由完整指标表派生，但两者元数据和存储契约独立。

## 7. 初始化与演进规则

1. YAML 是初始元数据唯一机器事实源，MD 不另存一份字段明细。
2. Seed 使用 Upsert/`--if-not-exists` 语义，可重复执行；修改既有契约时使用 `metadata apply` 做差异校验。
3. 新字段先选 FieldGroup，再定义 Field，最后绑定 DatasetColumn。
4. 新的计算指标优先定义为 Factor；只有稳定、可写、跨 Dataset 复用的原始业务语义才定义为 Field。
5. 原始目录新增时先判断能否映射现有 Dataset；只有粒度、主键或业务语义不同才新建 Dataset。
6. Subject 和 SubjectSymbol 属于运行数据目录，可在采集时注册；初始 seed 不静态枚举数千只证券和交易对。
