# MooX 量化初始元数据设计

## 1. 目标与事实源

[`examples/setup/default/metadata.yaml`](../examples/setup/default/metadata.yaml) 是新系统的业务元数据事实源。它不承担“展示未来能力”的目录职责，只导入字段契约完整、可写入且可查询的最小数据闭环。

```bash
moox-cli setup init \
  --file ./custom.toml \
  --config-dir ./examples/setup/default \
  --storage-host control
```

该 seed 面向新系统初始化，也支持在声明完全一致时重复执行。项目不保留旧元数据契约；
本次 scalar `series_tag` 切换需要清理旧 Metadata、Pebble、DuckDB、Archive 和
Factor 数据后重新导入，不执行迁移。

## 2. 初始空间

| Space ID | 中文名 | 边界 |
| --- | --- | --- |
| `stock_cn` | A股市场 | A股、A股指数和财务数据 |
| `crypto` | 加密货币市场 | 多交易所的现货和永续合约数据 |

Space 是业务、权限和数据隔离边界。DataSource 必须归属具体 Space，不将交易所、
供应商或本地目录单独建成 Space。Binance 和 OKX 分别使用 `binance`、`okx`
DataSource 管理各自的物理来源配置，共享 `crypto` Space 内的 Field 字典。接收多
venue 行的共享 Dataset 绑定逻辑聚合 DataSource `crypto`；具体来源由
`series_tag` 和必要的普通 Field 保留，因为 Dataset 仍只绑定一个 DataSource。

## 3. Dataset 契约

| Space | Dataset | 类型 | 频率 |
| --- | --- | --- | --- |
| `stock_cn` | `stock_cn_kline` | `time_series` | `5m`/`15m`/`1H`/`1d` |
| `stock_cn` | `stock_cn_index_kline` | `time_series` | `1H`/`1d` |
| `stock_cn` | `financial_statement_metric` | `record` | `quarter` |
| `stock_cn` | `financial_summary` | `record` | `quarter` |
| `crypto` | `spot_kline_1h` | `time_series` | `1H` |
| `crypto` | `perpetual_kline_1h` | `time_series` | `1H` |

Dataset ID 使用 `<instrument_type>_<data_kind>[_<frequency>]`，不把 venue 固化到
Dataset ID。同一 Schema、频率和生命周期的 Binance/OKX 行放在同一 Dataset，
分别使用 `series_tag=venue:binance` 和 `series_tag=venue:okx`。只有 Schema、频率、
粒度或生命周期不同才拆 Dataset；DataSource 仍保留来源管理语义。

所有 Dataset 至少有一个结构化业务列。`raw_payload` 只用于无损保留未标准化列，不能作为 Dataset 的唯一业务契约。

## 4. 时间与粒度

`subject_id`、`freq`、`data_time`、`series_tag` 是 TimeSeriesKey 的系统列，不在
Field 和 DatasetColumn 中重复定义。原始文件中的交易日期在导入时转换为
`data_time`。`series_tag` 是不透明标量，空字符串表示默认序列；元数据不登记
`series_tag_name` 或允许值。

Time-series View 统一使用：

```text
subject_id + freq + data_time + series_tag
```

Record 的存储键是 `record_id + version`。财报指标明细和财务摘要具有不同业务粒度，因此分成两个 Dataset 和两个 View，不进行不稳定的跨 Dataset 拼接。

## 5. View 设计

每个默认 Dataset 都有对应的可查询 View。

- Time-series Dataset 使用 `duckdb` View，并通过 `filter_json` 固定查询频率。
- Record Dataset 使用当前 Storage 支持的 `bleve` View。
- 每个 View 必须显式声明 `view_columns`，不允许只创建无活动 Schema 的 View 外壳。
- ViewColumn 使用 `dataset_id.column_name` 作为列名和 `origin_id`，避免未来多 Dataset View 中的列名冲突。
- 系统 Key 不重复定义为 ViewColumn，查询结果由行 Key 单独返回。

## 6. 演进规则

1. YAML 是初始元数据唯一机器事实源，文档只记录设计规则。
2. 默认 seed 不收录尚未提供导入、采集或查询闭环的 Dataset。
3. 新 Dataset 须同时提交 Field、DatasetColumn、View 和 ViewColumn 契约。
4. 只有频率、粒度、Schema 或数据生命周期不同时才新建 Dataset。
5. Subject 和 SubjectSymbol 属于运行数据目录，由采集或导入流程注册，初始 seed 不静态枚举数千个标的。
6. 同一 Dataset 中的来源或实体差异优先使用一个稳定 `series_tag`；不得恢复
   Dimensions Map、多 tag 或 venue 专属 Dataset 命名来绕过统一身份契约。
