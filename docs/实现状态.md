## 3. 尚不能承诺的能力

- Storage 的维护命令（`repair-view`、`delete-view`）要求 primary、view 在同一主机。
- 部署没有过程记录：重跑同一条命令就是再做一遍，没有变化的组件不重启；升级就是用新版本再部署一遍。真实 systemd 下的安装、启停和就绪等待没有自动化检查，只靠真机安装验证；已知差别见[部署与运维](部署与运维.md)。
- Linux 内核级恢复、真实进程强杀、多主机、跨架构与完整业务链路需专项门禁。普通 macOS Go 测试不会执行只在 Linux 上运行的用例（例如部署安装脚本的用例）；真实进程联调 `make test-e2e-gates` 里主机网关与 Admin 那一条也只在 Linux 上执行。
- 因子引擎的配置每次部署都从 `modules/factor/config/engine.yaml` 渲染（`compute.max_memory=4GiB`、回看 50000 根、进程预算不限），调过的值要写在 `moox.toml` 的 `[overrides]` 里；部署不按本机内存自动校准，`moox-factor-engine tune` 给出建议值。
- 离线表达式 `eval` 会屏蔽原始输入窗口里的缺期；常驻引擎读取本地存储中已按规则填充的连续网格。含缺期输入的离线结果不能直接当作生产路径等价验收。
- 因子本地历史没有定时淘汰，只有 `setup wipe` 或停掉引擎后删 `<部署根>/data/factor-engine` 才会清空；Storage 只保留配置窗口，恢复更早的本地历史需要导入文件或归档。
- 现货加永续的两种输入方式（方式 A：现货、永续各一个因子任务；方式 B：统一数据集上的一个任务）都保留，是否只留统一数据集还没定，等用户决定。
  只留统一数据集的代价：统一数据集挂着现货标签，采集时选不了资金费率，删掉方式 A 后现货加永续的回放与策略池不能计资金费、实时主帧拿不到资金费率；已有采集任务不能改成统一数据集，同一份行情要采两遍、因子算两遍；跨市场的策略池现在只能靠方式 A。
  可走的三条路：统一数据集允许只在永续序列上有的字段；资金费率改从附加来源读；维持现状。建议先维持现状，用过一段统一数据集再定。
- 统一数据集（现货、永续在同一个数据集）：策略侧已支持（方式 B，登记为 `multi`），不支持 `factor_params` 与策略池（回放可以，“因子现算”来源也可以；现货、永续各绑一个任务的实例不能用“因子现算”）；跨市场因子（基差、溢价）写不出来；已有的分开数据集不改造，已有任务也不能在单市场与统一数据集之间切换。
- A 股只有模拟盘（Trade 场所 `ASHARE`），实盘的 QMT 执行端还没接入；模拟盘不处理除权除息和分红送转。1m、日线、指数与可转债不在默认链路里。内嵌交易日历目前覆盖到 2027-12-31（2027 年按国办发明电〔2026〕10 号生成）。每年 11 月前后国务院发布次年节假日安排后，把休市日写进 `packages/marketcalendar/internal/gencn` 的 `closures`，在 `packages/marketcalendar` 下运行 `go run ./internal/gencn -year <次年>`，然后重新发布 Collector、Factor、Strategy、Monitor 与 CLI，并重新上传 stockcn、stockhk、stockus 三个 SCF 代码包（港股、美股日历的更新步骤见 `skills/moox/references/fresh-deploy.md`；漏传港股或美股包，旧日历的覆盖期一过，对应函数每期都返回 `no_work`，不报错）；交易所 12 月公布休市安排后再核对一遍。必须在 12 月中旬前发布：采集计划预检要求日历覆盖期至少还剩 14 天，Strategy 也会提前 2 个交易日判定日历过期。
- 港股只有模拟盘（Trade 场所 `HKEX`），不接任何券商：不含收市竞价，碎股不能买，费率是 2026 年公开费率的模拟口径，汇率不换算（账户以 HKD 计），标的范围只有恒生指数成分，除权除息、退市不处理；美股还没有 Trade 场所。
