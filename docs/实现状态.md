## 3. 尚不能承诺的能力

- 原生 Storage 部署要求 primary、node、view 在同一主机，DataNode ID 固定为 `storage-node-0`；不支持用该入口拆分三个角色到不同主机。
- `admin-ready`、`host-ready`、`storage-ready`、`control-ready` 是阶段收据。云资源/防火墙、业务 seed、SCF fleet、因子机外部程序（Factor Engine、Archive Worker）与实际采集至交易链路仍需各自初始化和验证。
- 原生部署重试绑定原始配置、制品、身份和状态目录；升级用 `setup release build` 构建新版本并以 `--release` 安装，不能通过更换源码或删除状态目录把重试当升级。
- Linux 内核级恢复、真实进程强杀、多主机、跨架构与完整业务链路需专项门禁。普通 macOS Go 测试不会执行 `_linux_test.go`，`make verify` 也未自动串起全部 `test-unit-*-linux` 门禁。
- 引擎默认配置与当前原生安装入口的默认值不完全相同；例如引擎配置为 `compute.max_memory=4GiB`，`setup deploy-unit --profile factor-engine` 调用的 `scripts/deploy/deploy-factor-engine.sh` 仍生成 `1GiB`。应分别核对具体入口，不能用仓库模板推断已安装值。
- 离线表达式 `eval` 会屏蔽原始输入窗口里的缺期；常驻引擎读取本地存储中已按规则填充的连续网格。含缺期输入的离线结果不能直接当作生产路径等价验收。
- 因子本地历史没有定时淘汰，但显式重置会清空；Storage 只保留配置窗口，恢复更早的本地历史需要导入文件或归档。
- 统一数据集（现货、永续在同一个数据集）：策略侧已支持（方式 B，登记为 `multi`），不支持 `factor_params`、策略池与闭环回放（研究回放可以）；跨市场因子（基差、溢价）写不出来；已有的分开数据集不改造，已有任务也不能在单市场与统一数据集之间切换。升级已有 Collector 库要先手工加列、重建两张表（见[采集](模块/采集.md)“统一数据集”）。
- A 股只有模拟盘（Trade 场所 `ASHARE`），实盘的 QMT 执行端还没接入；模拟盘不处理除权除息和分红送转。1m、日线、指数与可转债不在默认链路里。内嵌交易日历目前覆盖到 2027-12-31（2027 年按国办发明电〔2026〕10 号生成）。每年 11 月前后国务院发布次年节假日安排后，把休市日写进 `packages/marketcalendar/internal/gencn` 的 `closures`，在 `packages/marketcalendar` 下运行 `go run ./internal/gencn -year <次年>`，然后重新发布 Collector、stockcn SCF 代码包、Factor、Strategy、Monitor 与 CLI；交易所 12 月公布休市安排后再核对一遍。必须在 12 月中旬前发布：采集计划预检要求日历覆盖期至少还剩 14 天，Strategy 也会提前 2 个交易日判定日历过期。
