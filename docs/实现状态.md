## 3. 尚不能承诺的能力

- 原生 Storage 部署要求 primary、node、view 在同一主机，DataNode ID 固定为 `storage-node-0`；不支持用该入口拆分三个角色到不同主机。
- `core-ready`、`host-ready`、`storage-ready`、`control-ready` 是阶段收据。云资源/防火墙、业务 seed、SCF fleet、因子机外部程序（Factor Engine、Archive Worker）与实际采集至交易链路仍需各自初始化和验证。
- 原生部署重试绑定原始配置、制品、身份和状态目录；升级用 `setup release build` 构建新版本并以 `--release` 安装，不能通过更换源码或删除状态目录把重试当升级。
- Linux 内核级恢复、真实进程强杀、多主机、跨架构与完整业务链路需专项门禁。普通 macOS Go 测试不会执行 `_linux_test.go`，`make verify` 也未自动串起全部 `test-unit-*-linux` 门禁。

## 4. 文档维护依据

端口和 ACL 看 `packages/servicecatalog/catalog.yaml` 及各进程监听配置；部署生成的健康监听还要看
`modules/cli/internal/setup/unitinstall/render.go`。不要把模板中的回环默认值当成部署后的监听地址。

字段与方法看 `.proto`；表结构看各模块 `schema/*.sql`；默认保留期看 `packages/storagepolicy/policy.go`；
命令看 Cobra 注册处；测试覆盖看 `Makefile`、`.github/workflows/ci.yml` 与专项 gate 脚本。
修改这些契约时同步更新模块文档与本页。历史计划中的“当前”“待实现”只适用于其原始记录时间。
