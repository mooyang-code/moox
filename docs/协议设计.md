# Storage PB Protocol Design

当前 Storage 协议不保留旧架构别名。

Metadata 协议使用 Schema v5 的直接绑定模型：`Dataset.data_node_id` 指向唯一 DataNode，
DataNode 的一等字段 `service_target` 由部署注册。创建 Dataset 只产生 disabled/unlocked
记录；Doctor 使用 `CheckDatasetActivation` 做只读检查，调用方通过 `ActivateDataset` 显式
激活，成功后设置 `binding_locked`，后续不能修改绑定。`revision` 用于解绑和激活的 CAS。
项目为新系统，不定义旧拓扑迁移协议。

| Proto | 职责 |
| --- | --- |
| `rows.proto` | `RowKey`、字段级 Upsert 和查询结果 |
| `data_node.proto` | DataNode 精确读写、状态和桶清理 |
| `primary_store.proto` | Metadata 校验后的用户写读边界 |
| `packages/events/proto/eventpb/event_message.proto` | 所有业务事件的显式外层契约 |
| `packages/storagepb/storage_events.proto` | `storage.dataset.rows.upserted` 结构化 Dataset 增量事件（Space/Dataset identity + changed rows/fields） |
| `packages/cloudjobpb/job_events.proto` | `cloudnode.job.execution.requested` 云任务执行命令 |
| `packages/hostmetricpb/host_metric.proto` | `metrics.host.reported` 主机指标 |
| `packages/metricspb/metrics.proto` | `metrics.snapshot.reported` 服务指标快照 |
| `packages/tradeeventpb/trade_events.proto` | `trade.rebalance.requested` 策略调仓命令 |
| `view_index.proto` | ViewIndex Prepare/Apply/Stat/Remove/Query |
| `view.proto` | DataView TimeSeries 查询和 Record 搜索 |
| `metadata.proto` | Metadata CRUD、View Revision 和 Build CAS |

协议不包含：

```text
ShardKey / ShardRow / ShardTarget
Dimensions
RowMarker / content_hash
node_sequence / source_sequence
DatasetProgress / ViewIndexSourceProgress
ScanRows / Snapshot / DeleteRows
```

DataNode 写入使用 `RowFieldUpsert`。ViewIndex 使用 `LIVE_WRITE` 和 `BACKFILL`；
Backfill 不覆盖非空实时值。所有请求中的 `auth_info` 都由对应服务校验。

## 事件契约

当前公共事件只有五个：

| Event | 发布方 | 消费方 |
| --- | --- | --- |
| `cloudnode.job.execution.requested@1` | CloudNode | Worker/CloudNode route Consumer |
| `metrics.host.reported@1` | HostAgent | Monitor |
| `metrics.snapshot.reported@1` | 各服务 Reporter | Monitor |
| `storage.dataset.rows.upserted@1` | Storage | View、Factor、Archive |
| `trade.rebalance.requested@1` | Strategy | Trade |

事件在 `packages/events/registry.go` 中 code-first 声明。`EventMessage` 负责 transport identity，
具体 protobuf 负责业务 payload。EventBus 只拥有 Stream/KV；消费服务创建并拥有 Consumer。
`NewConsumer` 按 Event family 创建 Consumer；`NewSubjectConsumer` 按 Event、
`space_id` 和 `subject_id` 通过 Registry 渲染精确 Subject，供 CloudNode route Consumer
使用。业务模块不得向 `packages/events` 传入裸 `FilterSubject`。新项目不提供旧事件名、
旧 payload 或旧 Consumer API 的兼容层。

业务侧的代码目录不复制契约所有权：`outbox` 管理本地事务消息及 relay，
`eventconsumer` 管理绑定、抓取、解码和 ACK 生命周期，`eventpublisher` 管理无本地
事务的直接发布，`eventmapper` 只做本地模型和公共 payload 的双向转换，`inbox`
仍由提交幂等状态的 Store 所有。
