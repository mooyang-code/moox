# Strategy 模块架构设计

## 模块边界

`modules/strategy` 是独立 Go 服务。当前由调用方通过 `RunOnce` 提供 point-in-time
`data_json`、`data_revision` 和逻辑 Bar 时间，服务通过常驻 Python worker 执行版本化
策略，持久化运行状态和最终基础资产目标数量，再由事务 Outbox 把 paper/live 目标交给
Trade。Strategy 不创建订单、不保存成交或实际仓位，也不 import Trade internal。

```text
RunOnce(data_json, data_revision, trigger_bar_time)
  -> 输入与 Binding/Strategy 状态校验
  -> Python StrategyTask
  -> hold 或完整 TargetPosition 集合
  -> StrategyRun + State CAS + Outbox 同事务提交
  -> moox.trade.target.requested.v1
  -> Trade TargetExecution
```

Admin 只负责部署、路由和 Secret。EventBus 只负责传输。Trade 是 ExchangeAccount、
Order、Fill、Position 和交易账本的事实源。

## 设计原则

1. Python 只做确定性策略计算，不调用 RPC、Exchange 或数据库。
2. Go 管理版本、输入校验、超时、状态 CAS、审计和发布。
3. `hold` 不产生新目标；`rebalance` 必须给出完整目标集合。
4. 数量使用规范十进制字符串，含义固定为基础资产数量。
5. 同一逻辑调度点和 execution binding 都有稳定幂等身份。
6. 下游失败不回滚已经接受的 StrategyRun 或 State。

V1 不实现在线源码编辑、第三方代码沙箱、组合资金自动分配或在 Strategy 内生成订单。

## Python 协议

输入 `StrategyTask` 包含：

```text
api_version + strategy_id + strategy_version
run_id + trigger_bar_time + run_time
data_revision + freq
previous_state + previous_state_revision
previous_targets（当前 RunOnce 为空）
params + 调用方提供的 point-in-time data
```

输出固定为：

```json
{
  "action": "hold | rebalance",
  "targets": [
    {
      "instrument_id": "BTC-USDT",
      "symbol": "BTCUSDT",
      "target_quantity": "0.01",
      "reason": "optional",
      "source_time": "optional",
      "data_revision": "optional"
    }
  ],
  "next_state": {}
}
```

目标字段使用白名单校验，未知字段直接拒绝。`target_quantity` 必须符合规范十进制语法，
不能使用指数、NaN、Infinity 或浮点数。Symbol 在一个输出中唯一。`rebalance` 的空目标
当前拒绝，避免把意外空结果解释为全平仓。

每个 worker 同时执行一个任务。超时或进程异常后销毁并重建 worker；状态只在 Go 事务
成功后推进。源码更新发布新 version，不热改已启用版本。

## 领域对象

### StrategyDefinition

不可变版本记录：

```text
strategy_id + version
api_version
manifest_yaml
source_code + source_hash
state_schema_version
status
```

### Binding

把策略版本绑定到 Space、View、频率和参数：

```text
binding_id
strategy_id + strategy_version
space_id + view_id + freq
params_json
group_id
status
```

`group_id` 当前仅作为 execution binding 的路由键，不代表已实现组合资金聚合。

### StrategyState

```text
binding_id
strategy_version
state_revision
state_json
last_run_id
```

提交使用读取时的 revision 做 CAS，晚到响应不能覆盖新状态；发生冲突时由调用方决定
是否以新输入再次调用 `RunOnce`。

### StrategyRun

```text
run_id
binding_id + strategy_version + namespace
trigger_bar_time + data_revision + input_hash
previous_state_revision
action + output_json
status
```

实时幂等身份由 binding、版本、逻辑 Bar 时间和 namespace 决定。

### ExecutionBinding

```text
execution_binding_id
group_id
exchange_account_id
mode: observe | paper | live
status
```

`observe` 保存策略运行但不发布 Trade 命令。`paper` 和 `live` 必须绑定
`exchange_account_id`。同一 group 可以配置多个 execution binding，每个 binding 有独立
command sequence；一个账户失败不修改其他 binding 的目标。

## 提交与恢复

一次 `rebalance` 在同一 SQLite 事务中：

1. 校验 Output 和 TargetPosition。
2. CAS 更新 StrategyState。
3. 保存 StrategyRun。
4. 为每个启用的 paper/live ExecutionBinding 递增 command sequence。
5. 生成 `TargetIntent` 和完整 EventMessage，写入 `t_strategy_outbox`。

Outbox relay 在事务外发布。发布失败时保留原 event ID 重试，不重新执行 Python。Trade
按 `event_id` 和 `command_sequence` 幂等，较新的目标覆盖旧目标。

`TargetIntent` 包含：

```text
execution_id
strategy_run_id
execution_binding_id
exchange_account_id
data_revision
command_sequence
not_after_unix_ms
targets[instrument_id, symbol, target_quantity]
```

Strategy 不读取当前 Exchange 仓位来修改目标。Trade 在 readiness gate 通过后，结合
Exchange 权威快照和活动订单向最新目标收敛。

## 数据模型

当前 Strategy SQLite 表：

| 表 | 用途 |
| --- | --- |
| `t_strategy_defs` | 策略版本和源码 |
| `t_strategy_bindings` | 数据、参数和调度绑定 |
| `t_strategy_states` | 当前状态快照 |
| `t_strategy_runs` | 策略运行事实 |
| `t_strategy_outbox` | 待发布 TargetIntent |
| `t_strategy_command_sequences` | 每个 execution binding 的序号 |
| `t_strategy_execution_bindings` | observe/paper/live 路由 |
| `t_strategy_run_metrics` | 运行指标 |
| `t_strategy_binding_health` | Binding 健康状态 |
| `t_strategy_performance_points` | 绩效时间点 |
| `t_strategy_performance_daily` | 日绩效 |
| `t_strategy_operation_audits` | 暂停、恢复和模式变更审计 |

## EventBus

```yaml
stream: MOOX_TRADE
subject: moox.trade.target.requested.v1.<space>.<execution_binding>
consumer: trade_target_v1
```

Strategy 只发布，不创建 Consumer。Subject、Stream 和 payload 由 `packages/events` 与
`packages/tradeeventpb` 定义，业务配置不重复声明 durable 或 filter subject。

## 失败语义

| 失败点 | 行为 |
| --- | --- |
| 缺少或非法 point-in-time 数据 | 拒绝 `RunOnce`，不调用 Python |
| Python 异常或超时 | 本次调用失败，不推进状态 |
| 输出协议失败 | 不修正输出，不提交 |
| State CAS 冲突 | 拒绝晚到提交，由调用方决定是否重算 |
| SQLite 事务失败 | 不发布，可使用同一 run ID 重试 |
| Outbox 发布失败 | relay 使用同一 event ID 重试 |
| Trade 暂不可用 | Strategy 状态不回滚，Outbox 继续发布 |
| 命令已过期 | Trade 拒绝；新策略运行产生新 sequence |
