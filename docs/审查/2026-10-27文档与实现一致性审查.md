## 提交前增量核对

- **策略规则重构**：`type: tranche` 替代 `type: f1`，引入止损止盈与策略模板；因子算子 `*_partial` 更名为 `*_relaxed`。对应策略、因子和迁移文档已同步。
- **View 最长历史限制**：除每序列根数整理外，`storage_view.max_age` 按空间/频率限制新写入的历史范围，补采、导入、重算同样过滤。它不是定时删除全部存量过期行的清理器，也不改变 PrimaryStore 或因子本地历史。依据 `modules/storage/internal/service/view/max_age.go` 与 `packages/storagepolicy/policy.go`。
- **策略追赶与过期周期**：乱序仍跳过；追赶或有效期已过但输入就绪的周期会求值，成功时只保存推进后的规则状态，仍标记 skipped 且不发交易目标；下一期从最近带状态的记录恢复。相邻指纹检查、守门失败与求值失败仍可阻止状态推进。依据 `modules/strategy/internal/trigger/handler.go` 与 `internal/store/results.go`。

## 仍需区别对待的实现限制

这些是源码现状，本次通过文档说明，没有修改实现：

1. **因子内存默认值存在入口差异。** 引擎默认配置与 `engine.yaml` 是 `4GiB`，当前原生 `setup deploy-unit --profile factor-engine` 仍调用
   `scripts/deploy/deploy-factor-engine.sh` 生成 `1GiB`；`engine/tune.go` 仅把未设置或 `1GiB`
   当作无需 `force` 即可覆盖的计算内存值。不能把“采用默认值”和“自动调参会改写该值”等同。
2. **离线 eval 不等于所有实时输入路径。** `packages/factorexpr/cmd/factorexpr/main.go`
   对原始 CSV 缺期做 gap mask；常驻引擎先把缺期按本地序列规则填充。带缺期的等价验证必须明确输入预处理。
3. **本地历史并非永远可从 Storage 恢复。** 本地序列没有定时淘汰，但有显式 Wipe/reset；
   Storage 仅保留配置窗口，更早的历史需要原始导入文件或归档。
4. **config edit 不提供完整拓扑编辑。** `modules/cli/internal/configinit/editform.go` 中主机用途、地址、
   地域只读，提交未知 host 会报错；不能把该表单写成“可新增主机”。主机配置准备与部署步骤需分开说明。
5. **make clean 与构建输出存在范围差异。** `web-host/Makefile` 的 clean 仅清模块内目录，
   不删除仓库根目录的构建产物；README 明确该范围。

6. **研究回放未完整复现 hold。** `modules/strategy/internal/replay/runner.go` 把求值目标转为权重 map，
   `ledger.go` 的 Step 只有价格与权重，没有 Hold 字段。因此实时的 `hold=true` 保持数量行为不能由该研究回放证明等价。
7. **部分历史测试入口会空跑。** Makefile 仍把 `test-storage-market-pipeline` 列在 `.PHONY`，却无对应配方；
   `scripts/test/e2e/test-kline-resample.sh` 过滤旧测试名，当前只有 `TestKlineResample45mHistoryJobE2E` 与
   `TestKlineResampleAStockHourlyE2E`。示例改用真实测试名，未在本次文档修正中改动测试脚本。
8. **归档重置提示也有旧名残留。** `modules/archive/internal/bootstrap/reset.go` 的说明与保留项仍写 Parquet，
   但实际导出器只支持 CSV/CSV.GZ，配置校验明确拒绝 Parquet。文档按导出器说明，未改重置提示代码。

9. **行情注册与验证清单存在状态差异。** Sina Provider 的代码能力与 `route.yaml` 已启用，
   `config/markets/stockcn/provider-validation.yaml` 仍写 `catalog_only`。行情目录按实际注册与路由说明，不能用验证清单单独推断可用性。
