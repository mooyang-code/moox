## 导言：整体质量判断与已拍板决策总览

经历前期重构后，系统**核心主干扎实且自洽**：
- **数据流主干清晰**：“采集 → Storage Pebble 事实与周期完成唯一权威 → Factor 本地连续序列计算 → Storage View 派生索引 → Strategy 纯函数求值与会话/试运行防呆 → Trade 无状态 6 阶段目标收敛”整条链路靠因果顺序协作，无分布式锁。
- **前期收敛到位**：单 MooX CA、ed25519 网关签名、网关快照 v2 自算路由、View 与 Dataset 1:1 自动建删、统一策略回放执行器、下架并入 Trade、`setup wipe` 取代复杂在线 `reset`、全仓 `.proto` 清零 `reserved` 声明等均已落地。

本次审查识别出 **约 10 处高优逻辑/安全缺陷与热路径无效重扫**，并定稿以下 **8 项跨模块架构决策**：

| 编号 | 决策主题 | 定稿结论 |
| --- | --- | --- |
| **D1** | **归档内置 `SeaweedFS`** | **删除内置 `SeaweedFS` 组件**及 `servicecatalog` 中唯一为其存在的 `third_party` 机制。对象存储改为真正可选：未配 `[archive_object_store]` 时仅保留本地带 SHA-256 的 `.csv.gz` 目录，后端 `dataapi.go` 与前端 `archive-model.ts` 同步放开无对象存储时的本地文件校验下载；配了外部 S3（COS / R2）时才启用远端上传、恢复与每日抽查。 |
| **D2** | **SQLite 时间戳规范** | 涉及改动的表中，参与程序比较、排序、窗口过滤与审计的时间列统一使用 **`INTEGER NOT NULL`（Unix 毫秒）**，消除秒级文本、毫秒整数与带时区字符串混用引发的截断和索引失效 Bug。 |
| **D3** | **`Admin` 密钥管理** | `t_secrets` **去掉 `c_is_deleted` 改为物理硬删除**（配轻量已删初始项记录，防止 `moox-cli setup init` 把管理台主动删掉的作废初始密钥从 `moox.secrets.toml` 静默复活）；统一收口全部写入口（`SecretDAO`、`Setup`、`eventbus_credentials`、`system.go`）对 `c_extra_config` 做 AES-GCM 加密；收敛单点 `[]rune` + `•` 脱敏。 |

| **D7** | **前后端空间契约与统一分页** | 区分 **`global`（纯全局）** 与 **`space_optional`（无空间可调、有空间透传并随切空间取消）** 两档语义，同步放宽 `Strategy` 后端定义接口的 `requireSpaceID`、网关 `policy.go` 与前端 `space-client.ts`；将非游标类的分裂分页方言统一收敛到 `commonpb.Page` / `PageResult`。 |

## 第一部分：逐模块审查（前后端共 15 个模块）

### 1. `Admin`（管理后台：`modules/admin`）

**合理保留的主干**：单端口 `:9527` 内嵌静态页面（启动预压 gzip + 内容 ETag）+ 根证书下载 + `HttpOnly/SameSite=Strict` Cookie 会话与 `Origin` 强校验（`modules/admin/internal/webserver/server.go:169-201`、`modules/admin/internal/console/request_auth.go:54-112`）；`SysDeploy` 按 `moox.toml` 整份覆盖登记拓扑；`gorilla/mux` 单路由严格 404 方法约束稳定简洁，保持不动。

**问题与已定改造项**：
- **表设计与安全缺陷（高优）**：
  1. **`c_extra_config`（含 OKX `passphrase`）全入口加密**：`modules/admin/internal/service/secret/dao/secret.go:167-184` 原先只加密 `c_secret_value`，导致 `c_extra_config` 中的 OKX 交易口令明文落库；同时 `Setup`（`modules/admin/internal/service/setup/exchange_keys.go:84-95`、`impl.go:214`）、`modules/admin/cmd/cli/eventbus_credentials.go:176` 与 `modules/admin/internal/service/secret/dao/system.go:17-52` 直接用 GORM 读写 `t_secrets`。定稿：抽取统一的 `t_secrets` 字段加解密辅助函数覆盖全部读写入口，对 `c_secret_value` 与 `c_extra_config` 一并做 AES-GCM 加密。
  2. **软删除改为物理硬删除 + 初始密钥防复活保护**：原 `modules/admin/schema/admin.sql:127-134` 的 `UNIQUE (c_secret_id, c_is_deleted)` 导致固定 ID 密钥（`tencent-default` 或迁移导入同 ID 密钥）第二次删除必撞唯一索引报 `INNER_ERR`。定稿：`t_secrets` 去掉 `c_is_deleted` 列（及 `internal/softdelete` 包）改为物理硬删除（`UNIQUE (c_secret_id)`）；同时用极简的已删初始密钥 ID 记录表承接 `Setup`“管理台已删的作废初始 `[[exchange_keys]]` 不被 `setup init` 静默重建”（`exchange_keys.go:51-67`）的墓碑语义（手工新建或重新导入同 ID 时自动清除墓碑）。
  3. **移除二次脱敏冲突 + 修复 UTF-8 按字节截断**：`modules/admin/internal/service/secret/rpc/service.go:380-444` 先用 `•` 脱敏且按字节 `len(value)` 切片（多字节字符会切坏编码），随后 tRPC `masking` 过滤器调用 `modules/admin/proto/admingen/security.go:6-23` 覆盖为 `*` 使 `isMaskedSecret` 失效。定稿：删掉 `Secret.Masking()` 与 `admin`（及无任何 `Masking()` 实现的 `trade`）的 `trpc-filter/masking` 配置（同步更新 `scripts/test/contract/test-trpc-plugin-config.sh`），只保留一处基于 `[]rune` 与 `•` 的脱敏。
  4. **Schema 规范与 `t_activity_logs` 毫秒化**：修复 `admin.sql:21-25, 140-144` 触发器缺失的 `FOR EACH ROW WHEN NEW.c_mtime = OLD.c_mtime` 与行尾对齐注释；删掉只写不读的 `t_host_gateway_status.c_expected_hash`（`admin.sql:99`），补外键 `ON DELETE CASCADE`；将 `t_activity_logs.c_ctime` 改为 Unix 毫秒 `INTEGER NOT NULL`（修复 `modules/admin/internal/service/activitylog/dao.go:152-157` 秒级截断漏查）。
- **架构与端口收敛（D4）**：
  1. **7 个回环端口收敛为 1 个**：`Auth(11100)` 与 `Ssh(11106)` 仅注册到进程内 `LocalDispatcher`；将 `GatewayControl`（`modules/admin/internal/service/gatewaycontrol/trpc.go:19-27`）从监听器级 `SerializationTypeNoop` 改为标准生成 handler + 验签头/包体上限过滤器，并改造 `packages/servicecatalog/validate.go:54-93` 支持纯 `console` 服务 `port: 0` 及同组件多 `ServiceDesc` 共享单一回环端口，使 `SecretMgr`、`SysDeploy`、`Setup`、`GatewayControl`、`ActivityLog` 共用同一端口。
  2. **配置合并与显式主密钥**：合并 `app.yaml` 与 `console.yaml`（`yaml.v3` + `KnownFields(true)` 单次加载）；主密钥仅由 `bootstrap` 生成并显式传参，删掉 `os.Setenv`（`modules/admin/internal/bootstrap/config.go:191-214`）与 `eventbus_credentials.go:124-144` 的第二套生成逻辑；复用长生命周期 `TopologyDAO`/`keys.Store` 并为 `servicecatalog.LoadEmbedded()` 加 `sync.Once` 缓存（消除每分钟 120+ 次 YAML 重解析）。
- **分层与死代码清理**：删单行透传包 `sysdeploy/rpc` 与 `secret/service.go`、收拢 `service/auth` 7 个微包、`SftpList` 改强类型返回、删 `SetRawSessionOwnerVerifier`、删死包 `modules/admin/internal/spacecontext/spacecontext.go:1-34` 与孤立 `cmd/e2e-console` 及无用 CLI 子命令；撤回 `SecretMgr.ListSecrets` 对 `trade` 的授权与 `Setup` 对 `console` 的暴露（同步移除 `catalog.yaml` 的 `console_name: setup` 及 `LocalDispatcher` 注册）。

## 第二部分：总体架构核心决策依据记录

### 1. 为什么删掉内置 `SeaweedFS`（决策 D1 完整记录）

- **原有 4 项作用**：① 通过无删除权限的 `s3.json` 策略与内容哈希键保留同盘历史版本；② 本地 `.csv.gz` 误删或校验失败时同机拉回自愈；③ 作为 `dataapi.go` `/v1/partition` 网页下载的唯一读取源；④ 未配云存储时常驻跑通 S3 代码路径。
- **核心弊端与删除理由**：
  1. **不防硬件故障却制造“已复制”假象**：与归档目录位于同一因子机、同一块盘、同一 `<部署根>` 下（`setup wipe` 一并清空，换机需拷两份），坏盘时两份同丢，但界面显示“已复制”。
  2. **超过 2 倍磁盘空间与双倍写入 I/O**：每分区本地写一份 `.csv.gz` 后又回环 HTTP 写一份进同盘 `SeaweedFS` volume，且重导出旧版本永不清理。
  3. **全仓唯一的第三方重型组件运维负担**：为单机存 `.csv.gz` 引入 `master+volume+filer+s3` 占 8 个端口的 `weed` 进程，牵出外部二进制拉取脚本、密钥派生、systemd 编排、`servicecatalog` 专属 `third_party` 机制与监控豁免特判。
- **替代方案**：异地防坏盘直接配外部腾讯云 COS / Cloudflare R2；未配外部 S3 时退回诚实的**纯本地单份 `.csv.gz` 归档**，后端 `dataapi.go` 与前端 `archive-model.ts` 同步放开无对象存储时的本地文件流式校验下载。

### 2. 为什么拆分 `Collector` 补采来源 `c_source`（决策 D5 完整记录）

- **原阻塞链**：`t_collector_kline_backfill_jobs` 仅允许 `'manual' | 'auto'`，迫使数小时的 `HistorySeed`、`CloseRefetch`、`Catchup` 全部填为 `'manual'`。`system resume` 追赶期间实时采集保持关闭、下游全部停在栅栏前等待，而 `Catchup`（`modules/collector/internal/klinecheck/catchup.go:33-61`）要求整空间 `ActiveJobs == 0` 才提交追赶并判定追平——结果同空间只要有一个慢速 `HistorySeed` 在跑，全系统实时采集与实盘交易就会陪着停摆数小时。
- **定稿方案**：将 `c_source` 正交扩展为 `'manual' | 'auto' | 'seed' | 'close_refetch' | 'catchup'`，`Catchup` 只跟踪 `'catchup'` 作业（补完暂停窗口立即放行全系统恢复实时运行），`AutoScan` 收窄到 `(dataset_id, frequency)` 粒度。

### 3. 全仓单根 `go.mod` 合一与工程护栏（决策 D8 / 6B 完整记录）

- **动机**：消除 26 个子 `go.mod`（含 11 个 `proto/*gen/go.mod`）与 `go.work` 带来的跨模块伪版本同步噪音，模块引用边界继续由 `scripts/check/check-module-boundaries.sh` 静态门禁强制守护。
- **复核识别的 3 条硬护栏（落地必守）**：
  1. **防 SQLite 引擎退版本**：原各子模块 `go.mod` 写的是 `modernc.org/sqlite v1.45.0`，靠 `go.work` 的 `replace` 升到 `v1.49.1`。建根 `go.mod` 时必须直接 `require` 锁定 `modernc.org/sqlite v1.49.1`（`libc v1.72.0`、`memory v1.11.0`）及 `google.golang.org/genproto`。
  2. **保留按模块差异化的 `goom` 编译标志与 CI 分片**：`admin`、`hostagent`、`trade` 单测使用 `goom` 桩拦截，必须带 `-gcflags=all=-l -ldflags=-s=false`，而全仓一刀切加该标志会拖慢 `pebble` 与纯 Go `sqlite` 数倍。`scripts/test/contract/test-go-workspace.sh` 须改为按目录列表分片并仅对这 3 个目录附加 `goom` 标志，纯 Go 环境显式排除 `modules/storage` 的 CGO DuckDB 包。
  3. **同步更新 5 个门禁脚本**：`scripts/ci/check-go-version.sh`、`scripts/test/contract/test-build-factor.sh`、`scripts/test/contract/test-docs-architecture.sh`、`scripts/test/contract/test-go-workspace.sh`、`scripts/test/contract/test-trpc-plugin-config.sh`。
