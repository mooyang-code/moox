# 云节点管理

云节点能力已经从 admin 拆分为独立服务 `moox-cloudnode`，代码位于 `modules/cloudnode`。

admin 只负责：

- 管理台登录态鉴权。
- `/api/admin/cloudnode/*` 网关转发。
- `/api/service/cloudnode/*` 后台服务鉴权和转发。
- 在 `t_service_deployments` 中维护 `moox_cloudnode` 的部署地址。

admin 不再拥有云节点、云账户、云函数代码包、异步 JobItem 或同步 invocation 的业务表和实现。

## 独立服务

| 服务 | 模块 | 默认地址 | 说明 |
| --- | --- | --- | --- |
| `moox-cloudnode` | `modules/cloudnode` | `127.0.0.1:11401` | 云账户、云节点、代码包、异步 JobItem、同步 invocation |
| `moox-admin` | `modules/admin` | `127.0.0.1:11000` | 管理台/后台网关，只转发 cloudnode 请求 |
| `moox-collector` | `modules/collector` | `127.0.0.1:11402` | 采集规则和任务实例，向 cloudnode 提交采集 JobItem |

## 术语边界

```text
task_rule      = 采集规则
task_instance  = 采集任务实例
batch_change   = 云节点控制面批量管理变更
batch_id       = 某次 batch_change 的批次 ID
job_item       = SCF 异步执行待处理原子任务
attempt        = job_item 的一次执行尝试
invocation     = 同步云函数调用
```

`BatchCreateNodes`、`BatchDeleteNodes`、`BatchDeployNodes` 返回的 `batch_id` 只表示这次云节点批量管理变更，不表示采集任务实例，也不进入 SCF 异步执行队列。

## 目标精简模型

后续异步执行模型收敛为 Job / JobItem，而不是继续扩展通用任务平台：

```text
job          = collector 生成的一次采集作业
job_item     = job 拆出的最小可执行单元
job_item_id  = job_item 的唯一 ID，同时作为幂等键
job_type     = CloudRuntime handler 注册键，例如 collect.kline
code_package_id = 目标代码包 ID，用于派发到对应云函数节点
attempt      = job_item 的一次执行尝试
attempt_no   = 执行尝试序号，用于拒绝过期上报
```

执行路径保持简单：

```text
Collector 拆分 JobItem
  -> CloudNode 保存并派发 JobItem
  -> CloudRuntime 按 job_type 找 handler
  -> handler 执行业务并写 Storage
  -> CloudRuntime 回报执行摘要
```

CloudNode 只保存 JobItem 生命周期、attempt、错误和执行摘要。业务数据由业务 handler 写入 Storage。

当前异步执行队列不再包含 `owner_service`、`owner_ref`、`idempotency_key`、`payload_schema_version`、`lease_timeout_ms`、`RenewLease`、`LEASED`、Directive、routing labels 和 `max_inflight`。`job_item_id` 承担幂等语义；`attempt_no` 和服务端内部 `recover_at` 负责崩溃恢复。

`attempt` 表示同一个 JobItem 的某次执行尝试。节点超时未上报时，CloudNode 将当前 attempt 标记为 `LOST`，把 JobItem 放回 `PENDING`。下次派发时 `attempt_no + 1`。旧节点如果迟到上报，CloudNode 通过 `attempt_no` 拒绝旧结果。

列表分页继续使用全仓公共 `common.Page` / `common.PageResult`，不单独定义 `page_size` / `page_token`。

详细计划见 [CloudNode JobItem Runtime Simplification Plan](./superpowers/plans/2026-07-04-cloudnode-job-item-runtime-simplification.md)。

## 代码结构

```text
modules/cloudnode/
  cmd/moox-cloudnode/          独立服务入口
  config/                      app.yaml / trpc_go.yaml
  schema/cloudnode.sql         云节点模块独立 SQLite schema
  internal/bootstrap/          服务装配和 RPC 注册
  internal/rpc/                CloudNodeMgr RPC 入口
  internal/service/            JobItem 派发/回收、代码包业务逻辑
  internal/repository/         云账户、节点、代码包、job_item、invocation 持久化
  internal/providers/tencent-scf/ 腾讯云 SCF provider

```

## 数据表归属

`modules/cloudnode/schema/cloudnode.sql` 拥有：

```text
t_cloud_nodes
t_cloud_accounts
t_cloud_function_packages
t_cloud_job_items
t_cloud_job_item_attempts
t_cloud_invocations
t_cloud_invocation_results
```

这些表不属于 `modules/admin/schema/admin.sql`，也不写入 `data/admin.db`。

部署后默认数据库路径为：

```text
<data-dir>/cloudnode/moox_cloudnode.db
```

## 网关路径

管理台请求：

```text
/api/admin/cloudnode/ListCloudAccounts
/api/admin/cloudnode/GetNodeList
/api/admin/cloudnode/GetPackageList
/api/admin/cloudnode/BatchCreateNodes
/api/admin/cloudnode/BatchDeleteNodes
/api/admin/cloudnode/BatchDeployNodes
```

`BatchCreateNodes`、`BatchDeleteNodes`、`BatchDeployNodes` 是管理面操作，由 `moox-cloudnode` 直接维护
节点 catalog，不进入后台/SCF 的云执行 JobItem 队列。

这三个接口返回：

```text
batch_id
processed_count
message
```

后台/SCF 请求：

```text
/api/service/cloudnode/ReportHeartbeat
/api/service/cloudnode/SubmitJobItems
/api/service/cloudnode/PollJobItems
/api/service/cloudnode/ReportJobItemStatus
```

网关根据 `t_service_deployments` 中的 `moox_cloudnode` active 记录解析目标服务；缺失记录时请求直接失败，不再从 `modules/admin/config/gateway.yaml` 回退。

## 与采集服务的关系

- `moox-collector` 根据采集规则和 dataset subjects 生成任务实例。
- `moox-collector` 调用 `moox-cloudnode` 的 `SubmitJobItems` 提交采集 JobItem。
- SCF runtime 通过 `PollJobItems` 获取 JobItem，执行采集任务。
- SCF runtime 通过 `ReportJobItemStatus` 回报 JobItem 执行状态。
- 采集任务实例状态由 `moox-collector` 的 `ReportTaskStatus` 记录；它和 CloudNode JobItem 状态是两层状态，不要混用。

## 与代码包管理的关系

云函数代码包不再由 admin 内置包管理能力承载。代码包上传、COS 存储、下载 URL、部署关联都属于 `moox-cloudnode` 的 CloudNodeMgr 协议。

详情见 [代码包管理](./代码包管理.md)。
