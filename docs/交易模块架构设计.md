# Trade 交易模块架构设计

Trade 的现役架构只以以下模块内文档为事实源：

- [Trade 通用交易执行内核](../modules/trade/DESIGN.md)
- [Trade 使用与运行说明](../modules/trade/README.md)

本文保留为项目文档导航，不复制另一套架构契约。当前模型的关键术语是
`LogicalAccount`、`LogicalAccountTarget`、`InstrumentTarget.quantity`、
`TargetExecutor`、`OperatorAction` 和 `GetSecretValue`。

设计要点：

- 一个物理账户最多加入一个启用的 LogicalAccount。
- LogicalAccount 可以组合多个同质物理账户，并在执行时动态择优。
- 每条目标都是 FULL 快照；遗漏标的归零，空列表表示全部目标归零。
- 人工下单先暂停整个 LogicalAccount；清仓按物理账户分别完成。
- 订单、Fill、Position 和 Exchange 快照构成交易事实，不维护未使用的本地双式余额
  投影。
- 单进程、SQLite、幂等 ID、账户同步和必要恢复已满足个人量化边界，不引入通用事务
  编排或分布式协调。

Strategy 到 Trade 的契约见
[Strategy 模块架构设计](策略模块架构设计.md)和
[Strategy Python 策略接入手册](策略模块Python策略接入手册.md)。
