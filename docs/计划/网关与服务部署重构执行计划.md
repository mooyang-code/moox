# 网关、服务部署与监控告警重构：执行计划

> 状态：第一版，待编码。
> 依据：[网关、服务部署与监控告警重构：设计](网关与服务部署重构设计.md)（下文简称「设计文档」）。
> 本文只写怎么做：改哪些文件、按什么顺序做、每一步怎么验收、怎么上线。全部决策见设计文档第 1 节。
> 项目尚未上线，不做任何历史兼容，也不保留适配层。

## 1. 范围与原则

**范围**

- Go 模块：
  - 改动：`admin`、`storage`（迁出外部接入）、`collector`、`factor`、`strategy`、`trade`、`cloudnode`、`archive`、
    `monitor`、`cli`、`eventbus`、`hostagent`；
  - 改名：`gateway` 改为 `hostgateway`；
  - 新增：`access`、`egressproxy`。
- 共享包：
  - 新增：`packages/servicecatalog`、`packages/gatewayclient`；
  - 改名：`packages/gatewayproxy` 改为 `packages/gatewayroute`；
  - 调整：`packages/gatewayauth`、`packages/doctor`、`packages/cloudprovider/tencent`。
- 其余：前端 `web/src`；部署相关的 `scripts/deploy`、`scripts/build`、`scripts/lib`、`deploy/caddy`、
  `scripts/test/contract`；`skills/moox`；`docs`。
- 不在范围的内容见设计文档第 5 节。

**原则**

1. 新包先独立完成并配齐测试（阶段 A），然后各模块再切换过去。
2. 每个提交都必须能编译并通过测试。一个模块的协议切换要放在同一个提交里，包括三件事：服务端改用 tRPC、调用方改用
   `gatewayclient`、删除旧配置和旧代码。
3. 全部工作都在 `feature/mooyang` 分支上完成。所有阶段验收通过后，按第 13 节一次性停机切换；在此之前，生产环境不部署
   任何中间版本。
4. 每个阶段结束时，都要跑一遍第 15 节的持续检查。
5. Storage 内部三个角色之间现有的直连调用（DataNode 等内部端口，各自使用角色密钥）保持不变。凡是现在经过网关的调用，
   一律改为经过主机网关。

A6 `gatewayclient` 的要点：
- 接口为 `New(caller, keyFile, opts)` 和 `Options(servicePath)`；
- 目录来源抽象成接口，正式环境取本机网关的 `Directory`，测试时可以注入；
- 目录缓存在内存中并落盘，每 15 秒比对一次版本；
- 目标在本机时走 `127.0.0.1:11002`（明文），目标在其他主机时走 `<主机>:11003`（TLS）；
- 收到「服务不在本机」或连接被拒时，立即刷新目录；只读方法重试一次，写方法不重试。

测试：

- 目录校验的表格测试。以下几种情况都必须报错：端口冲突、未知调用方、白名单引用了未声明的方法、control 组件放到了
  其他主机；
- 编译结果的快照测试：用生产环境三台主机的部署作输入，断言每台主机的路由表、目录和哈希；
- `gatewayclient` 用假目录和假网关测试：本机 / 跨主机选路、TLS 配置、目录变更后的切换、刷新与重试。

验收：`go test ./packages/servicecatalog/... ./packages/gatewayclient/... ./packages/gatewayroute/... ./packages/gatewayauth/... ./packages/doctor/...`
通过；目录校验已加入 `make test-go`。

## 17. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 一次性切换的改动范围大 | 先做阶段 J 的本地全链路验证；生产上按主机分步切换，每一步都验证；保留上一版发布目录和数据库备份；在停机时段内完成 |
| 没有测试环境，部署脚本的问题只能在生产环境暴露 | 用 G12 的渲染快照测试和 G11 的契约测试兜底；按主机分步切换；可以整体回滚 |
| `deploy-moox.sh` 有 6000 多行，改动大 | 按 G10 的条目分步提交，每一步都跑契约测试 |
| 证书过期或信任配置出错，导致整个网络不通（compute-1 这次就是这个原因） | 证书由 MooX 私有 CA 签发，不再依赖 Caddy 自动生成的 CA；Admin 巡检证书到期时间；Monitor 探测每台主机网关，失联超过 2 分钟即告警 |
| 服务目录出错，调用被发往错误的主机 | 目录带版本号；主机网关拒绝不属于本机的服务，并返回明确的错误；客户端收到这类错误后立即刷新目录 |
| control 的主机网关故障，其他主机拉不到快照 | 其他主机继续使用缓存的路由；Monitor 告警；网关控制恢复后自动重新同步 |
| 切换期间 SCF 写入失败 | 切换前先暂停采集；新的外部接入就绪后，才发布 SCF 新版本 |
| JSON 透传与原来的 HTTP 行为不一致，控制台接口出错 | 阶段 J 跑通控制台的全部页面；上线后用 Playwright 对全部页面再检查一遍 |
| 外部接入是明文，可能被窃听 | 只传输行情和因子数据；签名可以防篡改和防重放；密钥类接口不对外部调用方开放 |
| compute-1 或出口代理故障，Binance 标签停止更新 | 标签同步失败会上报并告警，周期规划和 SCF 采集都不受影响；标签成员变化很慢，短时间不更新影响很小 |
