## 2. 交易所接口

| 用途 | 币安 U 本位 | 币安现货 | OKX（现货、永续同一套） |
| --- | --- | --- | --- |
| 资金流水 | `GET /fapi/v1/income`：startTime/endTime/limit≤1000，按时间升序；类型有 REALIZED_PNL、FUNDING_FEE、COMMISSION、TRANSFER、INSURANCE_CLEAR 等，权重 30 | 没有统一流水接口 | `GET /api/v5/account/bills`（近 7 天）、`bills-archive`（近 3 个月）：begin/end/after(billId)/limit≤100，按时间倒序；type 1 划转、2 交易、5 强平、7 利息、8 资金费、9 ADL 等，字段 `balChg`、`fee`、`pnl` |

## 3. 设计

### 3.1 交易所层：资金流水能力

`internal/exchange` 新增统一模型：

```go
type LedgerType string // TRADE、FEE、REALIZED_PNL、FUNDING_FEE、TRANSFER、LIQUIDATION、INTEREST、OTHER

type LedgerEntry struct {
    ID             string         // 交易所流水号（币安 tranId+类型，OKX billId）
    Time           time.Time
    Type           LedgerType
    ExchangeType   string         // 交易所原始类型，便于排查
    Asset          string
    Amount         shared.Decimal // 余额变动，带正负
    ExchangeSymbol string
    TradeID        string
    Info           string
}

type LedgerQuery struct {
    Start, End time.Time
    Limit      int
}

type LedgerPage struct {
    Entries []LedgerEntry // 按时间倒序
    HasMore bool          // 窗口内还有更早的记录没取到
}
```

`internal/execution` 新增可选能力接口，只有支持的适配器实现：

```go
type LedgerSource interface {
    ListLedger(context.Context, exchange.LedgerQuery) (exchange.LedgerPage, error)
}
```

- 币安永续：`/fapi/v1/income`，窗口超过 1000 条时只取最后 1000 条（从后往前翻：以上一页最早时间为 endTime 再查），按时间倒序返回。
- 币安现货：不实现，前端显示“该账户不支持资金流水”。
- OKX：开始时间在 7 天内用 `bills`，更早用 `bills-archive`；用 `after=<上一页最后 billId>` 翻页到 limit 或窗口起点。`instType` 按账户市场类型过滤。
- 模拟盘：用本地成交生成手续费、已实现盈亏两类流水（模拟盘没有资金费和划转）。

**只读、即查即用，不落库。** 流水只用于展示和对账，不参与交易决策；按需查询比定时同步简单，权重也只在有人看时才花。

### 3.2 应用层与接口

- RPC `ListAccountLedger(trading_account_id, start_time, end_time, limit)` 返回 `LedgerEntry` 列表和 `has_more`。
  - 窗口默认近 7 天，最长 90 天；limit 默认 200，最多 1000。
  - 适配器不支持时返回业务错误“该账户不支持资金流水”。
- `GetExecutionCapabilities` 增加 `ledger` 布尔值，前端据此显示或隐藏流水页签。

### 3.3 单账户一键平仓

- RPC `FlattenTradingAccount(action_id, trading_account_id, reason)`。
- 执行账户必须属于某个组合账户：所有交易动作都挂在组合账户下，不在组合里的账户 MooX 本来就不交易。
- 复用组合账户清仓：命令里带上要平的执行账户。
  - 只撤这个账户的单、只平这个账户的仓。
  - 组合账户照样置为暂停，防止执行器马上又把仓位建回来。
  - 请求 JSON 里带上执行账户 ID，幂等键随之不同。
- 同组合只允许一个运行中清仓、锁的短超时、终结与可重试原因的分类，这些规则全部沿用。

### 3.4 前端

- 执行账户页增加“资金流水”页签：时间范围选择、类型筛选、表格（时间、类型、资产、金额、标的、说明），以及“还有更早记录”的提示。
- 组合账户成员列表里，每个成员增加“平仓”按钮，确认后调用 `FlattenTradingAccount`，进度复用现有清仓结果的展示。

## 4. 不做

1. **不接交易所的订单历史、成交历史接口。** 本地已有 MooX 接入后的完整记录；接入之前的记录只有在接入时导入才有意义，以后需要再做。
2. **不接充值、提现、资金划转。** 需要额外权限；我们也不做资金划转。
3. **不用交易所自带的一键平仓（OKX `close-position`）。** 我们的清仓靠自己跟踪子单来对账、判断能否结束；统一走自己的下单路径，两家行为一致。
4. **不新增“一键撤所有单”接口。** 清仓本来就会先撤单，逐单撤能保持本地状态一致。
