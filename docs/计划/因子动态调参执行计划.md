# 因子动态调参执行计划

> 状态：执行计划 v3（2026-10-23，尚未编码；已吸收两轮 Codex 审查，处置见第 15 节）。依据是 2026-10-22～23 与用户的讨论，结论已逐条确认。
> 约束：新项目，不考虑兼容旧数据、旧接口与工作量，一切以模型合理为准。
> 实现后以[因子](../模块/因子.md)、[策略](../模块/策略.md)为准。

## 1. 目标

策略在运行过程中根据行情（以及持仓、盈亏等其他维度）动态调整因子参数：策略算完 T 期后得出 T+1 期的参数，
通过接口提交，因子引擎计算 T+1 期时使用新参数。调整可能每期都发生，参数值无法提前确定。

不采用“因子定义加生效时间的版本表”：每期一个版本会让版本表、`definition_hash` 与策略的指纹校验每期都变化。
改为：**定义只声明参数（类型、范围、默认值），参数值是策略每期提交的控制输入；每一期开算前由 FactorMgr 冻结
该期参数并持久保存冻结记录，计算、重试、补算与回放都只认冻结记录。**

## 2. 设计要点

### 2.1 概念模型

| 概念 | 内容 |
| --- | --- |
| 因子定义 | 分类（元数据）、`params` 声明、`let`、`outputs`；列名全部静态 |
| 策略定义 | 规则 DSL，外加因子声明：用哪些因子定义、成员别名 |
| 策略实例 | 启用时自动生成**私有因子集**，实例就是该集合的参数写入方 |
| 因子集 | 一个源数据集加一个频率、一个标的范围；成员是“因子定义 + 别名”；写入方可以为空（永远用默认值，供研究与浏览） |
| 成员 | 因子集内的业务身份 `(set_id, member_alias)`；周期标记、失败状态、策略绑定都以它为单位 |
| 计算组 | 同一源数据集、同一频率的全部因子集；引擎按计算组一次算完 |
| 参数快照 | 某个成员某一期的全部参数：每个参数一个默认值加按标的覆盖 |
| 冻结记录 | 某个成员某一期最终采用的快照及来源，FactorMgr 持久保存，是唯一事实来源 |
| 结果数据集 | 每个因子集一个：因子值列加实际参数列（冻结记录的投影） |

所有策略一视同仁：从未提交参数的实例全部用默认值，某天开始提交就从下一期起生效，不需要改配置或重新启用。
原先的“共享因子集”取消；不归任何策略的因子结果用没有写入方的因子集表达，模型不变。

### 2.2 因子定义

```yaml
params:
  window: {type: int,   min: 5, max: 120, default: 20}
  k:      {type: float, min: 0, max: 5,   default: 2.0}
let:
  ma: ts_mean(close, window)
outputs:
  boll_up: ma + k * ts_std(close, window)
```

- `params` 只做声明：`type`（`int` / `float`）、`min`、`max`、`default` 必填，`default` 在范围内。
  **取消列表参数与笛卡尔积展开，取消列名模板**（`bias_{window}`）。想同时算多组，在策略里把同一因子加两次，
  用别名区分，各自提交参数。
- 作者不希望被调的值直接写成字面常量，不声明为参数。
- 结构型参数（出现在窗口、位移等编译期参数位置的）由编译器推导，要求 `type: int`。
- **回看按算子的区间推导取最坏情况**，不是简单取各参数的 `max`：每个算子登记“参数区间 → 回看区间”的推导规则。
  窗口类取 `max`；`sma(x, n, m)` 的截断长度取决于 `α = m/n`，最坏情况取 `n.max`、`m.min`；嵌套时逐层累加。
  推导出的最坏回看仍不超过 5000，超过时定义被拒绝。
- **算子的联合约束**（如 `sma` 要求 `m < n`）在两处检查：定义编译时检查默认值组合；FactorMgr 收到快照时
  对默认值与每个覆盖逐一检查，不满足整份拒绝。约束检查由 `factorexpr` 导出，管理端与引擎同一份代码。
- 截面算子（`cs_*`）的函数参数只允许统一值：编译器给参数打上“禁止按标的覆盖”标记，提交带覆盖时拒绝。
- `definition_hash` 覆盖参数声明（名称、类型、范围、默认值、是否禁止覆盖），不覆盖每期取值。
- **分类**：`t_factor_defs` 增加 `c_category_id`，取值来自受管理的分类表（例如动量类、波动类，默认“未分类”）。
  分类是元数据，不进哈希；结果数据集的列元数据带上分类，供 View 与控制台按类浏览。分类只用于查找和挑选，
  不是运行时绑定。

### 2.3 因子集与策略实例

- 策略定义声明因子：

  ```yaml
  factors:
    fast: {factor: boll}
    slow: {factor: boll}
    mom:  {factor: momentum}
  ```

  DSL 规则里按 `fast_boll_up`、`mom_ret` 这样的列名引用（见下面的命名）。
- **启用实例时自动创建私有因子集**：源数据集、频率与标的范围取自实例绑定，成员恰好是声明的因子，写入方是该实例。
  实例停用时集合停用，删除时集合与结果数据集一起清理。手工维护私有集合成员的入口关闭。
- 实例暂停（手动 / 系统 / 自动）**不暂停**它的私有集合：因子照常计算，参数沿用上期，恢复后策略有连续的因子历史
  可读（`bars[-1]` 不会断）。
- 一个私有集合只有一个写入方，可以有多个读取方：别的实例可以只读绑定它的 View，但不能提交参数；
  有读取方时拒绝删除写入方实例。
- 现有约束的变化：
  - `t_factor_sets` 去掉 `(空间, 源数据集, 频率)` 唯一约束，增加 `c_owner_instance_id`（可空）。
  - 集合 ID 不再由源数据集加频率推出，改为生成；结果数据集 ID 由集合 ID 推出（`domain.SetID`、`domain.ResultDatasetID` 改写）。
  - 成员主键改为 `(set_id, member_alias)`，同一定义可以在集合里出现多次。
- 列命名（私有数据集只属于一个集合，不需要策略前缀）：

  | 列 | 规则 | 例子 |
  | --- | --- | --- |
  | 因子值 | `<别名>_<输出名>`；别名与定义 ID 相同时省略前缀 | `fast_boll_up`、`mom_ret` |
  | 实际参数 | `<别名>__<参数名>`，一个成员的全部输出共用 | `fast__window`、`fast__k` |

  列元数据 `origin_id` 记成员别名（不是定义 ID），另带 `factor_id` 与分类；参数列为 `origin=factor_param`。
  集合内列名冲突在创建集合时拒绝。**这些只是写入结果数据集时的外部列名**；计算组程序内部一律用
  `(set_id, member_alias, …)` 作为输入、参数槽与输出的身份，不同集合的同名别名互不冲突（2.5）。
- 私有结果数据集的保留期默认按策略需要设置（View 保留根数加最大回看的余量），磁盘增长可以接受。

### 2.4 参数提交与冻结

```json
{
  "set_id": "...", "member": "fast",
  "period_time": 1761206400000, "based_on_period": 1761206340000,
  "request_id": "...",
  "params": {
    "window": {"default": 20, "overrides": {"BTCUSDT": 10, "ETHUSDT": 30}},
    "k":      {"default": 2.0}
  }
}
```

- 每期提交**完整快照**（所有参数的默认值加覆盖），不提交增量；一次可以提交多个成员。
- **提交与冻结在 FactorMgr 的同一个库里串行化**，这是唯一的截止点：

  ```text
  T 期收盘 → 引擎调用 FactorMgr.FreezeFactorParams(计算组, T)
               FactorMgr 在一个事务里：为组内每个成员选出 period_time = T 的最后一份已接受请求（按库内序号，
               不按消息到达顺序）；没有就沿用该成员上一期的冻结快照；从未有过就用默认值
               → 写冻结记录（成员、期次、完整快照、来源、选中的请求 ID）→ 把这一期标为已冻结
           → 引擎按冻结记录计算 → 写结果（含参数列）与周期标记 → ViewDataReady(T)
    → 策略求值 T：下单，同时求出 T+1 的参数
    → FactorMgr.SubmitFactorParams：校验、落库为“已接受”；该期已冻结则返回 too_late
  ```

  不再经过 EventBus：引擎每期一次 `FreezeFactorParams` 调用（经 Access，毫秒级），提交和冻结的先后由数据库事务决定，
  不存在“请求落库了但事件没到”“冻结了但心跳没更新”的窗口。
- **“已接受”不等于“已生效”**：某期是否用了某份请求，以冻结记录为准（`GetFactorParams` 返回两者）。
- **FactorMgr 不可达时**：引擎在有限时间内重试冻结（默认 5 秒）；仍失败就在本地按沿用规则冻结，持久写入本地
  冻结日志并照常计算，结果标为 `params_source=carried_offline`；FactorMgr 恢复后引擎补报冻结记录，FactorMgr
  以它为准，把该期已接受的请求标为“未生效”。冻结记录始终只有一份，计算从不阻塞在参数上。
- **缺值沿用（`carry_forward`）**：已确认。引擎绝不等待参数到达，否则策略某期被跳过就会卡死整条链。
- 校验（FactorMgr 同步完成，失败整份拒绝）：提交方是集合的写入方；成员存在；参数齐全、类型正确、在范围内；
  结构型参数为整数；联合约束（2.2）满足；禁止覆盖的参数没有覆盖；覆盖里的标的属于集合的标的范围；
  `period_time` 在网格上且该期未冻结。
- 幂等：同一 `request_id` 重复提交返回同一结果；同一期不同 `request_id` 以冻结时库内最后一份为准，全部留审计。
- 写入方抽象为“参数写入身份”，第一期只有策略实例；以后独立的调参服务成为写入方即可走同一接口。

### 2.5 引擎计算

- **按计算组建 lane**：一期内把组内所有启用集合的所有成员合成一个程序计算，再按集合分别写入、分别上报；
  一个集合的成员编译或计算失败只影响它自己。内存窗口按数据源，组内共享一份（与现状一致）。
- **内部身份带集合命名空间**：程序里的参数槽、输出归属为 `(set_id, member_alias, 参数名 / 输出名)`。
  `NewProgram` 的“输出列名在集合内唯一”改为“内部身份唯一”；写入时再映射成各集合的外部列名。
  计算去重（结构 + 参数）与业务身份分开。
- **参数语义：目标期的快照覆盖整个回看区间。** 计算目标期 T 时，整棵表达式里的每个节点（包括嵌套在窗口里的子表达式）
  都用 T 的快照：`ts_mean(close * k, 2)` 在 T 期用 T 的 `k` 计算两根 `close * k` 再求均值，不用历史各期自己的 `k`。
  这等同于“参数一直是这个值”，结果只依赖“窗口数据 + 本期快照”，与之前用过什么参数无关。
- **参数是运行时输入，按序列取值**：编译时参数是参数槽，程序结构只随定义与成员变化，不按期重新编译。
  执行时每个参数槽是一个“每条序列一个值”的向量，在整个计算区间上广播。时序算子支持“每条序列各自的窗口”：
  滚动仍按序列进行，只是窗口长度逐序列取值；沿用现有的点纯实现方式（按绝对周期序号对齐的分块合并），
  结果与分块、并行度无关。字面常量窗口仍走现有内核。
- **补算按参数段计算**：连续若干期快照相同的为一段，一段内参数向量不变，整段按上一条一次算完；
  快照每期都变时退化为每期一段，每段重读回看区间（数据在本地 Pebble 与内存窗口里）。
- **运行时去重**：每期执行前，把“结构相同、本期参数向量摘要相同、有效标的范围相同”的节点合并成一个只算一次。
  - 不依赖截面算子的节点（纯时序、逐元素）与标的范围无关：在组内全部集合标的的并集上算一次，各集合取自己的标的。
  - 依赖截面算子的节点（截面节点及其下游）在各自集合的标的范围内计算，去重键包含标的范围摘要。
  - 大多数策略用默认值、范围相同时，计算量接近只有一个共享集合。
- 回看按 2.2 的最坏情况推导；内存窗口按它申请，参数切换时永远不缺数据。
- 实时写入的提交 ID（内容摘要）纳入每个成员冻结快照的摘要。

### 2.6 冻结记录、参数列与周期标记

- **冻结记录是权威**：FactorMgr 表 `t_factor_param_freezes`（集合、成员、期次、完整快照、来源、选中的请求 ID、冻结时间），
  引擎本地缓存一份。实时计算的重试、重启后的重算、补算、跳过恢复、失效重算都按冻结记录，不从结果列反推，
  所以“默认 20、全部覆盖为 10”和“默认 10”这类快照也能准确区分（对新增标的取值不同）。
- **存储按区间压缩、快照按内容复用**：每成员每期一行在 1m 频率、100 集合 × 11 因子下每天约 158 万行，不可接受。
  - 快照存在按内容哈希去重的 `t_factor_param_snapshots`（不可变）。
  - 冻结记录按区间存：`(集合, 成员, 起始期, 结束期, 快照哈希, 来源)`。沿用、默认值、或连续提交相同快照时
    只延长当前区间的结束期，快照或来源变化时才新开一行。只有每期都改参数的成员才每期一行。
  - 保留期：冻结区间与快照保留到所属结果数据集保留期之外再加一个回看（超出后补算不再可能，没有读取方）；
    请求审计 `t_factor_param_requests` 保留 30 天。由 factor-mgr 定时清理。
  - 引擎本地缓存只保留各成员最近的区间与补算任务所需的区间。
- **集合启用后的每一期都有冻结记录**：冻结发生在开算之前，与这一期最终有没有写出结果行（预热中、缺行、写入失败）无关。
  只有集合启用之前的历史回填没有冻结记录，回填用默认值，并为这些期次写入来源为 `default` 的冻结记录。
- **参数列是投影**：结果行里每个参数列写“这个标的这一期实际用的值”，与因子值同一行、同一次提交，供策略经 View 读取
  （包括 `bars[-1]` 读上期参数）和控制台展示。
- **周期标记以成员为单位**：`FactorPeriodState` 的身份从 `factor_id` 改为 `member_alias`（集合内唯一），
  另带 `factor_id`、`definition_hash`、`params_source`（`requested` / `carried` / `carried_offline` / `default`）、
  `params_digest`。事件校验（`packages/events/validation.go` 的重复检查）、策略就绪检查（`modules/strategy/internal/readiness`）、
  失败标的映射、相邻周期记录全部改按成员索引。`definition_hash` 不随参数变化，`factor_changed` 与 `bars[-1]` 校验照常工作。

### 2.7 补算与回填

- 补算只重写因子列，参数列按冻结记录重写（与原值相同）；补算任务从 FactorMgr 取所需区间的冻结记录（随任务下发或分页读取）。
- 回填负载：每个实例启用都会回填。补算任务按计算组合并：同一计算组、区间重叠的排队回填并成一个任务，
  一次计算写多个集合（与现有“同一集合只建一个回填任务”同理，范围从集合扩到计算组）。

### 2.8 策略侧

- DSL 增加 `factors` 声明（2.3）与参数输出：

  ```yaml
  factor_params:
    fast:
      window:
        default: "clip(round(20 * market_vol_ratio), 5, 120)"   # 标量表达式：本期的统一值
        per_subject: "clip(round(20 * vol_ratio), 5, 120)"      # 可选：逐标的求值，与 default 不同的进入 overrides
      k:
        default: "2"
  ```

  `default` 是标量表达式（可用截面聚合与策略状态）；`per_subject` 可选，按标的逐个求值，结果与 `default`
  不同的标的进入覆盖。没有 `factor_params` 的策略不提交，始终用默认值。
- **参数提交走策略模块的 outbox**：求值结果与“待提交的参数快照（含确定的 `request_id`）”在同一个事务里落库，
  由独立的投递 worker 调用 `SubmitFactorParams`，退避重试到该期冻结为止，记录终态（`accepted` / `too_late` / `rejected`）。
  这样“落库后、提交前”重启也能补送；事件处理不在锁内等待重试。复用 `modules/strategy/internal/outbox` 的投递框架，
  投递目标从 EventBus 扩展为 FactorMgr 接口。
- 观察实例（没有账户）也提交参数：参数影响的是它自己的因子，不涉及交易。
- 结果记录里保存本期产出的参数快照与提交终态；实际是否生效以冻结记录为准，实例页同时展示两者。
- **外显设置**：挂在策略实例上（新表 `t_strategy_display_settings`），存隐藏的列，默认全部展示；
  不进会话快照与哈希，改了立即生效。按因子分类、成员、输出列勾选，参数列跟随因子显示与隐藏。
  只影响控制台展示与默认导出（提供“导出全部字段”），不影响 View 的列和策略能读到的数据。

### 2.9 回放闭环

T+1 的因子依赖 T 的策略输出，**调参策略不能先离线算完因子再跑策略**：

- 复现已发生的历史：补算与重算按冻结记录，不需要重跑策略。
- 研究回放（改了策略再看效果）：必须逐期交替——因子算一期 → 策略求值 → 产出参数 → 下一期。
  回放会话内由回放编排驱动引擎的沙箱计算（不写正式结果数据集、不写正式冻结记录），策略回放从沙箱读因子。
  调参依赖的其他维度（持仓、盈亏）由策略回放的理论账本提供；依赖外部数据时回放不支持，启动时拒绝并说明原因。
- 没有 `factor_params` 的策略回放不变，仍直接读 View 历史。

### 2.10 监控

- 指标：`factor_param_requests_total{result}`（accepted / too_late / rejected）、按来源统计的冻结次数、
  每个成员连续沿用的期数、离线冻结次数、冻结调用耗时、运行时去重命中率、按序列窗口算子耗时。
- 连续沿用超过成员配置的期数（默认 10 期）告警，但继续沿用，不自动回退默认值；出现离线冻结即告警。
- View 数量随实例数增长，Storage 的 View 资源指标纳入监控页。

## 14. 风险与待验证

| 风险 | 应对 |
| --- | --- |
| 运行时去重收益不如预期，实例多时计算量上升 | 阶段 2 基准把关（全默认 100 集合不超过单集合 1.5 倍）；不达标先优化去重粒度再进入阶段 3 |

## 15. Codex 审查处置（第 1 轮）

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 提交成功与冻结没有统一截止点（心跳判断 `too_late`、事件异步） | 采纳：冻结改由 FactorMgr 在同一库内事务完成，去掉 EventBus 与心跳判断（2.4） |
| 2 | 结果参数列不能作为冻结、沿用与补算的权威 | 采纳：新增冻结记录表为唯一事实来源，参数列只是投影（2.6） |
| 3 | 计算组程序缺少集合命名空间 | 采纳：内部身份 `(set_id, member_alias, …)`，写入时再映射列名（2.3、2.5） |
| 4 | 同定义多别名无法通过周期标记与策略就绪链 | 采纳：周期状态、事件校验、就绪检查、失败映射改按成员（2.6、阶段 4、6） |
| 5 | 嵌套表达式的历史子节点用哪期参数未定义 | 采纳：目标期快照覆盖整个回看区间；参数按序列取值、补算按参数段（2.5） |
| 6 | 策略落库后的参数提交没有可恢复投递 | 采纳：结果与待提交快照同事务，经 outbox 投递（2.8） |
| 7 | 跨集合去重遗漏截面标的范围 | 采纳：截面依赖节点的去重键含标的范围，纯时序节点在并集上共享（2.5） |
| 8 | 按参数 `max` 推导回看不适用于 `sma` 等，缺联合约束 | 采纳：算子级区间推导取最坏回看，联合约束在编译与提交时检查（2.2） |

第 2 轮：上述 8 条判定为已解决；新增 1 条“冻结历史缺少容量控制”，采纳：快照按内容复用、冻结按区间压缩、
