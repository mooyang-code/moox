# 因子页面交互改版执行计划

> 执行计划 v3（2026-10-24，尚未编码，已吸收两轮 Codex 审查）。依据与用户逐轮讨论确认的页面示例；只改控制台前端，
> 不改协议与后端。实现后以[因子](../模块/因子.md)与控制台页面为准。

## 1. 背景与目标

因子数量会增长到几百上千个。两个页面在这个规模下都不好用：

- **因子定义页**（`#/factor/definitions`）：只有一张平铺表，靠顶部“分类”下拉筛选，分类的增删改藏在“管理分类”弹窗里。
- **因子结果页**（`#/factor/tasks?tab=results`）：复用通用浏览组件 `ViewBrowse`，每个因子的每个输出列、参数列都铺成表格列，逐列搜索栅格也为每一列各生成一个输入框。几百个因子会生成几千列、几千个输入框。

目标：

1. 定义页参照字段管理（`#/data/fields`）改成“左侧分类树 + 右侧列表”。
2. 结果页把**基础行情**与**因子值**分开：主表只显示行情列和用户钉住的因子列，其余因子值收进“查看全部”弹窗分页浏览。
3. 搜索保持现有的逐列交互，只对因子条件做特殊处理。

## 2. 已确认的交互决策

| 编号 | 决策 |
| --- | --- |
| D1 | 定义页采用字段管理的布局：左侧分类树（显示数量、“+”新建、行内重命名与删除），右侧表格带关键词搜索，点击行打开现有的详情抽屉 |
| D2 | 结果页主表默认只展示基础行情列（数据ID、频率、序列标签、时间、开高低收、成交量、成交额、成交笔数），末尾一列“因子”摘要显示“查看全部 N 个” |
| D3 | 点击“查看全部”打开弹窗，**分页**浏览该行全部因子值。弹窗内可按分类筛选、按关键词搜索，列为“因子 / 输出列 / 参数 / 值”。不用下拉，因为几千项放进下拉也太多 |
| D4 | 行情列的搜索沿用现有逐列栅格（输入框加算子切换，以及查询、K 线、清空按钮），交互不变 |
| D5 | 栅格下新增一行“因子条件”：已加的条件显示成 chip，点击“添加因子条件”在弹窗里选因子输出列（分类列表、搜索、分页），再选算子（`>` `≥` `<` `≤` `=` 区间）并填值 |
| D6 | 多个因子条件之间**只支持“且”**，并与行情列条件一起按“且”组合 |
| D7 | 新增“列设置”：可以隐藏行情列，也可以把指定的因子输出列钉成主表的外显列 |

## 3. 现状与约束（已核对代码）

### 3.1 后端能力已经够用，不改协议

- **成员清单自带列名**：结果页从 `FactorSetInfo.members` 就能拿到每个成员的 `member_alias`、`factor`（含当前 `category_id`）、`output_columns`、`param_columns`。因子目录以它为唯一依据。原因有两个：
  - 移除成员后，结果列仍保留在视图里（`RemoveFactorFromSet` 的注释写明 result columns are kept）。
  - 修改分类只更新定义；结果列属性里的 `category_id` 要等 reconcile 才会更新，可能是旧值。
- **视图列的来源类型不能用来区分因子列**：Storage 把行情、因子输出、参数列都转成 `COLUMN_ORIGIN_TYPE_DATASET_COLUMN`（`factor_result_view.go`）。视图里除了开高低收量，还复制了源数据集的其他业务列，例如 `request_id`、`quality_status`。
- **列投影**：`queryTimeSeriesRows` 的 `column_names` 只能放业务列：
  - 不能放系统列：DuckDB 遇到系统列直接报错 `is not projected`；四个系统键（subject_id、freq、series_tag、data_time）本来就随 `row.key` 返回。
  - 不能传空数组：空投影表示返回全部业务列。
  - 前端现在投影的是全部视图列。缩窄投影能减少 DuckDB 读取量、网络传输和前端处理。
- **数值比较**：DuckDB 与 Bleve 视图索引都支持 `FILTER_OP_GT/GTE/LT/LTE`，因子列都是 double。前端 `buildViewFilterExprs` 只产出单个 AND 组，正好满足 D6。
- **单行查询**：完整 selector（space、dataset、subject_id、freq，加上**显式的** `series_tag`）加 `time_range` 的 `[t, t+1ms)` 即可精确取到一行：
  - DuckDB 的结束时间是开区间（`data_time < end`）。
  - 不传 `series_tag` 与传空字符串的含义不同：默认序列必须显式传 `""`。
- **统计查询**：`total_mode` 不传时会触发全表计数，弹窗与单行查询必须传 `"NONE"`。
- **分类**：`listFactorCategories`、`upsertFactorCategory`、`deleteFactorCategory`、`setFactorCategory` 都已存在。
  - 分类只有一层，`uncategorized` 不可删除。
  - **后端只允许删除空分类**（`store/categories.go` 的 `DeleteCategory`）。
  - Upsert 会覆盖 `sort_order`。

## 4. 方案

### 4.1 因子定义页

布局与字段管理一致：顶部工具栏，下方左右两栏；窄屏时分类树收进抽屉（字段页的“字段组”按钮同样做法）。

- **工具栏**：关键词搜索（因子 ID 或名称）、类型筛选（全部 / 时序 / 横截面）、使用情况筛选（全部 / 使用中 / 未使用），以及现有的“新建因子”入口。原来的“分类”下拉和“管理分类”按钮删除，改由左侧分类树承担。
- **左侧分类树**：新组件 `factor-category-tree.vue`。
  - **列表**：第一行是“全部因子 N”，然后按 `sort_order` 列出各分类及其数量，“未分类”固定放最后。
  - **数量**：先按关键词、类型、使用情况过滤全量定义，再统计各分类的数量；选中的分类和分页只作用于右侧表格。字段页的数量来自分组接口、不随搜索变化，这里有意不同，因为定义是全量加载在前端的，联动计数更直观。
  - **新建**：标题右侧的“+”弹出内联表单，填分类 ID 与名称。
  - **重命名**：悬停分类时出现，提交时带上原 `sort_order`，避免排序被覆盖。
  - **删除**：“未分类”不可删除。删除非空分类时：
    1. 确认框说明“其中 N 个因子将归入未分类”。
    2. 用户确认后，从**未经筛选的全量定义**中找出该分类的全部定义，逐个调用 `setFactorCategory(id, "uncategorized")`。
    3. 全部成功后再调用 `deleteFactorCategory`。

    中途任一调用失败就停止、提示失败的因子并刷新列表。删除的如果是当前选中的分类，就回到“全部”。
  - **URL**：选中的分类写进 `?category=`，配合 `reuseOnQuery` 不会重建页面，关键词和其他筛选保持。
- **右侧表格**：保留现有全部列与行为，只去掉分类筛选：
  - 列：因子ID、类型、分类、可调参数、输入列、输出列、回看周期、使用情况。使用情况 chip 可以跳转到任务。
  - 操作：编辑、删除，被使用时禁用并显示原因。
  - 保留现有 20 条一页的分页。
  - 新增点击整行打开 `factor-detail-drawer.vue`，操作按钮和使用情况 chip 要阻止冒泡。
- **不复用 `FieldGroupTree` 的理由**：它服务的是带父子关系的字段组，接口按 `FieldGroup` 定义。因子分类只有一层，规则也不同（未分类固定、不可删、删除时要先迁走因子）。写一个约 150 行的扁平树，比给字段树加模式开关清楚，样式复用字段页的 SCSS 变量。

### 4.2 因子结果页

#### 有效范围与列的划分

页面准备阶段依次完成以下几步，全部成功后才发起首次查询：

1. 视图列元数据（分页取全）。
2. 分类清单。
3. 当前因子集的成员清单（来自 store）。
4. 策略外显设置（仅策略私有因子集）。

然后算出一份**有效范围**。目录、条件、钉住列、`?fc=` 都只认这份有效范围：

- **策略隐藏列**：按外显设置的三种规则逐列算出，被隐藏的列不进有效范围。
  - **分类**：按成员**当前定义**的 `factor.category_id` 判断，作用于该成员的全部输出列和参数列。现有 `hiddenColumnNames` 读的是列属性里的分类，可能是旧值，所以结果页不直接用它，在 `factor-scope.ts` 里另写。
  - **成员**：按 `member_alias`。
  - **单列**：按列名，既可能是行情列，也可能是某个输出列或参数列。
- **因子目录**：遍历当前成员清单，每个成员取 `output_columns` 与 `param_columns` 中“在视图里存在且未被策略隐藏”的列。分类取成员当前定义的 `factor.category_id`，分类名称取自分类清单。以成员别名为单位，因为同一个定义可以用不同别名出现多次。
- **行情列**：视图业务列中，不带 `column_kind` 属性（排除已移除成员留在视图里的残留因子列）、也未被策略隐藏的列，再分成两组：
  - **基础行情**：D2 清单与实际列的交集。清单写成常量：`open`、`high`、`low`、`close`、`volume`、`quote_volume`、`trade_num`（crypto），以及 `amount`（A 股、指数）。默认显示。
  - **其他源字段**：例如 `request_id`、`quality_status`。默认不显示，可在列设置里勾选显示。
- **系统键**：数据ID、频率、序列标签、时间。从 `row.key` 渲染，不进投影。频率、序列标签可以在列设置里隐藏，数据ID与时间不可隐藏。

“查看全部 N 个”的 N 是有效范围内的输出列数。纯函数放在新文件 `web/src/views/factor/results/factor-scope.ts`，便于单测。

#### 主表

- **显示与投影分开**：
  - 显示列 = 未隐藏的系统键 + 显示中的行情列 + 钉住的因子列（列头显示输出列名，悬停显示成员别名与参数列名）+ 末尾“因子”摘要列。
  - 请求投影 `column_names` = 显示中的业务列（行情列 + 钉住列）。投影为空时（用户隐藏了全部行情列，也没有钉住列），投影 `close`（不存在就取第一个基础行情列）但不显示，以免空投影读回全部列。
- **条件列不自动显示，也不投影**：过滤在服务端完成。用户想看条件列的值，可以把它钉住，或打开弹窗查看。
- **摘要列**：显示“查看全部 N 个”，N 每行相同。点击时打开该行的因子值弹窗。
- **K 线弹窗**：保留它自己的 OHLC 投影，不受列设置影响。

#### 搜索

- **逐列栅格**：只为“显示中的行情列 + 系统键”生成，交互与现在完全一致（D4）。
- **“因子条件”行**（D5、D6），放在栅格下：
  - **chip**：每个条件是一个 chip，例如“`rsi` > 70”或“`boll_pctb` 区间 0～1”，可以点击修改或关闭。
  - **添加**：末尾“添加因子条件”打开选择弹窗。
    - 左侧是分类列表（含数量），右侧是可搜索、20 条一页的输出列列表。
    - 选中一个输出列后，在下方选算子（`>` `≥` `<` `≤` `=` 区间）并填数值。
    - 数值必须是有限数字，用 `Number()` 整串校验；区间要求下限不大于上限。校验不通过不能确定。
  - **组合方式**：行内注明“多个条件同时满足”，不提供“或”的入口。
  - **查询**：因子条件以 `ViewFilterState` 传给 `ViewBrowse`，并明确带上 `valueType: FIELD_VALUE_TYPE_DOUBLE`（因子列不在栅格选项里，不能靠选项反推类型），与栅格条件合成单个 AND 组。
  - **触发**：条件变化后回到第一页重新查询。
  - **清空**：“清空”同时清掉因子条件。
- **因子条件随 URL 保存**（`?fc=`，编码列名、算子、值）：
  - 刷新或分享链接后条件仍在。
  - 解码后逐条校验：列在有效范围内、算子合法、数值有限、区间有序。不合格的条件丢弃，并提示“已忽略 N 个失效条件”。
  - 切换因子集时清除 `fc`，`use-factor-scope` 会保留其他 query，这里要显式去掉它。
  - 结果页在任务页里被 `keep-alive` 缓存，失活期间不处理 `?set=`。加了 `reuseOnQuery` 后组件不再重建，所以 `use-factor-scope` 要在 `onActivated` 里按 URL 重新同步因子集，再重算有效范围、恢复条件。否则“看过 A 的结果 → 回到任务 → 打开 B 的详情 → 查看结果”会出现 URL 是 B、页面仍显示 A 的情况。
  - 行情列条件保持现状，不进 URL；配合 `reuseOnQuery`，改写 `fc` 不会重建页面，也不会清掉行情条件。

#### 因子值弹窗（D3）

- **标题**：该行的“数据ID · 频率 · 序列标签 · 时间”。
- **布局**：左侧是分类筛选，右上是关键词搜索（按输出列名、成员别名、因子 ID 匹配），下方是**以输出项为单位、20 条一页**的表格。一个成员最多可以有 64 个输出，所以分页按输出项算，不按成员算。
- **列**：
  - 因子：成员别名；与 `factor_id` 不同时附注。
  - 输出列。
  - 参数：所属成员参数列的取值，例如 `window=20, k=2`。
  - 值：保留 6 位有效数字，空值显示“-”。
- **取数**：
  - 每翻一页（或改筛选），按该行完整的 `TimeSeriesKey` 单独查一次。
  - 投影 = 当前页的 20 个输出列 + 这些输出所属成员的参数列（去重）。
  - 请求参数：`page.size = 1`、`total_mode: "NONE"`。
  - 翻页时显示加载状态，用请求序号丢弃过期响应。
  - 同一个多输出成员跨页时，参数列在每页重复查询，不缓存，保持简单。

#### 列设置（D7）

- **入口**：工具栏的“列设置”按钮，打开抽屉，分三块：
  - **系统键**：可隐藏频率、序列标签；数据ID、时间不可隐藏。
  - **行情列**：基础行情默认勾选，其他源字段默认不勾选，都可以切换。
  - **外显因子列**：已钉住的列表，可以拖动排序或移除。下方“添加”复用因子条件的选择弹窗，只选输出列、不选算子。上限 30 列，超出时提示改用弹窗查看。
- **保存**：按因子集分别保存在 `localStorage`，键为 `moox.factor-results.columns.<set_id>`。单用户系统，不存后端。
- **读取时校验**：
  - 结构不对或 JSON 无效时，回退到默认（基础行情、无钉住列）。
  - 去掉重复项，超过 30 列的截断。
  - 不可隐藏的字段强制显示。
  - 不在有效范围内的钉住列和行情列剔除。剔除只在元数据成功加载之后做，加载失败时不清理已保存的设置。
- **异常**：读写都包在 try/catch 里。

### 4.3 `ViewBrowse` 的接入方式

不复制组件，也不把“因子”概念写进通用组件，只增加几个通用扩展点。未传时行为与现在完全相同：

| 扩展点 | 类型 | 作用 |
| --- | --- | --- |
| `queryReady` | `boolean`，默认 `true` | 为 `false` 时只加载元数据、不发查询；变成 `true` 后才首查 |
| `displayColumns` | `{ system: string[]; business: string[] }` | 显示的系统键与业务列及其顺序；未传时沿用现有逻辑 |
| `projectColumns` | `string[]` | 行查询的 `column_names`，只含业务列；未传时沿用现有的全部视图列 |
| `searchColumns` | `string[]` | 逐列搜索栅格只为这些列生成，系统键始终保留；未传时为全部列 |
| `extraFilters` | `ViewFilterState[]`（必须带 `valueType`） | 追加到查询条件，与栅格条件按 AND 组合；变化时回到第一页重查 |
| 插槽 `query-extra` | — | 栅格下方，放“因子条件”行 |
| 插槽 `toolbar-extra` | — | 刷新按钮旁，放“列设置” |
| 插槽 `row-extra`，参数 `{ key: TimeSeriesKey, values }` | — | 表格最后一列，放“因子”摘要；`key` 是原始的完整行键，含空间、数据集、标的、频率、序列标签和原始时间 |
| 事件 `cleared` | — | 点击“清空”时先发出事件，父组件同步清掉 `extraFilters`，`nextTick` 后再按新的 props 查询 |

其他约定：

- `displayColumns`、`projectColumns` 变化时重查当前页。
- `buildViewFilterExprs` 对 `extraFilters` 直接使用其自带的 `valueType`。
- 现有 `hiddenColumns` prop 由 `displayColumns` 与 `projectColumns` 取代。结果页是它唯一的调用方，一并删除。
- 分页取全的工具函数 `listAllViewColumns` 放在 `web/src/api/storage/metadata.ts`，供 `ViewBrowse`、结果页和策略外显设置页共用。

### 阶段 1：通用能力（ViewBrowse、工具函数、路由）
