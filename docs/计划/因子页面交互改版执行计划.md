# 因子页面交互改版执行计划

> 执行计划 v1（2026-10-24，尚未编码）。依据与用户逐轮讨论确认的页面示例；只改控制台前端，不改协议与后端。
> 实现后以[因子](../模块/因子.md)与控制台页面为准。

## 1. 背景与目标

因子数量会增长到几百上千个。两个页面在这个规模下都不好用：

- **因子定义页**（`#/factor/definitions`）：只有一张平铺表，靠顶部“分类”下拉筛选，分类的增删改藏在“管理分类”弹窗里。
- **因子结果页**（`#/factor/tasks?tab=results`）：复用通用数据浏览组件 `ViewBrowse`，每个因子的每个输出列、参数列都铺成表格列，逐列搜索栅格也为每一列各生成一个输入框。几百个因子会生成几千列、几千个输入框。

目标：

1. 定义页参照字段管理（`#/data/fields`）改成“左侧分类树 + 右侧列表”。
2. 结果页把**基础行情**与**因子值**分开：主表只显示行情列和用户钉住的因子列，其余因子值收进“查看全部”弹窗分页浏览。
3. 搜索保持现有的逐列交互，只对因子条件做特殊处理。

## 2. 已确认的交互决策

| 编号 | 决策 |
| --- | --- |
| D1 | 定义页采用字段管理的布局：左侧分类树（显示数量、“+”新建、行内重命名与删除），右侧表格带关键词搜索，点击行打开现有的详情抽屉 |
| D2 | 结果页主表默认只展示基础行情列（数据ID、频率、序列标签、时间、开高低收、成交量、成交额、成交笔数），末尾一列“因子”摘要显示“查看全部 N 个” |
| D3 | 点击“查看全部”打开弹窗，**分页**浏览该行全部因子值。弹窗内可按分类筛选、按关键词搜索，列为“因子 / 输出列 / 参数 / 值”。不用下拉，因为几千项放进下拉也太多 |
| D4 | 行情列的搜索沿用现有逐列栅格（输入框加算子切换，以及查询、K 线、清空按钮），交互不变 |
| D5 | 栅格下新增一行“因子条件”：已加的条件显示成 chip，点击“添加因子条件”在弹窗里选因子输出列（分类列表、搜索、分页），再选算子（`>` `≥` `<` `≤` `=` 区间）并填值 |
| D6 | 多个因子条件之间**只支持“且”**，并与行情列条件一起按“且”组合 |
| D7 | 新增“列设置”：可以隐藏行情列，也可以把指定的因子输出列钉成主表的外显列 |

## 3. 现状与约束（已核对代码）

### 3.1 后端能力已经够用，不改协议

- **结果列自带因子属性**：Factor 在 `modules/factor/internal/catalog/service.go` 的 `appendFactorColumns` 为每个结果列写入 `member_alias`、`factor_id`、`category_id`、`column_kind`（`output` 或 `param`），以及 `output_name` 或 `param_name`。前端靠这些属性就能区分行情列、输出列、参数列，并按成员分组。
- **列投影**：`queryTimeSeriesRows` 支持 `column_names`。不传时返回全部列。另外，Pebble 最新页的行数会随投影列数变少（`maxLatestPageValues / len(column_names)`），所以主表必须显式投影。
- **数值比较**：DuckDB 与 Bleve 视图索引都支持 `FILTER_OP_GT/GTE/LT/LTE`，因子列都是 double。`filterLogical` 在未指定时按 AND 组合，前端 `buildViewFilterExprs` 也只产出单个 AND 组，正好满足 D6。
- **单行查询**：用 selector（`subject_id`、`freq`、`series_tag`）加 `time_range` 的 `[t, t+1ms)` 即可精确取到一行；DuckDB 的结束时间是开区间（`data_time < end`）。
- **分类**：`listFactorCategories`、`upsertFactorCategory`、`deleteFactorCategory`、`setFactorCategory` 都已存在。分类只有一层，`uncategorized` 不可删除。

### 3.2 前端现状与要处理的点

| 位置 | 现状 | 本次处理 |
| --- | --- | --- |
| `web/src/views/data/view-browse/index.vue`（1869 行） | 通用浏览组件，另一个使用方是采集结果页（`views/collector/task-results`）；`listViewColumns` 只取 1 页、每页 1000 列（第 1094 行） | 改成分页取全；增加几个通用扩展点（见 4.3），采集结果页的行为不变 |
| `view-browse-utils.ts` | `ViewFilterOperator` 没有 gt、gte、lt、lte；`buildViewFilterFieldOptions` 为全部视图列生成搜索项 | 补齐这四个算子；可以只为指定的列生成搜索项 |
| `web/src/views/factor/results/index.vue` | 嵌入 `ViewBrowse`；`loadHiddenColumns` 同样只取 1000 列，并按策略外显设置算出要隐藏的列 | 改用分页取全的列元数据；在页内组装行情列、因子目录与列设置，传给 `ViewBrowse` |
| `web/src/views/factor/definitions/index.vue` | 顶部类型、分类、使用情况筛选，加“管理分类”弹窗（`category-manager.vue`） | 改成左侧分类树；分类增删改并进树，删除 `category-manager.vue` |

## 4. 方案

### 4.1 因子定义页

布局与字段管理一致：顶部工具栏，下方左右两栏；窄屏时分类树收进抽屉（字段页的“字段组”按钮同样做法）。

- **工具栏**：关键词搜索（因子 ID 或名称）、类型筛选（内置 / 表达式）、使用情况筛选（全部 / 使用中 / 未使用），以及“新建因子”按钮。原来的“分类”下拉删除，改由左侧分类树决定。
- **左侧分类树**：新组件 `factor-category-tree.vue`。
  - 第一行是“全部因子 N”，然后按 `sort_order` 列出各分类及其数量；“未分类”固定放最后。
  - 标题右侧的“+”新建分类，弹出内联表单，填分类 ID 与名称。
  - 悬停某个分类时显示“重命名 / 删除”。“未分类”不可删除，非空分类删除前提示其中的因子会归入未分类，删除前先确认。
  - 选中的分类写进 URL 的 `?category=`，刷新后保持。
  - 数量按“当前关键词、类型、使用情况筛选之后”的结果统计，与字段页一致。
- **右侧表格**：保留现有列（因子ID、类型、分类、可调参数、输入列、操作），加 20 条一页的分页；点击行打开现有的 `factor-detail-drawer.vue`。
- **不复用 `FieldGroupTree` 的理由**：它服务的是带父子关系的字段组，接口按 `FieldGroup` 定义。因子分类只有一层，规则也不同（未分类固定、不可删）。写一个约 120 行的扁平树，比给字段树加模式开关清楚，样式复用字段页的 SCSS 变量。

### 4.2 因子结果页

#### 列的划分

页面加载视图列元数据（分页取全）后，按属性把列分成三类：

| 类别 | 判定 | 用途 |
| --- | --- | --- |
| 行情列 | 系统列（subject_id、freq、series_tag、data_time），以及 `origin_type` 不是 factor 的列 | 主表固定列，参与逐列搜索 |
| 输出列 | `column_kind = output` | 因子目录、因子条件、钉住列、弹窗的“值” |
| 参数列 | `column_kind = param` | 只在弹窗的“参数”列中显示，例如 `window=20` |

“因子目录”以成员别名 `member_alias` 为单位（同一个定义可以用不同别名在集合里出现多次），每个成员包含：分类（`category_id`，名称取自 `listFactorCategories`）、`factor_id`、全部输出列和参数列。纯函数放在新文件 `web/src/views/factor/results/factor-columns.ts`，便于单测。

#### 与策略外显设置的关系

策略实例私有因子集已有“外显设置”（`getStrategyDisplaySettings` 加 `hiddenColumnNames`，按分类、成员、列隐藏）。本次**沿用它作为可见范围的上限**：被策略隐藏的成员，既不进因子目录，也不进弹窗，也不能被钉住或用作条件。新的列设置只在这个范围内调整主表外显，两者不重复。

#### 主表

- 查询投影 `column_names` = 未被隐藏的行情列 + 钉住的输出列 + 正在作为条件的输出列（条件列需要出现在结果里，方便核对）。
- 列顺序：行情列 → 钉住的因子列（列头显示“输出列名”，悬停显示成员与参数）→ 末尾“因子”摘要列。
- 摘要列显示“查看全部 N 个”，N 是可见范围内的输出列数。N 从列元数据统计，与该行的值无关，所以每一行都相同；点击时打开该行的因子值弹窗。

#### 搜索

- 逐列栅格只为行情列生成，交互与现在完全一致（D4）。
- 栅格下新增“因子条件”行（D5、D6）：
  - 每个条件是一个 chip，例如“`rsi` > 70”或“`boll_pctb` 区间 0～1”，可以点击修改或关闭。
  - 末尾“添加因子条件”打开选择弹窗：左侧分类列表（含数量），右侧可搜索、20 条一页的输出列列表；选中一个输出列后，下方选算子（`>` `≥` `<` `≤` `=` 区间）并填数值，确定后加入。
  - 行内注明“多个条件同时满足”，没有“或”的入口。
  - 查询时，因子条件和行情列条件一起交给 `buildViewFilterExprs`，组成单个 AND 组。
  - “清空”按钮同时清掉因子条件。
- 因子条件随 URL 保存（`?fc=` 编码列名、算子、值），刷新或分享链接后条件仍在；行情列条件维持现状不进 URL。

#### 因子值弹窗（D3）

- 标题显示该行的“数据ID · 频率 · 时间”。弹窗内左侧是分类筛选，右上是关键词搜索（按输出列名、成员别名、因子 ID 匹配），下方是 20 条一页的表格。
- 列：因子（成员别名，与 `factor_id` 不同时附注）、输出列、参数（同一成员的参数列取值，例如 `window=20, k=2`）、值（保留 6 位有效数字；为空时显示“-”）。
- 取数：分页在前端按因子目录切片，**每翻一页单独查一次**这一行（单行查询见 3.1），投影只含当前页成员的输出列和参数列。每页最多约 20 个成员，投影列数可控；翻页时显示加载状态，按请求序号丢弃过期响应。

#### 列设置（D7）

- 工具栏加“列设置”按钮，打开抽屉，分两块：
  - **行情列**：复选框列表，可以隐藏；数据ID与时间不可隐藏。
  - **外显因子列**：已钉住的列表，可以拖动排序或移除；下方“添加”复用因子条件的选择弹窗（只选输出列，不选算子）。上限 30 列，超出时提示改用弹窗查看。
- 设置按因子集分别保存在 `localStorage`（键 `moox.factor-results.columns.<set_id>`），读写都包在 try/catch 里，失败时退回默认（全部行情列、无钉住列）。单用户系统，不进后端。
- 钉住的列如果已不在可见范围（成员被移除或被策略隐藏），加载时静默剔除。

### 4.3 `ViewBrowse` 的接入方式

不复制组件，也不把“因子”概念写进通用组件，只增加几个通用扩展点，未传时行为与现在完全相同：

| 扩展点 | 类型 | 作用 |
| --- | --- | --- |
| `searchColumns` | `string[]` | 逐列搜索栅格只为这些列生成；未传时为全部列 |
| `projectColumns` | `string[]` | 行查询的 `column_names` 与表格列顺序；未传时沿用现有逻辑 |
| `extraFilters` | `ViewFilterState[]` | 追加到查询条件里，与栅格条件一起按 AND 组合 |
| 插槽 `query-extra` | — | 放在搜索栅格下方，用来放“因子条件”行 |
| 插槽 `toolbar-extra` | — | 放在刷新按钮旁，用来放“列设置” |
| 插槽 `row-extra`（参数为该行的 key 与 values） | — | 作为表格最后一列，用来放“因子”摘要 |
| 事件 `cleared` | — | 点击“清空”时通知外层清掉因子条件 |

现有 `hiddenColumns` prop 由 `projectColumns` 取代（结果页是它唯一的调用方），一并删除。列元数据分页取全的工具函数 `listAllViewColumns` 放在 `web/src/api/storage/metadata.ts`，`ViewBrowse` 与结果页共用。
