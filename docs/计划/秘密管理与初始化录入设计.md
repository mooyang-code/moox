# 秘密管理与初始化录入：设计

> 状态：设计稿第二版，决策已确认，尚未编码。第一版（提交 `6c74ead1`）经 Codex 审查提出 16 条问题，其中两条 P0 说明原流程接不上现有初始化实现；
> 本版按「个人量化项目」收敛：单用户、安全强度对标 SSH 私钥、不做本地密钥服务和加密暂存。各条审查意见的处理见第 12 节。
> 本文只写「做成什么样、为什么」；改哪些文件、按什么顺序、怎么验收，另写执行计划。项目尚未上线，不做任何历史兼容。
> 相关：[部署与运维](../部署与运维.md)（原生初始化顺序）、[管理后台](../模块/管理后台.md)、[命令行工具](../模块/命令行工具.md)。

## 1. 问题与目标

`moox.toml` 是用户的唯一配置入口，体验简单，但同时含有明文的服务器密码、腾讯云密钥和管理员密码。后果：

- 提交 git、截图、分享、交给 Agent 阅读时会泄露；
- 在 Agent 里初始化时，用户填的任何值都会进入对话上下文和转录；
- skill 只能规定「Agent 不得读取 `moox.toml`」，连拓扑和策略配置都看不了，排障很别扭。

这是个人使用的量化系统：**一个人、一套系统、一个超级管理员**，不追求防御同一台电脑上的恶意进程。目标：

1. 体验不退步：仍然「配置一次」，初始化后日常命令不再要密码；
2. `moox.toml` 不含秘密，可以提交、分享，Agent 可以随便读；
3. 在 Agent 里初始化时，秘密**不经过模型**；
4. 支持 macOS、Linux、Windows；
5. 保护强度和 `~/.ssh/id_ed25519` 同级：放在用户目录、权限限定本人，不额外加口令、密钥服务或钥匙串。

## 2. 已确认的决策

| # | 决策 |
| --- | --- |
| 1 | 单用户。没有多操作员，不做邀请、独立身份与审计归属；操作员就是管理员 |
| 2 | `moox.toml` 不再含任何秘密值，旧字段直接删除，写了就报错并指向录入流程，不做兼容 |
| 3 | 秘密不经过模型：非秘密配置用 Agent 表单（A2UI）或逐项问答收集；秘密由 `moox-cli` 起的本机一次性页面收集，Agent 只拿到状态 |
| 4 | 不做口令加密暂存、本地密钥服务、系统钥匙串。秘密放在操作员目录（`~/.config/moox/`）下的 0600 文件里，和 SSH 私钥同级 |
| 5 | SSH 只用密钥，**不保存任何 SSH 密码**：录入时用密码装一次公钥，随即丢弃。全系统只有**一把**密钥，操作员和 Admin 共用 |
| 6 | 云凭据、管理员密码在 `setup apply` 导入 Admin，读回确认后从本机删除；不做云账号类型校验 |
| 7 | 初始化第一步让用户选**安装方式**：预编译包，或从源码编译（需要用户提供 Linux 编译机，凭据同样走录入页） |
| 8 | 必须支持 Windows |
| 9 | 值只落在三处：录入页的用户输入、操作员目录里的 0600 文件、Admin 的加密存储；不进入对话、日志、命令行参数和 `moox.toml` |

## 3. 数据分流

```
                ┌─────────────────────────────────────────────┐
 用户 ──表单──▶ │ Agent（A2UI/问答）：安装方式、主机地址、地域、    │ ─▶ moox.toml（无秘密，可提交，Agent 可读）
                │ 组件放置、保留期、因子                          │
                └─────────────────────────────────────────────┘

                ┌──────────────────────────────────┐
 用户 ─浏览器─▶ │ moox-cli 本机一次性录入页           │── 状态（set/key_installed/…）──▶ Agent
                │ 127.0.0.1，随机端口，一次性令牌       │
                └────┬─────────────────────────────┘
                     │ 秘密值，不经过 Agent
                     ├─ SSH 密码 ──▶ 装公钥后丢弃，不落盘
                     ├─ SSH 私钥（新生成）──▶ ~/.config/moox/ssh/id_ed25519
                     └─ 云凭据 / 管理员密码 / webhook ──▶ ~/.config/moox/secrets.toml（0600）
                                                          │ setup apply
                                                          ▼
                                            Admin 加密存储（长期）──▶ 本机条目删除
```

| 数据 | 位置 | 生命周期 | Agent 能读吗 |
| --- | --- | --- | --- |
| 拓扑、策略、因子、安装方式 | `moox.toml` | 长期 | 能 |
| SSH 密码 | 内存，仅录入请求期间 | 装公钥后丢弃 | 不能，也看不到 |
| SSH 私钥（唯一一把） | `~/.config/moox/ssh/id_ed25519`；导入 Admin 的 `t_ssh_host`（`AuthType=cert`，加密） | 长期，删 `authorized_keys` 里那一行即吊销 | 不能 |
| 云凭据、管理员密码 | `secrets.toml`（暂存） | 导入 Admin 并读回确认后删除 | 不能 |
| webhook | `secrets.toml` | control 阶段读取并注入 Monitor 后删除 | 不能 |
| 云凭据（长期） | Admin `t_secrets` | 长期；CLI 需要时向 Admin 现取 | 不能 |
| 操作员网关签名密钥 | `~/.config/moox/` 下既有文件，**保持现状** | 长期 | 不能 |

「操作员目录」`~/.config/moox/`（Windows 为 `%USERPROFILE%\.config\moox\`）已经放着 `known_hosts` 和 `gateway-client.yaml`，现在再放 SSH 密钥和 `secrets.toml`。
**换机器就是复制这个目录。**

## 4. 安装方式与所需秘密

`moox.toml` 新增：

```toml
[install]
mode = "release"        # release：预编译包；source：从源码编译，需要 [hosts.compile]
```

`secrets intake --need` 由 `moox.toml` 推出，用户不必手写：

| 条件 | 需要录入 |
| --- | --- |
| 总是 | 每台部署主机一项 `ssh:<id>`；`admin` |
| 使用云能力（配了 `scf_plan` 等） | `tencent` |
| 配了通知渠道 | `webhook` |
| `install.mode = "source"` | 另加 `ssh:compile`（编译机，和其他主机一样装公钥，不保存密码） |

`release` 模式依赖已发布的 Linux 预编译制品（含需要 CGO 的 Storage）；`source` 模式沿用现有 `setup build-linux`。两种模式的分发细节不属于本文，列入执行计划。
装不了公钥的主机（例如受限的编译机）：录入页显示公钥，由用户自己追加到该主机的 `authorized_keys`，CLI 只验证能否登录；仍然不保存密码。

## 5. 用户输入

### 5.1 两条通道

- **非秘密字段**（含安装方式）：skill 随附表单描述（字段、默认值、校验），Agent 用 A2UI 渲染；客户端不支持就逐项问答；收集完生成 `moox.toml`。
- **秘密字段**：Agent 只执行一条命令：

```bash
moox-cli secrets intake --file ./moox.toml
```

命令在本机起页面并**由 CLI 自己用系统浏览器打开**（macOS `open`、Linux `xdg-open`、Windows `rundll32 url.dll,FileProtocolHandler`）。Agent 的任务只是提示用户「请在浏览器里填写，不要贴到对话里」，然后等命令返回状态。

### 5.2 录入页行为

| 项 | 用户输入 | 页面当场做的事 | 结果 |
| --- | --- | --- | --- |
| `ssh:<主机>` | 该主机 SSH 密码 | 连接主机，**显示主机指纹，要求用户确认已与独立渠道（云控制台等）核对**，写入 `known_hosts`；用密码登录，把操作员公钥追加到 `authorized_keys`；验证密钥可登录 | 密码丢弃；状态 `key_installed` |
| `tencent` | SecretId、SecretKey | 调一次身份接口确认能用，不判断账号类型 | 写入 `secrets.toml`；状态 `staged` |
| `admin` | 管理员密码；留空则自动生成强密码，页面显示一次 | 校验长度（bcrypt 上限 72 字节） | 写入 `secrets.toml`；状态 `staged` |
| `webhook` | 通知 URL | 无 | 写入 `secrets.toml`；状态 `staged` |

首次运行会生成唯一一把 SSH 密钥（ed25519，无口令），之后所有主机共用。

### 5.3 安全要求（适度）

- 只绑 `127.0.0.1`，端口随机；令牌放在 URL 路径里，单次使用，10 分钟失效；
- 校验 `Host` 与 `Origin`；响应加 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`；页面资源内嵌，不加载外部资源；
- 不记录请求体；提交后进程退出；令牌、密码不进入日志、错误信息和命令输出；
- 无图形环境或远程开发机：用户自己执行 `moox-cli secrets intake --terminal`（终端隐藏输入）；Agent 不代为执行。

**不防的**：同一用户下的恶意进程、读取进程内存、本机其他软件嗅探回环。个人电脑上这是合理的边界。

### 5.4 Agent 看到什么

只有状态，不含任何值，连末尾几位也不给：

```json
{"status": "done", "items": {"ssh:control": "key_installed", "ssh:storage": "key_installed", "tencent": "staged", "admin": "staged"}}
```

状态：`missing`、`staged`、`key_installed`、`imported`、`failed`。失败只给原因类别（`auth_failed`、`fingerprint_rejected`、`unreachable`、`credential_rejected`），不转发对端的原始错误文本。

## 6. 存储与协议改动

### 6.1 `moox.toml`

```toml
[install]
mode = "release"

[admin]
username = "admin"                 # 密码在录入页设置或自动生成

[tencent_cloud]
region = "ap-guangzhou"            # SecretId/SecretKey 不在这里

[hosts.control]
address = "203.0.113.10"
region = "ap-guangzhou"
provider = "tencent"
tls_mode = "auto"
ssh = { port = 22, username = "ubuntu" }
```

配置解析遇到旧秘密字段（`ssh.password`、`admin.password`、`tencent_cloud.secret_id/secret_key`、`notification.webhook_url`），报 `config_invalid` 并指向 `secrets intake`。
`scf_plan.cloud_account.credential_secret_id` 只是指向 Admin 里云凭据的标识，保留。

### 6.2 `secrets.toml`

操作员目录下，0600，明文 TOML，只含**尚未导入**的条目（云凭据、管理员密码、webhook）。导入成功后条目被删除，文件只剩空表。
没有加密层，所以没有口令、过期时间和解锁服务；保护强度与 SSH 私钥相同。

### 6.3 SSH 密钥：一把，操作员与 Admin 共用

单用户场景下，没有必要让 Admin 另生成一把。流程：

1. 录入页生成一对 ed25519 密钥，私钥存本机，公钥通过密码登录装到每台主机；
2. `setup apply` 时把私钥连同**用户确认过的主机公钥指纹**一起交给 Admin；Admin 写入 `t_ssh_host`（`AuthType=cert`，`CertData` 加密），并把指纹写入主机公钥记录，管理台终端和文件传输用它连接；
3. 吊销：删除各主机 `authorized_keys` 里 `moox` 那一行；本机私钥丢了，用管理台终端（Admin 持有的同一把）登录主机追加新公钥即可恢复。

代价：Admin 数据库与主密钥同机，控制机失陷就等于拿到这把密钥。对个人系统可接受，并且泄露的是可单独吊销的密钥，不是各主机的登录密码。

### 6.4 Admin 侧改动

- `SetupHost` 增加 `auth_type`、私钥、`host_key`（用户确认过的公钥或指纹）；去掉对主机密码的硬性要求；
- Admin 连接主机必须**严格匹配**记录的主机公钥；地址变化时拒绝并要求重新确认，不再自动重新信任（现有 `dao/ssh_host.go` 的自动 pin 要改）；
- `ApplySetup` 改为**幂等 upsert**，字段为空表示保持不变：云凭据更新不再返回冲突，便于轮换；`GetSetupStatus` 对秘密只比较一致性，不回传值；
- 管理员只在 `setup apply` 创建，Admin 存 bcrypt 哈希。

## 7. 处理流程

与[原生初始化顺序](../部署与运维.md)对齐，并修正两个与现有实现冲突的点（7.2）。

```
 0  Agent 表单收集非秘密配置（含安装方式）──▶ moox.toml
 1  moox-cli secrets intake
      ├ SSH：核对指纹 → 用密码装公钥 → 丢弃密码
      └ 云凭据 / 管理员密码 / webhook ──▶ secrets.toml
 2  moox-cli setup validate                    本地检查；云身份检查读 secrets.toml，没有则跳过
 3  moox-cli setup bootstrap --stage core      用 SSH 密钥；不再携带管理员密码
    setup deploy-host / build-linux（source 模式）/ deploy-unit …
 4  moox-cli setup apply                       Admin 可用后
      ├ 经签名网关通道提交：管理员、云凭据、主机（私钥 + 指纹）
      ├ Admin 幂等写入
      ├ CLI 读回确认（GetSetupStatus）
      └ 确认成功 → 删除 secrets.toml 里的 admin、tencent 条目
 5  moox-cli setup bootstrap --stage control   读取 webhook 注入 Monitor，成功后删除该条目
 6  验收：公开 HTTPS 登录、浏览器信任（从 apply 移到这里）
 7  日常：需要云凭据的命令向 Admin 现取（SecretMgr.GetSecretValue）
```

### 7.1 每项秘密的消费点

| 秘密 | 消费点 | 导入/使用后 |
| --- | --- | --- |
| SSH 密码 | 录入页（装公钥） | 立即丢弃 |
| SSH 私钥 | 本机 SSH 连接；`setup apply` 导入 Admin | 本机保留，Admin 保留 |
| 管理员密码 | `setup apply`（创建管理员，存哈希） | 本机条目删除 |
| 云凭据 | `setup apply`（写 `t_secrets`）；此前 `validate` 的云检查 | 本机条目删除；之后向 Admin 现取 |
| webhook | `setup bootstrap --stage control`（注入 Monitor 环境，沿用现状） | 本机条目删除 |

### 7.2 与现有实现冲突的两处

1. **core 阶段不再创建管理员。** 现有 `bootstrap --stage core` 强制校验管理员密码，放进 `InitialAdmin`，由 `unitbootstrap` 离线创建管理员，且整个请求参与摘要并写入本机状态目录、上传到目标机。
   改为：core 不带管理员密码，管理员只在 `setup apply` 创建。实现时要核对 control 阶段是否也有同样路径并一并去掉。这样请求摘要不再因管理员密码而变，也不会在状态目录里留下密码。
2. **`setup apply` 不再登录。** 现有 apply 写入后必调公开登录并信任浏览器 CA，要求 Console Proxy 已部署，而 apply 排在完整 control 之前。
   改为：apply 的成功条件是「Admin 已提交并读回一致」；公开 HTTPS 登录和浏览器信任挪到 control-ready 之后（步骤 6）。运维手册已经把这一步记为旧逻辑。

### 7.3 失败与恢复

不引入操作 ID 和提交收据，靠**幂等重试**：

- `setup apply` 可重复执行；Admin 端是 upsert。读回确认之前不删除本机条目，所以崩溃、断网、响应丢失后重跑即可；
- 读回确认通过之后才删除，删除用「写临时文件再原子替换」；
- 部分主机公钥已装、部分没装：`secrets intake` 重跑会跳过已能用密钥登录的主机，只处理其余的；
- 想重来：`moox-cli secrets purge` 清空 `secrets.toml`。

### 7.4 后续运维

| 场景 | 做法 |
| --- | --- |
| 新增主机 | `moox-cli host add`：录入页只出现该主机的 SSH 密码一项，装公钥，随后 `setup apply` 把它登记进 Admin |
| 轮换云凭据 | `moox-cli secrets intake --rotate tencent`，再 `setup apply`（upsert 更新） |
| 换电脑 | 复制整个 `~/.config/moox/`，在新机器上直接使用 |
| 吊销 SSH 访问 | 删除各主机 `authorized_keys` 里 `moox` 的行；Admin 里已建立的终端或 SFTP 会话不会因此立即断开，需要在管理台关闭会话或重启 Admin |

## 8. Windows 支持

| 方面 | 做法 |
| --- | --- |
| 操作员目录 | `%USERPROFILE%\.config\moox\`，与现有 `known_hosts`、`gateway-client.yaml` 的路径约定一致 |
| 文件权限 | 依赖用户目录的默认权限；不额外校验所有者（现有 `ownership_windows.go` 本来就直接返回 true）。文档如实说明这是个人电脑的边界 |
| 打开浏览器 | `rundll32 url.dll,FileProtocolHandler <url>` |
| SSH | 全部走 Go 实现（`x/crypto/ssh`），不依赖系统 `ssh`、`scp`、`rsync` |
| `source` 模式 | 现有 `setup build-linux` 调的是 shell 脚本（`scripts/build/build-storage-linux.sh`，用系统 `ssh/scp/rsync`），Windows 上不能用。需改成 CLI 内置的 Go 实现（SFTP 上传源码、远端编译、下载产物）；这是 Windows 支持 `source` 模式的前提，列入执行计划 |
| 换行与路径 | 写入 `authorized_keys` 等远端文件一律用 `\n`；本地路径用 `filepath` |

## 9. skill 与 Agent 规则

1. 秘密字段一律走 `moox-cli secrets intake`，不在对话里收，也不用聊天内表单或 `AskUserQuestion` 之类会把值送回模型的工具收。
2. 用户把秘密贴进了对话，视为已泄露：提醒轮换，之后不回显、不写入任何文件和命令行。
3. 不用 Agent 自带的浏览器工具打开、截图或读取录入页；页面由 CLI 用系统浏览器打开。
4. 工具输出只汇报状态，不出现秘密值。
5. `moox.toml` 不含秘密，Agent **可以读**；Agent 不读取 `~/.config/moox/`（`secrets.toml`、SSH 私钥、网关密钥）。现有「Agent 不得读取 `moox.toml`」的规则删除，[私有网络文档](../../skills/moox/references/private-network.md)中关于 `storage_gateway_host` 的例外一并取消。
6. SSH 主机指纹由用户在页面确认；Agent 不替用户确认，也不自行 `setup trust-host`。
7. `moox.toml` 里出现旧秘密字段：停止并引导用户走录入流程，不手工改写。

客户端能力：

| 客户端 | 非秘密字段 | 秘密字段 |
| --- | --- | --- |
| 支持 A2UI | 表单 | 本机录入页 |
| 只有终端对话 | 逐项问答 | 本机录入页；无浏览器时用户自己执行 `secrets intake --terminal` |

## 10. 子命令

| 命令 | 作用 |
| --- | --- |
| `moox-cli secrets intake [--rotate <项>] [--terminal]` | 起录入页收集秘密，返回状态 |
| `moox-cli secrets status [--json]` | 各项状态；不含值 |
| `moox-cli secrets purge` | 清空 `secrets.toml` |
| `moox-cli host add` | 新增主机，只录入这一台的 SSH 密码 |

## 11. 已知并接受的残留

个人系统，以下残留明确接受，不在本设计范围内处理：

| 残留 | 说明 |
| --- | --- |
| 明文 0600 文件 | `secrets.toml` 和 SSH 私钥没有口令保护；同一用户下的恶意进程能读到 |
| Admin 持有 SSH 私钥 | 数据库与主密钥同机；吊销靠删 `authorized_keys` |
| 部署产物里的残留 | webhook 仍在 Monitor 的环境文件和自己的库里；`cls prepare --credentials-output` 会写明文 `cls.env`；CloudNode 默认把管理密钥写进函数环境；SecretId 在 Admin 里是明文（`KeyID`） |
| 吊销不终止现有会话 | 已建立的终端、SFTP 会话和隧道在吊销公钥后仍可用，直到关闭会话 |
| 同机其他软件 | 不防回环嗅探、进程内存读取 |

## 12. 第一版审查意见的处理

| # | 审查意见 | 处理 |
| --- | --- | --- |
| 1 | P0 管理员密码 core 阶段就要 | 采纳：core 不创建管理员，只在 apply 创建（7.2） |
| 2 | P0 apply 依赖 Console Proxy 登录，成环 | 采纳：apply 不再登录，验收挪到 control 之后（7.2） |
| 3 | `validate` 需要云凭据 | 采纳：本地检查；云身份检查读 `secrets.toml`，没有就跳过；apply 之后不再检查 |
| 4 | 指纹没传给 Admin | 采纳：apply 携带用户确认的 `host_key`，Admin 严格匹配（6.4） |
| 5 | Setup 接口不支持单项更新与轮换 | 采纳：改为幂等 upsert，空表示保持（6.4） |
| 6 | 缺少可恢复的提交协议 | 简化：幂等重试，读回确认后才删除，不引入操作 ID（7.3） |
| 7 | 摘要与状态目录的断言不成立 | 采纳并更正：管理员密码不再进入请求，摘要不受其影响；webhook 仍在 control 阶段请求里，列入残留（11） |
| 8 | webhook 没有消费者 | 简化：沿用现状，control 阶段注入 Monitor，不经 Admin（7.1） |
| 9 | 「保存密码」例外矛盾 | 删除例外：任何主机都不保存密码；装不了公钥的由用户手工追加（4） |
| 10 | 本地密钥服务承接不了 HMAC 签名 | 删除本地密钥服务；网关签名密钥保持现状（3） |
| 11 | 构建脚本用系统 ssh | `source` 模式在 Windows 上改成 CLI 内置实现；类 Unix 沿用脚本并传入 `-i`（8） |
| 12 | 多操作员超出 Keys 模型 | 删除：单用户（2） |
| 13 | 两文件可移植不成立；Windows 权限 | 改为「复制整个操作员目录」；Windows 依赖用户目录权限并如实说明（3、8） |
| 14 | 漏了凭据导出路径 | 列入已知残留（11） |
| 15 | 录入页安全契约未闭合 | 适度化：回环、令牌、Host/Origin、no-store、no-referrer；不防同机恶意进程（5.3） |
| 16 | 吊销不终止会话；24 小时语义 | 吊销残留列入（11）；取消 24 小时过期，改为导入后删除 |

## 14. 验收口径

1. 全新环境按第 7 节走完，`moox.toml` 与对话转录里搜不到任何密码、SecretKey、webhook；
2. 初始化完成后，`secrets.toml` 里没有 admin、tencent、webhook 条目；`secrets status` 为 `imported`；
3. 初始化后，`moox-cli collector kline backfill` 之类命令、Agent 的 SSH 登录都不再要求密码；
4. 管理台终端能用 Admin 持有的密钥登录所有主机；Admin 连接主机严格匹配记录的公钥，地址变化时拒绝；
5. `setup apply` 中途失败后重跑能收敛，且读回确认通过前不删除本机条目；
6. `setup apply` 不依赖 Console Proxy 就能成功；core、control 请求里没有管理员密码；
7. 录入页拒绝：错误的 `Host`、重复使用的令牌、过期的令牌；
8. `moox.toml` 里写旧秘密字段，所有命令拒绝并给出指引；
9. 在 macOS、Linux、Windows 上分别完成一遍录入（Windows 的 `source` 模式在 `build-linux` 内置实现完成后验收）。
