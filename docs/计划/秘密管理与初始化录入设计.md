# 秘密管理与初始化录入：设计

> 状态：设计稿，决策已确认，尚未编码。本文只写「做成什么样、为什么」；改哪些文件、按什么顺序、怎么验收，另写执行计划。
> 项目尚未上线，不做任何历史兼容：`moox.toml` 里的旧秘密字段直接删除，写了就报错。
> 相关：[部署与运维](../部署与运维.md)（原生初始化顺序）、[管理后台](../模块/管理后台.md)（SecretMgr、Ssh、Keys）、[命令行工具](../模块/命令行工具.md)。

## 1. 问题与目标

`moox.toml` 是用户的唯一配置入口，体验简单，但它同时含有明文的服务器密码、腾讯云密钥和管理员密码。后果：

- 提交 git、截图、发给别人、交给 Agent 阅读时都会泄露；
- 在 Agent 里完成初始化时，用户填的任何值都会进入对话上下文和转录；
- 为了不泄露，skill 只能规定「Agent 不得读取 `moox.toml`」，连拓扑和策略配置都不能看，排障很别扭。

目标：

1. **体验不退步**：用户仍然是「配置一次」，初始化后日常操作不再弹任何密码；
2. **配置文件无秘密**：`moox.toml` 可以提交、分享，Agent 可以随便读；
3. **秘密不经过模型**：在 Agent 里初始化时，秘密字段由本机的一次性页面收集，模型只拿到状态；
4. **可移植**：不依赖系统钥匙串，换机器、容器、远程开发环境都能用；
5. **长期持有的秘密尽量少**，且都可单独吊销。

## 2. 现状：哪些秘密、何时用

以下来自 `moox.toml.example` 与代码（`modules/cli/internal/setup/config/config.go`、Admin 的 Setup 与 Ssh 服务）：

| 秘密 | 现在在哪 | 何时用 | 之后 |
| --- | --- | --- | --- |
| `hosts.<id>.ssh.password` | `moox.toml` | 首次部署的 SSH/SFTP；`setup apply` 把它加密写进 Admin（`t_ssh_host`，`AuthType=pwd`），供管理台 SSH 终端使用 | 日常运维走签名身份，SSH 只是隧道 |
| `tencent_cloud.secret_id/secret_key` | `moox.toml` | Admin 与 CloudNode 起来后开通 CLS、SCF、防火墙；`setup apply` 加密写进 `t_secrets`（`tencent-default`） | CloudNode 已通过 `SecretMgr.GetSecretValue` 向 Admin 读取，不再读文件 |
| `admin.password` | `moox.toml` | 创建初始管理员，Admin 只存 bcrypt 哈希 | 登录用 |
| `notification.webhook_url` | `moox.toml` | 告警通知 | Monitor 使用 |

两条现成的事实决定了方案：

- **大多数秘密只在引导期用一次**，却一直明文留在文件里；
- **Admin 已经具备长期保管的能力**：`t_secrets` 与 `t_ssh_host` 用 `MOOX_ADMIN_ENCRYPTION_KEY` 加密；SSH 主机模型本来就支持证书认证（`AuthType=cert`，`CertData`、`CertPwd` 加密存储）；`moox-cli` 在 `GetSecretValue` 的 ACL 里；操作员的网关签名身份（`gateway-client.yaml` 加密钥文件）本来就和 `moox.toml` 分开。

## 3. 已确认的决策

| # | 决策 |
| --- | --- |
| 1 | `moox.toml` 不再含任何秘密值；旧字段（`ssh.password`、`admin.password`、`tencent_cloud.secret_id/secret_key`、`notification.webhook_url`）直接删除，出现即报错并指向录入流程，不做兼容 |
| 2 | 秘密不经过模型。非秘密配置可以用 Agent 表单（A2UI）或逐项问答收集；秘密一律由 `moox-cli` 起的本机一次性页面收集 |
| 3 | 可移植：不使用系统钥匙串。本地暂存用口令加密的普通文件，解锁用仅驻内存、带有效期的本地服务 |
| 4 | SSH 只存**密钥**，不存密码。操作员持一把密钥，Admin 持另一把，都装进服务器；密码只用一次装密钥，用完丢弃。个别装不了密钥的主机可逐主机显式选择保存密码，默认关闭 |
| 5 | 云凭据、管理员密码、webhook 在引导期暂存在本机，控制面可用后一次性导入 Admin，**导入并读回确认后强制删除本地副本** |
| 6 | 不做云账号类型校验（根账号或子账号都不判断）；录入页只做「凭据能调通」的基本检查 |
| 7 | 本地解锁服务默认有效期 8 小时，可调；暂存期限默认 24 小时 |
| 8 | 秘密的值只出现在三个地方：录入页的用户输入、暂存文件和 Admin 的加密存储；不进入对话、日志、状态目录和命令行参数 |

## 4. 总体设计

### 4.1 三类数据分流

```
                 ┌─────────────────────────────────────────────────────────┐
  用户 ──表单──▶ │ Agent（A2UI/问答）：主机地址、地域、组件放置、保留期、因子 │ ─▶ moox.toml（无秘密，可提交，Agent 可读）
                 └─────────────────────────────────────────────────────────┘

                 ┌──────────────────────────────┐
  用户 ──浏览器─▶│ moox-cli 本机一次性录入页      │──▶ 状态（set/valid/…）──▶ Agent
                 │ 127.0.0.1，随机端口，一次性令牌 │
                 └──────┬───────────────────────┘
                        │ 秘密值，不经过 Agent
                        ├─ SSH 密码 ──▶ 装密钥后丢弃（不落盘）
                        └─ 云凭据 / 管理员密码 / webhook ──▶ moox.secrets（口令加密，暂存，24 小时）
                                                              │ setup apply
                                                              ▼
                                                        Admin 加密存储（长期）──▶ 本机副本删除
```

### 4.2 各类数据放哪、谁能读

| 数据 | 位置 | 保护 | 生命周期 | Agent 能读吗 |
| --- | --- | --- | --- | --- |
| 拓扑、策略、因子等配置 | `moox.toml` | 无秘密 | 长期 | 能 |
| SSH 密码 | 内存，仅录入请求期间 | 不落盘 | 用于装密钥后立即丢弃 | 不能，也看不到 |
| 云凭据、管理员密码、webhook | `moox.secrets`（暂存） | 口令派生密钥加密 | ≤24 小时，导入后删 | 不能（密文），也不应读 |
| 云凭据（长期） | Admin `t_secrets` | `MOOX_ADMIN_ENCRYPTION_KEY` 加密 | 长期 | 不能 |
| 操作员 SSH 私钥 | `~/.config/moox/ssh/` | OpenSSH 口令加密 | 长期，可吊销 | 不能 |
| Admin SSH 私钥 | Admin `t_ssh_host`（`AuthType=cert`） | 同上加密 | 长期，可吊销 | 不能 |
| 操作员网关签名密钥 | `~/.config/moox/` 下的密钥文件 | 口令加密，解锁后驻内存 | 长期，可吊销 | 不能 |

## 5. 用户输入

### 5.1 两条通道

- **非秘密字段**：skill 随附一份表单描述（字段、默认值、校验），Agent 用 A2UI 渲染；客户端不支持就逐项问答。收集完直接生成 `moox.toml`。
- **秘密字段**：Agent 只执行一条命令：

```bash
moox-cli secrets intake --file ./moox.toml --need ssh:control,ssh:storage,ssh:compute-1,tencent,admin,webhook
```

命令在本机起页面并**由 CLI 自己用系统浏览器打开**。Agent 的任务只是告诉用户「请在浏览器里填写，不要贴到对话里」，然后等命令返回状态。

`--need` 由 `moox.toml` 推出：`hosts` 里每个主机一个 `ssh:<id>`；配了 `scf_plan` 或使用云能力时需要 `tencent`；总是需要 `admin`；配了通知渠道时需要 `webhook`。

### 5.2 录入页行为

首次打开先设**本地口令**（用于加密暂存文件和保护本机密钥，至少 12 个字符，页面给强度提示）。之后按 `--need` 逐项出现：

| 项 | 用户输入 | 页面当场做的事 | 结果 |
| --- | --- | --- | --- |
| `ssh:<主机>` | 该主机 SSH 密码 | 连接主机，**显示主机指纹，要求用户确认已与独立渠道（云控制台等）核对**，然后写入 `known_hosts`；用密码登录，把**操作员公钥**追加到 `authorized_keys`；验证密钥可登录 | 密码丢弃；状态 `key_installed` |
| `tencent` | SecretId、SecretKey | 调一次身份接口确认凭据能用，不判断账号类型 | 写入暂存文件；状态 `staged` |
| `admin` | 管理员密码，**留空则自动生成强密码**，并在页面显示一次 | 校验长度（bcrypt 上限 72 字节） | 写入暂存文件；状态 `staged` |
| `webhook` | 通知 URL | 无 | 写入暂存文件；状态 `staged` |

对「保存密码」的逐主机选项：页面里每个主机有一个默认关闭的开关「同时保存此主机密码」，只给确实装不了密钥的主机（例如用户自管的编译机）使用。打开时该主机在 Admin 中走 `AuthType=pwd`，否则一律 `cert`。

### 5.3 安全要求

- 只绑定 `127.0.0.1`，端口随机；URL 带一次性令牌，单次使用，默认 5 分钟失效；
- 校验 `Host` 与 `Origin`，拒绝跨站请求（防 DNS 重绑定和 CSRF）；
- 页面资源全部内嵌在二进制里，不加载外部资源，设置严格的 CSP；
- 不记录请求体；提交后进程退出，内存清零；请求体、口令、密码不进入任何日志、状态目录和错误信息；
- 远程开发机或没有浏览器：打印端口转发提示；完全没有图形环境时，用户自己执行 `moox-cli secrets intake --terminal`（终端隐藏输入，Agent 不应代为执行）。

### 5.4 Agent 看到什么

命令只向 Agent 返回状态，不含任何值，连密钥后几位也不给：

```json
{
  "status": "done",
  "items": {
    "ssh:control": "key_installed",
    "ssh:storage": "key_installed",
    "tencent": "staged",
    "admin": "staged",
    "webhook": "staged"
  },
  "staged_until": "2026-10-16T09:30:00Z"
}
```

状态取值：`missing`、`staged`、`key_installed`、`imported`、`expired`、`failed`。失败只返回原因类别（`auth_failed`、`fingerprint_rejected`、`unreachable`、`credential_rejected`），不回传对端的原始错误文本。

## 6. 存储

### 6.1 `moox.toml`

去掉所有秘密字段，只留标识与策略：

```toml
[admin]
username = "admin"                 # 密码由录入页设置或自动生成

[tencent_cloud]
region = "ap-guangzhou"            # SecretId/SecretKey 不在这里

[notification]
channel_type = "wecom"             # webhook URL 不在这里

[hosts.control]
address = "203.0.113.10"
region = "ap-guangzhou"
provider = "tencent"
tls_mode = "auto"
ssh = { port = 22, username = "ubuntu" }                 # 默认用 moox 管理的密钥

[hosts.compile]
address = "192.0.2.30"
ssh = { port = 22, username = "builder", auth = "password" }   # 装不了密钥的主机显式选择
```

`scf_plan.cloud_account.credential_secret_id` 只是指向 Admin 里云凭据的**标识**，保留。

配置解析遇到旧秘密字段，报 `config_invalid` 并提示「秘密不再写在 `moox.toml`，请运行 `moox-cli secrets intake`」。因为 `moox.toml` 不再含秘密，**状态目录绑定的原始配置摘要不会因为轮换秘密而变化**，已安装单元的重试绑定不受影响。

### 6.2 暂存文件 `moox.secrets`

放在 `moox.toml` 旁边（权限 0600，加入 `.gitignore`），和 `moox.toml` 一起构成可移植的一对。

- 加密：口令经 Argon2id 派生密钥，XChaCha20-Poly1305 认证加密；头部记录版本、KDF 参数、盐。
- 条目：`name`（如 `tencent/default`）、`kind`、`value`、`created_at`、`expires_at`（默认创建后 24 小时）、`state`。
- 导入成功后删除条目并重写整个文件，文件里不会出现已导入的秘密；全部条目清空后文件只剩头部。
- 过期条目在 `secrets status` 里标为 `expired`，下次操作会提示并可 `secrets purge`；它们不会被导入。
- 忘记口令：暂存的内容丢失，重新运行 `secrets intake` 即可，因为暂存的秘密本来就是可重录的。

### 6.3 SSH 密钥

两把独立的密钥，对应「本机免密」和「管理台管理主机」：

| 密钥 | 生成位置 | 私钥存哪 | 公钥装到哪 | 用途 |
| --- | --- | --- | --- | --- |
| 操作员密钥（ed25519） | 录入页，本机 | `~/.config/moox/ssh/`，OpenSSH 口令加密；解锁后进入本地密钥服务 | 每台主机的 `authorized_keys`（备注 `moox-operator`） | `moox-cli` 与 Agent 免密 SSH、隧道 |
| Admin 密钥（ed25519） | **Admin 内部**，由 `ApplySetup` 生成 | Admin 的 `t_ssh_host`（`AuthType=cert`，`CertData` 加密），**私钥不离开 Admin** | 每台主机的 `authorized_keys`（备注 `moox-admin`），由 CLI 用操作员密钥登录后安装 | 管理台 SSH 终端、文件传输 |

Admin 密钥在 Admin 起来之后才生成，所以安装发生在 `setup apply` 阶段：Admin 返回公钥，CLI 用已有的操作员密钥登录各主机追加，Admin 再测试一次连通。SSH 密码在此之前就已丢弃，不再需要。

操作员密钥丢失的恢复路径：用管理台终端（Admin 密钥）登录主机，追加新的操作员公钥。吊销任一密钥只需删除对应的 `authorized_keys` 行。

### 6.4 Admin 侧

- `SetupHost` 增加 `auth_type`（`cert` 或 `pwd`）；`cert` 主机不带密码，`ApplySetup` 返回为该主机生成的 Admin 公钥；
- 只有显式选择保存密码的主机才写 `AuthType=pwd` 与加密密码；
- 云凭据沿用现有 `ensureTencentSecret`，管理员密码沿用 bcrypt 哈希；
- 新增 webhook 的写入与读取（沿用 `t_secrets`）；
- `GetSetupStatus` 对秘密只比较「是否一致」，不回传值（现有 `secretEqual` 做法）。

### 6.5 本地密钥服务

`moox-cli secrets agent`：只在内存里持有已解锁的暂存文件密钥、操作员网关签名密钥和操作员 SSH 私钥，对外提供 ssh-agent 协议兼容的接口（Unix 套接字 0600；Windows 用命名管道）。

- 解锁在录入页完成（输入本地口令），Agent 全程不接触口令；
- 默认有效期 8 小时，`moox-cli secrets lock` 立即锁定；
- `moox-cli` 的 SSH 隧道与签名优先向它取密钥，其次才是调用方环境里的 ssh-agent 与默认私钥；
- 进程崩溃或超时后内存里的密钥随之消失，不写交换文件之外的任何持久位置。

## 7. 处理流程

与[原生初始化顺序](../部署与运维.md)对齐，新增的只有「录入」「导入」两步。

```
 步骤 0   Agent 表单收集非秘密配置 ──▶ 生成 moox.toml
 步骤 1   moox-cli secrets intake          用户在本机页面填写
            ├ SSH：核对指纹 → 用密码装操作员公钥 → 丢弃密码
            └ 云凭据/管理员密码/webhook → moox.secrets（24 小时）
 步骤 2   moox-cli setup validate
          moox-cli setup bootstrap --stage core        用操作员密钥 SSH，生成操作员网关身份
          setup deploy-host / build-linux / deploy-unit …
 步骤 3   Admin 可用后：moox-cli setup apply
            ├ 把暂存秘密交给 Admin（经已有的签名网关通道，不经过 Agent）
            ├ Admin 写入：管理员哈希、云凭据、webhook、主机（cert）；生成 Admin SSH 密钥
            ├ CLI 用操作员密钥把 Admin 公钥装到各主机
            ├ 读回确认：Admin 能解密、一致；Admin 能用密钥连上各主机
            └ 确认成功 → 删除暂存条目；失败 → 保留并标注原因
 步骤 4   日常：需要云凭据的命令向 Admin 现取（SecretMgr.GetSecretValue），本机不留副本
 步骤 5   bootstrap --stage control 及其余业务单元
```

### 7.1 为什么导入点是 `setup apply`

Admin 起来之前没有地方能接收秘密；`bootstrap --stage core` 之后 Admin 即可用，这就是最早的安全导入点。Storage 等其余模块可以之后再部署，所以暂存窗口只覆盖「录入 → core-ready」这一段，通常是几十分钟。

### 7.2 暂存条目的状态机

```
 missing ──录入──▶ staged ──setup apply 成功且读回一致──▶ imported（本地条目删除）
                     │                                        
                     ├──超过 24 小时──▶ expired ──purge/重新录入──▶ missing
                     └──导入失败──▶ staged（附原因，可重试）
 SSH 密码：录入请求内完成「装密钥」即丢弃，没有暂存态
```

### 7.3 后续运维

| 场景 | 做法 |
| --- | --- |
| 新增主机 | `moox-cli host add`：录入页只出现该主机的 SSH 密码一项，装操作员公钥，随后 `setup apply` 为它装 Admin 公钥 |
| 轮换云凭据 | `moox-cli secrets intake --rotate tencent`，`setup apply` 更新 Admin 里的记录并删除本地暂存 |
| 新增操作员 | Admin 的 Keys 服务签发新的操作员网关身份，新人在录入页输入一次性邀请码，生成自己的 SSH 密钥；**不共享第一个操作员的密钥** |
| 吊销操作员 | 在 Admin 吊销其网关身份，并从主机 `authorized_keys` 删除对应行 |
| 吊销 Admin 的 SSH 访问 | 删除各主机 `authorized_keys` 里 `moox-admin` 的行；管理台终端随之不可用，可用操作员密钥重新生成并安装 |
| 暂存文件泄露的评估 | 它是口令加密的，且只含 24 小时内未导入的秘密；怀疑泄露就轮换对应秘密 |

## 8. skill 与 Agent 规则

`skills/moox` 的初始化文档（`custom-setup.md`）按本文重写，核心规则：

1. 秘密字段一律走 `moox-cli secrets intake`，**不在对话里收**，也不用聊天内表单、`AskUserQuestion` 之类会把值送回模型的工具收。
2. 用户把秘密贴进了对话，视为已泄露：提醒轮换，之后不回显、不写入任何文件、不放进命令行。
3. 不用 Agent 自带的浏览器工具打开、截图或读取录入页；页面由 CLI 用系统浏览器打开。
4. 工具输出里不出现任何秘密值；只汇报状态。
5. `moox.toml` 不再含秘密，Agent **可以读**；Agent 不读取 `moox.secrets`、`~/.config/moox/ssh/` 与各密钥文件。现有「Agent 不得读取 `moox.toml`」的规则删除，[私有网络文档](../../skills/moox/references/private-network.md)里对 `storage_gateway_host` 的例外一并取消。
6. SSH 主机指纹由用户在页面确认；Agent 不替用户确认指纹，也不用 `setup trust-host` 自行信任。
7. `moox.toml` 里出现旧的秘密字段，停止并引导用户重新走录入流程，不手工改写。

客户端能力自适应：

| 客户端能力 | 非秘密字段 | 秘密字段 |
| --- | --- | --- |
| 支持 A2UI | 表单 | 本机录入页 |
| 支持 MCP「URL 模式」征询（为敏感信息设计，值不经过模型） | 逐项问答或表单 | 可用它打开录入页 URL；CLI 自己调用系统浏览器就已够用，这是可选的 |
| 只有终端对话 | 逐项问答 | 本机录入页；无浏览器时由用户自己执行 `secrets intake --terminal` |

## 9. 子命令清单

| 命令 | 作用 |
| --- | --- |
| `moox-cli secrets intake [--need …] [--rotate <项>] [--terminal]` | 起录入页收集秘密，返回状态 |
| `moox-cli secrets status [--json]` | 各项状态、暂存剩余时间；不含值 |
| `moox-cli secrets set <name> --stdin` | 自动化场景（CI、无头环境）从标准输入写入暂存；值不进入命令行参数，Agent 不得用对话里的值调用 |
| `moox-cli secrets unlock` / `lock` | 解锁或锁定本地密钥服务（解锁走录入页） |
| `moox-cli secrets agent` | 本地密钥服务本体，通常由解锁自动拉起 |
| `moox-cli secrets purge [--all]` | 清除暂存条目（过期或手动） |
| `moox-cli host add` | 新增主机，必要时只录入这一台的 SSH 密码 |

## 10. 威胁模型

| 威胁 | 对策 | 剩余风险 |
| --- | --- | --- |
| 模型上下文与转录泄露 | 秘密不经 Agent；工具输出只含状态；用户误贴则提醒轮换 | 用户无视提示手动贴入 |
| 误提交 git、截图、分享 `moox.toml` | 文件里没有秘密；`moox.secrets` 在 `.gitignore` 且加密 | 用户主动提交加密文件，强度取决于口令 |
| 录入页被本机其他进程或网页攻击 | 回环、随机端口、一次性令牌、Host/Origin 校验、短有效期、CSP | 同一用户下的恶意进程可读进程内存，这是本方案不防的范围 |
| 暂存文件被窃后离线爆破 | Argon2id 参数（内存、迭代按当前推荐值）；仅含 24 小时内未导入的秘密 | 弱口令；因此强制最短长度并给强度提示 |
| Admin 数据库与主密钥泄露 | 云凭据、Admin SSH 私钥在同一主机加密存储，主密钥在 `identity/` | 控制机整体失陷时都会泄露；但泄露的是**可单独吊销的密钥**，不是各主机的登录密码 |
| 中间人伪造主机 | 指纹由用户与独立渠道核对后确认，写入 `known_hosts` | 用户不核对直接确认 |
| 崩溃转储、交换分区 | 密钥与口令只在内存短暂存在，尽量锁定内存并及时清零 | 操作系统层面的残留 |

## 12. 不做的事

- 不使用系统钥匙串，也不引入任何平台相关的存储依赖；
- 不判断云账号是根账号还是子账号，也不强制子账号或临时凭据（可以在文档里建议）；
- 不兼容旧的明文字段，也不提供自动迁移；
- 默认不长期保存任何 SSH 密码；
- 不把秘密交给模型，也不提供让 Agent 读取秘密值的接口，包括「脱敏后几位」。

## 13. 验收口径

1. 全新环境按 §7 走完，`moox.toml` 与对话转录里搜不到任何密码、SecretKey、webhook；
2. 初始化完成后本机没有暂存秘密，`secrets status` 全部是 `imported`；
3. 初始化后，`moox-cli collector kline backfill` 之类命令、Agent 的 SSH 登录都不再要求密码；
4. 管理台终端能用 Admin 密钥登录所有 `cert` 主机，吊销 `moox-admin` 公钥后立即失效；
5. 暂存超过 24 小时的条目不会被导入；导入失败时本地条目保留并给出原因；
6. 录入页对非回环来源、错误 `Host`、重复使用令牌、过期令牌的请求都拒绝；
7. `moox.toml` 里写旧秘密字段时，`setup validate` 与所有命令都拒绝并给出指引。
