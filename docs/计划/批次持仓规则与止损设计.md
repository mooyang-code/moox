# 批次持仓规则与止损设计

> 状态：设计稿，待审。尚未编码。
>
> 目标：
> 1. 把 F1 的选币与持有方式抽象成通用的规则类型 `tranche`（批次持仓），F1 只是它的一份预设。以后同类策略写配置即可，不用改代码、不用发布。
> 2. 增加通用的**止损**环节，`rank`、`signal`、`tranche` 三种规则都能用，默认关闭。
>
> 不变：`rank`、`signal` 规则的模型与现有写法不变，止损对它们只是可选的附加环节。

## 1. 现状

| 规则类型 | 适用 | 状态 | 能否配置出 F1 |
| --- | --- | --- | --- |
| `rank` | 截面打分、选前 N、配权；可选 `buffer` 或 `holding` 分批换仓 | 持有集合；分批换仓的批次 | 不能：权重按当期分数定，没有"每期开一批、按开仓数量持有 h 期" |
| `signal` | 固定池择时，entry / exit | 持有集合 | 不能 |
| `f1` | 与 alphalib F1 逐期一致 | 按排名签名分组的开仓记录 | 是，但各环节写死成 F1 的做法 |

`f1` 规则（`modules/strategy/internal/engine/f1.go`，约 600 行）的流程是 8 个固定环节，每个环节 F1 只用了其中一种做法。
它已经有"子策略模板 + 参数表展开"的机制（`modules/strategy/internal/dsl/f1.go`），新增 F1 子策略本来就不用改代码；
缺的是**环节里的做法不能换**，比如想按固定权重持有、或按 K 线根数计持有期，就得改代码。

## 2. 总体方案

分两层：

| 层 | 内容 | 新增策略时是否要发布 |
| --- | --- | --- |
| 规则层 | `rank`、`signal`、`tranche` 三种规则类型，止损是三者共用的可选环节。环节的每种做法都做成选项 | 只有需要一种**新机制**（新的定仓公式、新的止损方式）时要编码，而且只是给已有环节加一个选项 |
| 配置层 | 策略 DSL（已存库，管理台与 CLI 可改）；`tranche` 沿用参数表展开子策略 | 不用 |

打分的灵活性主要来自因子层：任意打分逻辑先写成因子表达式（见 [因子](../模块/因子.md)），规则只负责排名、过滤、选币与持有。

可选的第三步是**模板库**（第 6 节）：把常用的 DSL 骨架和参数列存成命名模板，建策略时选模板、填参数表。它只是复用 DSL 的便利层，不改变引擎，单独决定做不做。

## 3. `tranche` 规则

### 3.1 环节与选项

每期按下面的顺序求值。表中"F1"列是预设 `preset: f1` 填入的值，其余为可选值。

| 环节 | 选项 | F1 | 说明 |
| --- | --- | --- | --- |
| 1. 候选 | `candidates.require_volume` | `true` | 本期有行，且为真时要求 `volume > 0` |
| | 名单 | 多空各自的白、黑名单 | 沿用 F1 写法 |
| | 最少上市根数 | 由 `seal999` 推出 999 | 改用策略级 `universe.min_age_bars`，`seal999` 只保留在预设里 |
| 2. 打分 | `score.method` | `rank_mean` | `rank_mean`：各因子截面名次按权重平均（F1 的 `cross`）；`raw`：因子原值加权（F1 的 `vertical`） |
| | `score.missing` | `median` | 因子值为空时：`median` 补同期中位数名次；`drop` 不参与本期排名 |
| 3. 前置过滤 | `filter_before` | F1 写法 | 串联执行，`value` / `rank` / `pct`，可写逻辑组合 |
| 4. 选币 | `long_coin_num`、`short_coin_num` | F1 写法 | 整数是个数，0～1 之间是百分比 |
| 5. 后置过滤 | `filter_after` | F1 写法 | 在选中样本上判断，任一条件成立即剔除，不补位；结果记在开仓记录上 |
| 6. 开仓 | 每期新开一批 | 固定 | 本规则的定义：每根 K 线按本期选币开一批（tranche） |
| 7. 持有计数 | `hold.period` | `{h}` | 持有期 h |
| | `hold.count` | `candidate_rows` | `candidate_rows`：该标的本期是候选才 +1（F1）；`bars`：每根 K 线都 +1 |
| 8. 定仓 | `sizing.method` | `quantity` | `quantity`：开仓时定数量，权重随价格变动（本期权重 = 份额 × 本期 close / 开仓 close）；`weight`：每批份额固定，不随价格变动 |
| | `sizing.scale` | `0.5` | 份额 = `scale × side_weight / h / 本批同方向个数` |
| 9. 合成 | `stg_weight` | F1 写法 | 子策略按 `stg_weight` 归一化后乘规则预算 `weight.total` |
| 10. 止损 | `stop` | 不开 | 见第 4 节 |

去重沿用 F1：多空因子、打分方式、名单、前置过滤与个数都相同的子策略构成一个排名签名，每期只选一次；后置过滤与定仓逐个子策略计算。

### 3.2 DSL 写法

`type: f1` 删除，改为 `type: tranche`；`preset` 只填默认值，写出的字段覆盖预设。参数表展开与占位符规则不变。

```yaml
rules:
  - id: fh003
    type: tranche
    preset: f1                    # 可省略；省略时每个选项用第 3.1 节的通用默认值
    weight: {total: 1}
    tranche:                      # 子策略模板，"{列名}" 取参数表这一行的值
      hold: {period: "{h}"}       # count 用预设的 candidate_rows
      score: {method: rank_mean}
      long_factors: [{factor: "f1_po__{s}_{l}", descending: true, weight: 1}]
      long_weight: 2
      long_coin_num: 1
      filter_after:
        - {direction: long, factor: "f1_wick_max__{n2}", type: value, op: lte, value: "{p2}"}
      stg_weight: "{w}"
      stop: {loss: 0.08, cooldown_bars: 12}   # 可选，见第 4 节
    params:
      columns: [h, s, l, n2, p2, w]
      rows:
        - [1, 65, 193, 24, 0.1, 0.0033333333333333335]
```

不写 `preset` 时的通用默认值：`require_volume: true`、`score.method: rank_mean`、`score.missing: drop`、`hold.count: bars`、
`sizing.method: weight`、`sizing.scale: 1`。通用默认值按"对新策略最不意外"来定，和 F1 预设不同是有意的：
`score.missing: drop` 不让因子空值的标的靠补中位数入选，`hold.count: bars` 让持有期等于自然时间。

### 3.3 等价性

- `preset: f1` 必须与现有 `f1` 规则逐值一致：13 个黄金用例（`modules/strategy/internal/engine/testdata/f1/`）原样通过，
  对比测试（`f1_compare_test.go`）原样通过。
- 上线前在生产数据上用新旧两版对 FH002、FH003 各回放最近一段，权重逐期一致。
- 状态格式改名（`RuleState.f1` → `RuleState.tranche`，开仓记录增加止损字段），按项目原则不做迁移，发布时重新启用实例（第 7 节）。

## 4. 止损（三种规则共用，默认关闭）

### 4.1 配置

规则级的可选块，写在 `rank`、`signal` 规则上，或 `tranche` 的子策略模板里（可用参数表占位符）：

```yaml
stop:
  loss: 0.05            # 固定止损：相对入场价不利变动达到 5%
  trailing: 0.08        # 跟踪止损：相对持有期间最有利价格回撤 8%
  price: close          # close（默认）| extreme：多头看 low、空头看 high，要求绑定的 View 有该列
  cooldown_bars: 12     # 触发后该标的在本规则内 12 根不能重新入场；默认 0
```

- `loss` 与 `trailing` 至少写一个，可同时写，任一触发即止损。取值范围 (0, 1)。
- 不写 `stop` 时行为与现在完全一致。

### 4.2 持仓单位与入场价

| 规则 | 持仓单位 | 入场价 | 触发后 |
| --- | --- | --- | --- |
| `tranche` | 每一条开仓记录（一批里的一个标的） | 开仓 close（F1 本来就记录） | 该记录权重为 0 并删除；同组子策略共用这条记录，一起止损 |
| `rank`（无 `holding`） | 持有集合里的每个标的 | 进入持有集合那一期的 close，持有期间调权不改 | 移出持有集合；本期照常按名次选币，因冷却被排除的标的由后面的名次补上 |
| `rank`（`holding` 分批换仓） | 每个批次里的每个标的 | 该批建仓那一期的 close | 移出该批次，份额留现金，到下次重建批次再说 |
| `signal` | 持有集合里的每个标的 | 入场那一期的 close | 等同 exit；冷却期内 entry 成立也不入场 |

做空时方向相反：价格上涨为不利变动。

### 4.3 求值顺序

每期在规则求值的**最前面**检查止损：

1. 用本期参考价更新每个持仓单位的最有利价格（跟踪止损用），再判断是否触发。
2. 触发的单位按上表处理，标的写入冷却表（到期序号 = 本期 bar 序号 + `cooldown_bars`）。
3. 冷却中的标的在本期的候选、选币、entry 中都被排除。
4. 其余环节照常；本期新入场的单位记录本期 close 为入场价。

止损先于选币，所以同一期不会出现"刚止损又被选回来"（`cooldown_bars: 0` 时下一期可以重新入场）。

### 4.4 与现有机制的交互

- **缺数与空洞冻结**：本期没有参考价的标的不判止损、不更新最有利价格；`rank`、`signal` 缺数本来就会清仓，冻结的标的保持不动，止损也不动。
- **守门跳过**：整期跳过时状态不变，止损不推进。
- **追赶期与迟到周期**：这些周期求值并推进状态（#64），止损也照常推进，放行后与连续运行一致。
- **回放**：止损是规则求值的一部分，研究回放与闭环回放自动支持；`tranche` 规则的回放支持仍按 f1 规则现状（暂不支持），另行处理。
- **明细与摘要**：新增阶段 `stopped`，原因 `stop_loss` 或 `trailing_stop`；冷却中被排除的记 `cooldown`。规则摘要增加 `stopped` 计数。

### 4.5 边界

- 这是**按 K 线收盘判断的理论止损**：策略在一根 K 线结束后才求值，止损目标随下一次目标下发，由 Trade 执行。
  盘中触价止损需要 Trade 在交易所挂条件单，不在本设计范围内。
- 入场价是策略决策那一期的 close，不是实际成交价；两者的差额在实盘里体现为滑点。
- `price: extreme` 用本期最低（多头）或最高（空头）价判断，更接近盘中止损的触发，但仍在收盘后执行，可能实际成交价比止损线更差。

## 5. 状态

```text
RuleState
  held        []string            # 不变
  batches     []HoldingBatch      # 不变；批次内标的增加 entry/peak
  entries     map[id]{price, peak, bar}   # 新增：rank / signal 持有标的的入场价与最有利价格（只在开了 stop 时记录）
  cooldown    map[id]int          # 新增：冷却到期的 bar 序号（只在 cooldown_bars > 0 时记录）
  tranche     {groups: [...]}     # 由 f1 改名；开仓记录增加 peak（只在开了 trailing 时记录）
```

不开止损时这些字段为空，状态大小与现在相同。

## 6. 模板库（可选，单独决定）

- 模板 = 命名的 DSL 骨架 + 参数列定义（列名、类型、范围）+ 说明。存在策略模块的库里，管理台与 CLI 可增删改，不随代码发布。
- 用模板建策略：选模板、上传参数表（CSV），生成完整 DSL，走现有的策略定义与实例流程，引擎不感知模板。
- 内置一个 `f1` 模板（`tranche` + `preset: f1` + F1 参数表的列定义），方便迁移同类策略。
- 不做模板库时，复制一份现有策略的 DSL 修改，效果相同，只是没有参数列的校验与说明。
