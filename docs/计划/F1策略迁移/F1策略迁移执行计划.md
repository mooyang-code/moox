# F1 策略迁移执行计划

> 状态：执行计划 v1.2（2026-10-26），尚未编码。已吸收两轮 Codex 审查（第一轮 xhigh、第二轮 high 复审），处置见第 6 节。
> 设计依据：[F1策略迁移设计](F1策略迁移设计.md) v2.1（下文简称"设计"）。
> 原则：单用户、不过度设计、不写迁移、未上线的部分全新部署（见 `single-user-no-overdesign`）。

## 0. 目标、前提与范围

**目标**（用户 2026-10-26 提出）：
1. 改造 moox，让它能表达 F1 策略的各种写法，包括前置过滤和后置过滤。
2. 把 FH001、FH002、FH003 移植到 moox，基于现有的"合约五分钟链路 · 5m"分别运行，参数与原策略完全一致。
3. 部署到生产，测量三个策略的端到端耗时。

**前提与解读**：
- **任务与实例怎么配**：任务和实例是 1:1 独占关系，而现有的 `ftask_swap5m_chain`（展示名"合约五分钟链路"）已经被 `chain_ema20w_5m` 独占。所以"基于合约五分钟链路"在这里解读为：在它的**同一个源数据集** `dataset_dbev64ivka4d2219dbag`（5m 永续）上新建三个因子任务、三个观察实例。现有任务和实例都不动。
- **观察实例**：三个实例都不挂账户，只计算、不下单。
- **"参数一致"已经替设计做了几项决定**：
  - 持仓按数量持有；
  - 后置过滤遇到空值时保留（设计 F1-9、F1-13）；
  - 上市初期的出值与 F1 一致，为此表达式引擎要新增 partial 算子（设计第 2 节）。
- **不在本次范围内**：合约回放与资金费率采集、长 EMA 分块锚定（设计第 8 节）、参数搜索。
- **因子侧要换二进制**：factor-mgr 和因子引擎都要换（新算子），但只换二进制，**不执行 `deploy-unit`**。它会把 `engine.yaml` 重新渲染回默认值。

**涉及的改动**：

| 模块 | 改动 |
|---|---|
| `packages/factorexpr` | 新增 `ema_partial`、`ts_mean_partial`、`ts_std_partial`、`ts_min_partial`、`ts_max_partial` |
| `modules/factor/factors` | 新增 `f1.yaml`（5 个因子） |
| `modules/strategy` | DSL 新增 `type: f1` 与参数表；引擎新增 f1 求值；集合划分、守门、冻结、状态、明细、启用校验作相应调整；回放遇到 f1 拒绝 |
| `web` | DSL 预览接受 f1；规则摘要与明细原因的展示 |
| `local/f1/`（不进仓库） | 转换脚本、moox.toml 补丁工具、黄金用例生成脚本与因子对照脚本，以及它们的产物（含第三方参数，按用户决定不进仓库） |
| 文档 | `docs/模块/策略.md`、`docs/模块/因子.md`、本计划的上线结果 |
