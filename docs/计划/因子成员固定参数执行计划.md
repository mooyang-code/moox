# 因子成员固定参数执行计划

2026-10-25 · v1（待确认，未编码） · 分支 `feat/initial-import`

## 1. 目的

一个因子定义常常有多组参数要同时计算（EMA20 与 EMA50、预热 0 与预热 5 万）。现有设计里，参数只能由策略实例的私有因子集逐期提交，
**共享因子集的成员永远用定义的默认参数**，所以想在共享因子集里算 `ema(close, 20, 50000)`，只能新建一个把参数写进表达式的因子（`Ema20Warmup50000`）。
这样参数混进了因子名，每多一组参数就多一个定义，结果里也看不到参数。

本计划让**共享因子集的成员带一份固定参数**，同一个定义可以用不同参数、不同别名出现多次；别名由参数自动生成。

## 2. 决策

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 成员新增**固定参数**：加成员时给出，之后不可改；要换参数就换成员（删除后重加，别名随参数变） | 别名和结果列名由参数决定，参数不可变才能保证列的含义不变；也免去“改参数”的冻结与历史问题 |
| 2 | 别名默认由系统生成：**全部参数等于默认值 → 沿用因子 ID；否则 `因子ID_参数1_参数2…`**，按定义声明的顺序写全部参数值 | 同一组参数总是同一个别名；全默认时现有列名（`ema`、`macd_dif`）不变 |
| 3 | 别名可在加成员时手改，**成员启用后不可改**；字符限制沿用现有规则（字母、数字、下划线，无连续下划线），上限 64 个字符 | 别名决定结果列名 |
| 4 | 同一因子集内，**同一因子 + 同一组参数只能有一个成员** | 避免重复计算同一个东西 |
| 5 | **参数列只在策略私有因子集写入**；共享因子集不写 | 共享成员的参数是固定属性，别名与成员表已表达；参数列只有在逐期变化时才有意义（用户确认“参数列不用”，此处按该意思理解，见第 10 节） |
| 6 | 删除 `Ema20Warmup50000` 因子与成员，改为 `Ema` + 参数 `span=20, warmup=50000`（别名 `Ema_20_50000`）；`Ema50000` 暂保留 | 项目未上线，线上数据直接删除重建，不写迁移 |
| 7 | 因子定义的命名约定：只描述算法，不带参数值 | 参数属于成员，不属于定义 |

数值参数写进别名时：小数点写 `p`、负号写 `n`（`0.5` → `0p5`，`-1` → `n1`）；整型直接写数字。参数声明为浮点且值为整数时按整数写。

## 3. 数据模型

- `t_factor_set_members` 新增 `c_params TEXT NOT NULL DEFAULT '{}'`：参数名 → 数值的规范 JSON（键有序），**只存与默认值不同的参数**（全默认存 `{}`）；读取时与定义的默认值合并成完整参数。
- 唯一性：应用层校验“同集同因子同参数”；SQL 层加唯一索引 `(c_set_id, c_factor_id, c_params)`。
- 领域层：`domain.MemberDef` 增加 `Params`（完整参数）与 `TrackParams`（是否写参数列，私有集为真）；
  `domain.DefaultSnapshot(def)` 改为 `domain.MemberSnapshot(member)`：以成员固定参数覆盖定义默认值。
- 别名生成：`domain.DeriveMemberAlias(def, params)`，服务端权威实现；前端实现同一规则并用同一组用例（共享测试向量）核对。

## 4. 协议（`proto/factor.proto`）

- `AddFactorToSetReq` 增加 `map<string, double> params = 4`；`member_alias` 为空时按第 2 节规则生成（不再取定义 ID）。
- `FactorMember` 增加 `map<string, double> params`（完整参数，只读，派生）；`param_columns` 在共享因子集为空。
- `FactorUsage` 增加 `params_summary`（如 `span=20, warmup=50000`，全默认为空），供定义页抽屉显示。
- 引擎目录（`SyncEngineCatalog`）里的成员带 `params`，引擎按它求冻结快照。

## 5. 校验

加成员时：参数名必须是定义声明的；类型（整型必须是整数）与范围按定义校验；联合约束（如有）成立；
别名合法且在集内唯一；同因子同参数不重复。定义被更新（`UpdateFactor`）时，除了现有“成员须先停用”，还要校验所有成员的固定参数仍然合法，
不合法的拒绝并列出成员。

## 6. 冻结与计算

- 共享因子集的冻结来源仍是“默认”，但默认快照改为成员快照：`internal/engine/params.go`、`pipeline/compute.go`、`catalog/params.go`、`engine/replay.go`、`engine/runonce.go` 里五处 `DefaultSnapshot(member.Factor)` 改为 `MemberSnapshot(member)`。
- `params_digest` 用成员快照计算；周期标记里的 `params_source` 仍为 `default`（没有写入方提交）。
- 私有因子集不变：成员固定参数为空，参数仍由策略逐期提交，参数列照常写入。
- 结果列：`OutputColumn` 规则不变（别名等于因子 ID 时就是输出名，否则 `别名_输出名`）；`ParamColumns()` 在 `TrackParams` 为假时返回空，列对齐（`catalog/reconcile.go`、`catalog/service.go`）与组装（`pipeline/assemble.go`）随之不再包含参数列。

## 7. 前端

- **因子定义页**：不变，一个定义一行；详情抽屉的“使用情况”标签增加参数摘要（`计算任务 · 别名 · span=20, warmup=50000`）。
- **成员表**（`compute-tasks/member-section.vue`）：新增“参数”列，全默认显示“默认”；不再显示参数列名。
- **添加成员弹窗**（`add-factor-modal.vue`）：选因子后按定义声明展开参数输入框（带范围与默认值），别名与结果列名实时预览，别名可手改；提交带 `params`。
- `api/factor/types.ts`、`factor-scope.ts`（结果页按成员别名取列）同步；别名生成函数放 `views/factor/shared/`，用共享测试向量与服务端对齐。

## 8. CLI 与配置

- `moox.toml` 的 `[[factors.members]]` 增加可选 `params` 表；`member_alias` 缺省按第 2 节生成；`configinit/migrate_factors.go` 与示例同步。
- `moox-factor-mgr-cli` 与 `moox-cli` 里加成员的命令增加 `--param name=value`（可重复）。
- skill `factor-dsl.md`、`initial-import.md` 与 `docs/模块/因子.md` 同步：写明“同一定义多组参数用成员别名，不要为参数新建定义”。

## 9. 线上处理（未上线，不写迁移）

1. 停 factor-mgr，备份 `factor.db`，手工执行一次 `ALTER TABLE t_factor_set_members ADD COLUMN c_params TEXT NOT NULL DEFAULT '{}'` 与建唯一索引（不进代码），发布新版 factor-mgr 与因子引擎（引擎也要换，目录里的成员多了 `params`）。
2. 5m 因子集：停用并删除成员 `Ema20Warmup50000`，删除该因子定义；添加成员 `Ema`（`span=20, warmup=50000`，别名自动生成为 `Ema_20_50000`），按因子集生命周期启用（引擎里已经是“运行”，新成员随目录同步）。
3. 1m 现货、合约因子集不动（成员 `Ema` 全默认）。结果数据集里已有的旧参数列（`Ema__span` 等）留着不用，不清理；需要时用 `purge-dataset` 重建。
4. 前端随 web-host 发布（需重新生成内嵌静态文件）。

## 10. 需要确认

1. **“参数列不用”的含义**：本计划按“共享因子集不写参数列，只有策略私有因子集写”处理。如果你的意思只是“不要把参数列按别名展开成 `Ema_20_50000__span`，已有的 `Ema__span` 仍保留”，则第 5 条和第 6 节最后一条改为“共享成员的参数列仍按 `别名__参数名` 写”，其余不变。
2. 别名上限 64 个字符是否合适；超过时强制手改。
3. 要不要在本次一起把 `Ema` 的 `span` 上限放开，使 `Ema50000` 也能并入 `Ema`（`span=50000, warmup=50000`）：放开意味着“不设预热”的通常方式回看会超过引擎上限，需要给通常方式加硬限制，建议另议，本次不做。
