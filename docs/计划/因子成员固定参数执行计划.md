# 因子成员固定参数执行计划

2026-10-25 · v2（待 Codex 审查，未编码） · 分支 `feat/initial-import`

## 1. 目的与范围

现有设计里，一个因子定义常常要同时算多组参数（EMA20 与 EMA50、预热 0 与预热 5 万），但参数只能由策略实例的专属任务逐期提交，
**非策略专属的因子计算任务（页面上的“计算任务”，内部叫共享因子集）的成员永远用定义的默认参数**。要在这类任务里算 `ema(close, 20, 50000)`，
只能新建一个把参数写进表达式的因子（`Ema20Warmup50000`）：参数混进了因子名，每多一组参数就多一个定义，结果里也看不到参数。

另外，建任务时还要选“对象范围”（`all` / `include` 一组标的），而标的范围其实已经由源数据集决定；新建任务后还要在因子机手动 `lifecycle init / start / confirm`，
不做就一直是“未初始化”，不计算（2026-10-25 实际踩到）。

本计划做三件事，让“因子计算任务”成为唯一的用户概念：

> 因子计算任务 = 一个源数据集（决定标的、频率） + 一组成员（因子 + 固定参数 + 别名）

1. **成员带固定参数**，同一个因子定义可以用不同参数、不同别名在一个任务里出现多次；别名由参数自动生成。
2. **去掉任务的对象范围**：任务的标的就是源数据集当前的标的。
3. **所有任务自动推进生命周期**，不再手动 init / start / confirm。

不在本计划内：不引入“内置因子 / 自定义因子”的区分，不做按数据集自动绑定；回看仍按参数范围的最大组合推导（引擎按最大需求加载本地窗口，公共计算逻辑不变）。

## 2. 术语

| 说法 | 含义 |
| --- | --- |
| 因子计算任务 | 页面“计算任务”，内部 `FactorSet`；本计划不改内部名字 |
| 成员 | 任务里的一个因子，身份是 `(任务, 别名)` |
| 固定参数 | 加成员时给定、之后不变的参数值 |
| 策略实例专属任务 | 策略实例启用时自动建的任务（`owner_instance_id` 非空），参数由该实例逐期提交；是引擎内部的一类任务，不是用户要学的概念 |

## 3. 决策

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 成员新增**固定参数**：加成员时给出，之后不可改；要换参数就删除后重加（别名随参数变） | 别名与结果列名由参数决定，参数不可变才能保证列的含义不变，也免去“改参数”的冻结与历史问题 |
| 2 | 别名默认由系统生成：**全部参数等于默认值 → 沿用因子 ID；否则 `因子ID_参数1_参数2…`**，按定义声明的顺序写全部参数值 | 同一组参数总是同一个别名；全默认时现有列名（`ema`、`macd_dif`）不变 |
| 3 | 别名可在加成员时手改，**成员启用后不可改**；字符沿用现有规则（字母、数字、下划线，无连续下划线），上限 64 个字符，超过时必须手改 | 别名决定结果列名 |
| 4 | 同一任务内，**同一因子 + 同一组参数只能有一个成员** | 避免重复计算 |
| 5 | **参数列只在策略实例专属任务写入**；非专属任务不写 | 固定参数的任务里，参数列每行都一样，没有信息量；专属任务的参数逐期变化，列才有记录价值（按用户“参数列不用”理解，见第 11 节） |
| 6 | 去掉任务的对象范围：删除 `subject_mode`、`subjects` 与只改范围的 `UpdateFactorSet`；任务的标的 = 源数据集当前的标的，标的增减沿用现有行为 | 范围已体现在源数据集里 |
| 7 | 所有任务由引擎自动 `init`、`start`；**非专属任务另外在第一个预热周期完整算完后自动 `confirm` 进入运行**；专属任务保持现状（不自动 confirm） | 专属任务的预热阶段有“策略对预热实例发影子目标”的语义，不动；非专属任务没有策略依赖，预热与运行只是显示阶段不同 |
| 8 | 删除 `Ema20Warmup50000` 因子与成员，改为 `Ema` + `span=20, warmup=50000`（别名 `Ema_20_50000`）；`Ema50000` 暂保留 | 项目未上线，线上数据直接删除重建，不写迁移 |
| 9 | 因子定义命名约定：只描述算法，不带参数值 | 参数属于成员，不属于定义 |

数值参数写进别名：小数点写 `p`、负号写 `n`（`0.5` → `0p5`，`-1` → `n1`）；参数声明为整型或值为整数时按整数写。

## 4. 数据模型

- `t_factor_set_members` 新增 `c_params TEXT NOT NULL DEFAULT '{}'`：参数名 → 数值的规范 JSON（键有序），**只存与默认值不同的参数**（全默认存 `{}`）；读取时与定义的默认值合并成完整参数。
- 唯一性：应用层校验“同任务同因子同参数”；SQL 层加唯一索引 `(c_set_id, c_factor_id, c_params)`。
- `t_factor_sets` 删除 `c_subject_mode`、`c_subjects_json`。
- 领域层：`domain.MemberDef` 增加 `Params`（完整参数）与 `TrackParams`（是否写参数列，专属任务为真）；
  `domain.DefaultSnapshot(def)` 改为 `domain.MemberSnapshot(member)`，以成员固定参数覆盖定义默认值。
- 别名生成：`domain.DeriveMemberAlias(def, params)` 是服务端权威实现；前端实现同一规则，两边用同一份测试向量（放 `modules/factor/testdata/alias_vectors.json`，前端测试读取）。

## 5. 协议（`proto/factor.proto`）

- `AddFactorToSetReq` 增加 `map<string, double> params = 4`；`member_alias` 为空时按第 3 节规则生成（不再取定义 ID）。
- `FactorMember` 增加 `map<string, double> params`（完整参数，只读，派生）；`param_columns` 在非专属任务为空。
- `FactorUsage` 增加 `params_summary`（如 `span=20, warmup=50000`，全默认为空）。
- `FactorSet` 删除 `subject_mode`、`subjects`；`CreateFactorSetReq` 随之不再带；删除 `UpdateFactorSetReq/Rsp` 与 RPC `UpdateFactorSet`。
- 引擎目录（`SyncEngineCatalog`）的成员带 `params`；任务不再带 `subject_mode`、`subjects`。
- 服务目录（`packages/servicecatalog/catalog.yaml`）去掉 `UpdateFactorSet`，路由数与快照测试同步；这是目录变化，**Admin、Monitor、三台 host-gateway 要整体发布**（`native-release.md` 的“服务目录变化”流程）。

## 6. 校验

加成员时：参数名必须是定义声明的；类型（整型必须是整数）与范围按定义校验；联合约束成立；别名合法且在任务内唯一；同因子同参数不重复。
定义被更新（`UpdateFactor`）时，除了现有“成员须先停用”，还要校验所有成员的固定参数仍然合法，不合法的拒绝并列出成员。

## 7. 冻结与计算

- 非专属任务的冻结来源仍是“默认”，但默认快照改为成员快照：`engine/params.go`、`pipeline/compute.go`、`catalog/params.go`、`engine/replay.go`、`engine/runonce.go` 里五处 `DefaultSnapshot(member.Factor)` 改为 `MemberSnapshot(member)`。
- `params_digest` 用成员快照计算；周期标记里的 `params_source` 仍为 `default`。
- 专属任务不变：成员固定参数为空，参数仍由策略逐期提交，参数列照常写入。
- 结果列：`OutputColumn` 规则不变（别名等于因子 ID 时就是输出名，否则 `别名_输出名`）；`ParamColumns()` 在 `TrackParams` 为假时返回空，
  列对齐（`catalog/reconcile.go`、`catalog/service.go`）与组装（`pipeline/assemble.go`）随之不含参数列。
- 回看不变：成员回看仍按定义的参数范围取最大组合（不按成员固定参数缩小）。

## 8. 去掉对象范围

所有用到 `SubjectMode` / `Subjects` / `InScope` 的地方，统一改为“任务的标的 = 源数据集当前的标的”：

| 位置 | 改动 |
| --- | --- |
| `domain/types.go` | 删除 `SubjectModeAll/Include`、`FactorSet.SubjectMode/Subjects`、`InScope`（范围判断改为“标的在源数据集里”由调用方的标的列表决定） |
| `engine/preload.go` | 本地窗口共享键只用源数据集；预加载标的取源数据集全部标的 |
| `enginehub/snapshot.go`、`factorwire/convert.go` | 目录快照不再带范围 |
| `recalc/service.go` | 补算的 `subjects` 参数**保留**（它是这次补算的范围，不是任务范围），但校验改为“属于源数据集” |
| `preview/preview.go` | 试算的标的校验同上 |
| `store/sets.go`、`schema/factor.sql`、`catalog/service.go`、`catalog/instance.go`、`rpc/*` | 去掉字段与 `UpdateFactorSet` |
| `strategy/internal/input/factorsets.go` | 建专属任务时不再传 `SubjectMode: "all"` |
| 导入（`packages/seriesimport`、`cli import`） | 引擎接口 `SubjectInScope` 的语义改为“标的属于源数据集” |
| `cli/internal/command/setup_factors.go`、`cli/internal/setup/config/config.go`、`moox.toml.example`、`factor/cmd/cli/commands.go` | 配置与命令行去掉范围字段 |
| 前端 `compute-tasks/subject-scope-fields.vue`、`set-create-modal.vue`、`index.vue`、`recalc-create-drawer.vue`、`api/factor/types.ts` 等 | 去掉范围输入与显示；补算抽屉里的“补算标的”保留 |
| 文档与 skill | `因子.md`、`factor-dsl.md` 等去掉范围说明 |

标的随源数据集的标签增减，沿用引擎现有的“标的进出”处理，不加新机制。

## 9. 自动推进生命周期

- `engine/lifecycle.go` 的 `autoStartSet`：由“有拥有者的集合”改为“目录里的全部启用任务”，每个生命周期周期（`lifecycle.interval`，默认 30 秒）自动 `init`（未初始化）与 `start`（就绪）；检查没过的下一轮再推进，手动暂停、恢复追赶、重置中的不动（与现状一致）。
- 非专属任务：第一个预热周期**完整算完且无失败标的**后自动 `confirm` 进入运行。专属任务不变。
- 保留 `lifecycle init/start/confirm` 命令，供人工排障。
- skill `initial-import.md` 第 12 步里“手动走 lifecycle”的一段改为“自动推进，等 `lifecycle status` 显示运行”；`因子.md` 同步。

## 10. 前端与 CLI

- **因子定义页**：一个定义一行；详情抽屉“使用情况”的标签带参数摘要（`任务 · 别名 · span=20, warmup=50000`）。
- **成员表**（`compute-tasks/member-section.vue`）：新增“参数”列，全默认显示“默认”；非专属任务不显示参数列名。
- **添加成员弹窗**（`add-factor-modal.vue`）：选因子后按定义声明展开参数输入框（带范围与默认值），别名与结果列名实时预览，别名可手改；提交带 `params`。
- **建任务弹窗**（`set-create-modal.vue`）：只选源数据集，不再选对象范围。
- 别名生成函数放 `views/factor/shared/`，用共享测试向量与服务端对齐。
- `moox.toml` 的 `[[factors.members]]` 增加可选 `params` 表；`member_alias` 缺省按第 3 节生成；`configinit/migrate_factors.go` 与示例同步。
- `moox-factor-mgr-cli`、`moox-cli` 加成员的命令增加 `--param name=value`（可重复）。

## 11. 需要确认

1. **“参数列不用”的含义**：按“非专属任务不写参数列，只有策略实例专属任务写”处理。若你的意思只是“不要按别名展开成 `Ema_20_50000__span`，已有的 `Ema__span` 仍保留”，则决策 5 与第 7 节最后一条改为“非专属成员的参数列仍按 `别名__参数名` 写”，其余不变。
2. 自动 `confirm` 的触发条件（第一个预热周期完整算完且无失败标的）是否合适。
3. `Ema` 的 `span` 上限是否放开使 `Ema50000` 也并入 `Ema`：放开会让“不设预热”的通常方式回看超过引擎上限，建议另议，本次不做。

## 12. 上线（未上线，不写迁移）

1. 发布顺序：Admin、Monitor、三台 host-gateway（服务目录整体发布）→ factor-mgr（含 CLI）→ 因子引擎 → strategy → web-host（需重新生成内嵌静态文件）→ 操作机 `moox-cli`。
2. 停 factor-mgr 后，对 `factor.db` 手工执行一次结构调整（备份在先，不进代码）：成员表加 `c_params` 与唯一索引，任务表删范围两列。
3. 线上现有 3 个任务（两个 1m、一个 5m）的范围都是 `all`，不受影响。5m 任务：停用并删除成员 `Ema20Warmup50000`、删除该因子定义，添加成员 `Ema`（`span=20, warmup=50000`，别名自动生成 `Ema_20_50000`）；1m 任务的 `Ema` 成员全默认，保持原名。
4. 结果数据集里已有的旧参数列（`Ema__span` 等）留着不用，不清理；需要时用 `purge-dataset` 重建。
5. 验收：5m 任务出现 `Ema_20_50000_ema`，与同期 `Ema20Warmup50000` 旧列的值一致；新建一个任务后不做任何手动命令，30 秒内进入预热并出结果。

## 14. 请审查重点关注

1. 非专属任务的固定参数进入冻结与计算后，与现有的“冻结记录 / 参数区间 / 补算按冻结记录分段”是否有冲突（固定参数永远不变，补算分段应只有一段）。
2. 去掉对象范围后，`allow_partial_universe`、截面因子（`cs_*`）、连续水位、缺口账本对“标的 = 源数据集当前标的”的假设是否成立；标的进出时本地窗口与结果列的行为。
3. `autoStartSet` 扩大到全部任务后，启动顺序（引擎重启后阶段恢复）与 `lifecycle.json` 持久化阶段是否会被覆盖；非专属任务自动 confirm 的判定是否会误触发。
4. 别名规则的边界：参数值精度（浮点）、`p`/`n` 编码是否可能冲突、别名长度、与已有 `别名__参数名` 命名的歧义（`Ema_20_50000` 与参数列前缀）。
5. 删除 `UpdateFactorSet` 与服务目录整体发布的遗漏项（调用方、白名单、前端 API）。
6. 计划与代码事实不符的描述，以及遗漏的必要步骤。
