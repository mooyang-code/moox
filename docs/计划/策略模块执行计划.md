## 1. 已确认的决策

| # | 决策 |
| --- | --- |
| 1 | 实例只绑定一个 View（因子结果 View 或 K 线 View）；只由 `ViewDataReady` 触发；删除 cron 定时触发 |
| 2 | 规则用列表组织：`id`（稳定标识）、`name`（展示）、`type`（固定词表 `rank` / `signal`） |
| 3 | 标的池：默认 all；`universe` 可按 Storage 标签收窄或排除；规则可用 `pool` 显式覆盖；删除 UDF 机制 |
| 4 | 上期持有、本期缺数的标的：本期不参与计算，权重 0（清仓）；缺数按预期集合与可用集合的差统计，按规则分别计算 |
| 5 | 选择结果为空允许发布空目标（转现金）；`portfolio.min_universe` 与 `max_missing`（默认 0.2）守门 |
| 6 | 回放只读 View，定位为研究回放；维护理论持仓与现金账本；不承诺复现历史实时结果 |
| 7 | DSL 保留可选的 `bar` 断言 |
| 8 | 每个周期都落库：`ok` 带解释明细，`skipped` 带原因；`skipped` 不取消 pending、不参与最新性判断 |
| 9 | 因子版本：Factor 计算 `definition_hash` 随事件下发；策略做事件级校验；DSL 经 `bars[-1]` 读取因子列时要求相邻上一根对这些因子有指纹记录且相同，没有则 `skipped(previous_version_unknown)`（第五轮调整）；不做行级版本持久化 |
| 10 | `min_age_bars`：语义"N 根之前已有数据"，每期探针查询，无缓存；探针查询失败按基础设施错误重试，探针窗口的日历换算失败记 `skipped(config_error)`（第五轮调整） |
| 11 | 换仓控制第一版只有 `select.buffer`；不做 `min_delta`；`portfolio.max_weight` 超出留现金 |
| 12 | 权重方法第一版 `equal` 与 `rank`；`score` 延后 |
| 13 | 投递次数不设上限；求值尝试在进程内限次后转 skipped；终态记录落库成功后才 ACK；CAS 冲突重读后分类 |
| 14 | 会话：重启恢复原会话与状态；重复启用幂等；显式停用再启用才新建会话并清零状态 |
| 15 | 市场类型沿 `source_dataset_id` 读源数据集属性，缺失拒绝启用 |
| 16 | Trade 事件契约不变；`valid_until` 从 4 根 bar 改为 2 根 |
| 17 | 标的集合按规则计算：U = 事件名单 ∩ 活跃标的；E(r) = U ∩（显式 pool 或 universe 过滤）；G(r)、A(r)、M(r) 与缺数比例都按 E(r)；输入读取覆盖 ∪E(r) |
| 18 | 过期周期：处理时已过期或重试期间跨过有效期 ─► `skipped(expired)`，允许过去的 `valid_until`，不更新状态、不投递，落库后 ACK |
| 19 | 回放缺价只用截至当期的信息：缺价期保留持仓按最后价估值，调仓记为未成交；连续缺价 3 期（可配置）后按最后价清算；清算只在 ok 期判断，skipped 期只推进估值与计数 |
| 20 | 回放费用：`fee_rate = fee_bps / 10000`；目标金额按扣费后权益迭代计算，现金不为负；一致性验收以引擎级等式为准 |
| 21 | 历史快照：`t_strategy_def_versions` 保存每个 DSL 版本，`t_strategy_sessions` 保存会话的 DSL 版本与绑定快照 |
| 22 | 实例与定义软删除（`c_deleted_at`）：实例须先停用，定义须无未删除实例引用；会话、版本、结果不级联删除 |
| 23 | `definition_hash` 是派生字段，读取时计算；Factor 数据库不加列、不重建 |
| 24 | 现货 View 启用时拒绝 `leverage > 1`，运行时 Σw > 1 记 `skipped(config_error)` |
| 25 | 回放账本：目标金额按总权益计算（冻结持仓计入总权益）；冻结持仓不提供资金；先卖后买，买单受现金约束按比例缩减并记录未达成；费用只按实际成交额；迭代带容差与回退 |
| 26 | 相邻记录可信条件：同实例、同 View、同 bar 与日历、恰好早一根、含经 `bars[-1]` 读取的全部因子指纹；优先当前会话，其次最新 |
| 27 | 回放任务不做断点续跑：重启时遗留 `running` 标记为 `failed(interrupted)`，保留 bars |
| 28 | 第一版只支持现货回放：`StartReplay` 拒绝源数据集 `market_type = swap` 的 View；合约账本另行设计 |
| 29 | 阶段验收以实际通过为准：B 覆盖 S1～S21、S23、S25，S22、S24、S26、S27 在 D 验收；不接受 `t.Skip` |

## 2. 范围与原则

- 范围：`modules/strategy` 全部、`modules/strategy/proto`、`web/src` 的策略页面与 API、Admin 服务目录中的策略
  网关白名单、`docs/模块/策略.md`、部署脚本中与策略配置相关的部分。
- 跨模块的小改动（只加字段，向前兼容）：Factor 的 `definition_hash`、Storage 周期标记协议与
  `packages/storagepb` 事件协议的 `FactorPeriodState.definition_hash`、`packages/events` 的校验。
- 不在范围：Trade 代码；`packages/tradeeventpb`；Storage 的行写入与 View 查询语义。
- 原则：与旧包不冲突的新包先独立完成并带齐语义测试；协议变更、调用方切换与旧包删除放在一个可编译的集成提交里；
  阶段之间可独立合入，但阶段 B 完成前不部署新版本。

### B0 语义测试规格

在动手写包之前先把下列用例写成 `engine`、`store`、`readiness`、`replay` 的表格测试骨架（未实现的可以先 `t.Skip` 占位），
作为后续步骤的验收标准；各阶段验收以用例实际通过为准，不接受 `t.Skip`：

| 编号 | 用例 |
| --- | --- |
| S1 | 规则 r 的预期集合 E(r) 有 100 个标的，40 个完全没有行：`max_missing=0.2` 必须触发整期跳过；黑名单、标签与年龄剔除不计入缺数；universe 排除的 BTC 仍出现在显式 `pool: [BTC-USDT]` 规则的 E(r) 中并被读取 |
| S2 | 某因子只对规则 r1 失败：r1 的候选剔除该标的，r2 不受影响 |
| S3 | 上期持有、本期缺数：目标权重为 0，解释明细写 `missing:<col>`；buffer 不保留它 |
| S4 | `top=5`、`total=0.8`、`cap=0.3`，只有 2 个标的通过：分配 0.6，其余留现金 |
| S5 | 两条规则选中同一标的，合计超过 `portfolio.max_weight`：超出留现金；gross 不超过 leverage |
| S6 | `bottom` 选择配合 `method=rank`：低分标的得到更高权重 |
| S7 | rank 同分、单样本、zscore 零方差、`rank(zscore(x))` 嵌套：结果确定且可重复 |
| S8 | 选择结果为空：`Status=ok`、零目标、现金 100% |
| S9 | 上期 ok 待发送、本期 skipped：上期目标仍可在有效期内发送；规则状态从上期 ok 恢复 |
| S10 | 重复投递、乱序投递：分别记为重复 ACK 与 `skipped(out_of_order)`，不重复发布 |
| S11 | 分页读取中 index 或 revision 变化：丢弃已读页面，整体重读 |
| S12 | 探针查询失败：返回基础设施错误，不把标的记为年龄不足；探针窗口的日历换算失败记 `skipped(config_error)`，不按基础设施错误重试（第五轮调整） |
| S13 | `definition_hash` 与固化值不同、或经 `bars[-1]` 读取的因子在相邻上一根记录里的指纹与本期不同：`skipped(factor_changed)` |
| S14 | 进程重启后实例沿用原会话与规则状态；重复启用不新建会话；显式停用再启用新建会话且状态清零 |
| S15 | 求值尝试超过预算后写 `skipped(infra_retry_exhausted)` 并 ACK；终态落库失败则 NAK 而不 ACK |
| S16 | 首次收到已过期周期的事件：写 `skipped(expired)`（允许过去的 `valid_until`）后 ACK，不更新规则状态、不进 outbox |
| S17 | 决策已算出但提交失败，重试期间跨过有效期：转为 `skipped(expired)` 落库后 ACK，不发布 |
| S18 | 因子 H1 → H2 后重新启用、DSL 用了 `bars[-1]`：首期按相邻记录是否存在分别为 `skipped(factor_changed)`（旧会话有 H1 记录）或 `skipped(previous_version_unknown)`（无记录），并记录本期指纹；次期正常求值 |

## 10. 顺序与依赖

```text
A（可选）
B0 测试规格 ─► B1 dsl ─► B2 engine ─► B3 readiness ─┐
B4 Factor 指纹（独立合入）───────────────────────────┼─► B5 集成提交 ─► B6 收尾
                                                     │
                                                     ├─► C 前端与网关
                                                     ├─► D 回放（依赖 B2、B5）
                                                     └─► E 运维（依赖 B、C、D）
```

B1 与 B2 可以并行；B4 与 B1 到 B3 并行；C 与 D 在 B6 之后可以并行。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 集成提交体量大 | B0 的测试规格先于代码存在；B5 前先在分支上让新包各自通过测试；集成后用阶段 B 的完整验收清单（S1～S21、S23、S25 与五项环境验收）兜底 |
| 因子结果 View 缺少某个携带列（例如采集任务输出字段变化） | 启用时解析列，缺列直接报错；运行时列缺失记为 `config_error` 跳过并标记实例 `degraded` |
| `MaxDeliver` 无限后的毒消息 | 解码与契约错误 TERM；业务错误都转 skipped 并 ACK；只有落库失败才持续 NAK，且 `MaxAckPending` 限制在途数量 |
| 解释明细使数据库增长 | 每期每规则对 E 一行；按天清理；主键即索引；必要时缩短 `result_items_days` |
| 探针查询每期一次 | 只读 `close` 列、只覆盖 E；失败按基础设施错误重试，不影响正确性 |
| 回放占用 CPU 与 Storage 查询 | 单工作协程；分段读取；可取消 |
| 调大 `view_bars` 后 DuckDB 文件增大 | 只在需要长回放时调整，并观察 `max_view_file_bytes` 触发的容量重建 |
| 并行会话同时改动仓库 | 每个阶段单独分支与提交，提交只包含本阶段文件 |

## 12. 不做的事

- 不迁移旧 `strategy.sqlite` 数据；不保留旧 DSL（map 形式、`triggers`、`data`、UDF 池）的解析。
- 不改 Trade 代码；不改 `packages/tradeeventpb`；不改 Storage 的行写入与 View 查询语义。
- 不做行级因子版本持久化、`min_delta`、`method: score`、多周期、组合优化、持仓反馈、Python 策略运行时、盘口级回测、合约回放。
