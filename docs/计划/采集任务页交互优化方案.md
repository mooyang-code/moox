# 采集任务页交互优化方案

- 基线：`docs/kline-resample-design` 分支；页面 `web/src/views/collector/collection-tasks/`（`collection-tasks.vue`）
- 关联：[K线合成设计](K线合成设计.md)第 6 节定目标形态（「合成来源」列、「新建合成 / 历史合成」），本方案在其之外补齐通用交互层
- 状态：**第一批已实施**（2026-10-23，含后端 `keyword` 搜索参数）；第二批随合成设计第 11 步落地

## 1. 现状问题（改前）

1. 检索不畅：仅有「按内部任务 ID 筛选」——task_id 是系统生成 ID，用户记不住；筛选不写 URL，刷新即丢；输入无回车触发。
2. 列表信息架构：9 列横向滚动 1450px；「结果状态」「最近数据时间」与「采集结果」tab 重复；且列表加载后 `inspectCollectionTaskResults` 逐行调 `GetTaskDetail` 巡检（N+1）只为刷新这两列。
3. 操作列风险：4～5 个按钮平铺；「禁用」无二次确认，误触即停采集；「删除」与普通操作平级。
4. 表单与弹窗层叠：新建 / 编辑是 860px 弹窗装 4 个分节 + 高级设置，纵向深滚动；输出字段选择器弹窗叠弹窗；编辑态一排禁用控件可读性差。

## 2. 第一批：通用交互优化（已实施）

不依赖合成后端改造，纯前端 + 后端搜索参数。

| 项 | 改动 |
| --- | --- |
| 搜索 | 输入框改 `keyword`（placeholder「搜索任务名称 / 任务 ID」），回车触发查询、allow-clear 清除即查；后端 `GetTaskListReq` 新增 `keyword` 字段，store 层对 `LOWER(c_task_name)` / `LOWER(c_task_id)` 做 `LIKE %kw% ESCAPE '\'`（转义 `%`、`_`、`\`），沿用存储侧 keyword 惯例 |
| URL 同步 | `keyword` / `dataType` / `enabled` / `page` 写入 query（`syncListQuery`），刷新、分享可还原；`taskId` 详情深链保留；切空间清空筛选（任务清单随空间变化） |
| 列调整 | 移除「结果状态」「最近数据时间」两列（信息归「采集结果」tab 与详情抽屉「运行信息」分组），保留「启用状态」tag 列；横向滚动 1450 → 1050 |
| 巡检删除 | 删除 `inspectCollectionTaskResults` / `tasksNeedingResultInspection` 及列表页逐行 `GetTaskDetail` 调用 |
| 操作列 | 「修改」平铺（primary mini）；启停 / 回填（kline_resample）/ 删除收进「⋯」下拉，删除红色；启停先 `Modal.confirm`（文案说明后果），执行期间该行 loading（`togglingTaskId`） |
| 表单抽屉化 | 新建 / 编辑弹窗 → 右侧抽屉（680px，底部「取消 / 保存任务」，`saveEditor` 成功后手动关闭）；编辑态不可变项（数据类型、频率、标的、源行情、源周期、序列标签）由禁用控件改**只读摘要**（`readonly-summary`）；输出字段选择器改第二层抽屉，消除弹窗叠弹窗 |
| 详情抽屉化 | 详情弹窗 → 右侧抽屉（640px），分「基本信息 / 执行方式 / 输出字段 / 运行信息」四组；运行信息含结果状态、最近数据时间、准备信息 |
| 空态 | 无任务显示「还没有采集任务」+ 新建按钮；有筛选无结果显示「没有匹配的任务」+「清除筛选」 |

改动文件：`modules/collector/proto/collector.proto`（+`collectorgen`）、`internal/store/task.go`、`internal/rpc/service.go`、`internal/store/task_test.go`、`web/src/api/collector/index.ts`、`web/src/views/collector/collection-tasks/collection-tasks.vue`、`collection-task-params.ts`（删巡检）及两个测试文件。

保留不动：删除确认弹窗（radio 二选一）、回填弹窗 `resample-backfill.vue`（第二批替换）、`taskId` 深链、空间切换时关闭打开中的表单窗口。

与原型的差异：启停确认用 `Modal.confirm` 而非气泡（Popconfirm 嵌在下拉菜单项里有关闭时序冲突，`Modal.confirm` 是项目已有惯例）。

## 3. 第二批：随合成设计落地（待实施）

依赖 [K线合成设计](K线合成设计.md)第 3、8 步与控制台改造接口（`PreviewKlineResampleSource`、作业接口），交互细化：

1. **「合成来源」列**：合成任务显示「源任务名 → 目标频率」，点源任务名定位该行（不在当前页则带 `taskId` 查询）。
2. **「新建合成」行操作**：kline 与合成任务行都有（支持 15m → 45m → 135m 链式），打开合成表单，源任务预填锁定。
3. **合成表单**：源任务下拉「任务名 · 频率 · 市场」，不满足规则置灰并说明原因；选中后调预览接口展示后端推导摘要卡片（源数据集 / 源周期 / 序列标签 / 标的数 / 市场），替代手填；目标频率标准档快捷 + 自由输入，失焦即时校验（语法 / 被源周期整除 / 整除一天）；采集标的只读「继承源任务，共 N 个标的」。
4. **历史合成抽屉**替换回填弹窗：上半提交作业（UTC 时间范围、可选标的、request_id 幂等说明），下半作业列表（来源「手动 / 补采触发」、进度游标 / 总桶数、写入 / 跳过，展开跳过样例，运行中可取消）。
5. **详情抽屉**补「合成来源」组与「依赖它的合成任务」反向列表（删除源任务前确认下游）。
6. 操作列终态：「修改 + 新建合成」平铺，「⋯」内启停 / 历史合成 / 删除。

## 4. 明确不做

批量操作（任务量小）、列自定义 / 排序、列表自动轮询（结果状态移除后无实时性诉求）、i18n、合成任务拆独立页面（设计稿已否决——「一任务一结果」，列表 / 详情 / 删除 / 结果管理不重做一遍）。
