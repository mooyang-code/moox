# 采集运行状态页改造执行计划

> 状态：已实施（2026-10-15）。

## 1. 目标

采集任务页的「采集实例」Tab 改为「运行状态」，首要回答“采集有没有问题”：

- 顶部一眼看出整体是否正常、哪里不正常；
- 以数据集为单位展示健康度，异常排前；
- 上百个函数可搜索、筛选；
- 补采作业可筛选、看详情、重试失败分块；
- “行情源本来没有的 K 线”被确认后视为正常，不再反复报缺口、不再算失败。

不考虑兼容：协议、表结构与页面按合理性重写，旧接口与旧表直接删除。

## 3. 表结构

Collector 的 SQLite 没有迁移机制，`CREATE TABLE IF NOT EXISTS` 不会给已有表加列。补采作业与分块是可重建的运行状态，
因此改名重建，旧表在 schema 中 `DROP TABLE IF EXISTS`；自动补采水位表结构不变、原样保留（清掉它会让自动补采从最早生效点重扫历史）。

升级时未完成的补采作业会丢失：自动作业的水位没有推进，下次扫描会重新覆盖同一窗口；手动作业需要重新提交。

### 3.1 `t_collector_kline_backfill_jobs`（替代 `t_collector_backfill_jobs`）

去掉 `c_request` JSON，范围拆成列：

| 列 | 说明 |
| --- | --- |
| `c_job_id`、`c_space_id`、`c_source`、`c_status`、`c_last_error` | 同原表 |
| `c_dataset_id`、`c_frequency` | 空表示全部数据集；自动作业总是单个数据集与频率 |
| `c_subject_id` | 空表示全部标的 |
| `c_from`、`c_to` | 范围，`c_to` 不含 |
| `c_kind` | `gap`（按缺口）、`force`（整段重拉）、`history`（确认历史缺口） |
| `c_advance_watermark` | 1 表示自动作业，成功后推进水位 |

索引：`(c_space_id, c_status)`、`(c_space_id, c_source, c_ctime)`、`(c_space_id, c_mtime)`。

### 3.2 `t_collector_kline_backfill_chunks`（替代 `t_collector_backfill_chunks`）

在原列基础上增加 `c_missing TEXT`：上一次执行后复查仍缺的 K 线（规范化的区间串），用于“连续两次一致”的判定。
增加索引 `(c_status, c_mtime)` 供 24 小时失败统计。

### 3.3 `t_collector_source_absences`（新增）

已确认“行情源没有”的 K 线，按连续区间记录，永久保存：

| 列 | 说明 |
| --- | --- |
| `c_space_id`、`c_dataset_id`、`c_frequency`、`c_subject_id` | 序列 |
| `c_from`、`c_to` | 区间，`c_to` 不含 |
| `c_bars` | 区间内的根数（写入时按日历计算） |
| `c_ctime` | 确认时间 |

主键 `(c_space_id, c_dataset_id, c_frequency, c_subject_id, c_from)`。

### 3.4 `t_collector_history_scans`（新增）

每个数据集最近一次历史缺口扫描的结果，替代内存里的扫描节奏与只写日志的结果：

| 列 | 说明 |
| --- | --- |
| `c_space_id`、`c_dataset_id`、`c_frequency` | 主键 |
| `c_scanned_at` | 最近一次扫描完成（或失败）时间，决定下次扫描 |
| `c_from`、`c_to` | 读回范围 |
| `c_gap_bars`、`c_gap_subjects` | 扣除已确认缺失后的缺口根数与标的数 |
| `c_gaps` | 缺口分组 JSON（至多 200 组），供“补采确认”精确提交 |
| `c_last_error` | 扫描失败原因 |

## 4. “行情源没有”的判定

1. **单根分块**：函数执行成功、写入无误，复查仍缺 → 直接确认（沿用现有规则）。
2. **多根分块**：函数执行成功、写入无误，复查仍缺一部分：
   - 与该分块 `c_missing` 相同 → 确认这些 K 线行情源没有，写入 `t_collector_source_absences`，分块按成功结束，说明“行情源缺 N 根”；
   - 不同（含首次）→ 记下 `c_missing`，分块退回待执行（尝试次数照常累计），由补位立即重跑；超过最大尝试次数才标记失败。
3. 检查（`CheckKline`、自动补采、历史扫描）读取缺口后扣除已确认区间；`Result` 增加 `Absent`（扣除的根数）。
   整段重拉（`force`）不扣除，按操作员意图全部重拉。
4. 删除内存里的 `absent` map、`markAbsent`、`dropAbsent`。
5. **清除并重新检查**：按数据集清空已确认区间，同时清掉该数据集的历史扫描记录，下一轮历史扫描重新进行；
   实时区间由操作员用“检查缺口”确认。
6. 不提供“手动标记为行情源缺失”，避免误标掩盖真实缺口。

## 5. 健康等级

每个数据集给出 `ok` / `warn` / `error` 与原因列表；空间总体取最严重的一级，计划层面的问题单独计入。

| 条件 | 等级 |
| --- | --- |
| 计划最近一次下发失败（`last_error` 非空） | error（空间级） |
| 自动检查滞后超过 1 小时 | error |
| 自动检查滞后超过 15 分钟 | warn |
| 近 24 小时有失败分块 | warn |
| 历史扫描发现未确认缺口 | warn |
| 历史扫描失败 | warn |
| 有函数处于下发中且计划超过 30 分钟未生效 | warn（空间级） |

检查滞后 = 该数据集当前应扫到的时间（`now - 迟到容忍 - 一个周期`，按频率对齐）减去水位；
日线等低频数据集不会因为周期长被误判。近 24 小时实时缺口（自动作业发现的根数与标的数）只展示，不影响等级。

## 6. 接口

### 6.1 新增

| 方法 | 作用 |
| --- | --- |
| `GetCollectorStatus` | 运行状态一次返回：计划概要、总体健康、数据集健康、函数列表、补采汇总。替代 `GetFetchPlans` |
| `RetryKlineBackfill` | 已结束且有失败分块的作业：失败分块退回待执行、尝试次数与 `c_missing` 清零，作业改回等待中 |
| `ConfirmHistoryGaps` | 按 `t_collector_history_scans.c_gaps` 精确建立 `history` 补采作业，补完后行情源没有的部分自动进入确认表 |
| `ClearSourceAbsences` | 按数据集清空已确认的“行情源缺失”并重置历史扫描 |

### 6.2 修改

- `ListKlineBackfills` 增加筛选：`source`（manual/auto）、`attention`（未结束或有失败）、`dataset_id`；作业返回范围列，不再返回 `request` JSON。
- `GetKlineBackfill` 返回范围列与失败分块（至多 50 个）。
- `CheckKlineRsp` 增加 `absent`。

### 6.3 删除

- `GetFetchPlans` 及其消息（`FetchDatasetState.hash` 等展示用不上的字段一并去掉）；
- `GetTaskInstanceList`、`TaskInstanceFilter` 及仅它使用的消息与转换代码。

服务目录（`packages/servicecatalog/catalog.yaml`）同步增删方法；`RetryKlineBackfill`、`ConfirmHistoryGaps`、`ClearSourceAbsences`
开放给 `console` 与 `moox-cli`。服务目录变化需要 Admin、Monitor 与各主机 host-gateway 一起发布。

CLI：新增 `collector status`；`collector fetch-plan` 改用 `GetCollectorStatus` 只输出计划与函数；`collector kline` 增加 `backfill-retry`、`history-confirm`、`absences-clear`，`backfill-status` 支持筛选。

## 7. 数据保留

在 Collector 每分钟的维护任务中按预算清理已结束的补采作业及其分块：自动作业保留 7 天，手动作业保留 30 天。

## 8. 前端

- Tab 改名「运行状态」，URL 参数 `tab=status`；目录 `views/collector/runtime-status/`，删除 `task-instances/`。
- 状态条：总体等级与原因、5 张汇总卡（采集计划、函数、数据集/标的、近 24h 实时缺口、补采），右上角“变更记录”抽屉（标的变更日志）与刷新。
- 数据集健康表：异常排前；展开行显示原因、首次生效、水位、历史扫描、已确认缺失、服务函数，操作“检查缺口”“补采”“补采确认”“清除并重新检查”。
- 二级切换「函数」「补采作业」：
  - 函数：搜索、地域、市场、只看异常放在一行，异常排前，分页；
  - 补采作业：需关注/手动/自动/全部筛选，分段进度条，详情抽屉（范围、失败分块、取消、重试失败分块）。
- 补采表单：数据集下拉、UTC 日期时间范围与快捷范围；缺口结果可一键“补采这些缺口”。
