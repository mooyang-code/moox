# 主机登记与命名统一执行计划

执行计划 v2（2026-10-24，阶段 1～7 已编码完成，待 Codex 代码审查与阶段 8 上线）。依据：[主机登记与命名统一设计](主机登记与命名统一设计.md) v7.1，下文简称“设计”。
本计划只把设计拆成可以逐项执行、逐项验收的任务，不另做设计决策。遇到与设计不一致的地方，先改设计，再改本计划。

- **v1**：按设计拆成 7 个阶段。
- **v2**：吸收 Codex 审查（15 条）。
  - 把机械改名单独做成第一个阶段，在一次提交里改完全部调用方；
  - 删除服务目录方法时，与对应的协议、实现放在同一个提交里；
  - 先加 Doctor 字段，再加外部程序组件；
  - 补上漏掉的改动：前端角色过滤、终端建连链路、离线 bootstrap 的 SSH 传递与主密钥顺序、外部程序的业务凭据投递、Monitor 失联告警链、密钥接口的角色判断、Doctor 命令入口、中文名生成、全局日志的查询语义、`DeployUnit` 的 profile 白名单；
  - 测试命令改为按模块执行；`proto-check` 放到提交之后再跑。

## 0. 约定

- **原则**：只有一个超级用户，不分权限；个人系统，不过度设计；项目未上线，表结构直接改 `schema/*.sql`，上线全新部署，不写迁移和回退。
- **分支**：从 `main` 新建 `feat/host-registry`，阶段 1～7 都在这个分支上完成。每完成一个任务（`T*.*`）就跑它的测试并单独提交，提交信息写明任务编号。**每次提交后整个仓库都必须能编译、测试通过**，不允许留下中间状态。
- **改名规则**：凡是指“组件部署在哪台主机”的 placement，统一改成 deployment（中文“部署”）。对应关系：
  - `Placement` → `Deployment`、`placements` → `deployments`、`ComponentPlacement` → `Deployment`；
  - `SyncHostPlacements` → `SyncHostDeployments`、`ListPlacements` → `ListDeployments`、`SetPlacementStatus` → `SetDeploymentStatus`。

  以下不改：Storage（视图放置）、Trade（下单）、`packages/cloudprovider/tencent` 的 `Placement.Zone`、前端组件属性 `placement="left"`、`replacement` 一类子串。
- **Go 测试**：仓库根目录不是一个模块，`packages/` 也不是，所以不能用 `go test ./packages/...`。单个模块在它自己的目录里执行 `go test ./...`；全量测试执行 `make test-go`（`scripts/test/contract/test-go-workspace.sh` 会逐个模块跑）。
- **协议**：修改 `.proto` 后执行 `make proto`，把生成代码和改动一起提交。`make proto-check` 要求工作区干净，所以在**提交之后**再跑，确认生成代码与协议一致。
- **schema**：遵守 AGENTS.md 的“数据库 Schema 格式规范”。改完每个 schema 文件都要能单独载入空 SQLite 库，并通过 `git diff --check`。
- **前端**：测试与构建按惯例在编译机 `192.168.0.103:~/moox-web` 上执行（rsync 后跑 vitest、vue-tsc、vite build）。
- **构建**：不要在模块目录里不带 `-o` 执行 `go build ./cmd/x`，否则二进制会被 `git add` 提交进去。

## 3. 阶段 2：服务目录与 Doctor 契约

## 4. 阶段 3：Admin

### T3.1 表结构

改 `modules/admin/schema/admin.sql`，按设计 4.2：

- `t_hosts`：增加 `c_label`、`c_ssh_port INTEGER NOT NULL DEFAULT 0`、`c_ssh_user`、`c_ssh_fingerprint`；
- `t_secrets`：删除 `c_last_used_at`、`c_last_used_by`；
- `t_users`：只保留 `c_id`、`c_user_id`、`c_username`、`c_password_hash`、`c_last_login_at`、`c_last_login_ip`、`c_ctime`、`c_mtime`；
- 删除 `t_ssh_host`、`t_ssh_host_key`、`t_ssh_session`、`t_login_history`、`t_space_members` 及其索引、触发器；
- 同步 `schema/schema.go` 与 `schema_test.go` 里的表清单。

这一步只改 schema，依赖这些表的代码在 T3.2～T3.8 里修改。**T3.1 与 T3.2～T3.8 在同一个提交里完成**，保证每次提交都能编译、测试通过。如果改动太大，可以按“改 schema 与相关代码”成对拆分，但每个提交都要能通过 `make test-go`。

### T3.2 SysDeploy：中文名与 SSH 同步

- **协议** `proto/sysdeploy_service.proto`：
  - `DeploymentHost` 增加 `label`、`ssh_port`、`ssh_user`；
  - `SyncHostDeploymentsReq` 增加 `label` 和 SSH 信息：端口、用户名、凭据类型（`password` / `ssh_key`）、凭据内容。
- **服务**（`internal/service/sysdeploy/`）：
  - 同步时在一个事务里写 `t_hosts`（`label` 与 SSH 列）和 `t_secrets` 的 `ssh-host-<主机ID>`；
  - 没带 SSH 信息就置空：`c_ssh_port = 0`，并删除密钥记录；
  - 地址或 SSH 端口变化时清空 `c_ssh_fingerprint`；
  - 这套写入逻辑做成函数，供离线 bootstrap（T3.8）复用。
- **删除主机** `DeleteHost`：在一个事务里依次删除 `ssh-host-` 密钥、`t_host_gateway_status`、`t_deployments`、`t_hosts`；提交后调用 SSH 会话管理器，关闭该主机的全部会话。
- **约束**：凭据不进日志和错误信息。
- **测试**：同步写入与置空 SSH；指纹清空规则；删除主机的事务与关闭会话；`make test-host-deployment`。

### T3.3 SSH 服务改用主机登记

- **删除**：`internal/service/ssh/model/ssh_host.go`、`model/ssh_session.go`、`dao/ssh_host.go`、`dao/ssh_session.go`；`impl.go` 与 `rpc/service.go` 里的主机增删改查。
- **协议** `proto/ops_service.proto`：
  - 删除主机增删改查的方法和消息，`catalog.yaml` 里同步删除这些方法（同一提交）；
  - `CreateSessionReq` 的主机参数改为字符串 `host_id`；断开、调整窗口、SFTP 仍按 `session_id`。
- **连接**（`conn/ssh_conn.go`、`conn/session_manager.go`、`impl.go`）：
  - 从 `t_hosts` 读地址、端口、用户，从 `t_secrets` 解密凭据；`ssh_key` 按私钥处理，不支持带口令的私钥；
  - 指纹按“地址 + 端口”校验：首次连接用带条件的 `UPDATE` 写回 `t_hosts.c_ssh_fingerprint`，保证只写一次；主机已被删除时影响 0 行；
  - 会话管理器增加“关闭某主机的全部会话”；
  - 按主机的锁覆盖四件事：创建会话（从确认主机存在到注册会话）、写回指纹、SysDeploy 同步 SSH、删除主机。
- **rawhandler.go**：WebSocket 与 SFTP 的一次性 ticket 校验不变，只把查主机的方式换成新的。
- **测试**：
  - 按 `host_id` 建连、首次写指纹；
  - 改端口或改地址后指纹被清空，并能重新建立信任；
  - 删除主机与创建会话并发时不留下连接；
  - 凭据错误时的报错里不含凭据。

### T3.4 密钥表

## 12. 与设计的偏差

编码中与设计不完全一致的地方，以代码为准：

- 密钥 ID 前缀是 `moox:ssh-host:<主机ID>`（设计写作 `ssh-host-`），与 `moox:gateway-keyring:` 同属系统密钥前缀。
- 协议消息名为 `ComponentDeployment`（组件部署），主机消息为 `DeploymentHost`。
- 指纹固定不加按主机的锁：`PinHostKey` 用“地址:端口 指纹”做比较并交换，只接受当前登记的端点，旧端点不能覆盖。
- 前端 `HostMetrics` 增加 `agent_id`，`host_id` 改为登记主机 ID；首页与告警链接只带 `host_id`。
- 终端外观使用固定默认值，只从 `localStorage` 读取覆盖，没有设置界面。
- 管理台“数据节点”页只读；写操作改为 `moox-cli storage node update|delete`。
- `go test` 在本机（macOS）不会执行 `*_linux_test.go`；这些测试和七个 `test-unit-*-linux` 门禁在 Linux 编译机上运行（见上线前检查记录）。
- Codex 实现审查（9 项）已修 7 项：外部程序停止前先确认 systemd 可达、主机启用登记失败不再启动程序、doctor 保留 SSH 密码到连接用完、登录成功日志移到令牌签发之后、旧采集器的失联通知在新采集器接替后作废并补发换采集器后的主机恢复、监控页链接不再误开终端、主机列表补内网地址/地域/可达性。
- 审查后接受不改的两项：① SSH 建连与主机同步/删除之间的极短窗口（只有一个使用者，窗口内同步主机时旧连接会留到断开）；② 外部程序部署与启用的就绪检查只在目标机本机执行，经中转的链路由 Monitor 与 `doctor` 验证，不在部署命令里重复。
