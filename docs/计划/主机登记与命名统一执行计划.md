# 主机登记与命名统一执行计划

执行计划 v1（2026-10-24，尚未开始）。依据：[主机登记与命名统一设计](主机登记与命名统一设计.md) v7.1，下文简称“设计”。
本计划只把设计拆成可以逐项执行、逐项验收的任务，不另做设计决策。遇到与设计不一致的地方，先改设计，再改本计划。

## 0. 约定

- **原则**：只有一个超级用户，不分权限；个人系统，不过度设计；项目未上线，表结构直接改 `schema/*.sql`，上线全新部署，不写迁移和回退。
- **分支**：从 `main` 新建 `feat/host-registry`，阶段 1～6 都在这个分支上完成。每完成一个任务（`T*.*`）就跑它的测试并单独提交，提交信息写明任务编号。
- **改名规则**：凡是指“组件部署在哪台主机”的 placement，统一改成 deployment（中文“部署”）。
  对应关系：`Placement` → `Deployment`、`placements` → `deployments`、`ComponentPlacement` → `Deployment`、`SyncHostPlacements` → `SyncHostDeployments`、`ListPlacements` → `ListDeployments`、`SetPlacementStatus` → `SetDeploymentStatus`。
  以下不改：Storage（视图放置）、Trade（下单）、`packages/cloudprovider/tencent` 的 `Placement.Zone`、前端组件属性 `placement="left"`、`replacement` 一类子串。改完用第 9 节的检查命令确认没有残留。
- **协议**：修改 `.proto` 后执行 `make proto` 重新生成，再执行 `make proto-check`。
- **schema**：遵守 AGENTS.md 的“数据库 Schema 格式规范”。改完每个 schema 文件都要能单独载入空 SQLite 库，并通过 `git diff --check`。
- **前端**：测试与构建按惯例在编译机 `192.168.0.103:~/moox-web` 上执行（rsync 后跑 vitest、vue-tsc、vite build）。
- **构建**：不要在模块目录里不带 `-o` 执行 `go build ./cmd/x`，否则二进制会被 `git add` 提交进去。
- **服务目录变更**：服务目录变了，Admin、Monitor、全部网关以及各服务都要用同一提交重新构建。本计划上线就是全新部署，自然满足这条要求。

## 3. 阶段 2：Admin

### T2.1 表结构

改 `modules/admin/schema/admin.sql`，按设计 4.2：

- `t_hosts`：增加 `c_label`、`c_ssh_port INTEGER NOT NULL DEFAULT 0`、`c_ssh_user`、`c_ssh_fingerprint`；
- `t_placements` 改为 `t_deployments`，索引改为 `idx_t_deployments_component`，触发器改为 `trg_t_deployments_mtime`；
- `t_secrets`：删除 `c_last_used_at`、`c_last_used_by`；
- `t_users`：只保留 `c_id`、`c_user_id`、`c_username`、`c_password_hash`、`c_last_login_at`、`c_last_login_ip`、`c_ctime`、`c_mtime`，删除其余列和对应索引；

**测试**：`go test ./modules/admin/schema/...`；把 schema 单独载入空 SQLite 库；`git diff --check`。

### T2.2 SysDeploy：改名与 SSH 同步

- **协议** `proto/sysdeploy_service.proto`：
  - 三个方法与 `ComponentPlacement` 按改名规则改名；
  - `DeploymentHost` 增加 `label`、`ssh_port`、`ssh_user`；
  - `SyncHostDeploymentsReq` 增加 `label` 和 SSH 信息：端口、用户名、凭据类型（`password` / `ssh_key`）、凭据内容；
  - 执行 `make proto`。
- **服务**（`internal/service/sysdeploy/` 下的 `topology.go`、`topology_model.go`、`topology_service.go`、`topology_snapshot.go`、`rpc/topology.go`、`eventbus_endpoint.go`）：
  - 全部改名；
  - 同步时在一个事务里写 `t_hosts`（`label`、SSH 列）和 `t_secrets` 的 `ssh-host-<主机ID>`；没带 SSH 信息就把该主机的 SSH 置空（`c_ssh_port = 0`，并删除密钥记录）；地址或 SSH 端口变化时清空 `c_ssh_fingerprint`。
- **删除主机** `DeleteHost`：在一个事务里依次删除 `ssh-host-` 密钥、`t_host_gateway_status`、`t_deployments`、`t_hosts`；提交后调用 SSH 会话管理器，关闭该主机的全部会话。
- **约束**：凭据不进日志和错误信息。
- **测试**：同步写入与清空 SSH、指纹清空规则、删除主机的事务与关闭会话；把 `Makefile` 的 `test-host-placement-deployment` 改名为 `test-host-deployment`，并更新其中的 `-run` 正则，确认它仍能跑到改名后的测试。

### T2.3 SSH 服务改用主机登记

- **删除**：`internal/service/ssh/model/ssh_host.go`、`model/ssh_session.go`、`dao/ssh_host.go`、`dao/ssh_session.go`；`impl.go` 和 `rpc/service.go` 里的主机增删改查。
- **协议** `proto/ops_service.proto`：删除主机增删改查的方法和消息；`CreateSessionReq` 的主机参数改为字符串 `host_id`。断开、调整窗口和 SFTP 仍按 `session_id`。
- **连接**（`conn/ssh_conn.go`、`conn/session_manager.go`、`impl.go`）：
  - 从 `t_hosts` 读地址、端口、用户，从 `t_secrets` 解密凭据；`ssh_key` 类型按私钥处理，不支持带口令的私钥；
  - 指纹按“地址 + 端口”校验：首次连接写回 `t_hosts.c_ssh_fingerprint`，用带条件的 `UPDATE` 保证只写一次；主机已被删除时影响 0 行；
  - 会话管理器增加“关闭某主机的全部会话”；
  - 按主机的锁覆盖四件事：创建会话（从确认主机存在到注册会话）、写回指纹、SysDeploy 同步 SSH、删除主机。
- **rawhandler.go**：WebSocket 与 SFTP 的一次性 ticket 校验逻辑保持不变，只把查主机的方式换成新的。
- **测试**：按 `host_id` 建连、首次写指纹、改端口或改地址后指纹被清空并能重新建立信任、删除主机与创建会话并发时不留下连接、凭据错误时的报错里不含凭据。

### T3.4 启停命令

- **新增**：`command/setup_host_status.go`（`setup host enable|disable`）、`command/setup_deployment_status.go`（`setup deployment enable|disable`），都是先预览、加 `--yes` 才执行。
- **行为**：
  - 普通组件只改登记状态；
  - 外部程序停用：先经 SSH `systemctl --user stop` 加 `disable`，核对已停止，再改登记；
  - 外部程序启用：主机停用时拒绝；先改登记，再 `enable` 加 `start`，经中转等待 `/readyz`；
  - 主机停用：先逐个停掉启用部署的外部程序，全部成功后才改主机状态，结果逐个程序返回；
  - 主机启用：先改主机状态，再只启动启用部署的外部程序。
- **测试**：用假 SSH 执行器和假 Admin 覆盖：预览不产生任何修改；部分失败时不改登记；停用主机上拒绝启用；恢复主机时保留单独停用的程序。
