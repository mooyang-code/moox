# Auth 模块文档

## 1. 模块概述

Auth 模块是 MooX Admin 的用户认证和鉴权模块，提供用户登录、JWT 令牌管理、密码加密、登录保护等功能。

### 1.1 核心功能

- **用户登录**：基于用户名密码的登录认证
- **JWT 令牌**：生成和验证 JWT 访问令牌
- **密码加密**：服务端存储 `SHA256(password + user_salt)`，客户端用登录盐值和时间戳派生 AES-GCM 密钥后提交加密密码
- **登录保护**：失败次数限制、账户锁定
- **盐值验证**：防止重放攻击
- **用户信息**：注册、查询当前用户信息、更新昵称/邮箱/头像
- **密码管理**：修改密码
- **登录历史**：记录用户登录日志

### 1.2 安全特性

- **密码不可逆存储**：数据库只保存密码哈希和用户盐值
- **盐值机制**：每个用户独立的盐值
- **时间戳验证**：防止重放攻击
- **失败锁定**：连续失败后锁定账户
- **JWT 过期**：令牌有效期控制
- **敏感信息脱敏**：日志和 API 返回不包含密码

### 5.2 密码验证逻辑

```go
// 前端提交
encryptedPassword = AES_GCM_ENCRYPT(password, SHA256(loginSalt + timestamp))

// 后端验证
password = AES_GCM_DECRYPT(encryptedPassword, SHA256(loginSalt + timestamp))

// 对比
if serverHash == storedPasswordHash {
    // 验证通过
}
```

## 6. 安全机制

### 6.1 密码加密

**存储过程**：
```go
// 1. 生成随机盐值
salt := crypto.GenerateSalt()

// 2. 保存 SHA256(password + salt)
passwordHash := crypto.HashPassword(password, salt)

// 3. 存储 passwordHash 和 salt
user.PasswordHash = string(passwordHash)
user.Salt = salt
```

**验证过程**：
```go
// 1. 使用 login salt + timestamp 派生 AES-GCM 解密密钥
key := crypto.DeriveEncryptionKey(loginSalt, timestamp)

// 2. 解密客户端提交的 password_hash 字段，得到明文密码
password := AESGCMDecrypt(req.PasswordHash, key)

// 3. 用用户盐值重新计算 SHA256(password + userSalt)，与数据库哈希比较
ok := crypto.VerifyPasswordHash(password, userSalt, storedPasswordHash)
```

### 6.2 登录保护

**失败计数**：
```go
// 缓存键
key := fmt.Sprintf("login_attempt:%s:%s", username, clientIP)

// 记录失败次数
attempts := cache.Get(key)
attempts++
cache.Set(key, attempts, 15*time.Minute)

// 检查是否超过限制
if attempts >= 5 {
    // 锁定账户 15 分钟
    return "账户已被锁定"
}
```

**锁定时间**：
- 默认：15 分钟
- 可配置：`gateway.yaml` 的 `security.lock_duration`

### 6.3 重放攻击防护

**时间戳验证**：
```go
// 检查时间戳有效性
if time.Now().Unix() - timestamp > 300 { // 5 分钟
    return "请求已过期"
}
```

登录盐值保存在 BadgerDB，并按 TTL 过期；`GetLoginSalt` 会复用仍有足够剩余有效期的盐值，剩余时间过短时重新生成。

### 6.4 JWT 安全

**令牌结构**：
```go
type JWTClaims struct {
    UserID    string          `json:"user_id"`
    Username  string          `json:"username,omitempty"`
    Role      int32           `json:"role,omitempty"`
    TokenType crypto.TokenType `json:"token_type"`
    jwt.RegisteredClaims
}
```

**过期时间**：
- 默认：24 小时
- 可配置：`config.JWT.AccessExpired`

**签名算法**：
- HS256（HMAC + SHA256）

### 7.4 JWT 验证

**在统一 HTTP 转发层（gateway）的 authorize filter 中验证**：

auth 模块已不再使用 Gin 中间件做鉴权。控制台请求经统一 HTTP 转发层（`/api/admin/{service}/{method}`）进入，由 `internal/gateway/authorize.go` 的 `authorize` filter 统一校验 `Authorization` 头中的 access_token，并将用户元数据（user_id/username/role）注入请求 context，供下游 RPC 服务使用。

```go
import "github.com/mooyang-code/moox/modules/admin/internal/service/auth/utils"

// authorize filter 简化逻辑（实际实现见 internal/gateway/authorize.go）：
// 1. 从 HTTP Header 取 Authorization: Bearer <access_token>
// 2. utils.ValidateAccessToken(token, secretKey) 校验并解析 claims
// 3. 校验失败 → 返回 ret_info.code = ErrorCode_NO_AUTH 的鉴权失败响应
// 4. 校验通过 → 将 user_id/username/role 写入 ctx，调用 next 继续分发到 RPC 服务
//
// 免鉴权方法（如 Register/GetLoginSalt/Login）在 gateway.yaml 的 no_auth_methods 中配置放行。
```

下游 RPC 服务可通过 `utils.GetUserInfoFromCtx(ctx)` 获取当前用户 ID、用户名和角色。

## 11. 最佳实践

### 11.1 密码策略

```go
// 密码复杂度验证
func ValidatePassword(password string) error {
    if len(password) < 8 {
        return errors.New("密码长度至少 8 位")
    }
    if !regexp.MustCompile(`[a-z]`).MatchString(password) {
        return errors.New("密码必须包含小写字母")
    }
    if !regexp.MustCompile(`[A-Z]`).MatchString(password) {
        return errors.New("密码必须包含大写字母")
    }
    if !regexp.MustCompile(`[0-9]`).MatchString(password) {
        return errors.New("密码必须包含数字")
    }
    return nil
}
```

### 11.2 JWT 生命周期

当前 AuthService 只签发访问令牌，过期后客户端需要重新登录。协议中没有 `RefreshToken` RPC，配置中也不保留 refresh token 过期时间。

### 11.3 日志审计

```go
// 记录所有认证相关操作
log.InfoContextf(ctx, "[Auth] User %s login from %s", username, clientIP)

log.InfoContextf(ctx, "[Auth] User %s changed password", userID)
```

### 11.4 错误处理

```go
// 统一错误返回，不泄露敏感信息
if err != nil {
```

## 13. 常见问题

### 13.1 登录失败"盐值无效"

**原因**：
- 盐值已过期（5 分钟）
- 盐值已使用
- 客户端时钟不准

**解决**：
- 重新获取盐值
- 同步系统时间

### 13.2 JWT 验证失败

**原因**：
- Token 已过期
- 签名密钥不匹配
- Token 格式错误

**解决**：
- 重新登录获取新 Token
- 检查服务端配置

### 13.3 账户被锁定

**原因**：
- 连续登录失败次数过多

**解决**：
- 等待 15 分钟后自动解锁
- 管理员手动解锁（清除缓存）
