# 认证与鉴权

MooX 将人机控制面和机器控制面分开：

| API | 调用方 | 公开入口 | 鉴权 |
| --- | --- | --- | --- |
| `/api/admin/*` | 浏览器和交互式管理用户 | `https://<host>:9527` | 24 小时 JWT + 会话请求 HMAC |
| `/api/service/*` | Collector、Factor、Trade、CloudRuntime/SCF 等后台运行时 | `https://<host>:11001` | service HMAC |

前端代码禁止调用 `/api/service/*`。浏览器不直连 Admin 的 `11000`，后台服务调用也不经过 web-host 或 `9527`。

## 用户和密码

用户密码在服务端使用 bcrypt 存储。公开注册和在线改密 RPC 已移除；管理员由 CLI 在部署数据库中配置：

```bash
printf '%s\n' "$PASSWORD" | bin/moox-admin-cli user ensure --db-path data/admin.db --username admin --password-stdin
printf '%s\n' "$NEW_PASSWORD" | bin/moox-admin-cli user reset-password --db-path data/admin.db --username admin --password-stdin
```

CLI 只从标准输入读取密码，不应把密码放入命令行、日志或发布包。

## 登录和会话

1. `GetLoginSalt` 返回有效期默认 5 分钟的登录挑战。挑战在每次 `Login` 尝试时先消费，无论密码是否正确都不能重用。
2. 浏览器用挑战加密登录密码；挑战只保护登录交换，不替代登录后的请求防重放。
3. 登录成功返回默认 24 小时的 JWT、session id 和独立请求签名密钥。前端将 HMAC 密钥以不可导出的 Web Crypto `CryptoKey` 存入 IndexedDB。
4. 每个已登录的 `/api/admin/*` 请求同时提交 JWT、`X-Moox-Timestamp`、`X-Moox-Nonce` 和 `X-Moox-Signature`。签名覆盖方法、原始路径、原始 body 的 SHA-256、时间戳和 64 位小写十六进制 nonce。
5. Admin 校验时钟窗口并原子消费 nonce；会话过期、登出或重放都会失败。`Logout` 使当前 session 立即失效，不只是清理浏览器本地 token。

SSH WebSocket、SFTP 下载等无法按普通 JSON 请求签名的原始通道，先通过已签名的 `IssueRawSessionTicket` 获取默认 60 秒、绑定 session 和 operation 的一次性 ticket。

## Service HMAC

`/api/service/*` 使用 `moox-auth-v2` service HMAC，由 access key/secret key、时间戳、有效期、nonce 和请求内容防伪造与防重放。默认签名有效期为 60 秒、允许 30 秒时钟偏差；Admin 进程内原子消费 nonce。nonce 缓存不会跨 Admin 重启持久化，因此重启后的最坏重放窗口被限制在 90 秒内，调用方和服务端应保持 NTP 同步。远程调用必须同时校验 Caddy CA；同主机内部调用可按配置契约使用 `http://127.0.0.1:11002`。

## 健康端点

`/healthz`、`/readyz` 和 `/metrics` 位于独立内部监听端口，使用与 service HMAC 分离的 `X-Moox-Health-Auth`。缺失、过期或重放的 health HMAC 返回 `401`。公开 Caddy 端口不暴露诊断路由，而是返回 `404`。部署会生成 `secrets/health-auth.env`；这是配置契约，不应将密钥提交到仓库。

## 配置契约

`gateway.yaml` 定义 24 小时 session、请求 nonce 和 raw ticket 的默认时间；生产 JWT、service HMAC、health HMAC 和 Admin 加密密钥必须由部署环境注入。具体变量和证书操作见 [管理台 HTTPS 与证书](运维/管理台HTTPS与证书.md)。
