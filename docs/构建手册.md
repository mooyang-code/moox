# 构建手册

MooX 的所有二进制都在**你自己的机器上**构建：

- 纯 Go 的服务（绝大多数组件）用本机固定版本的 Go **交叉编译**成 `linux/amd64`，不需要 Docker；
- 只有 **Storage**（`storage`、`storage-primary`、`storage-node`、`storage-view`）依赖 DuckDB，需要 CGO，在本机的 **Docker 编译镜像**里构建；
- 前端和 Web Host 在本机用 Node 构建。

本手册面向两类读者：想自己搭环境的人，和**让 Agent 代劳**的人。后者只需要把本页交给 Agent，让它从“[让 Agent 搭环境](#让-agent-搭环境)”开始做。

## 1. 先检查环境

```bash
bash scripts/build/check-build-env.sh --profile all      # 人看的表格
bash scripts/build/check-build-env.sh --profile all --json   # Agent 解析用
```

脚本逐项列出已有、缺少、版本不符、Docker 没运行的工具，并按**本机的操作系统和包管理器**给出“修复”命令；全部通过时退出码为 0。
`--profile` 可以只检查你要做的事：

| 场景 | 要做的事 | 需要 |
| --- | --- | --- |
| `build` | 构建纯 Go 的 Linux 二进制 | Git、固定版本的 Go、SHA-256 工具 |
| `cgo` | 再加上构建 Storage | + Docker 在运行，可用内存 ≥ 4 GB |
| `web` | 再加上构建前端与 Web Host | + Node（`^20.19 \|\| ^22.13 \|\| ≥24`）、pnpm |
| `verify` | 推送前本地预检（`scripts/ci/local-verify.sh`） | + make、真正的 `rg`、Python 3 + PyYAML、jq、rsync、Node、pnpm |
| `release` | 发布到线上主机 | + Docker、ssh、scp |
| `all` | 以上全部（默认） | — |

固定的 Go 版本写在仓库根的 `.go-version`，**构建脚本要求与它完全一致**（不接受更新或更旧的版本，也不会联网下载 toolchain）。

## 2. 各系统怎么准备

### macOS

```bash
# 基础工具（Apple 芯片和 Intel 都一样）
xcode-select --install                      # git、make
brew install ripgrep jq python node@24 pnpm  # 只需要 verify / web 场景时
python3 -m pip install --user pyyaml        # verify 场景

# 固定版本的 Go：装到 ~/.local/go<版本>，不影响系统里已有的 Go
bash scripts/build/install-go.sh

# Storage 需要 Docker：用 colima（命令行、免图形界面和许可确认）；Docker Desktop / OrbStack 也可以
brew install colima docker
colima start --vm-type vz --cpu 4 --memory 8
```

Apple 芯片上不需要 x86 模拟：编译镜像里是 arm64 的编译器，用交叉编译器产出 `linux/amd64`。

### Linux（Debian / Ubuntu / RHEL / Fedora / Arch 等）

```bash
# Debian / Ubuntu
sudo apt-get install -y git make curl ripgrep jq rsync python3 python3-pip python3-yaml
# RHEL / Fedora
sudo dnf install -y git make curl ripgrep jq rsync python3 python3-pip python3-pyyaml

bash scripts/build/install-go.sh            # 固定版本的 Go

# Storage 需要 Docker
sudo apt-get install -y docker.io           # RHEL 系：sudo dnf install -y docker && sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"             # 重新登录后生效

# Node 24（发行版自带的通常太旧）：用 nvm 或 NodeSource，见 https://nodejs.org/en/download
corepack enable && corepack prepare pnpm@10.28.2 --activate
```

### Windows

构建脚本是 bash 写的，在 Windows 上要在 **WSL2（推荐）** 或 **Git Bash** 里运行。

```powershell
# 先在 PowerShell 里检查 Windows 一侧有没有这些入口
powershell -ExecutionPolicy Bypass -File scripts\build\check-build-env.ps1

# 推荐：WSL2 + Ubuntu，之后在 Ubuntu 里按上面“Linux”一节操作
wsl --install -d Ubuntu                       # 管理员权限，装完重启

# 备选：Git Bash
winget install --id Git.Git -e

# Storage 需要 Docker Desktop，并打开 WSL2 后端和对应发行版的 WSL 集成
winget install --id Docker.DockerDesktop -e
```

进入 WSL 或 Git Bash 后，运行 `bash scripts/build/check-build-env.sh --profile all` 做完整检查。
Git Bash 没有 rsync，`verify` / `release` 场景请用 WSL。

## 3. 构建

```bash
# 构建 linux/amd64 二进制：纯 Go 的在本机交叉编译，含 CGO 的（Storage）进 Docker；产物默认在 bin/
bash scripts/build/build-linux-local.sh admin monitor collector storage-primary

# 指定输出目录
bash scripts/build/build-linux-local.sh --out /tmp/moox-bin storage

# 当前系统自己用的二进制（不是 Linux 版）
./scripts/build/build.sh admin
```

- 构建目标就是 `scripts/build/build.sh` 的目标名；`build-linux-local.sh` 会按目标自动选择“本机交叉编译”还是“Docker”。
- 脚本在 stdout 打印 `BUILT:<文件名>:<sha256>`，进度走 stderr；只列出**这次新产出**的文件，没有新产物会直接报错，不会把旧文件当成成果。
- 版本信息取当前提交（也可用 `VERSION`、`GIT_COMMIT` 环境变量覆盖）。
- `make build-storage-linux` 等价于构建 `storage`；`moox-cli setup build-linux --module storage` 同样调用这个脚本。
- 前端与 Web Host：`web/` 下 `pnpm install && pnpm build`，再到 `web-host/` 下 `make statik && make build-linux`。

### Storage 的编译镜像

第一次构建 Storage 时脚本会自动构建镜像 `moox-linux-cgo-builder:go<版本>-<摘要>`（Ubuntu 22.04 + 固定版本的 Go + gcc），之后复用；
Dockerfile 或 `.go-version` 变了会按新的标签重建。选 Ubuntu 22.04 做基础，是为了让产物依赖的 glibc / libstdc++ 版本较低，能在更新的线上系统上运行。
源码和产物都通过 tar 管道进出容器，不依赖主机目录能否被 Docker 挂载（colima 默认只共享 `$HOME`，远程 Docker 更是完全没有共享），所以输出目录可以放在任何位置。
Go 模块缓存和编译缓存放在 Docker 卷 `moox-go-mod-cache`、`moox-go-build-cache` 里，重复构建很快（镜像和缓存都在时，构建 Storage 只要几秒）。

升级 `.go-version` 时要同步更新 `scripts/build/docker/go-sha256.txt` 里两条 Linux 安装包的 SHA-256（来源 `https://golang.google.cn/dl/?mode=json`），
`scripts/test/contract/test-build-linux-local.sh` 会检查这一点。

### 国内网络

GitHub、Docker Hub 等直连很慢时：

| 场景 | 做法 |
| --- | --- |
| 下载 Go | `install-go.sh` 默认就用官方国内镜像 `golang.google.cn/dl`；可用 `MOOX_GO_DL_BASE` 改 |
| Go 模块 | 构建 Storage 的容器默认用 `https://mirrors.tencent.com/go,direct`；可用 `MOOX_BUILD_GOPROXY` 改；本机构建设 `GOPROXY` |
| 镜像里的 apt | `MOOX_BUILD_APT_MIRROR=http://mirrors.aliyun.com`（中科大、清华的 http 镜像也行）。必须是**不跳转 https** 的 http 镜像：基础镜像里还没有 ca-certificates，https 源取不到索引（软件包有 GPG 签名校验）；腾讯云镜像会强制跳转 https，不能用 |
| Homebrew | 设 `HOMEBREW_API_DOMAIN` 与 `HOMEBREW_BOTTLE_DOMAIN` 指向清华镜像；**镜像在国内时直连比走本机代理快得多**，下载前取消 `HTTPS_PROXY` |
| 拉取 Docker 基础镜像 | Docker Hub 直连不通（域名会被解析到错误地址）。给 Docker 配置可用的 `registry-mirrors`：colima 在 `~/.colima/default/colima.yaml` 的 `docker:` 段写 `registry-mirrors: [https://docker.m.daocloud.io, https://docker.1ms.run]`，再 `colima restart`；用 `curl -s -o /dev/null -w '%{http_code}' https://<镜像>/v2/` 返回 401 说明镜像可用 |
| colima 虚拟机镜像 | 第一次 `colima start` 会从 GitHub 下载约 330 MB 的镜像；太慢时经 `ghfast.top` 之类的镜像站下载 `colima-core` 发布的 `ubuntu-24.04-minimal-cloudimg-<arch>-docker.raw.gz`，校验 SHA-512 后用 `colima start --disk-image <本地文件>` |
| colima 首次启动很久 | 虚拟机第一次启动要 `apt-get update` 并装 rsync，国内访问 ubuntu 源很慢，会超过 colima 的 10 分钟等待而报 `did not receive an event with the running status`。虚拟机其实还在后台继续：用 `LIMA_HOME=~/.colima/_lima limactl shell colima cloud-init status` 看到 `done` 后，`colima stop -f && colima start` 一次即可，之后启动只要几秒 |
| colima 虚拟机里解析不了域名 | 精简镜像没有 systemd-resolved，`/etc/resolv.conf` 是悬空链接。在 `colima.yaml` 的 `provision:` 里加一段系统脚本，缺失时写入 `nameserver 223.5.5.5`，或进虚拟机手动写一次（`LIMA_HOME=~/.colima/_lima limactl shell colima sudo sh -c 'printf "nameserver 223.5.5.5\n" > /etc/resolv.conf'`） |
| 构建镜像时 apt 失败 | 见上一行的 `MOOX_BUILD_APT_MIRROR`；报 `Unable to locate package` 通常是 apt 源取不到索引（https 源没有证书、或镜像把 http 跳转到 https） |
| `docker build` 提示 legacy builder | 装 `docker-buildx`（`brew install docker-buildx`），并在 `~/.docker/config.json` 加 `"cliPluginsExtraDirs": ["/opt/homebrew/lib/docker/cli-plugins"]`；不装也能构建，只是有一条弃用提示 |

## 4. 常见问题

- **`构建没有产出新的二进制`**：目标名写错，或 Go 版本与 `.go-version` 不一致。先跑 `check-build-env.sh`。
- **`含 CGO 的目标需要 Docker`**：安装并启动 Docker（macOS：`colima start`）；只构建纯 Go 目标时不需要。
- **`Docker 没有在运行`**：macOS 上 `colima status` 看状态；Linux 上 `systemctl status docker`，并确认当前用户在 `docker` 组里。
- **Go 版本“不符”**：系统里的 Go 不是 `.go-version` 指定的版本。运行 `bash scripts/build/install-go.sh`，构建脚本会自动优先使用 `~/.local/go<版本>/bin`。
- **容器里编 Storage 很慢或内存不足**：给 Docker 至少 4 GB 内存（colima：`colima stop && colima start --memory 8`）。
- **shell 里的 `rg` 不生效**：`rg` 是 shell 函数或别名时，make 和脚本看不到它；装真正的 ripgrep 可执行文件。
- **前端测试报 `ERR_REQUIRE_ESM`**：Node 低于 22.13，升级到 24。

## 让 Agent 搭环境

把下面这段交给 Agent：

> 请在这个仓库里搭好 MooX 的构建环境。先读 `docs/构建手册.md`，然后：
> 1. 运行 `bash scripts/build/check-build-env.sh --profile all --json`（Windows 先运行 `scripts\build\check-build-env.ps1`，再进入 WSL 或 Git Bash）；
> 2. 对 `status` 不是 `ok` 的每一项，执行它的 `fix` 命令；需要管理员密码的命令让我自己在终端里输入，不要索取或记录我的密码；
> 3. 重新运行检查，直到 `ok` 为 `true`；
> 4. 运行 `bash scripts/build/build-linux-local.sh admin` 验证能构建，需要 Storage 时再构建 `storage-primary`；
> 5. 把做过的事和还缺的事告诉我。

Agent 需要知道的规则：

- 检查脚本的 `fix` 字段已经按本机系统和包管理器选好命令；没有把握的项给出的是指引而不是命令，照指引处理，不要编造。
- Go 必须装成 `.go-version` 的版本，用 `install-go.sh`，不要用 `brew install go` 或发行版的 Go。
- 安装需要管理员权限的软件（`sudo`、系统安装包）前先告诉用户，并由用户输入密码；不要绕过校验（不要 `curl -k`，不要关掉 SHA-256 校验）。
- Docker 在 macOS 上优先 colima；用户已经装了 Docker Desktop 或 OrbStack 就直接用，不要再装一套。
- 国内网络下载慢，先按上面的“国内网络”一节换镜像，不要反复重试直连。

## 5. 发布

构建好的二进制怎么上线见[原生部署的发布流程](https://github.com/mooyang-code/moox/blob/main/skills/moox/references/native-release.md)；
`native-release.sh build <目标>` 会调用 `build-linux-local.sh`，在本机构建、校验 sha，然后用 `install` 逐台安装并重启。
部署形态和日常运维见[部署与运维](部署与运维.md)，推送前的本地预检见 `scripts/ci/local-verify.sh`。
