# Trade 交易模块功能说明

Trade 是 MooX 的交易事实源和交易执行入口，负责账户接入、订单执行、成交结算、资金账本、仓位、撤单换单、目标仓位调仓和交易运维控制。

## 使用边界

- 当前系统面向个人使用，数据按 Space 隔离，不区分管理员和普通成员。
- Trade 自有数据库保存交易事实；Storage 只提供行情或市场快照，不保存订单、成交、账本和仓位。
- 当前仅允许真实交易通道。模拟交易没有专用适配器时会安全拒绝，不会回退到实盘。
- 项目尚未上线，不提供旧 Trade 数据兼容和迁移。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 账户管理 | 创建、更新、删除和查询交易账户，同步交易所账户与余额。 |
| API 凭证 | 管理交易所 API Key、Secret 和 Passphrase；敏感值加密保存且不回显。 |
| 交易通道 | 绑定账户、凭证、交易所和市场类型，支持连通性测试与交易规则查询。 |
| 下单 | 支持幂等订单意图、资金预留、异步提交和明确的订单状态机。 |
| 撤单 | 先持久化撤单意图，再调用交易所；结果不确定时先查询交易所事实。 |
| 改单 | 通过“撤单后重新下单”的持久化 Saga 实现，避免原单和替代单同时暴露。 |
| 成交结算 | Binance/OKX 私有 WebSocket 实时接收成交，REST 对账补齐断线缺口。 |
| 资金账本 | 使用双式账本记录冻结、解冻、成交、手续费、保证金和对账调整。 |
| 余额与仓位 | 在成交事务中同步更新余额和仓位投影，支持查询与重建。 |
| 目标仓位调仓 | 支持 `FULL` 和 `PATCH` 目标，反向仓位自动拆为先平仓、后开仓。 |
| 运维控制 | 支持暂停账户/通道、立即对账、检查撤单换单 Saga。 |
| 可观测性 | 提供健康检查、Prometheus 指标和跨 RPC/EventBus 的 TraceContext。 |

## 订单执行

### 下单

1. 校验价格、数量、方向、市场和账户/通道暂停状态。
2. 按现货或合约资金模型预留资金。
3. 在同一事务中保存订单、账本变更和 Outbox 消息。
4. EventBus durable consumer 调用交易所。
5. 根据结果进入 `OPEN`、`REJECTED` 或 `SUBMIT_UNKNOWN`。

客户端应提供稳定的 `client_order_id`。相同 Space 下重复提交同一 ID 时，Trade 返回已有订单，不会重复下单。

### 结果不确定

网络超时不等于交易所没有接收订单。Trade 在 `SUBMIT_UNKNOWN` 或 `CANCEL_UNKNOWN` 状态下会先按 `client_order_id` 查询交易所；只有交易所明确返回订单不存在时，才使用相同 ID 安全重试。

### 撤单换单

改单使用以下 Saga：

```text
CANCEL_REQUESTED
  -> CANCEL_CONFIRMED
  -> REPLACEMENT_CREATED
  -> REPLACEMENT_SUBMITTED
```

任一步结果不确定都会持久化。进程重启后从原状态继续，不会跳过撤单确认直接创建替代单。

## 成交、资金与仓位

### 成交来源

- 主路径：Binance/OKX 鉴权私有 WebSocket。
- 补偿路径：有界 REST `ListFills` 和订单状态对账。

两条路径统一进入 `FillHandler`。成交按 Space、账户、通道、交易对和交易所成交号幂等，因此 WebSocket 重发与 REST 补录不会重复结算。

### 资金模型

- 现货买入冻结报价资产。
- 现货卖出冻结基础资产。
- 合约开仓预留报价资产保证金，成交后转入 `margin` bucket。
- 合约 `reduce_only` 不冻结基础资产。
- 余额同步保留本地在途 `frozen` 和 `margin`，不会覆盖未完成订单的预留资金。

每笔账本事务必须借贷平衡。余额不足时下单事务整体回滚，订单不会落库。

## 目标仓位调仓

`RebalanceSvc` 根据当前仓位和目标仓位生成确定性 legs：

- `FULL`：未出现在目标中的现有仓位也会被平掉。
- `PATCH`：只调整请求中出现的交易对。
- 仓位反转：拆为 `reduce_only` 平仓 leg 和依赖它的开仓 leg。
- 每个 leg 复用普通订单内核，因此共享资金校验、成交结算、幂等和恢复能力。

调仓请求由 `trade_rebalance_v1` 消费；成交后由 `trade_progress_v1` 推进依赖 legs。定时扫描只负责故障恢复。

## 运维接口

`TradeOpsSvc` 监听 `11212`：

| 方法 | 用途 |
| --- | --- |
| `SetPause` | 按账户或通道暂停/恢复新单；已有订单仍允许成交和撤销。 |
| `ReconcileNow` | 经 Outbox/EventBus 发起限定 Space、账户和通道的立即对账。 |
| `InspectSaga` | 查询撤单换单 Saga 的状态、版本、关联订单和最后错误。 |

具体排障步骤见 [MooX Trade 运维](运维/MooX-Trade运维.md)。

## 服务入口

| 端口 | 服务 |
| --- | --- |
| `11200-11208` | 账户、余额、资金、凭证、通道、交易操作、订单、成交和仓位。 |
| `11211` | `RebalanceSvc` 目标仓位调仓。 |
| `11212` | `TradeOpsSvc` 运维控制。 |
| `11210` | 健康检查与指标相关入口。 |

所有业务接口均通过 Admin 网关的 `trade_*` deployment 转发。
